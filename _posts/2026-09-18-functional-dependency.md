`Functional Dependency`는 <mark>하나의 Attribute 값이 정해지면 다른 Attribute 값이 하나로 결정되는 관계</mark>입니다.

정규화에서는 어떤 Attribute가 다른 Attribute를 결정하는지를 분석하는 것이 매우 중요합니다.

<blockquote class="prompt-info">
<p>한 줄: A가 정해지면 B가 하나로 결정될 때 B는 A에 함수적으로 종속됩니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

결정자 값이 같으면 종속자의 값도 항상 같아야 합니다.

</details>

## 기본 개념

다음과 같은 학생 Table이 있다고 가정합니다.

| 학생번호 | 이름 | 학과 |
| --- | --- | --- |
| 1001 | 학생1 | 컴퓨터공학 |
| 1002 | 학생2 | 통계학 |
| 1003 | 학생3 | 컴퓨터공학 |

학생번호가 하나 정해지면 이름과 학과가 하나로 결정됩니다.

```text
학생번호
→ 이름

학생번호
→ 학과
```

이때 학생번호는 **결정자**, 이름과 학과는 **종속자**입니다.

## 결정자와 종속자

함수적 종속은 다음처럼 표현합니다.

```text
A → B
```

의미는 다음과 같습니다.

```text
A
→ 결정자

B
→ 종속자
```

즉, A 값이 같다면 B 값도 같아야 합니다.

## 예시

다음 Table을 보겠습니다.

| 학번 | 이름 | 학과 |
| --- | --- | --- |
| 1001 | 학생1 | 컴퓨터공학 |
| 1002 | 학생2 | 통계학 |
| 1003 | 학생3 | 컴퓨터공학 |

다음 관계는 성립합니다.

```text
학번 → 이름
학번 → 학과
```

하지만 다음 관계는 일반적으로 성립하지 않습니다.

```text
학과 → 이름
```

같은 학과에 여러 학생이 있을 수 있기 때문입니다.

## 함수적 종속 판단

함수적 종속 여부는 <mark>결정자 값이 같을 때 종속자 값이 항상 같은지</mark>를 보면 됩니다.

### 예시

| 학과 | 학과장 |
| --- | --- |
| 컴퓨터공학 | 교수1 |
| 통계학 | 교수2 |
| 경영학 | 교수3 |

학과 하나에 학과장이 한 명이라고 가정하면 다음 관계가 성립합니다.

```text
학과
→ 학과장
```

학과가 정해지면 학과장이 하나로 결정되기 때문입니다.

## 완전 함수 종속

복합 Key 전체가 있어야 종속자의 값이 결정되는 경우입니다.

### 예시 · 수강

| 학생번호 | 강의번호 | 성적 |
| --- | --- | --- |
| 1001 | C01 | A |
| 1001 | C02 | B |
| 1002 | C01 | A |

Primary Key가 다음과 같다고 가정합니다.

```text
학생번호 + 강의번호
```

성적은 두 Attribute가 모두 있어야 하나로 결정됩니다.

```text
학생번호 + 강의번호
→ 성적
```

학생번호만으로는 성적을 알 수 없습니다.

강의번호만으로도 성적을 알 수 없습니다.

따라서 성적은 복합 Key 전체에 완전 함수 종속됩니다.

```text
복합 Key 전체
→ 종속자 결정
```

## 부분 함수 종속

복합 Key 전체가 아니라 일부 Attribute만으로도 종속자의 값이 결정되는 경우입니다.

### 예시

| 학생번호 | 강의번호 | 학생이름 | 성적 |
| --- | --- | --- | --- |
| 1001 | C01 | 학생1 | A |
| 1001 | C02 | 학생1 | B |
| 1002 | C01 | 학생2 | A |

Primary Key가 다음이라고 가정합니다.

```text
학생번호 + 강의번호
```

하지만 학생이름은 학생번호만 알면 결정됩니다.

```text
학생번호
→ 학생이름
```

즉, 복합 Key의 일부인 학생번호만으로 학생이름이 결정됩니다.

```text
부분 함수 종속
→ 복합 Key 일부에만 종속
```

<blockquote class="prompt-warning">
<p>부분 함수 종속은 복합 Key가 있을 때 특히 중요하며 제2정규형과 직접 연결됩니다.</p>
</blockquote>

## 이행 함수 종속

A가 B를 결정하고 B가 C를 결정하여, 결과적으로 A가 C를 결정하는 관계입니다.

### 예시

| 학생번호 | 학과코드 | 학과명 |
| --- | --- | --- |
| 1001 | D01 | 컴퓨터공학 |
| 1002 | D02 | 통계학 |
| 1003 | D01 | 컴퓨터공학 |

다음 관계가 있다고 가정합니다.

```text
학생번호
→ 학과코드

학과코드
→ 학과명
```

그러면 다음 관계도 성립합니다.

```text
학생번호
→ 학과명
```

하지만 학과명은 학생번호가 직접 결정한다기보다 학과코드를 거쳐 결정됩니다.

```text
학생번호
→ 학과코드
→ 학과명
```

이런 관계를 이행 함수 종속이라고 합니다.

## 완전 · 부분 · 이행 비교

| 구분 | 핵심 |
| --- | --- |
| 완전 함수 종속 | 복합 Key 전체가 필요 |
| 부분 함수 종속 | 복합 Key 일부만으로 결정 |
| 이행 함수 종속 | 다른 Attribute를 거쳐 결정 |

```text
완전
A + B → C
A만으로 X
B만으로 X
```

```text
부분
A + B가 Key인데
A → C
```

```text
이행
A → B
B → C
따라서 A → C
```

## 정규화와 연결

함수적 종속은 정규화를 이해하는 핵심 기준입니다.

```text
부분 함수 종속 제거
→ 제2정규형
```

```text
이행 함수 종속 제거
→ 제3정규형
```

즉, Table 안에 어떤 함수적 종속이 존재하는지를 찾는 것이 정규화의 출발점입니다.

## Primary Key와 함수적 종속

Primary Key는 각 Row를 고유하게 식별하므로 일반적으로 다른 Attribute들을 결정합니다.

### 예시

| 고객번호 | 이름 | 지역 |
| --- | --- | --- |
| C001 | 고객1 | 서울 |
| C002 | 고객2 | 부산 |

```text
고객번호
→ 이름

고객번호
→ 지역
```

고객번호가 하나 정해지면 해당 고객의 이름과 지역이 하나로 결정됩니다.

## 잘 놓치는 핵심

### 1. 함수적 종속은 값의 크기 관계가 아니다

```text
A → B
```

는 A가 B보다 크다는 뜻이 아닙니다.

A가 정해지면 B가 하나로 결정된다는 뜻입니다.

### 2. 같은 결정자에는 같은 종속자 값이 와야 한다

결정자 값은 같은데 종속자 값이 다르다면 해당 함수적 종속은 성립하지 않습니다.

### 3. 부분 함수 종속은 복합 Key에서 확인한다

복합 Key 일부만으로 일반 Attribute가 결정되는지 봅니다.

### 4. 이행 함수 종속은 중간 Attribute를 거친다

```text
A → B → C
```

형태를 찾으면 됩니다.

## 시험·면접

### 핵심 암기

```text
A → B
→ A가 B를 결정
```

```text
결정자
→ 왼쪽
```

```text
종속자
→ 오른쪽
```

```text
부분 함수 종속
→ 복합 Key 일부
→ 제2정규형과 관련
```

```text
이행 함수 종속
→ A → B → C
→ 제3정규형과 관련
```

### 시험 함정

함수적 종속은 현재 Table에 우연히 중복값이 없다고 해서 무조건 성립하는 것이 아닙니다.

업무 규칙상 결정자 값 하나에 종속자 값 하나가 대응되어야 합니다.

### 면접 짧은 답변

함수적 종속은 하나의 Attribute 값이 정해졌을 때 다른 Attribute 값이 하나로 결정되는 관계입니다. `A → B`로 표현하며 A를 결정자, B를 종속자라고 합니다. 복합 Key의 일부에만 종속되면 부분 함수 종속, 다른 Attribute를 거쳐 종속되면 이행 함수 종속이라고 하며 각각 제2정규형과 제3정규형에서 중요합니다.

## 객관식 문제

### 문제 1 · 기본 개념

다음 표현의 의미로 옳은 것은?

```text
학번 → 이름
```

① 이름이 학번보다 크다.  
② 학번이 정해지면 이름이 하나로 결정된다.  
③ 이름이 학번을 삭제한다.  
④ 학번과 이름은 관계가 없다.

<details markdown="1">
<summary>정답</summary>

②

학번 하나가 정해지면 해당 학생의 이름이 하나로 결정된다는 뜻입니다.

</details>

### 문제 2 · 결정자

다음 함수적 종속에서 결정자는?

```text
고객번호 → 고객이름
```

① 고객번호  
② 고객이름  
③ 둘 다 종속자  
④ 없음

<details markdown="1">
<summary>정답</summary>

①

화살표 왼쪽에 있는 Attribute가 결정자입니다.

</details>

### 문제 3 · 부분 함수 종속

Primary Key가 `학생번호 + 강의번호`이고 다음 관계가 있을 때 부분 함수 종속은?

```text
학생번호 → 학생이름
```

① 완전 함수 종속  
② 부분 함수 종속  
③ 이행 함수 종속  
④ 함수적 종속이 아님

<details markdown="1">
<summary>정답</summary>

②

복합 Key 전체가 아니라 일부인 학생번호만으로 학생이름이 결정되므로 부분 함수 종속입니다.

</details>

### 문제 4 · 이행 함수 종속

다음 관계에서 나타나는 종속은?

```text
학생번호 → 학과코드
학과코드 → 학과명
```

① 부분 함수 종속만 존재  
② 이행 함수 종속  
③ 함수적 종속이 없음  
④ Cardinality

<details markdown="1">
<summary>정답</summary>

②

학생번호가 학과코드를 거쳐 학과명을 결정하므로 이행 함수 종속이 존재합니다.

```text
학생번호
→ 학과코드
→ 학과명
```

</details>

### 문제 5 · 정규화

부분 함수 종속 제거와 가장 직접적으로 관련된 것은?

① 제1정규형  
② 제2정규형  
③ 제3정규형  
④ 반정규화

<details markdown="1">
<summary>정답</summary>

②

제2정규형에서는 복합 Key에 대한 부분 함수 종속을 제거하는 것이 핵심입니다.

</details>

## Functional Dependency 전체 요약

| 개념 | 핵심 |
| --- | --- |
| 함수적 종속 | 결정자 값이 정해지면 종속자 값이 결정 |

| 종속자 | 화살표 오른쪽 |

| 부분 함수 종속 | 복합 Key 일부에 종속 |
| 이행 함수 종속 | 중간 Attribute를 거쳐 종속 |

```text
A → B
→ A가 B를 결정
```

```text
부분 함수 종속
→ 제2정규형
```

```text
이행 함수 종속
→ 제3정규형
```

<blockquote class="prompt-danger">
<p>함수적 종속 문제에서는 먼저 결정자와 종속자를 찾고, 복합 Key 일부에만 종속되는지 또는 중간 Attribute를 거치는지 확인합니다.</p>
</blockquote>
