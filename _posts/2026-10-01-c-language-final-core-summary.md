C 언어는 **값보다 객체·주소·수명·자료형의 관계를 직접 다루는 언어**입니다.

문법은 작지만 배열, 문자열, 함수 호출, 동적 메모리까지 결국 포인터와 객체 모델로 연결됩니다.

<blockquote class="prompt-info">
<p>한 줄: C의 핵심은 별표 개수를 외우는 것이 아니라 지금 어떤 객체를 어떤 자료형의 포인터로 가리키고 있는지 추적하는 것입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

포인터 → 배열 → 문자열 → 동적 메모리 → 함수 포인터 → 객체 수명 → 정의되지 않은 동작 순서로 연결해서 이해하면 C 전체가 정리됩니다.

</details>

## 1. C다운 코딩 스타일

C 코드는 **메모리 소유권과 실패 처리**가 코드에 직접 드러나는 경우가 많습니다.

| 대표 표현 | 의미 |
| --- | --- |
| `int *p` | 정수 객체를 가리키는 포인터 |
| `sizeof *p` | 대상 자료형을 반복하지 않고 크기 계산 |
| `int **out` | 호출자의 포인터 자체를 변경 |
| `return 0` | 상태값으로 성공·실패 전달 |
| `NULL` 검사 | 포인터 유효성 검사 |
| `goto cleanup` | 여러 자원 해제를 한곳에 모음 |
| 헤더 + 소스 | 선언과 구현 분리 |

대표적인 할당 패턴입니다.

```c
int *p = malloc(n * sizeof *p);

if (p == NULL)
    return 1;
```

C에서는 `malloc` 반환값에 불필요한 형변환을 붙이지 않는 스타일이 일반적입니다.

## 2. C 선언자는 변수 이름부터 읽는다

| 선언 | 의미 |
| --- | --- |
| `int *p` | `int` 포인터 |
| `int **pp` | `int *`를 가리키는 포인터 |
| `int *a[3]` | `int *` 3개짜리 배열 |
| `int (*p)[3]` | `int[3]` 배열 포인터 |
| `int (*fp)(int)` | 정수를 받고 정수를 반환하는 함수 포인터 |
| `int *(*fp)(int)` | 정수를 받고 `int *`를 반환하는 함수 포인터 |
| `int (*f(void))[3]` | `int[3]` 배열 포인터를 반환하는 함수 |

가장 중요한 구분입니다.

```c
int *a[3];
int (*p)[3];
```

첫 번째는 **포인터 배열**, 두 번째는 **배열 포인터**입니다.

<blockquote class="prompt-warning">
<p>함수 괄호와 배열 대괄호가 별표보다 강하게 결합하므로 괄호 하나가 전체 자료형을 바꿉니다.</p>
</blockquote>

## 3. 포인터의 본질과 포인터 연산

```c
int a[4] = {10, 20, 30, 40};
int *p = a;

p++;
```

이후:

```text
p → a[1] → 20
```

입니다.

`p + 1`은 1바이트가 아니라 **다음 `int` 원소**로 이동합니다.

포인터 산술은 원칙적으로 같은 배열 객체 내부 또는 한 칸 뒤 위치까지를 기준으로 생각합니다.

한 칸 뒤 포인터는 만들 수 있지만 역참조하면 안 됩니다.

## 4. 이중 포인터 `int **`

```c
int x = 10;
int *p = &x;
int **pp = &p;
```

구조:

```text
pp → p → x → 10
```

따라서:

```c
**pp = 30;
```

은 `x`를 30으로 바꿉니다.

이중 포인터의 핵심은 **포인터가 가리키는 값이 아니라 포인터 변수 자체를 함수에서 바꿀 수 있다는 것**입니다.

대표적인 사용처:

- 동적 메모리 주소를 함수 밖으로 전달
- 연결 리스트 머리 포인터 변경
- 트리 루트 포인터 교체
- 문자열 포인터 배열 처리
- 이중 포인터 자체를 자료구조로 사용

```c
int allocate(int **out)
{
    *out = malloc(sizeof **out);

    if (*out == NULL)
        return 0;

    **out = 100;
    return 1;
}
```

호출은 다음과 같습니다.

```c
int *p = NULL;
allocate(&p);
```

`&p`의 자료형이 `int **`입니다.

## 5. 삼중 포인터

```c
int ***ppp;
```

한 단계씩 읽으면 됩니다.

```text
ppp
→ int **
→ int *
→ int
```

역참조도:

```text
*p   → int **
**p  → int *
***p → int
```

입니다.

포인터 단계가 지나치게 늘어나면 구조체로 의미를 묶는 편이 유지보수에 좋습니다.

## 6. 배열과 포인터는 비슷하지만 같지 않다

```c
int a[5];
int *p = a;
```

배열 이름은 대부분의 식에서 첫 원소 포인터로 변환됩니다.

하지만 다음은 다릅니다.

```c
sizeof(a)
sizeof(p)
```

`sizeof(a)`는 배열 전체 크기이고 `sizeof(p)`는 포인터 객체 크기입니다.

배열이 포인터로 변환되지 않는 대표 상황은 다음과 같습니다.

- `sizeof(a)`
- `&a`
- 문자열 리터럴로 배열 초기화

## 7. `a[i]`의 정체

C에서:

```c
a[i]
```

는 포인터 관점에서:

```c
*(a + i)
```

와 연결됩니다.

따라서 포인터도 배열처럼 인덱싱할 수 있습니다.

```c
p[2]
```

는 `p`에서 두 원소 뒤를 역참조합니다.

## 8. 2차원 배열과 배열 포인터

```c
int a[3][4];
```

에서 `a`가 식에서 포인터로 변환되면 **정수 4개짜리 행을 가리키는 포인터**가 됩니다.

```c
int (*p)[4] = a;
```

```text
p     → a[0]
p + 1 → a[1]
p + 2 → a[2]
```

입니다.

`int **`와 `int (*)[4]`는 완전히 다른 자료형입니다.

## 9. 함수 매개변수 배열의 조정

함수 매개변수에서 다음 둘은 같은 방식으로 조정됩니다.

```c
void f(int a[]);
void f(int *a);
```

따라서 함수 안에서 `sizeof(a)`로 호출자의 원본 배열 전체 크기를 얻을 수 없습니다.

반면 다음은 배열 포인터입니다.

```c
void f(int (*a)[4]);
```

## 10. C의 특징적인 배열 문법

C에는 다음처럼 함수 배열 매개변수에 `static`을 쓸 수 있습니다.

```c
void process(size_t n, int a[static 10]);
```

호출자가 최소 10개의 `int`를 가리키는 포인터를 제공한다는 계약입니다.

또 C99에는 가변 길이 배열이 있습니다.

```c
void f(size_t n)
{
    int a[n];
}
```

C11 이후에는 구현에서 선택적일 수 있으므로 이식성이 필요하면 지원 여부를 확인합니다.

## 11. 문자열과 `\0`

```c
char s[] = "abc";
```

실제 배열:

```text
'a' 'b' 'c' '\0'
```

따라서:

```text
sizeof(s) → 4
strlen(s) → 3
```

입니다.

`strlen`은 `\0`을 만날 때까지 읽기 때문에 종료 문자가 없는 배열에는 사용하면 안 됩니다.

문자열 리터럴은 다음처럼 읽기 전용으로 다루는 것이 안전합니다.

```c
const char *p = "hello";
```

수정이 필요하면 배열로 만듭니다.

```c
char s[] = "hello";
```

## 12. `const` 네 가지

| 선언 | 포인터 이동 | 대상 수정 |
| --- | --- | --- |
| `int *p` | 가능 | 가능 |
| `const int *p` | 가능 | 불가 |
| `int * const p` | 불가 | 가능 |
| `const int * const p` | 불가 | 불가 |

다중 포인터에서는 단일 포인터의 `const` 규칙을 그대로 일반화하면 안 됩니다.

다음 변환은 안전한 단순 `const` 추가가 아닙니다.

```c
int **pp;
const int **cpp = pp;
```

반면 다음은 중간 포인터 객체를 읽기 전용으로 보는 중요한 형태입니다.

```c
int *p;
int * const *q = &p;
```

## 13. `restrict`와 `volatile`

`restrict`는 C의 대표적인 포인터 한정자입니다.

```c
void add(
    size_t n,
    int *restrict dst,
    const int *restrict src);
```

같은 수정 대상 객체를 독립적인 `restrict` 기반 접근 경로가 겹쳐 다루지 않는다는 계약에 사용됩니다.

표준 C++에는 `restrict` 키워드가 없습니다.

`volatile`은 값이 프로그램 코드 외부 요인에 의해 바뀔 수 있는 객체 접근에 사용됩니다.

```c
volatile unsigned int *reg;
```

하지만 `volatile`은 스레드 동기화 기능이 아닙니다.

## 14. 동적 메모리

| 함수 | 핵심 |
| --- | --- |
| `malloc` | 바이트 할당, 초기값 미정 |
| `calloc` | 개수 × 크기 할당, 바이트를 0으로 초기화 |
| `realloc` | 기존 할당 크기 변경 |
| `free` | 동적 할당 해제 |

안전한 `realloc` 패턴입니다.

```c
int *tmp = realloc(
    p,
    new_count * sizeof *p
);

if (tmp == NULL) {
    free(p);
    return 1;
}

p = tmp;
```

실패하면 기존 `p`는 여전히 유효합니다.

성공하면 이전 객체 내부를 가리키던 별칭 포인터를 계속 사용하지 말고 새 `p` 기준으로 다시 계산합니다.

## 15. `free`와 별칭 포인터

```text
p → 메모리
q ─┘
```

상태에서:

```c
free(p);
p = NULL;
```

을 해도 `q`까지 자동으로 `NULL`이 되지는 않습니다.

`q`는 해제된 저장소의 이전 주소값을 들고 있으며 역참조하면 안 됩니다.

## 16. 구조체·공용체·열거형·유연 배열 멤버

구조체:

```c
typedef struct {
    int x;
    int y;
} Point;
```

포인터 접근:

```c
p->x
```

은:

```c
(*p).x
```

와 연결됩니다.

공용체는 모든 멤버가 같은 저장 공간을 공유합니다.

```c
union Value {
    int i;
    float f;
};
```

열거형은 상태 상수를 표현할 때 자주 씁니다.

```c
enum State {
    READY,
    RUNNING,
    DONE
};
```

C의 유연 배열 멤버는 구조체 마지막에 둡니다.

```c
typedef struct {
    size_t n;
    int data[];
} Block;
```

할당:

```c
Block *p = malloc(
    sizeof *p
    + n * sizeof p->data[0]
);
```

표준 C++에는 같은 형태의 유연 배열 멤버가 없습니다.

## 17. `typedef`와 함수 포인터

`typedef`는 기존 자료형에 별칭을 붙입니다.

```c
typedef int (*Compare)(int, int);
```

함수 포인터는 콜백, 정렬 함수, 상태 기계, 명령 디스패치에 자주 사용합니다.

```c
int (*ops[3])(int, int) = {
    add,
    sub,
    mul
};
```

호출:

```c
result = ops[index](a, b);
```

입니다.

## 18. `void *`

`void *`는 객체 포인터를 일반화할 때 사용합니다.

C에서는 객체 포인터와 `void *` 사이 변환이 일반적으로 암시적으로 가능합니다.

그래서 다음처럼 씁니다.

```c
int *p = malloc(sizeof *p);
```

C++에서는 변환 규칙이 다릅니다.

## 19. 정수 승격과 부호 변환

작은 정수형은 산술 전에 `int` 등으로 승격될 수 있습니다.

```c
unsigned char a = 250;
unsigned char b = 20;

int x = a + b;
```

일반적인 환경에서는 중간 계산이 `int`에서 수행되어 `x`가 270이 됩니다.

부호 있는 정수와 부호 없는 정수를 섞으면 일반 산술 변환 때문에 음수가 큰 양수처럼 변환될 수 있습니다.

`sizeof` 결과 자료형은 `size_t`, 같은 배열 안 포인터 차이는 `ptrdiff_t`를 사용합니다.

## 20. 비트 연산

| 연산자 | 의미 |
| --- | --- |
| `&` | 비트 AND |
| `|` | 비트 OR |
| `^` | 비트 XOR |
| `~` | 비트 반전 |
| `<<` | 왼쪽 시프트 |
| `>>` | 오른쪽 시프트 |

비트 마스크, 플래그, 장치 제어, 자료구조 최적화에서 자주 등장합니다.

## 21. 전위·후위 증가와 시퀀싱

```c
++i
```

는 증가된 값을 식에서 사용합니다.

```c
i++
```

는 증가 전 값을 식의 값으로 사용합니다.

하지만 다음은 단순 계산 문제가 아닙니다.

```c
i++ + ++i
```

C17에서 정의되지 않은 동작입니다.

쉼표 연산자는 왼쪽을 먼저 완료한 뒤 오른쪽을 평가합니다.

```c
(i++, i + 1)
```

반면 함수 인자 구분 쉼표는 평가 순서를 보장하는 쉼표 연산자와 다릅니다.

## 22. 전처리기

대표 지시문:

```text
#include
#define
#if
#ifdef
#ifndef
#endif
```

매크로는 함수가 아니라 토큰 치환입니다.

```c
#define SQUARE(x) ((x) * (x))
```

처럼 괄호를 충분히 넣어야 하지만 다음은 여전히 위험합니다.

```c
SQUARE(i++)
```

전처리기에는 문자열화와 토큰 결합도 있습니다.

```c
#define STR(x) #x
#define JOIN(a, b) a##b
```

## 23. 저장 기간과 `static`, `extern`

| 상황 | 핵심 |
| --- | --- |
| 일반 지역 변수 | 블록 실행과 수명 연결 |
| `static` 지역 변수 | 프로그램 실행 동안 값 유지 |
| 파일 범위 `static` | 외부 연결 제한에 사용 |
| `extern` | 다른 번역 단위의 객체·함수 선언에 사용 |
| `_Thread_local` | 스레드별 저장 객체 |

`static`은 위치에 따라 의미가 다르다는 점이 중요합니다.

## 24. C의 특징적인 표준 문법

| 기능 | 핵심 |
| --- | --- |
| `_Generic` | 자료형에 따라 식 선택 |
| `_Static_assert` | 컴파일 시 조건 검사 |
| `_Atomic` | 원자 객체 선언 |
| 복합 리터럴 | 식 안에서 이름 없는 객체 생성 |
| 지정 초기화 | 멤버·배열 인덱스를 지정해 초기화 |
| 가변 길이 배열 | 실행 시 결정되는 배열 길이 |
| 유연 배열 멤버 | 구조체 마지막의 크기 없는 배열 |
| `restrict` | 포인터 별칭 접근 계약 |

복합 리터럴 예시:

```c
struct Point p =
    (struct Point){1, 2};
```

지정 초기화 예시:

```c
struct Point p = {
    .y = 20,
    .x = 10
};
```

배열 인덱스 지정도 가능합니다.

```c
int a[10] = {
    [3] = 7,
    [8] = 2
};
```

## 25. 정의되지 않은 동작을 먼저 찾는다

대표 예:

- 배열 범위 밖 역참조
- 해제한 메모리 사용
- 지역 변수 주소 반환 후 역참조
- 정수 0 나눗셈
- 문자열 리터럴 수정
- 겹치는 영역에 `memcpy`
- 시퀀싱되지 않은 같은 객체의 수정과 접근

구분도 중요합니다.

| 구분 | 의미 |
| --- | --- |
| 정의된 동작 | 표준이 결과 규정 |
| 구현 정의 | 구현이 선택하고 문서화 |
| 미지정 | 허용된 여러 결과 중 하나 |
| 정의되지 않은 동작 | 표준이 결과를 보장하지 않음 |

<mark>정의되지 않은 동작이면 특정 출력값부터 계산하면 안 됩니다.</mark>

## 26. `memcpy`, `memmove`, 객체 표현

`memcpy`는 원본과 목적지 범위가 겹치지 않아야 합니다.

겹칠 가능성이 있으면:

```c
memmove(dst, src, n);
```

를 사용합니다.

C에서는 객체의 바이트 표현을 `unsigned char` 계열로 관찰할 수 있습니다.

하지만 아무 자료형 포인터로 임의 변환해 읽는 것이 전부 허용되는 것은 아닙니다.

동적 저장소에서는 유효 형식과 엄격 별칭 규칙도 함께 확인해야 합니다.

## 27. 헤더 파일과 번역 단위

헤더에는 선언을 둡니다.

```c
#ifndef MY_MODULE_H
#define MY_MODULE_H

int add(int a, int b);

#endif
```

소스에는 구현을 둡니다.

```c
#include "my_module.h"

int add(int a, int b)
{
    return a + b;
}
```

C는 여러 번역 단위를 링크하여 하나의 프로그램을 만드는 구조를 자주 사용합니다.

## 28. C다운 오류 정리 패턴

여러 자원을 순서대로 획득할 때 `goto cleanup`이 실용적으로 사용될 수 있습니다.

```c
int result = 1;
int *a = NULL;
int *b = NULL;

a = malloc(sizeof *a);
if (a == NULL)
    goto cleanup;

b = malloc(sizeof *b);
if (b == NULL)
    goto cleanup;

result = 0;

cleanup:
free(b);
free(a);
return result;
```

무조건적인 `goto` 남용과는 다르게 **오류 정리 경로를 한곳으로 모으는 용도**입니다.

## 29. 연결 리스트에서 이중 포인터가 강력한 이유

```c
void push_front(
    Node **head,
    int value)
{
    Node *n = malloc(sizeof *n);

    if (n == NULL)
        return;

    n->value = value;
    n->next = *head;
    *head = n;
}
```

호출:

```c
push_front(&head, 10);
```

머리 포인터 자체를 바꿔야 하므로 `Node **`가 필요합니다.

## 30. `char **argv`도 이중 포인터다

```c
int main(
    int argc,
    char **argv)
```

구조:

```text
argv
↓
문자열 포인터 배열
↓
각 명령행 문자열
```

따라서:

```text
argv[i]    → char *
argv[i][j] → char
```

입니다.

## 31. 복잡한 C 코드를 읽는 최종 순서

1. 선언 자료형을 해석합니다.
2. 객체의 저장 기간과 수명을 확인합니다.
3. 포인터가 가리키는 대상을 화살표로 그립니다.
4. 배열 경계를 확인합니다.
5. 정수 승격과 형변환을 확인합니다.
6. `const`, `restrict`, 별칭 규칙을 확인합니다.
7. 시퀀싱과 정의되지 않은 동작부터 검사합니다.
8. 그다음 실제 값을 계산합니다.
9. 마지막에 해제·재할당 후 포인터 상태를 확인합니다.

## 잘 놓치는 핵심

### 1. 배열과 포인터는 동일하지 않다

배열은 객체이고 포인터는 주소를 저장하는 별도 객체입니다. 많은 식에서 배열 이름이 첫 원소 포인터로 변환될 뿐입니다.

### 2. 이중 포인터의 핵심은 포인터 자체를 수정하는 것

`int **`는 단순히 별표가 두 개라는 문법이 아니라 호출자의 `int *` 값 자체를 변경할 수 있는 연결 구조입니다.

### 3. C에서는 계산 전에 정의된 동작인지 확인한다

정의되지 않은 동작이 있다면 컴파일러가 우연히 출력한 값을 표준이 보장하는 정답처럼 취급하면 안 됩니다.

### 4. 메모리 소유권과 객체 수명은 따로 추적한다

`free` 이후 별칭, `realloc` 이후 내부 포인터, 지역 변수 주소 반환이 대표적인 함정입니다.

### 5. 작은 정수형도 산술에서는 더 넓은 형으로 승격될 수 있다

`char`나 8비트 정수형을 사용해도 중간 계산까지 항상 작은 자료형으로 수행되는 것은 아닙니다.

### 6. C의 고급 문법은 결국 객체와 접근 방식으로 연결된다

`restrict`, 가변 길이 배열, 유연 배열 멤버, 함수 포인터, `_Generic`, 원자 객체도 어떤 객체를 어떤 자료형으로 접근하는지 이해하면 정리됩니다.

## 시험·면접에서 바로 보는 포인트

- `int *a[3]`와 `int (*a)[3]`를 반드시 구분합니다.
- `int **`가 나오면 어느 포인터 변수를 가리키는지 표시합니다.
- 함수 매개변수 `int a[]`는 포인터로 조정됩니다.
- `sizeof`와 `strlen`을 구분합니다.
- `const int *`와 `int * const`를 구분합니다.
- `realloc` 성공 후 기존 내부 별칭을 다시 사용하지 않습니다.
- `memcpy`는 겹치는 영역에 사용하지 않습니다.
- 함수 포인터 선언은 변수 이름에서부터 해석합니다.
- 정수 승격과 부호 변환 후 실제 계산 자료형을 봅니다.
- 같은 변수의 증감이 한 식에 반복되면 시퀀싱부터 확인합니다.

## 예시로 한 바퀴

다음 코드는 함수 포인터, 이중 포인터, 동적 메모리, 출력 매개변수를 한 번에 보여 줍니다.

```c
#include <stdio.h>
#include <stdlib.h>

typedef int (*Op)(int, int);

int add(int a, int b)
{
    return a + b;
}

int make_result(
    int **out,
    Op op,
    int a,
    int b)
{
    int *p = malloc(sizeof *p);

    if (p == NULL)
        return 0;

    *p = op(a, b);
    *out = p;
    return 1;
}

int main(void)
{
    int *result = NULL;

    if (!make_result(
            &result,
            add,
            10,
            20)) {
        return 1;
    }

    printf("%d\n", *result);

    free(result);
    result = NULL;

    return 0;
}
```

## 최종 체크리스트

- 포인터 단계 수를 정확히 세었는가
- 배열과 포인터를 같은 것으로 착각하지 않았는가
- `sizeof` 대상이 배열인지 포인터인지 확인했는가
- 문자열에 `\0`이 존재하는가
- 동적 메모리를 누가 해제하는지 정했는가
- `realloc` 이후 이전 별칭을 버렸는가
- `const`가 대상에 붙었는지 포인터에 붙었는지 확인했는가
- 정수 승격과 부호 변환을 확인했는가
- 같은 객체를 한 식에서 여러 번 수정하지 않았는가
- 배열 범위를 벗어난 역참조가 없는가
- 함수 포인터의 입력·반환 자료형이 맞는가
- 정의되지 않은 동작을 특정 출력값으로 계산하지 않았는가
