이번 세트는 단순 문법 암기가 아니라 **C의 자료형 체계, 포인터 의미론, 평가 순서, 메모리 모델을 정확하게 이해하고 있는지**를 확인하는 고난도 문제로 구성했습니다.

기준은 별도 언급이 없는 한 **ISO C17**이며, 정의되지 않은 동작이 포함된 경우 특정 실행 결과를 계산하지 않고 코드 자체의 유효성을 먼저 판단합니다.

<blockquote class="prompt-info">
<p>한 줄: 코드를 계산하기 전에 “이 표현이 어떤 자료형이고, 어떤 객체를 가리키며, 어떤 평가 순서와 메모리 규칙을 따르는가”부터 판별해야 풀 수 있는 심화 문제입니다.</p>
</blockquote>

<details markdown="1">
<summary>풀이 방법</summary>

1. 출력값을 계산하기 전에 코드가 C17에서 정의된 동작인지 확인합니다.
2. 포인터 문제는 포인터의 자료형과 이동 단위를 먼저 적습니다.
3. 다중 포인터는 별표를 한 단계씩 제거하면서 실제 대상이 무엇인지 확인합니다.
4. 정수 연산은 저장 자료형이 아니라 연산 직전의 정수 승격과 일반 산술 변환을 확인합니다.
5. 재귀·반복문은 이전 단계에서 변경된 메모리 상태를 다음 단계에 그대로 반영합니다.
6. `realloc`, `restrict`, 유연 배열 멤버는 단순 출력 문제가 아니라 객체 수명과 별칭 규칙까지 확인합니다.
7. 비트 문제는 지정된 폭의 이진 표현으로 변환한 뒤 계산합니다.

</details>

## 문제 1. 가변 길이 배열 포인터와 제자리 갱신

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stddef.h>

void transform(size_t r, size_t c, int a[r][c])
{
    int (*p)[c] = a;

    for (size_t i = 0; i < r; i++) {
        for (size_t j = 0; j < c; j++) {
            if ((i + j) % 2 == 0) {
                p[i][j] += p[(i + 1) % r][(j + 1) % c];
            }
        }
    }
}

int main(void)
{
    int a[3][3] = {
        {1, 2, 3},
        {4, 5, 6},
        {7, 8, 9}
    };

    transform(3, 3, a);

    printf("%d %d %d %d\n",
           a[0][0],
           a[1][1],
           a[2][2],
           a[2][0]);

    return 0;
}
```

① `6 14 18 9`  
② `6 14 15 9`  
③ `6 10 15 7`  
④ `6 14 15 7`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>6 14 15 9</code></strong>입니다.</p>

### 1. 실행 전 상태

초기 행렬은 다음과 같습니다.

```text
        열0  열1  열2
행0      1    2    3
행1      4    5    6
행2      7    8    9
```

함수의 매개변수:

```c
int a[r][c]
```

는 함수 매개변수 위치에서 개념적으로 다음과 같은 가변 길이 배열 포인터로 조정됩니다.

```c
int (*a)[c]
```

따라서:

```c
int (*p)[c] = a;
```

에서 `p`는 **정수 `c`개로 이루어진 한 행을 가리키는 포인터**입니다.

현재 `c = 3`이므로:

```text
p     → a[0]
p + 1 → a[1]
p + 2 → a[2]
```

입니다.

### 2. 가장 중요한 함정

이 문제는 원본 행렬을 따로 복사해 놓고 계산하지 않습니다.

```c
p[i][j] += ...
```

가 실행될 때마다 원래 배열 자체가 즉시 바뀝니다.

따라서 뒤쪽 반복에서 이미 수정된 원소를 참조하면 **수정된 값**을 사용해야 합니다.

### 3. i = 0, j = 0

```text
(i + j) % 2
= 0
```

이므로 갱신합니다.

```c
p[0][0] += p[1][1];
```

현재:

```text
p[0][0] = 1
p[1][1] = 5
```

따라서:

```text
a[0][0] = 1 + 5 = 6
```

현재 행렬:

```text
6  2  3
4  5  6
7  8  9
```

### 4. i = 0, j = 1

```text
0 + 1 = 홀수
```

이므로 변경하지 않습니다.

### 5. i = 0, j = 2

짝수이므로:

```c
p[0][2] += p[1][0];
```

현재:

```text
3 + 4 = 7
```

따라서:

```text
a[0][2] = 7
```

현재:

```text
6  2  7
4  5  6
7  8  9
```

### 6. i = 1

`j = 0`, `j = 2`는 홀수 합이므로 건너뜁니다.

`j = 1`에서:

```c
p[1][1] += p[2][2];
```

따라서:

```text
5 + 9 = 14
```

현재:

```text
6   2   7
4  14   6
7   8   9
```

### 7. i = 2, j = 0

짝수입니다.

행 인덱스는:

```text
(i + 1) % r
= 3 % 3
= 0
```

열 인덱스는:

```text
(j + 1) % c
= 1
```

따라서:

```c
p[2][0] += p[0][1];
```

```text
7 + 2 = 9
```

현재:

```text
6   2   7
4  14   6
9   8   9
```

### 8. i = 2, j = 2

마지막으로:

```c
p[2][2] += p[0][0];
```

여기서 가장 중요한 부분이 나옵니다.

`p[0][0]`의 원래 값은 1이었지만 첫 반복에서 이미 6으로 변경되었습니다.

따라서:

```text
9 + 6 = 15
```

입니다.

최종 행렬:

```text
6   2   7
4  14   6
9   8  15
```

### 9. 최종 출력

```text
a[0][0] = 6
a[1][1] = 14
a[2][2] = 15
a[2][0] = 9
```

따라서:

```text
6 14 15 9
```

### 반드시 알아야 할 개념

이 문제에는 세 가지 핵심이 결합되어 있습니다.

첫째, 함수 매개변수의 가변 길이 배열은 런타임 열 크기를 가진 배열 포인터로 다룰 수 있습니다.

둘째:

```c
p + 1
```

은 정수 하나가 아니라 **한 행 전체**를 이동합니다.

셋째, 제자리 갱신 알고리즘은 앞에서 변경한 값이 뒤 계산에 영향을 줄 수 있습니다.

<mark>행렬 문제에서 원본값을 계속 사용하는지, 갱신된 값을 이어서 사용하는지를 반드시 먼저 확인해야 합니다.</mark>

### 자주 하는 실수

마지막 `a[2][2]`를:

```text
9 + 1 = 10
```

또는 다른 초기값 기준으로 계산하면 안 됩니다.

이 시점의 `a[0][0]`은 이미 6입니다.

</details>

## 문제 2. 함수를 반환하는 함수 포인터와 중첩 호출

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef int (*Op)(int, int);

int add(int a, int b)
{
    return a + b;
}

int mul(int a, int b)
{
    return a * b;
}

int sub(int a, int b)
{
    return a - b;
}

Op pick(int key)
{
    static Op table[3] = {
        add,
        mul,
        sub
    };

    return table[(unsigned)key % 3];
}

int main(void)
{
    Op (*factory)(int) = pick;

    int x = factory(4)(3, 5);
    int y = factory(x % 3)(x, 4);
    int z = factory(y % 3)(y, 7);

    printf("%d %d %d\n", x, y, z);

    return 0;
}
```

① `15 19 133`  
② `8 32 25`  
③ `15 11 77`  
④ `15 60 53`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>15 19 133</code></strong>입니다.</p>

### 1. typedef부터 해석

```c
typedef int (*Op)(int, int);
```

`Op`는:

```text
정수 2개를 입력받고
정수 1개를 반환하는 함수의 포인터
```

를 의미합니다.

따라서:

```c
Op pick(int key)
```

는 단순한 정수를 반환하는 함수가 아닙니다.

**함수 포인터를 반환하는 함수**입니다.

### 2. factory 선언 해석

```c
Op (*factory)(int) = pick;
```

안쪽부터 읽습니다.

```text
factory
→ 포인터
→ int 하나를 받는 함수
→ 그 함수는 Op를 반환
```

즉 `factory`는 `pick`을 가리킵니다.

따라서:

```c
factory(4)
```

의 결과는 함수 포인터 `Op`입니다.

그리고 바로 뒤에:

```c
(3, 5)
```

를 붙여 반환된 함수를 즉시 호출할 수 있습니다.

### 3. 함수 테이블

```text
table[0] → add
table[1] → mul
table[2] → sub
```

입니다.

### 4. x 계산

```c
int x = factory(4)(3, 5);
```

먼저:

```text
4 % 3 = 1
```

따라서:

```text
factory(4)
→ pick(4)
→ table[1]
→ mul
```

입니다.

그 결과를 즉시 호출합니다.

```text
mul(3, 5) = 15
```

따라서:

```text
x = 15
```

### 5. y 계산

```c
int y = factory(x % 3)(x, 4);
```

현재:

```text
x = 15
```

따라서:

```text
x % 3 = 0
```

함수 선택:

```text
table[0] → add
```

따라서:

```text
add(15, 4) = 19
```

```text
y = 19
```

### 6. z 계산

```c
int z = factory(y % 3)(y, 7);
```

현재:

```text
y = 19
```

따라서:

```text
19 % 3 = 1
```

함수 선택:

```text
table[1] → mul
```

따라서:

```text
mul(19, 7) = 133
```

```text
z = 133
```

### 7. 최종 출력

```text
15 19 133
```

### 반드시 알아야 할 개념

이 문제는 함수 포인터를 단순히 호출하는 수준이 아닙니다.

```c
factory(4)(3, 5)
```

는 다음 두 단계입니다.

```text
1. factory(4)가 함수 주소를 반환
2. 반환된 함수를 (3, 5)로 즉시 호출
```

### 자주 하는 실수

`factory(4)`의 결과를 정수라고 생각하면 이후 문법 자체를 해석할 수 없습니다.

먼저 각 함수의 **반환 자료형**을 정확하게 읽어야 합니다.

</details>

## 문제 3. 정수 승격과 축소 변환

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint8_t a = 250;
    uint8_t b = 10;

    int8_t c = -120;
    int8_t d = -10;

    int x = a + b;
    int y = c + d;

    uint8_t z = (uint8_t)(c + d);
    uint16_t w = (uint16_t)(a + b) << 3;

    printf("%d %d %u %u\n",
           x,
           y,
           (unsigned)z,
           (unsigned)w);

    return 0;
}
```

① `4 126 126 32`  
② `260 -130 126 2080`  
③ `260 126 126 2080`  
④ `4 -130 126 32`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>260 -130 126 2080</code></strong>입니다.</p>

### 1. 가장 중요한 전제

`uint8_t`, `int8_t`가 제공되는 환경에서는 각각 정확히 8비트 폭을 가집니다.

하지만 산술식에 들어간다고 해서 반드시 8비트 상태로 계산되는 것은 아닙니다.

작은 정수형은 대부분의 산술 연산 전에 **정수 승격**을 거칩니다.

### 2. a + b

```text
a = 250
b = 10
```

둘 다 `uint8_t`입니다.

일반적인 C의 정수 승격 규칙에서 `int`가 `uint8_t`의 모든 값을 표현할 수 있으므로 두 값은 `int`로 승격됩니다.

따라서 계산은 8비트 덧셈이 아니라:

```text
250 + 10 = 260
```

입니다.

따라서:

```text
x = 260
```

### 3. c + d

```text
c = -120
d = -10
```

두 `int8_t` 값도 `int`로 승격됩니다.

따라서:

```text
-120 + -10
= -130
```

입니다.

```text
y = -130
```

8비트 signed 범위를 벗어났다고 해서 이 연산 자체가 오버플로하는 것이 아닙니다.

연산이 이미 `int`에서 수행되기 때문입니다.

### 4. z 계산

```c
uint8_t z = (uint8_t)(c + d);
```

먼저:

```text
c + d = -130
```

입니다.

그다음 `uint8_t`로 변환합니다.

8비트 부호 없는 정수 범위는:

```text
0 ~ 255
```

입니다.

부호 없는 형으로의 변환은 해당 범위의 모듈러 값으로 대응됩니다.

```text
-130 mod 256 = 126
```

따라서:

```text
z = 126
```

### 5. w 계산

```c
uint16_t w = (uint16_t)(a + b) << 3;
```

먼저:

```text
a + b = 260
```

입니다.

`uint16_t`로 변환해도 값 260은 그대로 표현 가능합니다.

왼쪽으로 3비트 이동하는 것은 이 값에서는:

```text
260 × 8 = 2080
```

과 같습니다.

따라서:

```text
w = 2080
```

### 6. 최종 출력

```text
260 -130 126 2080
```

### 반드시 알아야 할 개념

`uint8_t`를 사용한다고 해서 모든 중간 계산이 자동으로 8비트에서 일어나는 것은 아닙니다.

<mark>C의 작은 정수형 연산에서는 먼저 정수 승격을 의심해야 합니다.</mark>

### 자주 하는 실수

`250 + 10`을 바로 8비트에서 계산하여 4라고 답하면 안 됩니다.

저장할 때의 자료형과 **연산할 때의 자료형**을 분리해서 봐야 합니다.

</details>

## 문제 4. 시퀀싱과 정의되지 않은 동작

초기값이 다음과 같다고 하겠습니다.

```c
int i = 1;
```

다음 보기 중 **C17에서 정의되지 않은 동작을 일으키지 않고**, 실행 후 `i`의 값이 3이 되는 코드는 무엇입니까?

①

```c
i = i++ + 1;
```

②

```c
i = (i++, i + 1);
```

③

```c
printf("%d %d\n", i++, i++);
```

④

```c
int a[3] = {0};
a[i] = i++;
```

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>②</strong>입니다.</p>

### 1. 이 문제의 핵심

단순히 `++` 계산 순서를 묻는 문제가 아닙니다.

같은 스칼라 객체 `i`를 한 표현식 안에서 여러 번 읽거나 수정할 때 **평가 사이에 시퀀싱 관계가 존재하는가**를 판단해야 합니다.

### 2. 보기 ①

```c
i = i++ + 1;
```

`i++`는 `i`를 변경하고 대입 연산 역시 `i`를 변경합니다.

이 두 부수 효과 사이에 필요한 시퀀싱이 보장되지 않습니다.

따라서 C17에서 이 코드는 정의되지 않은 동작을 포함합니다.

숫자 결과를 계산하면 안 됩니다.

### 3. 보기 ②

```c
i = (i++, i + 1);
```

쉼표 연산자:

```c
,
```

는 왼쪽 피연산자의 평가와 부수 효과를 완료한 뒤 오른쪽 피연산자를 평가하도록 시퀀싱합니다.

초기값:

```text
i = 1
```

먼저:

```c
i++
```

가 완료됩니다.

따라서:

```text
i = 2
```

그 후 오른쪽:

```c
i + 1
```

을 계산합니다.

```text
2 + 1 = 3
```

마지막으로:

```text
i = 3
```

이 됩니다.

따라서 잘 정의된 코드이며 최종값은 3입니다.

### 4. 보기 ③

```c
printf("%d %d\n", i++, i++);
```

함수 인자 두 개의 평가 순서는 C17에서 서로 필요한 시퀀싱 관계가 없습니다.

같은 객체 `i`를 두 인자에서 각각 수정하므로 정의되지 않은 동작입니다.

어느 값이 먼저 출력될지를 논하면 안 됩니다.

### 5. 보기 ④

```c
a[i] = i++;
```

왼쪽의 배열 인덱스를 계산하기 위해 `i`를 읽고, 오른쪽에서 같은 `i`를 후위 증가로 수정합니다.

필요한 시퀀싱이 보장되지 않으므로 역시 정의되지 않은 동작입니다.

### 반드시 알아야 할 개념

고난도 C 문제에서 가장 먼저 확인해야 하는 것 중 하나입니다.

```text
같은 객체를 한 full expression 안에서
여러 번 수정하거나
수정과 값 읽기가 섞여 있는가?
```

그렇다면 단순 계산 전에 시퀀싱 규칙을 확인해야 합니다.

### 자주 하는 실수

컴파일러에서 우연히 특정 숫자가 출력되었다고 해서 그 결과가 C 표준에서 보장되는 것은 아닙니다.

정의되지 않은 동작은 **출력값 추론 대상이 아닙니다.**

</details>

## 문제 5. 다중 포인터와 const 한정자

다음 초기 선언이 있습니다.

```c
int x = 10;

int *p = &x;
const int *cp = &x;
```

다음 중 **C17의 포인터 형식 제약 조건을 위반하지 않고 초기화할 수 있는 선언**은 무엇입니까?

①

```c
const int **q = &p;
```

②

```c
int **q = &cp;
```

③

```c
int * const *q = &p;
```

④

```c
int **q = (const int **)&cp;
```

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③</strong>입니다.</p>

### 1. 먼저 기본 자료형을 분해

```c
int *p;
```

에서:

```text
p → int
```

입니다.

따라서:

```c
&p
```

의 자료형은:

```text
int **
```

입니다.

반면:

```c
const int *cp;
```

에서:

```text
cp → const int
```

이므로:

```c
&cp
```

의 자료형은:

```text
const int **
```

입니다.

### 2. 보기 ①

```c
const int **q = &p;
```

겉보기에는 단순히 `const`를 추가한 것처럼 보입니다.

하지만:

```text
int **
→ const int **
```

변환은 일반적인 안전한 한정자 추가로 허용되지 않습니다.

왜냐하면 이 변환이 허용된다면 다음과 같은 문제가 생길 수 있기 때문입니다.

개념적으로:

```c
const int c = 100;
int *p;

const int **q = &p;
*q = &c;
```

가 가능해지고, 그러면 원래 `int *`인 `p`가 `const int` 객체를 가리키게 됩니다.

그 후:

```c
*p = 3;
```

같은 코드로 `const` 객체를 변경하려는 상황을 만들 수 있습니다.

따라서 이런 다단계 포인터 한정자 변환은 허용되지 않습니다.

### 3. 보기 ②

```c
int **q = &cp;
```

`&cp`는:

```text
const int **
```

입니다.

이를:

```text
int **
```

에 넣으면 `const`를 제거하게 되므로 올바르지 않습니다.

### 4. 보기 ③

```c
int * const *q = &p;
```

`q`가 가리키는 대상은:

```text
const로 한정된 int * 객체
```

입니다.

즉 `q`를 통해 `p`라는 포인터 객체 자체를 바꾸지 못하게 하는 한정자를 추가한 것입니다.

`&p`를 이 형식으로 보는 것은 허용 가능한 한정자 추가입니다.

### 5. 보기 ④

```c
int **q = (const int **)&cp;
```

명시적 형변환을 사용했다고 해서 최종 초기화 대상의 자료형 불일치가 자동으로 사라지는 것은 아닙니다.

오른쪽 표현식의 형식은 `const int **`이고 왼쪽은 `int **`입니다.

올바른 호환 관계가 아닙니다.

### 반드시 알아야 할 개념

다중 포인터에서:

```text
int **
const int **
```

는 단순히 `int *`에서 `const int *`로 변환하는 문제와 다릅니다.

<mark>포인터 단계가 하나 더 늘어나면 const 안전성 규칙도 훨씬 엄격해집니다.</mark>

### 자주 하는 실수

다음 변환은 자연스럽고 안전합니다.

```c
int *p;
const int *cp = p;
```

하지만 이것을 보고:

```c
int ** → const int **
```

도 똑같이 가능하다고 일반화하면 안 됩니다.

</details>

## 문제 6. 유연 배열 멤버와 realloc

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdlib.h>
#include <stddef.h>

typedef struct {
    size_t n;
    unsigned char data[];
} Packet;

int main(void)
{
    Packet *p = malloc(sizeof(Packet) + 5);

    if (p == NULL)
        return 1;

    p->n = 5;

    for (size_t i = 0; i < p->n; i++)
        p->data[i] = (unsigned char)(i * 3 + 1);

    Packet *tmp = realloc(p, sizeof(Packet) + 8);

    if (tmp == NULL) {
        free(p);
        return 1;
    }

    p = tmp;
    p->n = 8;

    for (size_t i = 5; i < p->n; i++)
        p->data[i] = (unsigned char)(p->data[i - 5] + p->data[i - 4]);

    p->data[4] ^= p->data[5];

    printf("%zu %u %u %u %u\n",
           p->n,
           (unsigned)p->data[4],
           (unsigned)p->data[5],
           (unsigned)p->data[6],
           (unsigned)p->data[7]);

    free(p);

    return 0;
}
```

① `8 13 5 11 17`  
② `8 8 5 11 17`  
③ `8 8 8 14 20`  
④ `5 8 5 11 17`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>8 8 5 11 17</code></strong>입니다.</p>

### 1. 유연 배열 멤버

구조체:

```c
typedef struct {
    size_t n;
    unsigned char data[];
} Packet;
```

에서:

```c
unsigned char data[];
```

는 유연 배열 멤버입니다.

구조체 본체 뒤에 필요한 만큼 추가 메모리를 붙여 사용할 수 있습니다.

### 2. 최초 할당

```c
malloc(sizeof(Packet) + 5)
```

를 통해 구조체 본체와 데이터 5바이트를 함께 확보합니다.

```text
n
data[0]
data[1]
data[2]
data[3]
data[4]
```

### 3. 최초 데이터 생성

반복문:

```c
p->data[i] = i * 3 + 1;
```

결과:

```text
i = 0 → 1
i = 1 → 4
i = 2 → 7
i = 3 → 10
i = 4 → 13
```

따라서:

```text
data = {1, 4, 7, 10, 13}
```

### 4. realloc

```c
Packet *tmp = realloc(p, sizeof(Packet) + 8);
```

성공하면 기존 데이터 내용은 새 크기와 기존 크기 중 작은 범위까지 보존됩니다.

안전한 패턴대로 반환값을 `tmp`에 먼저 저장하고 성공 후:

```c
p = tmp;
```

를 실행했습니다.

### 5. 새 원소 data[5]

```text
i = 5
```

식:

```c
p->data[5]
=
p->data[0] + p->data[1]
```

따라서:

```text
1 + 4 = 5
```

### 6. data[6]

```text
i = 6
```

```text
data[1] + data[2]
= 4 + 7
= 11
```

### 7. data[7]

```text
i = 7
```

```text
data[2] + data[3]
= 7 + 10
= 17
```

현재:

```text
data = {1, 4, 7, 10, 13, 5, 11, 17}
```

### 8. XOR 연산

```c
p->data[4] ^= p->data[5];
```

현재:

```text
data[4] = 13
data[5] = 5
```

이진수:

```text
13 = 1101
 5 = 0101
```

XOR:

```text
1101
0101
----
1000
```

따라서:

```text
data[4] = 8
```

### 9. 최종 출력

```text
n       = 8
data[4] = 8
data[5] = 5
data[6] = 11
data[7] = 17
```

따라서:

```text
8 8 5 11 17
```

### 반드시 알아야 할 개념

이 문제는 다음 세 개념을 결합합니다.

```text
유연 배열 멤버
realloc의 객체 내용 보존
비트 XOR
```

유연 배열 멤버 자체는 `sizeof(Packet)`에 데이터 원소 개수를 포함시키지 않습니다.

필요한 추가 바이트를 직접 계산해서 할당합니다.

### 자주 하는 실수

`realloc`로 크기를 늘렸다고 해서 새로 추가된 영역이 자동으로 0으로 초기화된다고 생각하면 안 됩니다.

이번 코드는 새 원소 `5~7`을 사용하기 전에 직접 값을 대입하고 있습니다.

</details>

## 문제 7. 겹치는 메모리의 두 번 이동

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    int a[] = {1, 2, 3, 4, 5, 6};

    memmove(a + 1, a, 4 * sizeof *a);
    memmove(a + 2, a + 3, 3 * sizeof *a);

    for (size_t i = 0; i < 6; i++)
        printf("%d ", a[i]);

    return 0;
}
```

① `1 1 2 3 4 6`  
② `1 1 3 4 6 6`  
③ `1 2 3 4 5 6`  
④ `1 1 3 4 5 6`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>1 1 3 4 6 6</code></strong>입니다.</p>

### 1. 초기 배열

```text
인덱스   0   1   2   3   4   5
값       1   2   3   4   5   6
```

### 2. 첫 번째 memmove

```c
memmove(a + 1, a, 4 * sizeof *a);
```

원본 범위:

```text
a[0] ~ a[3]
= 1 2 3 4
```

목적지 범위:

```text
a[1] ~ a[4]
```

입니다.

영역이 겹치지만 `memmove`이므로 안전하게 원본의 논리적 내용을 보존하여 복사합니다.

결과:

```text
인덱스   0   1   2   3   4   5
값       1   1   2   3   4   6
```

### 3. 두 번째 memmove의 원본

이제 두 번째 문장이 실행됩니다.

```c
memmove(a + 2, a + 3, 3 * sizeof *a);
```

중요한 점은 **초기 배열이 아니라 첫 번째 이동이 끝난 현재 배열**을 기준으로 한다는 것입니다.

현재:

```text
a = {1, 1, 2, 3, 4, 6}
```

원본:

```text
a[3], a[4], a[5]
= 3, 4, 6
```

목적지:

```text
a[2], a[3], a[4]
```

입니다.

### 4. 두 번째 이동 후

복사하면:

```text
a[2] = 3
a[3] = 4
a[4] = 6
```

따라서 최종 배열:

```text
1 1 3 4 6 6
```

### 5. 최종 출력

```text
1 1 3 4 6 6
```

### 반드시 알아야 할 개념

`memmove`은 원본과 목적지가 겹치는 경우에도 사용할 수 있습니다.

하지만 여러 번 호출되면 **각 호출 사이의 배열 상태를 반드시 갱신**해야 합니다.

### 자주 하는 실수

두 번째 `memmove`에서도 초기 배열의:

```text
4 5 6
```

을 복사한다고 생각하면 안 됩니다.

첫 번째 호출 이후 `a[3]`, `a[4]` 값은 이미 바뀌었습니다.

## 문제 8. 재귀 반환과 원본 배열 동시 변경

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int process(int *a, int n)
{
    if (n == 1)
        return a[0];

    int tail = process(a + 1, n - 1);

    a[0] += tail % 5;

    return a[0] + tail;
}

int main(void)
{
    int a[] = {2, 4, 6, 8};

    int result = process(a, 4);

    printf("%d %d %d %d %d\n",
           result,
           a[0], a[1], a[2], a[3]);

    return 0;
}
```

① `20 2 4 6 8`  
② `28 5 6 9 8`  
③ `28 5 4 9 8`  
④ `25 5 6 6 8`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>28 5 6 9 8</code></strong>입니다.</p>

### 1. 초기 배열

```text
인덱스   0   1   2   3
값       2   4   6   8
```

함수 호출:

```text
process(a, 4)
```

입니다.

이 함수는 먼저 끝까지 재귀 호출을 내려간 다음 **반환되는 과정에서 원본 배열을 수정**합니다.

```text
process(&a[0], 4)
```

두 번째:

```text
process(&a[1], 3)
```

세 번째:

```text
process(&a[2], 2)
```

네 번째:

```text
process(&a[3], 1)
```

### 3. 종료 조건

```c
if (n == 1)
    return a[0];
```

마지막 호출의 `a[0]`은 원본 배열의 `a[3]`입니다.

```text
process(&원본 a[3], 1)
= 8
```

입니다.

### 4. 원본 a[2] 처리

한 단계 돌아오면:

```text
tail = 8
```

현재 위치의 값은 원본:

```text
a[2] = 6
```

입니다.

실행:

```c
a[0] += tail % 5;
```

이 호출 프레임에서 `a[0]`은 원본 `a[2]`입니다.

```text
8 % 5 = 3
```

따라서:

```text
원본 a[2] = 6 + 3 = 9
```

반환:

```text
9 + 8 = 17
```

이제 이전 호출로 돌아옵니다.

```text
tail = 17
```

```text
원본 a[1] = 4
```

```text
17 % 5 = 2
```

따라서:

```text
a[1] = 4 + 2 = 6
```

반환값:

```text
6 + 17 = 23
```

### 6. 원본 a[0] 처리

최상위 호출로 돌아옵니다.

```text
tail = 23
```

현재:

```text
a[0] = 2
```

```text

```

따라서:

```text
a[0] = 2 + 3 = 5
```

최종 반환값:

```text
5 + 23 = 28
```

```text
result = 28

a[1] = 6

```

따라서:

```text
28 5 6 9 8
```

이번 함수는:

```c
int tail = process(...);
```

뒤에서 원본 배열을 변경하므로 실제 변경 순서는:

```text
a[2]
→ a[1]
→ a[0]
```

입니다.

### 자주 하는 실수

호출이 `a[0]`부터 시작하므로 `a[0]`도 가장 먼저 수정된다고 생각하면 안 됩니다.

재귀 호출 뒤에 있는 코드는 **재귀가 되돌아오는 순서**로 실행됩니다.

## 문제 9. restrict 별칭 규칙

다음 함수가 있습니다.

```c
#include <stddef.h>

void accumulate(size_t n,
                int *restrict dst,
                const int *restrict src)
{
    for (size_t i = 0; i < n; i++)
        dst[i] += src[i];
}
```

그리고 다음 배열이 있습니다.

```c
int a[5] = {1, 2, 3, 4, 5};
int b[5] = {10, 20, 30, 40, 50};
```

다음 중 위 함수의 `restrict` 사용 계약을 위반하지 않는 호출은 무엇입니까?

①

```c
accumulate(3, a, a);
```

②

```c
accumulate(3, a + 1, a);
```

③

```c
accumulate(3, a, b);
```

④

```c
accumulate(3, a, a + 1);
```

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③</strong>입니다.</p>

### 1. restrict의 목적

`restrict`는 단순히 성능을 빠르게 만드는 장식이 아닙니다.

해당 포인터를 통해 수정되는 객체에 접근할 때, 같은 실행 범위 안에서 다른 독립적인 `restrict` 기반 포인터가 동일한 객체를 별칭으로 접근하지 않는다는 계약을 프로그래머가 컴파일러에 제공하는 것입니다.

이번 함수:

```c
int *restrict dst
const int *restrict src
```

에서 `dst`가 가리키는 객체는 수정됩니다.

```c
dst[i] += src[i];
```

따라서 같은 객체를 `src`라는 별도의 restrict 기반 경로로 동시에 접근하면 문제가 됩니다.

### 2. 보기 ①

```c
accumulate(3, a, a);
```

`dst`와 `src`가 같은 배열 영역을 가리킵니다.

각 원소가 `dst`로 수정되면서 동시에 `src` 경로로도 읽힙니다.

`restrict` 계약을 위반합니다.

### 3. 보기 ②

```c
accumulate(3, a + 1, a);
```

접근 범위를 적으면:

```text
dst → a[1], a[2], a[3]
src → a[0], a[1], a[2]
```

입니다.

겹치는 객체:

```text
a[1], a[2]
```

가 존재합니다.

따라서 계약을 위반합니다.

### 4. 보기 ③

```c
accumulate(3, a, b);
```

접근 범위:

```text
dst → a[0], a[1], a[2]
src → b[0], b[1], b[2]
```

서로 다른 배열 객체입니다.

별칭 충돌이 없습니다.

따라서 이 호출은 의도된 `restrict` 계약을 만족합니다.

### 5. 보기 ④

```c
accumulate(3, a, a + 1);
```

범위:

```text
dst → a[0], a[1], a[2]
src → a[1], a[2], a[3]
```

역시:

```text
a[1], a[2]
```

가 겹칩니다.

계약을 위반합니다.

### 반드시 알아야 할 개념

`restrict`는 단순한 `const`와 완전히 다른 개념입니다.

```text
const    → 그 경로로 값을 수정할 수 있는가
restrict → 같은 객체를 다른 별칭 경로로 접근하는가
```

를 다룹니다.

<mark>restrict를 잘못 사용하면 단순히 최적화가 덜 되는 것이 아니라 프로그램의 동작 자체가 표준상 보장되지 않을 수 있습니다.</mark>

### 자주 하는 실수

`src`가 `const int *`이므로 같은 배열을 읽기만 하면 괜찮다고 생각하면 안 됩니다.

문제는 `src`가 수정하느냐가 아니라 **dst를 통해 수정되는 동일 객체를 독립적인 restrict 경로로 함께 접근하느냐**입니다.

</details>

## 문제 10. 8비트 순환 이동과 비트 개수 알고리즘

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdint.h>

int main(void)
{
    uint8_t x = 0xB6u;

    uint8_t y = (uint8_t)(
        (uint8_t)(x << 3) |
        (x >> 5)
    );

    y ^= 0x3Cu;

    unsigned count = 0;
    uint8_t t = y;

    while (t != 0) {
        t = (uint8_t)(t & (uint8_t)(t - 1));
        count++;
    }

    printf("%02X %u\n",
           (unsigned)y,
           count);

    return 0;
}
```

① `B5 5`  
② `89 3`  
③ `8D 4`  
④ `B6 5`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>89 3</code></strong>입니다.</p>

### 1. 초기값을 8비트로 표현

```text
x = 0xB6
```

16진수를 이진수로 바꾸면:

```text
B = 1011
6 = 0110
```

따라서:

```text
x = 1011 0110
```

입니다.

### 2. 왼쪽 부분 계산

```c
(uint8_t)(x << 3)
```

`x`는 산술 연산에서 정수 승격을 거치지만 최종적으로 `uint8_t`로 다시 잘라냅니다.

8비트 관점에서 왼쪽으로 3칸 이동한 하위 8비트는:

```text
1011 0110 << 3
→ 1011 0000
```

즉:

```text
0xB0
```

입니다.

### 3. 오른쪽 부분 계산

```c
x >> 5
```

```text
1011 0110 >> 5
→ 0000 0101
```

따라서:

```text
0x05
```

입니다.

### 4. OR 결합

```text
0xB0 = 1011 0000
0x05 = 0000 0101
```

OR:

```text
1011 0101
```

따라서:

```text
y = 0xB5
```

이 단계는 실질적으로 8비트 왼쪽 순환 이동 3칸과 같은 결과를 만듭니다.

### 5. XOR 마스크 적용

```c
y ^= 0x3C;
```

이진수:

```text
0xB5 = 1011 0101
0x3C = 0011 1100
```

XOR:

```text
1011 0101
0011 1100
---------
1000 1001
```

따라서:

```text
y = 0x89
```

입니다.

### 6. 비트 개수 알고리즘

현재:

```text
t = 1000 1001
```

1비트는 세 개입니다.

하지만 반복문을 직접 보면 더 중요한 원리를 확인할 수 있습니다.

```c
t = t & (t - 1);
```

이 연산은 `t`의 **가장 낮은 위치에 있는 1비트 하나를 제거**합니다.

#### 첫 번째 반복

```text
1000 1001
→ 1000 1000
```

```text
count = 1
```

#### 두 번째 반복

```text
1000 1000
→ 1000 0000
```

```text
count = 2
```

#### 세 번째 반복

```text
1000 0000
→ 0000 0000
```

```text
count = 3
```

반복 종료.

### 7. 최종 출력

`%02X`이므로 두 자리 대문자 16진수로:

```text
89
```

그리고 비트 개수:

```text
3
```

따라서:

```text
89 3
```

### 반드시 알아야 할 개념

다음 식은 대표적인 비트 알고리즘입니다.

```c
x & (x - 1)
```

현재 값에서 가장 낮은 1비트 하나를 제거합니다.

따라서 1비트 개수를 세는 알고리즘에서는 전체 비트 수만큼 반복하는 대신 **실제로 존재하는 1비트 개수만큼만 반복**할 수 있습니다.

### 자주 하는 실수

왼쪽 시프트 결과를 무한 정밀 정수처럼 그대로 사용하면 안 됩니다.

이번 코드는 최종적으로 `uint8_t`로 변환하므로 **하위 8비트만 남는 과정**까지 추적해야 합니다.

</details>

## 잘 놓치는 핵심

### 1. 제자리 갱신 알고리즘은 과거 값과 현재 값을 구분해야 한다

앞에서 변경된 배열 원소를 뒤에서 읽으면 변경된 값을 사용합니다.

### 2. 함수는 함수 포인터를 반환할 수 있다

`factory(x)(a, b)` 같은 형태는 첫 호출이 함수 주소를 반환한 뒤 그 함수를 즉시 호출하는 구조일 수 있습니다.

### 3. 작은 정수형도 연산 전 정수 승격을 거친다

`uint8_t`끼리 더한다고 항상 8비트 연산이 되는 것은 아닙니다.

### 4. 출력값 계산 전에 시퀀싱을 확인한다

같은 객체의 여러 수정이 시퀀싱되지 않았다면 정의되지 않은 동작입니다.

### 5. 다중 포인터의 const 변환은 단일 포인터보다 엄격하다

`int * → const int *`가 가능하다고 해서 `int ** → const int **`도 가능한 것은 아닙니다.

### 6. 유연 배열 멤버는 구조체 뒤의 추가 메모리를 직접 확보한다

`sizeof`만으로 데이터 영역 전체가 자동 포함되지 않습니다.

### 7. memmove를 연속해서 사용하면 매 호출 후 상태를 갱신한다

두 번째 복사는 첫 번째 복사가 끝난 배열을 기준으로 합니다.

### 8. 재귀는 반환 과정에서 데이터를 변경할 수 있다

호출 순서와 실제 수정 순서가 반대가 될 수 있습니다.

### 9. restrict는 별칭 계약이다

동일 객체를 서로 다른 restrict 기반 포인터로 접근하면 표준의 보장을 잃을 수 있습니다.

### 10. 비트 알고리즘은 정수 승격과 고정 폭 변환까지 함께 본다

단순 이진수 계산뿐 아니라 중간 표현의 자료형도 확인해야 합니다.

## 시험·면접에서 바로 보는 포인트

- 다차원 배열은 포인터가 한 번 증가할 때 몇 바이트가 아니라 몇 **원소 단위**를 이동하는지 봅니다.
- 함수 선언은 변수 이름에서 시작해 안쪽에서 바깥쪽으로 읽습니다.
- `uint8_t`, `int8_t`가 보여도 즉시 정수 승격 여부를 확인합니다.
- 같은 변수에 증감 연산자가 여러 번 등장하면 숫자를 계산하기 전에 정의된 동작인지 판별합니다.
- `const`가 어느 포인터 단계에 붙었는지 정확히 구분합니다.
- `realloc` 이후 기존 내용 보존 범위와 새 영역의 초기화 여부를 구분합니다.
- 메모리 이동 함수는 현재 배열 상태를 매번 새로 적습니다.
- 재귀 함수는 호출 단계와 반환 단계를 따로 적습니다.
- `restrict`는 두 포인터가 실제로 겹치는 객체를 접근하는지 확인합니다.
- 비트 문제는 지정된 비트 폭으로 다시 잘리는 시점을 표시합니다.
