스키마(Schema)는 **데이터베이스의 구조와 규칙을 정의한 설계 정보**입니다.

어떤 Table과 Column이 존재하고, 자료형·Key·제약조건이 무엇인지 정의합니다.

<blockquote class="prompt-info">
<p>한 줄: Schema는 실제 데이터가 아니라 데이터가 어떤 구조로 저장될지를 정의한 설계도입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

Schema = 데이터베이스의 구조와 규칙입니다.

</details>

## 핵심 예시

EMPLOYEE의 일부 데이터입니다.

| EMP_ID | EMP_NAME | DEPT_ID | SALARY |
| ---: | --- | ---: | ---: |
| 1001 | 직원1 | 10 | 2890 |
| 1002 | 직원2 | 20 | 2980 |
| 1003 | 직원3 | 30 | 3070 |

위 값들은 실제 데이터입니다.

반면 다음은 구조입니다.

```text
Table
→ EMPLOYEE

Column
→ EMP_ID
→ EMP_NAME
→ DEPT_ID
→ SALARY

Primary Key
→ EMP_ID

Foreign Key
→ DEPT_ID
```

<mark>Schema는 데이터 자체가 아니라 데이터를 담는 구조입니다.</mark>

## Schema와 Instance

두 개념은 반드시 구분해야 합니다.

```text
Schema
= 구조

Instance
= 특정 시점의 실제 데이터
```

Schema의 예시는 다음과 같습니다.

```text
EMPLOYEE(
    EMP_ID,
    EMP_NAME,
    DEPT_ID,
    SALARY
)
```

Instance의 예시는 다음과 같습니다.

```text
1001 | 직원1 | 10 | 2890
1002 | 직원2 | 20 | 2980
```

Row가 추가되어도 Table 구조가 같다면 Schema는 그대로입니다.

## 왜 Schema가 필요한가

Schema는 데이터가 어떤 형식으로 저장될지 기준을 만듭니다.

- 모든 Row가 같은 Column 구조를 따르게 합니다.
- 저장할 값의 종류를 정합니다.
- Key와 제약조건을 정의합니다.
- Table 사이의 관계를 정의합니다.

즉 데이터의 일관성을 유지하는 기본 설계입니다.

## Schema가 정의하는 것

대표적으로 다음 정보가 포함됩니다.

- Table 이름
- Column 이름
- Data Type
- Primary Key
- Foreign Key
- Constraint
- Table 사이 관계

Column 이름만 적어 둔 것이 Schema의 전부는 아닙니다.

## Data Type

각 Column에는 저장할 값의 종류가 있습니다.

```text
EMP_ID → INTEGER
EMP_NAME → TEXT
SALARY → INTEGER
HIRE_DATE → TEXT
```

SQL에서는 다음처럼 정의합니다.

```sql
CREATE TABLE EMPLOYEE(
    EMP_ID INTEGER,
    EMP_NAME TEXT,
    SALARY INTEGER,
    HIRE_DATE TEXT
);
```

Data Type도 Schema의 일부입니다.

## Key도 Schema의 일부다

Primary Key는 각 Row를 고유하게 식별합니다.

```sql
EMP_ID INTEGER PRIMARY KEY
```

Foreign Key는 다른 Table의 Key를 참조합니다.

```text
EMPLOYEE.DEPT_ID
↓
DEPARTMENT.DEPT_ID
```

SQL에서는 다음처럼 정의합니다.

```sql
FOREIGN KEY(DEPT_ID)
REFERENCES DEPARTMENT(DEPT_ID)
```


## 실제 EMPLOYEE Schema

실습 DB의 EMPLOYEE 구조입니다.

```sql
CREATE TABLE EMPLOYEE(
    EMP_ID INTEGER PRIMARY KEY,
    EMP_NAME TEXT NOT NULL,
    DEPT_ID INTEGER,
    SALARY INTEGER,
    HIRE_DATE TEXT,
    MANAGER_ID INTEGER,
    BONUS INTEGER,
    FOREIGN KEY(DEPT_ID)
        REFERENCES DEPARTMENT(DEPT_ID)
);
```

여기에는 Column, Data Type, Primary Key, NOT NULL, Foreign Key가 모두 포함됩니다.

## DEPARTMENT로 다시 보기

DEPARTMENT Schema입니다.

```sql
CREATE TABLE DEPARTMENT(
    DEPT_ID INTEGER PRIMARY KEY,
    DEPT_NAME TEXT NOT NULL,
    REGION TEXT
);
```

실제 데이터는 다음과 같습니다.

| DEPT_ID | DEPT_NAME | REGION |
| ---: | --- | --- |
| 10 | 개발 | 서울 |
| 20 | 인사 | 부산 |
| 30 | 영업 | 대전 |
| 40 | 회계 | 광주 |
| 50 | 마케팅 | 서울 |

`DEPT_ID INTEGER PRIMARY KEY`는 Schema이고, `10 | 개발 | 서울`은 Instance입니다.

## Schema 변경

EMPLOYEE에 EMAIL Column을 추가해봅시다.

```sql
ALTER TABLE EMPLOYEE
ADD COLUMN EMAIL TEXT;
```

변경 전에는 EMAIL이 없습니다.

변경 후에는 EMAIL Column이 생깁니다.

Table 구조 자체가 바뀌었기 때문에 Schema 변경입니다.

## INSERT와 ALTER의 차이

INSERT는 새로운 Row를 추가합니다.

```sql
INSERT INTO EMPLOYEE
VALUES (
    1051,
    '직원51',
    10,
    5000,
    '2026-09-16',
    1001,
    300
);
```

이 경우 Instance만 변합니다.

ALTER는 구조를 바꿉니다.

```sql
ALTER TABLE EMPLOYEE
ADD COLUMN EMAIL TEXT;
```

이 경우 Schema가 변합니다.

<blockquote class="prompt-warning">
<p>INSERT는 데이터를 바꾸고, ALTER는 구조를 바꿉니다.</p>
</blockquote>

## DDL과 Schema

Schema를 정의하거나 변경하는 SQL을 DDL(Data Definition Language)이라고 합니다.

- CREATE: 구조 생성
- ALTER: 구조 변경
- DROP: 구조 삭제

예를 들어 다음 SQL은 Table Schema를 변경합니다.

```sql
ALTER TABLE EMPLOYEE
ADD COLUMN EMAIL TEXT;
```

<mark>DDL은 실제 값보다 데이터 구조를 정의하고 변경하는 데 초점이 있습니다.</mark>


## Schema와 Instance 비교

| 구분 | Schema | Instance |
| --- | --- | --- |
| 의미 | 구조와 규칙 | 실제 데이터 |
| 변화 | 상대적으로 적음 | 계속 변할 수 있음 |
| 예시 | Column, Data Type, Key | 직원1, 급여 2890 |
| 관련 SQL | CREATE, ALTER, DROP | INSERT, UPDATE, DELETE |

Schema와 Instance의 차이는 시험에서 자주 나옵니다.

## 잘 놓치는 핵심

### 1. Schema는 실제 데이터가 아니다

```text
Schema = 구조
Instance = 실제 데이터
```

### 2. Column 이름만이 Schema는 아니다

Data Type, Key, Constraint, Relationship도 포함됩니다.

### 3. INSERT는 Schema 변경이 아니다

```text
INSERT
→ Instance 변경
```

### 4. ALTER는 Schema 변경이다

```text
ALTER
→ Schema 변경
```

### 5. CREATE TABLE은 Schema 정의다

```sql
CREATE TABLE ...
```

Table의 구조를 정의합니다.

## 시험·면접

### 핵심 암기

```text
Schema
= 데이터베이스 구조와 규칙

Instance
= 특정 시점의 실제 데이터
```

### DDL 핵심

```text
CREATE
ALTER
DROP
```

### 시험 함정

```text
INSERT → Schema 변경 X
ALTER → Schema 변경 O
```

### 면접에서 짧게 답한다면

Schema는 데이터베이스의 구조를 정의한 설계 정보입니다.

Table과 Column뿐 아니라 Data Type, Key, 제약조건과 Table 사이 관계까지 포함합니다.

## 예시로 한 바퀴

먼저 Schema를 정의합니다.

```sql
CREATE TABLE EMPLOYEE(
    EMP_ID INTEGER PRIMARY KEY,
    EMP_NAME TEXT NOT NULL,
    DEPT_ID INTEGER
);
```

그다음 실제 데이터를 넣습니다.

```sql
INSERT INTO EMPLOYEE
VALUES (1001, '직원1', 10);
```

정리하면 다음과 같습니다.

```text
CREATE TABLE
→ Schema 정의

INSERT
→ Instance 변경
```
