UNION과 UNION ALL은 두 SELECT 결과를 같은 Column 구조로 세로 방향으로 결합하는 집합 연산자입니다.

복잡한 SQL도 괄호 안쪽 결과부터 작게 나누어 보면 이해하기 쉽습니다.

<blockquote class="prompt-info">
<p>한 줄: UNION은 중복을 제거하고 UNION ALL은 중복을 그대로 유지합니다.</p>
</blockquote>

<summary>한 줄로</summary>

</details>

## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT REGION
FROM DEPARTMENT
UNION
SELECT REGION
FROM CUSTOMER;
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>UNION은 중복을 제거하고 UNION ALL은 중복을 그대로 유지합니다.</mark>

### 규칙 1. 양쪽 SELECT의 Column 개수가 같아야 한다.

이 문장은 `UNION · UNION ALL` 문제를 풀 때 핵심 기준입니다.

```text
질문 1 → Subquery 또는 집합 결과가 무엇인가
질문 2 → 바깥 Query가 그 결과를 어떻게 사용하는가
질문 3 → Row 수와 Column 수가 연산자에 맞는가
질문 4 → NULL과 중복은 결과에 어떤 영향을 주는가
```

## UNION 기본

부서 지역과 고객 지역을 하나의 지역 목록으로 합친다고 해봅시다.

```sql
SELECT REGION
FROM DEPARTMENT
UNION
SELECT REGION
FROM CUSTOMER;
```

같은 지역명이 여러 번 나타나도 UNION 결과에서는 중복이 제거됩니다.

## UNION ALL 기본

중복까지 모두 유지하려면 UNION ALL을 사용합니다.

```sql
SELECT REGION
FROM DEPARTMENT
UNION ALL
SELECT REGION
FROM CUSTOMER;
```

서울이 여러 번 등장하면 그 횟수만큼 결과에 남을 수 있습니다.

## Column 개수

다음 두 SELECT의 Column 개수가 다르면 일반적인 UNION 구조로 결합할 수 없습니다.

```text
첫 번째 SELECT
→ 2 Column

두 번째 SELECT
→ 1 Column
```

양쪽 결과의 Column 수를 맞춰야 합니다.

## Column 위치

이름이 아니라 위치가 대응됩니다.

```text
첫 번째 SELECT의 1번째 Column
↔
두 번째 SELECT의 1번째 Column
```

따라서 의미가 전혀 다른 Column을 같은 위치에 두면 문법적으로 가능하더라도 결과 해석이 이상해질 수 있습니다.

## 중복 제거 비용

UNION은 중복을 제거하는 작업이 필요합니다.

UNION ALL은 중복 제거가 필요 없습니다.

따라서 중복 제거가 필요하지 않다면 UNION ALL이 더 단순하고 효율적인 경우가 많습니다.

하지만 실제 성능은 DBMS와 실행 계획을 확인합니다.

## ORDER BY 위치

집합 연산 전체를 정렬하려면 마지막에 ORDER BY를 둡니다.

```sql
SELECT REGION
FROM DEPARTMENT
UNION
SELECT REGION
FROM CUSTOMER
ORDER BY REGION;
```

각 SELECT 내부의 ORDER BY 사용 가능 여부는 DBMS와 Query 구조에 따라 제한됩니다.

## Column 이름

결과 Column 이름은 일반적으로 첫 번째 SELECT의 Column 이름이나 별칭을 따릅니다.

```sql
SELECT REGION AS LOCATION
FROM DEPARTMENT
UNION
SELECT REGION
FROM CUSTOMER;
```

결과 이름은 `LOCATION`으로 보일 수 있습니다.

## UNION과 JOIN 비교

UNION은 결과를 세로로 이어 붙입니다.

JOIN은 관련 Row를 가로 방향으로 연결합니다.

```text
UNION
→ Row 추가

JOIN
→ Column 조합
```

둘은 목적 자체가 다릅니다.

## 시험·면접

### 핵심 암기

```text
UNION = 합치고 중복 제거 / UNION ALL = 합치고 중복 유지
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

`결과 Column 이름은 일반적으로 첫 번째 SELECT의 이름이나 별칭을 기준으로 한다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

UNION과 UNION ALL은 두 SELECT 결과를 같은 Column 구조로 세로 방향으로 결합하는 집합 연산자입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT REGION
FROM DEPARTMENT
UNION
SELECT REGION
FROM CUSTOMER;
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
