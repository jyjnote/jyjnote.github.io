IN은 값이 후보 집합 안에 포함되는지 확인하고, EXISTS는 서브쿼리가 Row를 하나라도 반환하는지 확인합니다.

복잡한 SQL도 괄호 안쪽 결과부터 작게 나누어 보면 이해하기 쉽습니다.

## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>IN은 값의 포함 여부를 보고 EXISTS는 Row의 존재 여부를 봅니다.</mark>

## IN 기본 구조

서울 부서 번호 중 하나에 속한 직원을 찾습니다.

```sql
SELECT EMP_NAME, DEPT_ID
FROM EMPLOYEE
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
);
```

안쪽 결과가 `10, 50`이라면 개념적으로 다음과 같습니다.

```text
DEPT_ID = 10 또는 50
```

## EXISTS 기본 구조

주문이 있는 고객을 찾습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

안쪽 Query가 한 Row라도 찾으면 해당 고객을 남깁니다.

## SELECT 1의 의미

EXISTS는 서브쿼리가 무엇을 SELECT했는지보다 Row 존재 여부를 봅니다.

그래서 다음처럼 자주 씁니다.

```sql
SELECT 1
```

`1` 자체를 바깥 Query에 반환하려는 목적이 아닙니다.

"조건을 만족하는 Row가 있는가"만 확인하는 표현입니다.

## IN과 EXISTS 비교

| 구분 | IN | EXISTS |
| --- | --- | --- |
| 중심 | 값 포함 여부 | Row 존재 여부 |
| 서브쿼리 결과 | 후보 값 집합 | 존재 여부 판단용 Row |
| 상관 여부 | 독립형도 흔함 | 상관형이 흔함 |
| NULL 주의 | 특히 NOT IN | NOT EXISTS가 안전한 경우 많음 |

둘 다 같은 목적을 표현할 수 있는 경우가 있지만 사고 방식이 다릅니다.

## NOT IN NULL 함정

가장 중요한 시험 포인트입니다.

다음 후보 집합을 생각합니다.

```text
10
20
NULL
```

`X NOT IN (10, 20, NULL)`은 단순히 10과 20이 아니면 참이라고 끝나지 않습니다.

NULL과의 비교가 UNKNOWN이 되어 전체 조건이 UNKNOWN으로 남을 수 있습니다.

WHERE는 참인 Row만 남기므로 예상과 다르게 아무 Row도 안 나올 수 있습니다.

## NOT EXISTS

미연결 데이터를 찾을 때 NOT EXISTS가 명확한 경우가 많습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE NOT EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

주문이 하나도 없는 고객만 남습니다.

## LEFT JOIN과 NOT EXISTS

주문 없는 고객은 LEFT JOIN으로도 찾을 수 있습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
LEFT JOIN ORDERS O
    ON C.CUSTOMER_ID = O.CUSTOMER_ID
WHERE O.ORDER_ID IS NULL;
```

NOT EXISTS와 목적이 비슷한 경우가 있습니다.

어떤 문법이 더 좋은지는 가독성과 실행 계획을 함께 봅니다.

## 성능 오해

다음처럼 단정하면 안 됩니다.

```text
EXISTS는 항상 IN보다 빠르다.
IN은 항상 EXISTS보다 빠르다.
```

현대 DBMS는 Query를 다양한 방식으로 최적화합니다.

데이터 분포, Index, 통계, 실행 계획을 확인해야 합니다.

## 시험·면접

### 핵심 암기

```text
IN = 값 비교 / EXISTS = 존재 여부
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

`NOT EXISTS는 미존재 관계를 표현할 때 NULL 함정을 피하기 쉬운 경우가 많다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

IN은 값이 후보 집합 안에 포함되는지 확인하고, EXISTS는 서브쿼리가 Row를 하나라도 반환하는지 확인합니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
