DELETE는 Table에서 조건에 맞는 Row를 제거하는 DML 명령어입니다.

SQL 명령은 비슷해 보여도 **구조를 바꾸는지, 데이터를 바꾸는지, 권한을 바꾸는지**를 구분하면 이해하기 쉽습니다.

</blockquote>

## 핵심 예시

대표 문법은 다음과 같습니다.

```sql
DELETE FROM EMPLOYEE
WHERE EMP_ID = 1001;
```

<mark>DELETE는 WHERE 조건으로 삭제할 Row를 선택하고 Table 구조는 그대로 유지합니다.</mark>

## 기본 DELETE

특정 Row를 삭제합니다.

```sql
DELETE FROM EMPLOYEE
WHERE EMP_ID = 1001;
```

Table 구조는 남고 조건에 맞는 Row만 제거됩니다.

## WHERE가 핵심

WHERE를 생략하면 Table의 모든 Row가 삭제됩니다.

```sql
DELETE FROM EMPLOYEE;
```

SQLite에서 TRUNCATE 대신 전체 삭제에 사용하는 형태이기도 합니다.

<blockquote class="prompt-danger">
<p>DELETE 전에 동일한 WHERE 조건으로 SELECT를 실행해 대상 Row를 확인하는 것이 안전합니다.</p>
</blockquote>

## 여러 Row 삭제

조건에 맞는 여러 Row를 한 번에 삭제할 수 있습니다.

```sql
DELETE FROM EMPLOYEE
WHERE SALARY < 3000;
```

조건을 만족하는 모든 Row가 대상이 됩니다.

## Subquery와 DELETE

서브쿼리를 이용해 대상을 정할 수 있습니다.

```sql
DELETE FROM EMPLOYEE
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
);
```

삭제 전에 같은 조건을 SELECT로 검증하는 것이 좋습니다.

## Foreign Key 영향

부모 Row를 삭제하려고 할 때 자식 Table이 참조 중이면 참조 무결성 때문에 제한될 수 있습니다.

```text
DEPARTMENT.DEPT_ID = 10
↑
EMPLOYEE.DEPT_ID = 10
```

삭제 동작은 Foreign Key의 `ON DELETE` 옵션에 따라 달라질 수 있습니다.

## ON DELETE CASCADE

부모 Row 삭제 시 관련 자식 Row도 함께 삭제하도록 설정할 수 있습니다.

```sql
FOREIGN KEY(DEPT_ID)
REFERENCES DEPARTMENT(DEPT_ID)
ON DELETE CASCADE
```

매우 강력한 동작이므로 의도한 관계인지 확인해야 합니다.

## ON DELETE SET NULL

부모 Row가 삭제될 때 자식 Foreign Key를 NULL로 바꿀 수도 있습니다.

```sql
ON DELETE SET NULL
```

해당 Column이 NULL을 허용해야 의미가 맞습니다.

## DELETE와 DROP

DELETE는 Row를 제거합니다.

DROP은 객체 자체를 제거합니다.

```text
DELETE
→ 데이터 제거
→ Table 유지

DROP
→ Table 자체 제거
```

## DELETE와 TRUNCATE

일반적인 DBMS에서는 TRUNCATE가 전체 Row를 빠르게 비우는 용도로 사용될 수 있습니다.

SQLite는 TRUNCATE를 지원하지 않으므로

```sql
DELETE FROM TABLE_NAME;
```

형태를 사용합니다.

## Transaction

대량 삭제는 Transaction으로 보호하는 것이 좋습니다.

```text
BEGIN
→ DELETE
→ 결과 확인
→ COMMIT 또는 ROLLBACK
```

복구 가능 여부와 실제 Transaction 동작은 DBMS에 따라 확인합니다.
