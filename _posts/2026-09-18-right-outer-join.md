오른쪽 외부 조인은 연결 조건을 만족하는 행을 연결하면서, 짝이 없는 오른쪽 행도 결과에 남기는 연산입니다. 왼쪽에서 연결할 행을 찾지 못하면 왼쪽 열을 결측값으로 채웁니다.

<blockquote class="prompt-info">
<p>오른쪽 행은 모두 보존합니다. 왼쪽 짝이 있으면 연결하고, 짝이 없으면 왼쪽 열을 결측값으로 채웁니다.</p>
</blockquote>

<mark>먼저 오른쪽 표가 무엇인지 확인합니다. 그 표가 빠짐없이 남겨야 할 기준입니다.</mark>

<details>
<summary>한 줄로</summary>

오른쪽 행을 보존하고, 왼쪽 짝이 없으면 왼쪽 열을 결측값으로 채웁니다.

</details>

## 1. 핵심 예시 — 직원이 없는 부서도 조회

**직원 표**

| 직원번호 | 이름 | 부서번호 |
| --- | --- | --- |
| 1 | 민수 | 10 |
| 2 | 지연 | 10 |
| 3 | 현우 | 20 |
| 4 | 수진 | NULL |
| 5 | 도윤 | 40 |

**부서 표**

| 부서번호 | 부서명 |
| --- | --- |
| 10 | 개발부 |
| 20 | 영업부 |
| 30 | 인사부 |

부서를 오른쪽에 놓고 부서번호가 같은 행끼리 연결합니다. 도윤의 부서번호 40은 연결 실패를 보여 주기 위한 예시입니다.

```sql
SELECT 직원.이름, 부서.부서번호, 부서.부서명
FROM 직원
RIGHT OUTER JOIN 부서
ON 직원.부서번호 = 부서.부서번호;
```

**조회 결과**

| 이름 | 부서번호 | 부서명 |
| --- | --- | --- |
| 민수 | 10 | 개발부 |
| 지연 | 10 | 개발부 |
| 현우 | 20 | 영업부 |
| NULL | 30 | 인사부 |

인사부에 연결되는 직원이 없어도 인사부는 남습니다. 이 행에서 왼쪽 직원 표의 이름은 `NULL`입니다.

수진과 도윤은 연결되는 부서가 없으므로 제외됩니다. **직원 표가 왼쪽에 있다고 해서 모든 직원을 남기는 것은 아닙니다.**

결과는 **연결된 3행 + 직원 없는 인사부 1행 = 4행**입니다.

## 2. 왜 필요한가

오른쪽에 놓인 기준 대상을 관련 정보의 유무와 관계없이 보여 주고 싶을 때 사용합니다.

| 조회 목적 | 왼쪽 표 | 보존할 오른쪽 표 |
| --- | --- | --- |
| 직원이 없는 부서도 조회 | 직원 | 부서 |
| 주문하지 않은 고객도 조회 | 주문 | 고객 |
| 판매되지 않은 상품도 조회 | 판매 | 상품 |
| 제출하지 않은 학생도 조회 | 제출 | 학생 |

같은 목적을 왼쪽 외부 조인으로 표현할 수도 있습니다. 중요한 것은 조인 방향의 이름보다 **어느 표를 보존하느냐**입니다.

## 3. 작동 방식 — 오른쪽 행에서 짝을 찾기

### 3.1. 기본 문법

```sql
SELECT 왼쪽표.조회열, 오른쪽표.조회열
FROM 왼쪽표
RIGHT OUTER JOIN 오른쪽표
ON 왼쪽표.연결열 = 오른쪽표.연결열;
```

위 코드는 문법의 틀입니다. 실제 표와 열 이름으로 바꾸어 사용합니다.

| 구문 | 역할 |
| --- | --- |
| FROM 왼쪽표 | 연결할 왼쪽 입력 표 |
| RIGHT OUTER JOIN 오른쪽표 | 보존할 오른쪽 입력 표 |
| ON | 어떤 행끼리 연결할지 지정 |
| SELECT | 결과에 보여 줄 열 선택 |

`OUTER`는 생략할 수 있습니다. `RIGHT JOIN`과 `RIGHT OUTER JOIN`은 같은 조인 종류입니다.

### 3.2. 짝이 있으면 모든 짝을 연결

개발부에는 민수와 지연의 두 행이 연결됩니다. 따라서 개발부는 조회 결과에서 두 행에 나타납니다.

영업부에는 현우 한 행이 연결됩니다. 영업부의 결과는 한 행입니다.

### 3.3. 짝이 없으면 왼쪽 열에 결측값을 채운다

인사부에는 연결할 직원이 없습니다. 그래도 인사부를 보존해야 하므로 직원 표의 열을 결측값으로 채운 한 행이 나옵니다.

| 오른쪽 한 행의 왼쪽 짝 수 | 만들어지는 결과 행 수 |
| --- | --- |
| 0개 | 1행 — 왼쪽 열을 결측값으로 채움 |
| 1개 | 1행 — 그 짝과 연결 |
| 2개 | 2행 — 각 짝과 연결 |

<blockquote class="prompt-info">
<p>이는 결과를 이해하기 위한 논리적 설명입니다. 실제 실행은 데이터베이스의 실행 계획을 따릅니다. 결과 행의 표시 순서는 별도의 정렬 구문으로 지정합니다.</p>
</blockquote>

## 4. 주요 개념

### 4.1. 표 순서를 바꾸면 왼쪽 외부 조인으로 표현할 수 있다

앞의 오른쪽 외부 조인은 다음과 같이 바꿀 수 있습니다.

```sql
SELECT 직원.이름, 부서.부서번호, 부서.부서명
FROM 부서
LEFT OUTER JOIN 직원
ON 부서.부서번호 = 직원.부서번호;
```

| 표현 | 보존하는 표 |
| --- | --- |
| 직원 RIGHT JOIN 부서 | 부서 |
| 부서 LEFT JOIN 직원 | 부서 |

표 순서를 바꾸고 같은 연결 조건과 같은 조회 열을 사용하면 같은 결과 행을 얻습니다. 표시 순서는 별개입니다.

<mark>오른쪽 외부 조인을 왼쪽 외부 조인으로 바꿀 때는 표 순서도 함께 바꿉니다.</mark>

### 4.2. 방향만 바꾸면 결과가 달라진다

직원과 부서의 순서를 그대로 둔 채 조인 방향만 바꾸면 보존 대상이 달라집니다.

| 표현 | 보존 대상 | 기본 예시의 결과 행 수 |
| --- | --- | --- |
| 직원 LEFT JOIN 부서 | 직원 | 5 |
| 직원 RIGHT JOIN 부서 | 부서 | 4 |

첫 번째는 수진과 도윤이 남습니다. 두 번째는 직원이 없는 인사부가 남습니다.

### 4.3. 결측값으로 채우는 쪽은 보존 대상의 반대쪽이다

인사부 행에서 부서번호 30과 부서명은 그대로 남습니다. 연결되지 않은 직원번호·직원 이름 등 **왼쪽 직원 표의 열**이 결측값으로 채워집니다.

원본 직원 표나 부서 표를 수정하는 것은 아닙니다. 결측값을 채운 조회 결과를 만드는 것입니다.

## 5. 장점과 주의할 점

| 구분 | 내용 |
| --- | --- |
| 장점 | 오른쪽에 놓인 기준 대상을 빠짐없이 조회 |
| 장점 | 관련 정보가 없는 대상도 확인 가능 |
| 장점 | 왼쪽 외부 조인과 대응 관계를 이해하기 쉬움 |
| 주의 | 연결되는 행이 여러 개면 결과 행 수 증가 |
| 주의 | 표 순서를 그대로 두고 방향만 바꾸면 결과가 달라짐 |
| 주의 | 조회 조건이 보존한 행을 걸러낼 수 있음 |

실제 사용할 때는 데이터베이스의 구문 지원 범위를 확인합니다. 지원하지 않는 환경이라면 표 순서를 바꾼 왼쪽 외부 조인으로 표현할 수 있습니다.

## 6. 다른 조인과 비교

직원을 왼쪽, 부서를 오른쪽에 놓고 부서번호의 등호 조건을 사용합니다.

| 구분 | 연결된 직원 3행 | 수진·도윤 | 직원 없는 인사부 | 전체 행 수 |
| --- | --- | --- | --- | --- |
| 내부 조인 | 포함 | 제외 | 제외 | 3 |
| 왼쪽 외부 조인 | 포함 | 포함 | 제외 | 5 |
| 오른쪽 외부 조인 | 포함 | 제외 | 포함 | 4 |
| 완전 외부 조인 | 포함 | 포함 | 포함 | 6 |

**내부 조인 결과에 오른쪽의 미연결 행을 추가한 것**으로 오른쪽 외부 조인을 이해할 수 있습니다.

## 잘 놓치는 핵심

### 1. 결과 행 수가 항상 오른쪽 표의 행 수와 같지는 않다

기본 예시의 부서는 3행이지만 결과는 4행입니다. 개발부 한 행에 직원 두 행이 연결되기 때문입니다.

등호 조건에서는 연결값별로 다음처럼 계산합니다.

| 연결값 | 왼쪽 행 수 | 오른쪽 행 수 | 결과 행 수 |
| --- | --- | --- | --- |
| 10 | 3 | 2 | 6 |
| 20 | 1 | 1 | 1 |
| 30 | 0 | 2 | 2 |
| 40 | 2 | 0 | 0 |
| 합계 | 6 | 5 | 9 |

**짝이 있으면 양쪽 행 수를 곱하고, 짝이 없으면 오른쪽 행 수를 남깁니다.** 왼쪽에만 있는 값 40은 결과에 포함하지 않습니다.

### 2. 연결 조건과 조회 조건은 역할이 다르다

다음은 모든 부서를 남기되, 직원 이름이 민수인 행만 연결합니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
RIGHT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
AND 직원.이름 = '민수';
```

다음은 연결된 결과에서 직원 이름이 민수인 행만 남깁니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
RIGHT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
WHERE 직원.이름 = '민수';
```

| 부서 | 민수 조건을 ON에 지정 | 민수 조건을 WHERE에 지정 |
| --- | --- | --- |
| 개발부 | 민수와 연결된 1행 | 민수와 연결된 1행 |
| 영업부 | 직원 이름을 NULL로 채운 1행 | 제외 |
| 인사부 | 직원 이름을 NULL로 채운 1행 | 제외 |
| 전체 행 수 | 3행 | 1행 |

첫 번째 조회의 영업부는 실제 직원이 있어도 민수라는 추가 연결 조건을 만족하지 못합니다. 그러므로 직원 열을 결측값으로 채워 남깁니다.

<blockquote class="prompt-warning">
<p>오른쪽 외부 조인은 조인 단계에서 오른쪽 행을 보존합니다. 이후 조회 조건을 적용한 최종 결과에서는 보존했던 행도 제외될 수 있습니다.</p>
</blockquote>

### 3. 미연결 행을 찾을 때는 왼쪽 기본키를 검사한다

직원번호가 직원 표의 기본키라면 다음 조회로 직원이 연결되지 않는 부서를 찾을 수 있습니다.

```sql
SELECT 부서.부서번호, 부서.부서명
FROM 직원
RIGHT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
WHERE 직원.직원번호 IS NULL;
```

결과는 **부서번호 30인 인사부**입니다. 기본키는 실제 직원 행에서 결측일 수 없으므로 연결 실패를 구분할 수 있습니다.

직원 이름만 검사하면 원래 이름이 결측인 실제 직원 행을 연결 실패로 오해할 수 있습니다.

### 4. 연결값의 결측과 조회 열의 결측을 구분한다

일반적인 등호 조건에서 `NULL = NULL`은 참이 아니므로 결측 연결값끼리는 짝을 이루지 않습니다.

오른쪽 연결값이 결측이라면 왼쪽 짝은 찾지 못하지만, 오른쪽 행 자체는 보존됩니다. 단, 별도의 조회 조건이 없어야 합니다.

또한 부서번호가 일치하고 직원 이름만 결측인 경우에는 정상적으로 연결됩니다. **결측값이 있다고 무조건 연결 실패인 것은 아닙니다.**

### 5. 직원 수를 집계할 때 전체 행 수를 세면 안 된다

직원이 없는 부서까지 인원 집계에 포함하는 예시입니다. 직원번호는 직원 표의 기본키라고 가정합니다.

```sql
SELECT 부서.부서명, COUNT(직원.직원번호) AS 직원수
FROM 직원
RIGHT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
GROUP BY 부서.부서번호, 부서.부서명;
```

| 부서명 | COUNT(직원.직원번호) | COUNT(*)를 사용했다면 |
| --- | --- | --- |
| 개발부 | 2 | 2 |
| 영업부 | 1 | 1 |
| 인사부 | 0 | 1 |

인사부도 결측값을 채운 한 행으로 남기 때문에 `COUNT(*)`는 1입니다. 직원번호가 결측인 행을 세지 않는 `COUNT(직원.직원번호)`는 0입니다.

## 시험·면접

### 핵심 암기 포인트

- 오른쪽 표의 행을 보존합니다.
- 왼쪽 짝이 없으면 왼쪽 열을 결측값으로 채웁니다.
- 왼쪽에만 있는 미연결 행은 제외합니다.
- 왼쪽 짝이 여러 개라면 각 조합을 모두 반환합니다.
- 표 순서를 바꾸면 왼쪽 외부 조인으로 표현할 수 있습니다.
- 조회 조건에 따라 보존했던 행도 최종 결과에서 사라질 수 있습니다.

### 면접에서 바로 말하기

“오른쪽 외부 조인은 오른쪽 표의 모든 행을 보존하면서 조건에 맞는 왼쪽 행을 연결합니다. 연결할 왼쪽 행이 없으면 왼쪽 열을 결측값으로 채웁니다. 표 순서를 바꾸면 같은 보존 대상을 왼쪽 외부 조인으로 표현할 수 있습니다.”

### 시험 함정 정리

| 잘못된 설명 | 올바른 판단 |
| --- | --- |
| 결과 행 수는 오른쪽 행 수와 항상 같다 | 여러 짝이 있으면 더 많아짐 |
| 왼쪽 행도 모두 보존한다 | 왼쪽의 미연결 행은 제외 |
| 조인 방향만 바꾸어도 결과가 같다 | 표 순서도 바꾸어야 같은 보존 대상 |
| 결측값을 채우는 쪽은 오른쪽이다 | 연결 실패 시 왼쪽 열을 결측값으로 채움 |

## 예시로 한 바퀴 — 직원 없는 부서 찾기

**첫째, 모든 부서를 보존합니다.** 부서를 오른쪽에 놓습니다.

**둘째, 부서번호가 같은 직원을 연결합니다.** 개발부에는 두 명, 영업부에는 한 명이 연결됩니다.

**셋째, 왼쪽 기본키가 결측인 행을 찾습니다.** 인사부만 남습니다.

```sql
SELECT 부서.부서번호, 부서.부서명
FROM 직원
RIGHT OUTER JOIN 부서
ON 직원.부서번호 = 부서.부서번호
WHERE 직원.직원번호 IS NULL
ORDER BY 부서.부서번호;
```

| 부서번호 | 부서명 |
| --- | --- |
| 30 | 인사부 |

## 객관식 문제

### 문제 1. 오른쪽 외부 조인의 설명으로 옳은 것은?

① 왼쪽 표의 모든 행만 보존한다.  
② 짝이 있는 행만 남긴다.  
③ 오른쪽 행을 보존하고 짝이 없으면 왼쪽 열을 결측값으로 채운다.  
④ 양쪽 표의 모든 미연결 행을 보존한다.

<details>
<summary>정답과 해설</summary>

**③**. 보존 대상은 오른쪽 표이며, 결측값을 채우는 쪽은 연결되지 않은 왼쪽 표의 열입니다.

</details>

### 문제 2. 기본 예시의 직원 RIGHT JOIN 부서 결과는 몇 행인가?

부서번호의 등호 조건을 사용하고 추가 조회 조건은 없습니다.

① 3행  
② 4행  
③ 5행  
④ 6행

<details>
<summary>정답과 해설</summary>

**②**. 연결된 직원 3행에 직원이 없는 인사부 1행을 더합니다. 수진과 도윤은 제외합니다.

</details>

### 문제 3. 같은 결과를 얻도록 바꾼 표현은?

원래 표현은 `직원 RIGHT JOIN 부서`입니다. 같은 연결 조건과 같은 조회 열을 사용합니다.

① 직원 LEFT JOIN 부서  
② 부서 RIGHT JOIN 직원  
③ 직원 INNER JOIN 부서  
④ 부서 LEFT JOIN 직원

<details>
<summary>정답과 해설</summary>

**④**. 표 순서를 바꾸고 왼쪽 외부 조인으로 바꾸면 부서를 보존하는 같은 결과가 됩니다.

</details>

### 문제 4. 오른쪽 한 행에 연결되는 왼쪽 짝이 2개라면?

추가 조회 조건과 중복 제거는 없습니다.

① 0행  
② 1행  
③ 2행  
④ 결측값을 채운 행까지 포함해 3행

<details>
<summary>정답과 해설</summary>

**③**. 두 짝과 각각 연결된 결과가 나옵니다. 연결에 성공했으므로 별도의 결측 행을 추가하지 않습니다.

</details>

### 문제 5. 민수 조건을 WHERE에 적용한 기본 예시의 결과는?

직원 RIGHT JOIN 부서 뒤에 `WHERE 직원.이름 = '민수'`를 적용합니다.

① 모든 부서가 남는다.  
② 민수와 연결된 개발부 1행만 남는다.  
③ 직원 없는 인사부만 남는다.  
④ 모든 직원이 남는다.

<details>
<summary>정답과 해설</summary>

**②**. 조회 조건을 만족하는 행만 남습니다. 직원 이름이 결측인 인사부도 민수라는 조건을 만족하지 못합니다.

</details>

### 문제 6. 직원 없는 부서를 찾는 적절한 조회 조건은?

직원 RIGHT JOIN 부서이며 직원번호는 직원 표의 기본키입니다.

① 직원.직원번호 IS NULL  
② 부서.부서번호 IS NULL  
③ 직원.직원번호 = NULL  
④ 부서.부서번호 = 0

<details>
<summary>정답과 해설</summary>

**①**. 왼쪽 직원 행이 연결되지 않으면 직원번호가 결측값으로 채워집니다. 기본키의 결측 여부로 연결 실패를 확인합니다.

</details>
