<p>한 줄: 값만 계산하지 말고 주소 관계와 실행 순서를 먼저 추적하는 고난도 문제 세트입니다.</p>

## 문제 1. 이중 포인터와 포인터 이동

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[] = {10, 20, 30, 40};

    int *p = a;
    int **pp = &p;

    (*pp)++;
    **pp += 5;
    (*pp)++;
    **pp -= 10;

    printf("%d %d %d %d\n",
           a[0], a[1], a[2], a[3]);

    return 0;
}
```

① `10 20 20 40`  
② `10 25 20 40`  
③ `15 25 20 40`  
④ `10 25 30 30`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>10 25 20 40</code></strong>입니다.</p>

### 1. 실행 전 상태

배열은 다음과 같습니다.

```text
인덱스   0   1   2   3
값      10  20  30  40
```

포인터 관계는 다음과 같습니다.

```text
pp → p → a[0] → 10
```

즉:

```text
p  = &a[0]
pp = &p
```

### 2. 첫 번째 코드 실행

```c
(*pp)++;
```

괄호 안의 <code>*pp</code>는 포인터 변수 <code>p</code> 자체입니다.

따라서 이 코드는 실제로 다음과 같습니다.

```c
p++;
```

현재 <code>p</code>는 <code>a[0]</code>을 가리키고 있으므로 한 칸 이동합니다.

```text
p → a[1] → 20
```

배열 값은 아직 변하지 않습니다.

### 3. 두 번째 코드 실행

```c
**pp += 5;
```

현재 관계는 다음과 같습니다.

```text
pp → p → a[1]
```

따라서:

```text
**pp = a[1]
```

실제 효과는:

```c
a[1] += 5;
```

이므로:

```text
a[1] = 25
```

현재 배열:

```text
10 25 30 40
```

### 4. 세 번째 코드 실행

```c
(*pp)++;
```

다시 포인터 <code>p</code> 자체가 한 칸 이동합니다.

```text
p → a[2] → 30
```

### 5. 네 번째 코드 실행

```c
**pp -= 10;
```

현재:

```text
pp → p → a[2]
```

이므로:

```text
a[2] = 30 - 10 = 20
```

### 6. 최종 상태

```text
a[0] = 10
a[1] = 25
a[2] = 20
a[3] = 40
```

최종 출력:

```text
10 25 20 40
```

### 반드시 알아야 할 개념

이중 포인터는 다음처럼 단계별로 읽습니다.

```text
pp   → p의 주소
*pp  → p 자체
**pp → p가 가리키는 실제 값
```

따라서:

```c
(*pp)++;
```

는 실제 값을 증가시키는 것이 아니라 포인터 <code>p</code>를 이동시킵니다.

반면:

```c
(**pp)++;
```

라면 실제 값을 증가시킵니다.

### 자주 하는 실수

<code>(*pp)++</code>와 <code>(**pp)++</code>를 같은 것으로 보면 안 됩니다.

별표 하나 차이로 **포인터 자체를 이동하는지, 실제 값을 변경하는지**가 달라집니다.

</details>

## 문제 2. 문자 포인터 배열과 이중 포인터

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    const char *s[] = {
        "APPLE",
        "BANANA",
        "CHERRY"
    };

    const char **p = s + 1;

    printf("%c %s %c\n",
           (*p)[2],
           *(p + 1),
           *(*(p - 1) + 4));

    return 0;
}
```

① `N CHERRY E`  
② `A BANANA L`  
③ `N BANANA E`  
④ `A CHERRY E`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>N CHERRY E</code></strong>입니다.</p>

### 1. 문자 포인터 배열의 상태

<code>s</code>의 각 원소에는 문자열의 시작 주소가 저장됩니다.

```text
s[0] → "APPLE"
s[1] → "BANANA"
s[2] → "CHERRY"
```

포인터 선언:

```c
const char **p = s + 1;
```

따라서:

```text
p → s[1] → "BANANA"
```

### 2. 첫 번째 출력값

```c
(*p)[2]
```

먼저:

```text
*p = s[1]
```

즉 문자열 <code>BANANA</code>를 가리킵니다.

```text
인덱스   0   1   2   3   4   5
문자     B   A   N   A   N   A
```

따라서:

```text
(*p)[2] = N
```

### 3. 두 번째 출력값

```c
*(p + 1)
```

현재 <code>p</code>는 <code>s[1]</code>을 가리킵니다.

한 칸 이동하면:

```text
p + 1 → s[2]
```

따라서:

```text
*(p + 1) → "CHERRY"
```

<code>%s</code>로 출력하므로:

```text
CHERRY
```

가 출력됩니다.

### 4. 세 번째 출력값

```c
*(*(p - 1) + 4)
```

먼저:

```text
p - 1 → s[0]
```

따라서:

```text
*(p - 1) → "APPLE"
```

문자열 인덱스:

```text
인덱스   0   1   2   3   4
문자     A   P   P   L   E
```

따라서 인덱스 4의 문자는:

```text
E
```

입니다.

### 5. 최종 출력

```text
N CHERRY E
```

### 반드시 알아야 할 개념

```c
const char *s[3];
```

은 문자열 세 개를 직접 저장하는 2차원 배열이 아니라 **문자 포인터 세 개를 저장하는 배열**입니다.

또한:

```c
const char **p;
```

는 문자 포인터를 가리키는 포인터입니다.

```text
p → s[1] → "BANANA"
```

처럼 두 단계를 나눠 읽으면 쉽습니다.

### 자주 하는 실수

<code>p + 1</code>이 문자열 안에서 다음 문자로 이동한다고 생각하면 안 됩니다.

<code>p</code>가 가리키는 대상은 문자 하나가 아니라 **문자 포인터 배열의 원소**입니다.

</details>

## 문제 3. 구조체 배열과 포인터 연산

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef struct {
    int id;
    int score;
} Student;

int main(void)
{
    Student s[3] = {
        {1, 70},
        {2, 80},
        {3, 90}
    };

    Student *p = s + 1;

    p->score += (p - 1)->score / 10;
    (p + 1)->score -= p->id * 5;

    printf("%d %d %d\n",
           s[0].score,
           s[1].score,
           s[2].score);

    return 0;
}
```

① `70 87 80`  
② `70 87 85`  
③ `77 80 80`  
④ `70 80 85`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>70 87 80</code></strong>입니다.</p>

### 1. 실행 전 상태

```text
s[0] = {id = 1, score = 70}
s[1] = {id = 2, score = 80}
s[2] = {id = 3, score = 90}
```

포인터는:

```c
Student *p = s + 1;
```

이므로:

```text
p → s[1]
```

### 2. 첫 번째 코드 실행

```c
p->score += (p - 1)->score / 10;
```

왼쪽:

```text
p->score = s[1].score = 80
```

오른쪽에서:

```text
p - 1 → s[0]
```

따라서:

```text
(p - 1)->score = 70
```

정수 나눗셈:

```text
70 / 10 = 7
```

결과:

```text
s[1].score = 80 + 7 = 87
```

### 3. 두 번째 코드 실행

```c
(p + 1)->score -= p->id * 5;
```

먼저:

```text
p + 1 → s[2]
```

따라서 왼쪽은:

```text
s[2].score = 90
```

오른쪽:

```text
p->id = s[1].id = 2
```

따라서:

```text
2 × 5 = 10
```

결과:

```text
s[2].score = 90 - 10 = 80
```

### 4. 최종 상태

```text
s[0].score = 70
s[1].score = 87
s[2].score = 80
```

최종 출력:

```text
70 87 80
```

### 반드시 알아야 할 개념

구조체 포인터의:

```c
p->score
```

는 다음과 같습니다.

```c
(*p).score
```

그리고 구조체 포인터의 <code>p + 1</code>은 다음 구조체 배열 원소를 가리킵니다.

### 자주 하는 실수

<code>p + 1</code>이 구조체 내부의 다음 멤버로 이동한다고 생각하면 안 됩니다.

포인터는 자신이 가리키는 자료형 전체 크기 단위로 이동합니다.

</details>

## 문제 4. 재귀와 포인터 이동

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int sum(int *p, int n)
{
    if (n == 0)
        return 0;

    return *p + sum(p + 1, n - 1);
}

int main(void)
{
    int a[] = {2, 4, 6, 8, 10};

    printf("%d\n", sum(a + 1, 3));

    return 0;
}
```

① `12`  
② `18`  
③ `24`  
④ `28`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>18</code></strong>입니다.</p>

### 1. 실행 전 배열

```text
인덱스   0   1   2   3   4
값       2   4   6   8  10
```

호출:

```c
sum(a + 1, 3)
```

따라서 첫 호출에서는:

```text
p → a[1] → 4
n = 3
```

### 2. 첫 번째 호출

```c
return *p + sum(p + 1, n - 1);
```

현재:

```text
*p = 4
```

따라서:

```text
sum(a + 1, 3)
= 4 + sum(a + 2, 2)
```

### 3. 두 번째 호출

현재:

```text
p → a[2] → 6
n = 2
```

따라서:

```text
sum(a + 2, 2)
= 6 + sum(a + 3, 1)
```

### 4. 세 번째 호출

현재:

```text
p → a[3] → 8
n = 1
```

따라서:

```text
sum(a + 3, 1)
= 8 + sum(a + 4, 0)
```

### 5. 종료 조건

```c
if (n == 0)
    return 0;
```

따라서:

```text
sum(a + 4, 0) = 0
```

### 6. 반환값 계산

```text
8 + 0 = 8
6 + 8 = 14
4 + 14 = 18
```

### 7. 최종 출력

```text
18
```

### 반드시 알아야 할 개념

재귀가 한 단계 깊어질 때마다:

```text
p → 다음 배열 원소
n → 1 감소
```

합니다.

따라서 이번 문제에서 실제로 더하는 값은:

```text
4 + 6 + 8
```

입니다.

### 자주 하는 실수

인자 <code>3</code>을 배열 인덱스라고 생각하면 안 됩니다.

여기서는 앞으로 처리할 원소의 개수를 의미합니다.

</details>

## 문제 5. 함수 포인터 배열과 순차 실행

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int f1(int x)
{
    return x + 2;
}

int f2(int x)
{
    return x * 3;
}

int f3(int x)
{
    return x - 4;
}

int main(void)
{
    int (*f[3])(int) = {f1, f2, f3};

    int x = 5;

    x = f[0](x);
    x = f[1](x);
    x = f[2](x);

    printf("%d\n", x);

    return 0;
}
```

① `13`  
② `15`  
③ `17`  
④ `21`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>17</code></strong>입니다.</p>

### 1. 함수 포인터 배열 구성

```c
int (*f[3])(int) = {f1, f2, f3};
```

각 위치는 다음 함수를 가리킵니다.

```text
f[0] → f1
f[1] → f2
f[2] → f3
```

각 함수 역할:

```text
f1(x) = x + 2
f2(x) = x × 3
f3(x) = x - 4
```

### 2. 초기값

```text
x = 5
```

### 3. 첫 번째 호출

```c
x = f[0](x);
```

즉:

```text
f1(5) = 7
```

따라서:

```text
x = 7
```

### 4. 두 번째 호출

```c
x = f[1](x);
```

현재 값 7을 사용합니다.

```text
f2(7) = 21
```

따라서:

```text
x = 21
```

### 5. 세 번째 호출

```c
x = f[2](x);
```

현재 값 21을 사용합니다.

```text
f3(21) = 17
```

따라서:

```text
x = 17
```

### 6. 최종 출력

```text
17
```

### 반드시 알아야 할 개념

```c
int (*f[3])(int)
```

은 정수 하나를 받아 정수 하나를 반환하는 함수의 주소를 3개 저장하는 배열입니다.

함수 포인터 배열은 여러 동작을 인덱스로 선택할 때 사용할 수 있습니다.

### 자주 하는 실수

세 함수가 모두 처음 값 <code>5</code>를 받는 것이 아닙니다.

앞 함수의 반환값이 <code>x</code>에 저장되고 그 변경된 값이 다음 함수의 입력이 됩니다.

</details>


## 문제 6. 비트 마스크로 상위·하위 4비트 분리

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    unsigned int x = 0xAC;

    unsigned int a = x & 0x0F;
    unsigned int b = (x >> 4) & 0x0F;

    printf("%u %u %u\n",
           a,
           b,
           a + b);

    return 0;
}
```

① `10 12 22`  
② `12 10 22`  
③ `12 10 20`  
④ `10 12 20`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>12 10 22</code></strong>입니다.</p>

### 1. 16진수를 4비트씩 해석

```text
0xAC
```

16진수 한 자리는 이진수 4비트입니다.

```text
A = 10 = 1010
C = 12 = 1100
```

따라서:

```text
x = 1010 1100
```

### 2. 하위 4비트 추출

```c
unsigned int a = x & 0x0F;
```

<code>0x0F</code>는:

```text
0000 1111
```

입니다.

AND 연산:

```text
1010 1100
0000 1111
---------
0000 1100
```

결과는:

```text
12
```

따라서:

```text
a = 12
```

### 3. 상위 4비트 이동

```c
x >> 4
```

원래 값:

```text
1010 1100
```

오른쪽으로 4비트 이동하면:

```text
0000 1010
```

즉:

```text
10
```

입니다.

### 4. 하위 4비트만 다시 남기기

```c
(x >> 4) & 0x0F
```

현재 값이:

```text
0000 1010
```

이므로 결과는 그대로 10입니다.

```text
b = 10
```

### 5. 합 계산

```text
a + b
= 12 + 10
= 22
```

### 6. 최종 출력

```text
12 10 22
```

### 반드시 알아야 할 개념

비트 마스크는 특정 비트만 남기고 나머지를 제거하는 데 사용합니다.

```c
x & 0x0F
```

는 하위 4비트를 남깁니다.

```c
x >> 4
```

는 상위 비트를 오른쪽으로 이동시킵니다.

### 자주 하는 실수

16진수 <code>0xAC</code>를 십진수 10과 12를 단순히 이어 붙인 값처럼 생각하면 안 됩니다.

각 16진수 한 자리를 4비트 단위로 분리해서 보는 것이 가장 안전합니다.

</details>

## 문제 7. 겹치는 메모리와 memcpy

다음 코드에 대한 설명으로 가장 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char s[] = "ABCDE";

    memcpy(s + 1, s, 4);

    printf("%s\n", s);

    return 0;
}
```

① 반드시 `AABCD`를 출력한다.  
② 반드시 `ABCDE`를 출력한다.  
③ 원본과 목적지 영역이 겹치므로 `memcpy`를 사용하면 안 된다.  
④ 컴파일되지 않는다.

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③</strong>입니다.</p>

### 1. 실행 전 문자열 상태

문자열은 실제로 다음과 같이 저장됩니다.

```text
인덱스   0   1   2   3   4   5
문자     A   B   C   D   E  \0
```

### 2. memcpy의 인자 해석

```c
memcpy(s + 1, s, 4);
```

형태는 다음과 같습니다.

```text
memcpy(목적지, 원본, 복사크기)
```

따라서:

```text
목적지 = s + 1 = &s[1]
원본   = s     = &s[0]
크기   = 4바이트
```

### 3. 원본 영역 확인

원본으로 읽는 영역은:

```text
s[0] ~ s[3]
```

즉:

```text
A B C D
```

입니다.

### 4. 목적지 영역 확인

목적지로 쓰는 영역은:

```text
s[1] ~ s[4]
```

입니다.

### 5. 두 영역 비교

```text
원본     s[0] s[1] s[2] s[3]
목적지        s[1] s[2] s[3] s[4]
```

<code>s[1]</code>부터 <code>s[3]</code>까지 겹칩니다.

### 6. 왜 문제가 되는가

<code>memcpy</code>는 원본과 목적지 영역이 겹치지 않는 경우를 전제로 합니다.

겹치는 영역에 사용하면 동작이 보장되지 않습니다.

따라서 특정 문자열이 반드시 출력된다고 판단하면 안 됩니다.

### 7. 올바른 함수

겹치는 영역을 안전하게 복사하려면:

```c
memmove(s + 1, s, 4);
```

를 사용합니다.

### 반드시 알아야 할 개념

두 함수의 차이는 다음과 같습니다.

| 함수 | 메모리 영역 겹침 |
| --- | --- |
| `memcpy` | 겹치면 안 됨 |
| `memmove` | 겹쳐도 처리 가능 |

### 자주 하는 실수

특정 환경에서 우연히 <code>AABCD</code>처럼 보이는 결과가 나왔다고 해서 그 결과가 언어 규칙상 보장되는 것은 아닙니다.

<mark>한 번 실행해서 나온 결과와 C 표준이 보장하는 결과는 구분해야 합니다.</mark>

</details>

## 문제 8. 역순 포인터 접근

다음 코드가 `50 40 30 20 10`을 출력하도록 빈칸에 들어갈 표현으로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[] = {10, 20, 30, 40, 50};
    int *p = a + 5;

    for (int i = 0; i < 5; i++) {
        printf("%d ", ____________);
    }

    return 0;
}
```

① `*p--`  
② `*--p`  
③ `(*p)--`  
④ `*(p++)`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>*--p</code></strong>입니다.</p>

### 1. 실행 전 상태

배열:

```text
인덱스   0   1   2   3   4
값      10  20  30  40  50
```

포인터 선언:

```c
int *p = a + 5;
```

원소가 5개이므로 <code>a + 5</code>는 마지막 원소 바로 다음 위치입니다.

```text
a[0] a[1] a[2] a[3] a[4] [a+5]
 10    20    30    40    50     ↑
                               p
```

이 위치를 직접 역참조하면 안 됩니다.

### 2. 정답 표현 해석

```c
*--p
```

전위 감소이므로 먼저 <code>p</code>를 한 칸 줄입니다.

첫 반복:

```text
p : a + 5 → a + 4
```

그 후 역참조합니다.

```text
*p = a[4] = 50
```

### 3. 두 번째 반복

다시 먼저 감소합니다.

```text
p : a[4] → a[3]
```

따라서:

```text
*p = 40
```

### 4. 나머지 반복

같은 방식으로:

```text
a[2] → 30
a[1] → 20
a[0] → 10
```

을 출력합니다.

### 5. 최종 출력

```text
50 40 30 20 10
```

### 6. 오답 ①

```c
*p--
```

는 다음처럼 해석됩니다.

```c
*(p--)
```

즉 현재 위치를 먼저 역참조한 뒤 포인터를 줄입니다.

하지만 첫 반복에서 현재 위치는 <code>a + 5</code>이므로 잘못된 접근입니다.

### 7. 오답 ③

```c
(*p)--
```

는 포인터가 아니라 포인터가 가리키는 값을 감소시키는 코드입니다.

이번 문제의 목표와 다릅니다.

### 8. 오답 ④

```c
*(p++)
```

는 포인터를 더 뒤쪽으로 이동시키므로 방향도 반대입니다.

### 반드시 알아야 할 개념

```c
*p--
```

는:

```text
현재 위치의 값을 사용한 뒤 포인터 감소
```

이고:

```c
*--p
```

는:

```text
포인터를 먼저 감소시킨 뒤 값 사용
```

입니다.

### 자주 하는 실수

배열의 마지막 원소 주소는 <code>a + 4</code>입니다.

<code>a + 5</code>는 마지막 원소 다음 위치라는 점을 반드시 구분해야 합니다.

</details>

## 문제 9. 연산자 우선순위와 포인터 식

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[] = {5, 10, 15};
    int *p = a;

    int x = *p + *(p + 1) * 2;
    int y = (*p + *(p + 1)) * 2;

    printf("%d %d\n", x, y);

    return 0;
}
```

① `25 30`  
② `25 40`  
③ `30 30`  
④ `30 40`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>25 30</code></strong>입니다.</p>

### 1. 실행 전 상태

배열:

```text
인덱스   0   1   2
값       5  10  15
```

포인터:

```text
p → a[0] → 5
```

따라서:

```text
*p = 5
*(p + 1) = 10
```

### 2. 첫 번째 식

```c
int x = *p + *(p + 1) * 2;
```

포인터 식을 값으로 치환하면:

```text
x = 5 + 10 × 2
```

곱셈이 덧셈보다 먼저입니다.

```text
10 × 2 = 20
5 + 20 = 25
```

따라서:

```text
x = 25
```

### 3. 두 번째 식

```c
int y = (*p + *(p + 1)) * 2;
```

괄호 안을 먼저 계산합니다.

```text
5 + 10 = 15
```

그다음:

```text
15 × 2 = 30
```

따라서:

```text
y = 30
```

### 4. 최종 출력

```text
25 30
```

### 반드시 알아야 할 개념

복잡한 포인터 식은 바로 계산하지 말고 먼저 실제 값으로 바꾸는 것이 안전합니다.

```c
*p + *(p + 1) * 2
```

를:

```text
5 + 10 × 2
```

로 바꾼 뒤 일반 연산자 우선순위를 적용합니다.

### 자주 하는 실수

첫 번째 식을 왼쪽부터 무조건 계산하여:

```text
(5 + 10) × 2
```

로 처리하면 안 됩니다.

곱셈이 덧셈보다 우선합니다.

</details>

## 문제 10. 포인터 이동과 변경된 값 재사용

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[] = {3, 6, 9, 12};

    int *p = a + 1;
    int *q = a + 3;

    *p += *q / 3;
    q--;
    *q -= *p / 2;

    printf("%d %d %d %d\n",
           a[0], a[1], a[2], a[3]);

    return 0;
}
```

① `3 10 4 12`  
② `3 10 9 12`  
③ `3 9 5 12`  
④ `3 10 5 12`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>3 10 4 12</code></strong>입니다.</p>

### 1. 실행 전 상태

배열:

```text
인덱스   0   1   2   3
값       3   6   9  12
```

포인터:

```text
p → a[1] → 6
q → a[3] → 12
```

### 2. 첫 번째 코드 실행

```c
*p += *q / 3;
```

현재:

```text
*p = 6
*q = 12
```

오른쪽부터 계산합니다.

```text
12 / 3 = 4
```

따라서:

```text
*p = 6 + 4 = 10
```

즉:

```text
a[1] = 10
```

현재 배열:

```text
3 10 9 12
```

### 3. 포인터 q 이동

```c
q--;
```

현재 <code>q</code>는 <code>a[3]</code>을 가리킵니다.

한 칸 감소하면:

```text
q → a[2] → 9
```

현재 포인터 관계:

```text
p → a[1] → 10
q → a[2] → 9
```

### 4. 다음 코드 실행

```c
*q -= *p / 2;
```

왼쪽:

```text
*q = 9
```

오른쪽:

```text
*p = 10
```

중요한 점은 <code>*p</code>가 원래 값 6이 아니라 앞에서 변경된 값 10이라는 것입니다.

```text
10 / 2 = 5
```

따라서:

```text
*q = 9 - 5 = 4
```

즉:

```text
a[2] = 4
```

### 5. 최종 상태

```text
a[0] = 3
a[1] = 10
a[2] = 4
a[3] = 12
```

최종 출력:

```text
3 10 4 12
```

### 반드시 알아야 할 개념

코드 추론 문제에서는 앞에서 변경된 메모리 상태가 뒤 코드에 그대로 이어집니다.

```c
*p += *q / 3;
```

이 실행된 뒤 <code>*p</code>는 더 이상 6이 아니라 10입니다.

### 자주 하는 실수

두 문장을 독립적으로 보고 두 번째 계산에서 원래 배열 값 <code>6</code>을 다시 사용하면 안 됩니다.

<mark>코드는 위에서 아래로 실행되며 앞에서 변경된 값이 이후 계산의 기준이 됩니다.</mark>

</details>

## 잘 놓치는 핵심

### 1. 이중 포인터는 단계별로 읽는다

```text
pp → p → 값
```

형태로 그리면 어떤 단계가 바뀌는지 쉽게 확인할 수 있습니다.

### 2. 문자 포인터 배열은 문자열 주소의 배열이다

```c
const char *s[3];
```

은 문자열 세 개를 직접 저장하는 2차원 문자 배열과 다릅니다.

### 3. 구조체 포인터도 배열 원소 단위로 이동한다

```c
p + 1
```

은 다음 구조체 원소를 가리킵니다.

### 4. 재귀에서는 매 호출의 포인터와 개수를 따로 본다

재귀가 깊어질수록 포인터 위치와 남은 원소 수가 어떻게 변하는지를 추적해야 합니다.

### 5. 함수 포인터 배열은 함수 대응 관계부터 적는다

```text
f[0] → f1
f[1] → f2
f[2] → f3
```

처럼 먼저 정리하면 순차 호출을 쉽게 추적할 수 있습니다.

### 6. 비트 문제는 2진수 또는 16진수로 분해한다

비트 마스크는 특정 비트만 남기기 위한 연산입니다.

### 7. memcpy와 memmove를 구분한다

복사 영역이 겹칠 수 있다면 <code>memcpy</code>가 아니라 <code>memmove</code>를 사용합니다.

### 8. 배열 끝 다음 위치는 만들 수 있지만 역참조하지 않는다

배열 마지막 다음 주소는 포인터 계산에는 사용할 수 있지만 그 위치의 값을 읽어서는 안 됩니다.

### 9. 앞에서 변경된 값은 뒤에서 그대로 사용한다

코드 각 줄을 독립적으로 계산하지 않습니다.

## 시험·면접에서 바로 보는 포인트

- <code>(*pp)++</code>와 <code>(**pp)++</code>의 차이를 구분합니다.
- 문자 포인터 배열과 2차원 문자 배열을 혼동하지 않습니다.
- 구조체 포인터의 <code>-></code>는 <code>(*p).</code>와 같은 의미입니다.
- 재귀 함수는 호출 경로를 한 단계씩 내려가며 정리합니다.
- 함수 포인터 배열은 인덱스별 함수 대응 관계부터 적습니다.
- 비트 마스크는 남기려는 비트를 1로 둡니다.
- 메모리 복사 함수는 원본과 목적지 영역이 겹치는지 먼저 확인합니다.
- <code>*p--</code>와 <code>*--p</code>의 실행 순서를 구분합니다.
- 복잡한 포인터 식은 먼저 실제 값으로 치환한 뒤 계산합니다.
