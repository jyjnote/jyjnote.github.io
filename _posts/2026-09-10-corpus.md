자연어 처리에서 사용하는 **텍스트 데이터의 집합**입니다.  
문장 하나가 아니라, 분석·학습에 쓸 문서들을 모아 둔 전체 데이터입니다.

<blockquote class="prompt-info">
  <p>Corpus = 자연어 모델이 읽고 규칙을 배우는 원본 텍스트 묶음입니다.</p>
</blockquote>

$$
C=\{D_1,D_2,\ldots,D_n\}
$$

- $$C$$: 전체 Corpus
- $$D_i$$: 하나의 Document
- $$n$$: 문서 수

<mark>Corpus는 모델이 아니라 데이터입니다. NLP는 대부분 Corpus를 만들고 정리하는 것에서 시작합니다.</mark>

<details>
<summary>한 줄로</summary>

Document 하나하나를 모은 NLP용 Dataset이 Corpus입니다.

</details>

## Document와의 차이

다음 세 문서가 있다고 하겠습니다.

```text
D1: 나는 사과를 좋아한다.
D2: 나는 바나나를 좋아한다.
D3: 사과는 맛있다.
```

각 문장은 **Document**, 세 문서를 모두 모은 것이 **Corpus**입니다.

```text
Corpus
├─ Document 1
├─ Document 2
└─ Document 3
```

Document 단위는 고정이 아닙니다.

- 리뷰 하나
- 뉴스 기사 하나
- 이메일 하나
- 논문 하나
- 문장 하나

분석 목적에 따라 하나의 Document를 어디까지 볼지 정합니다.

## Corpus에서 Token까지

모델은 문자열 자체를 바로 계산하지 못합니다.  
Corpus를 잘게 나누고 숫자로 바꾸는 과정이 필요합니다.

```text
Corpus
  ↓
Document
  ↓
Sentence
  ↓
Tokenization
  ↓
Token
```

예:

```text
나는 사과를 좋아한다
```

공백 기준 Token:

```text
나는 / 사과를 / 좋아한다
```

<blockquote class="prompt-warning">
  <p>Token은 항상 단어가 아닙니다. 형태소, 문자, Subword도 Token이 될 수 있습니다.</p>
</blockquote>

현대 LLM에서는 긴 단어 하나가 여러 Subword Token으로 나뉠 수도 있습니다.

## Vocabulary

Corpus에 나타난 **서로 다른 Token의 집합**입니다.

```text
D1: AI is good
D2: AI is useful
```

전체 Token:

```text
AI / is / good / AI / is / useful
```

Token 수:

$$
N_{\text{token}}=6
$$

중복을 제거한 Vocabulary:

```text
AI / is / good / useful
```

$$
|V|=4
$$

| 개념 | 중복 | 뜻 |
| --- | --- | --- |
| Token 수 | 포함 | Corpus 전체에 실제 등장한 Token 수 |
| Vocabulary | 제거 | 서로 다른 Token의 집합 |

<mark>Token 수와 Vocabulary 크기는 다릅니다.</mark>

## 말뭉치의 종류

| 종류 | 구성 | 대표 용도 |
| --- | --- | --- |
| 단일언어 | 한 언어 | 일반 NLP |
| 다국어 | 여러 언어 | 다국어 모델 |
| 병렬 말뭉치 | 번역문 쌍 | 기계번역 |
| 대화 말뭉치 | 발화 순서 | 챗봇·대화 모델 |
| 도메인 말뭉치 | 특정 분야 문서 | 금융·의료·법률 모델 |

병렬 말뭉치 예:

```text
안녕하세요. ↔ Hello.
감사합니다. ↔ Thank you.
```

도메인 말뭉치 예:

```text
금융: 여신, 담보, 채권, 연체
의료: 진단, 처방, 증상, 검사
```

같은 한국어라도 분야가 달라지면 자주 쓰는 단어와 문맥이 달라집니다.

## 품질이 중요한 이유

Corpus가 크다고 무조건 좋은 것은 아닙니다.

문제가 되는 데이터:

- 중복 문서
- 광고·스팸
- 깨진 문자
- 다른 언어가 섞인 문서
- 지나치게 짧은 문서
- 목적과 무관한 문서
- 잘못된 라벨

같은 문장이 수십만 번 중복되면 실제 언어보다 그 패턴을 과하게 보게 됩니다.

```text
Raw Corpus
    ↓
Filtering
    ↓
Deduplication
    ↓
Cleaning
    ↓
Normalization
    ↓
Processed Corpus
```

<blockquote class="prompt-warning">
  <p>대규모 Corpus에서는 데이터 양뿐 아니라 중복, 오염, 도메인 비율도 중요합니다.</p>
</blockquote>

## 전처리와의 위치

전통 NLP의 기본 흐름:

```text
Corpus
  ↓
정제 · 정규화
  ↓
Tokenization
  ↓
Vocabulary
  ↓
BoW · DTM
  ↓
TF-IDF
  ↓
Machine Learning
```

현대 LLM:

```text
대규모 Corpus
  ↓
Tokenizer
  ↓
Token ID
  ↓
Embedding
  ↓
Transformer
  ↓
Language Model
```

방법은 달라도 출발점은 Corpus입니다.

## Python으로 보면

가장 단순한 Corpus는 리스트입니다.

```python
corpus = [
    "나는 사과를 좋아한다",
    "나는 바나나를 좋아한다",
    "사과는 맛있다"
]
```

Document 수:

```python
print(len(corpus))
```

```text
3
```

공백 기준 Tokenization:

```python
tokens = []

for document in corpus:
    tokens.extend(document.split())

print(tokens)
```

Vocabulary:

```python
vocabulary = set(tokens)

print(len(tokens))
print(len(vocabulary))
```

단, 한국어에서는

```text
사과는
사과를
```

이 공백 Tokenization에서는 서로 다른 Token입니다.

형태소 분석이 필요한 이유 중 하나입니다.

## 잘 놓치는 핵심

### 1. Corpus ≠ Document

Document 여러 개를 모은 전체가 Corpus입니다.

### 2. Corpus ≠ Vocabulary

Corpus는 원래 텍스트 집합.  
Vocabulary는 Corpus에서 뽑은 서로 다른 Token 집합입니다.

### 3. Token ≠ 항상 단어

Tokenizer가 정한 처리 단위입니다.

### 4. 큰 Corpus = 좋은 Corpus가 아님

중복·오염·도메인 불균형이 크면 양이 많아도 문제가 됩니다.

### 5. Document 단위는 문제마다 다름

리뷰 하나일 수도 있고 기사 하나일 수도 있습니다.

## 시험·면접

<blockquote class="prompt-info">
  <p>단골: Corpus와 Document 차이, Token과 Vocabulary 차이, Tokenization의 위치, 말뭉치 품질.</p>
</blockquote>

자주 나오는 문장:

- Corpus는 자연어 텍스트의 집합이다
- Document는 Corpus를 구성하는 하나의 단위다
- Vocabulary는 서로 다른 Token의 집합이다
- Token 수에는 중복이 포함된다
- Corpus 품질은 모델 성능에 영향을 준다

## 숫자로 한 바퀴

Corpus:

```text
D1: data is useful
D2: data is important
```

Token:

```text
data / is / useful / data / is / important
```

전체 Token:

$$
6
$$

Vocabulary:

```text
data / is / useful / important
```

Vocabulary 크기:

$$
4
$$

따라서

```text
Document = 2
Token = 6
Vocabulary = 4
```

입니다.
