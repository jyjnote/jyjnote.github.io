이번 세트는 포인터의 단계를 더 깊게 들어가 **삼중 포인터, 포인터 반환 함수, 구조체 내부 포인터, 동적 2차원 배열**까지 다룹니다.

단순히 출력값만 계산하지 않고, 주소가 어디를 가리키는지와 메모리가 언제까지 유효한지도 함께 판단합니다.

<blockquote class="prompt-info">
<p>한 줄: 포인터의 단계와 메모리 수명까지 함께 추적하는 고난도 C 언어 문제 10개입니다.</p>
</blockquote>

<details markdown="1">
<summary>풀이 방법</summary>

1. 포인터가 몇 단계인지 먼저 확인합니다.
2. `*`를 한 번 제거할 때마다 무엇이 나오는지 적습니다.
3. 함수가 포인터를 반환하면 그 주소가 함수 종료 후에도 유효한지 확인합니다.
4. 구조체 내부 포인터는 구조체 자체의 값과 외부 메모리를 구분합니다.
5. 동적 배열은 실제 메모리 배치와 포인터 자료형을 함께 확인합니다.
6. 앞에서 변경된 값과 주소는 뒤 코드에 그대로 이어집니다.

</details>

## 문제 1. 삼중 포인터와 가리키는 대상 변경

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int x = 10;
    int y = 20;

    int *p = &x;
    int **pp = &p;
    int ***ppp = &pp;

    ***ppp += 5;
    **ppp = &y;
    ***ppp -= 4;

    printf("%d %d\n", x, y);

    return 0;
}
```

① `10 16`  
② `15 16`  
③ `15 20`  
④ `11 16`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>15 16</code></strong>입니다.</p>

### 1. 실행 전 상태

변수:

```text
x = 10
y = 20
```

포인터 관계는 다음과 같습니다.

```text
ppp → pp → p → x → 10
```

각 단계는 다음 의미입니다.

```text
p   = &x
pp  = &p
ppp = &pp
```

따라서:

```text
*ppp   = pp
**ppp  = p
***ppp = x의 값
```

### 2. 첫 번째 코드 실행

```c
***ppp += 5;
```

삼중 포인터를 세 번 역참조합니다.

```text
ppp
↓
pp
↓
p
↓
x
```

따라서 실제 효과는:

```c
x += 5;
```

입니다.

```text
x = 15
y = 20
```

포인터 관계는 아직:

```text
ppp → pp → p → x
```

입니다.

### 3. 두 번째 코드 실행

```c
**ppp = &y;
```

이번에는 두 번만 역참조합니다.

```text
*ppp  = pp
**ppp = p
```

즉 <code>**ppp</code>는 실제로 포인터 변수 <code>p</code>입니다.

따라서 이 코드는 다음과 같은 효과를 냅니다.

```c
p = &y;
```

포인터 관계가 다음처럼 바뀝니다.

```text
ppp → pp → p → y → 20
```

<code>x</code>의 값 15는 그대로 남습니다.

### 4. 세 번째 코드 실행

```c
***ppp -= 4;
```

현재 <code>p</code>는 <code>y</code>를 가리키고 있습니다.

따라서:

```text
***ppp = y
```

실제 효과는:

```c
y -= 4;
```

입니다.

```text
y = 16
```

### 5. 최종 상태

```text
x = 15
y = 16
p → y
pp → p
ppp → pp
```

최종 출력:

```text
15 16
```

### 반드시 알아야 할 개념

삼중 포인터도 한 번에 이해하려 하지 말고 단계별로 읽습니다.

```text
ppp     → pp의 주소
*ppp    → pp
**ppp   → p
***ppp  → p가 가리키는 실제 값
```

<mark>역참조 횟수가 줄어들면 실제 값이 아니라 중간 포인터 자체를 변경할 수 있습니다.</mark>

### 자주 하는 실수

<code>**ppp = &y;</code>를 <code>x = y</code>처럼 값 복사로 생각하면 안 됩니다.

이 문장은 포인터 <code>p</code>가 가리키는 대상을 <code>x</code>에서 <code>y</code>로 바꾸는 코드입니다.

</details>

## 문제 2. 배열 원소의 주소를 반환하는 함수

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int *find_max(int *a, int n)
{
    int *max = a;

    for (int i = 1; i < n; i++) {
        if (a[i] > *max)
            max = &a[i];
    }

    return max;
}

int main(void)
{
    int a[] = {4, 9, 3, 12, 7};

    int *p = find_max(a, 5);

    *p -= 2;

    printf("%d %d\n", *p, a[3]);

    return 0;
}
```

① `10 10`  
② `12 10`  
③ `10 12`  
④ `9 10`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>10 10</code></strong>입니다.</p>

### 1. 실행 전 배열

```text
인덱스   0   1   2   3   4
값       4   9   3  12   7
```

함수 호출:

```c
find_max(a, 5)
```

배열의 첫 원소 주소가 함수에 전달됩니다.

### 2. 함수 시작

```c
int *max = a;
```

처음에는:

```text
max → a[0] → 4
```

입니다.

### 3. 반복문 i = 1

```text
a[1] = 9
*max = 4
```

조건:

```text
9 > 4
```

참입니다.

따라서:

```c
max = &a[1];
```

현재:

```text
max → a[1] → 9
```

### 4. 반복문 i = 2

```text
a[2] = 3
*max = 9
```

```text
3 > 9
```

는 거짓입니다.

포인터는 그대로입니다.

### 5. 반복문 i = 3

```text
a[3] = 12
*max = 9
```

조건은 참입니다.

```c
max = &a[3];
```

따라서:

```text
max → a[3] → 12
```

### 6. 반복문 i = 4

```text
a[4] = 7
*max = 12
```

조건은 거짓입니다.

최종적으로:

```text
max → a[3]
```

입니다.

### 7. 함수 반환

```c
return max;
```

반환되는 주소는 <code>a[3]</code>의 주소입니다.

<code>a</code>는 <code>main</code>의 지역 배열이므로 <code>find_max</code>가 끝나도 여전히 유효합니다.

따라서:

```text
p → a[3] → 12
```

입니다.

### 8. 반환된 포인터로 값 변경

```c
*p -= 2;
```

<code>p</code>가 <code>a[3]</code>을 가리키므로:

```text
a[3] = 12 - 2 = 10
```

### 9. 최종 출력

```c
printf("%d %d\n", *p, a[3]);
```

두 표현 모두 같은 메모리를 읽습니다.

```text
*p   = 10
a[3] = 10
```

따라서:

```text
10 10
```

### 반드시 알아야 할 개념

함수가 포인터를 반환한다고 해서 항상 위험한 것은 아닙니다.

중요한 것은 **반환하는 주소가 함수 종료 후에도 유효한가**입니다.

이번 문제에서 반환하는 주소는 <code>main</code>에 존재하는 배열 <code>a</code>의 원소 주소입니다.

따라서 함수가 끝나도 유효합니다.

### 자주 하는 실수

포인터를 반환하는 함수는 전부 위험하다고 생각하면 안 됩니다.

함수 내부에서 새로 만들어진 일반 지역 변수의 주소를 반환하는 경우가 문제이고, 호출한 쪽에서 전달한 배열 원소의 주소를 반환하는 것은 가능합니다.

</details>

## 문제 3. 구조체 내부 포인터와 외부 배열 변경

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef struct {
    int *data;
    int size;
} Buffer;

void update(Buffer *b)
{
    for (int i = 0; i < b->size; i++)
        b->data[i] += i * 2;
}

int main(void)
{
    int a[] = {10, 10, 10, 10};

    Buffer b = {a + 1, 3};

    update(&b);

    printf("%d %d %d %d\n",
           a[0], a[1], a[2], a[3]);

    return 0;
}
```

① `10 10 12 14`  
② `10 12 14 16`  
③ `10 10 14 18`  
④ `10 12 12 14`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>10 10 12 14</code></strong>입니다.</p>

### 1. 실행 전 배열

```text
인덱스   0   1   2   3
값      10  10  10  10
```

### 2. 구조체 초기화

```c
Buffer b = {a + 1, 3};
```

구조체의 멤버는:

```text
b.data = a + 1
b.size = 3
```

입니다.

따라서:

```text
b.data → a[1]
```

관계를 표시하면:

```text
b.data[0] → a[1]
b.data[1] → a[2]
b.data[2] → a[3]
```

입니다.

### 3. 함수 호출

```c
update(&b);
```

구조체 자체가 복사되는 것이 아니라 <code>b</code>의 주소가 전달됩니다.

함수 안의 <code>b</code>는 구조체 포인터입니다.

### 4. 첫 번째 반복

```text
i = 0
```

실행:

```c
b->data[0] += 0 * 2;
```

<code>b->data[0]</code>은 실제로 <code>a[1]</code>입니다.

```text
a[1] = 10 + 0 = 10
```

### 5. 두 번째 반복

```text
i = 1
```

```c
b->data[1] += 1 * 2;
```

<code>b->data[1]</code>은 <code>a[2]</code>입니다.

```text
a[2] = 10 + 2 = 12
```

### 6. 세 번째 반복

```text
i = 2
```

```c
b->data[2] += 2 * 2;
```

<code>b->data[2]</code>은 <code>a[3]</code>입니다.

```text
a[3] = 10 + 4 = 14
```

### 7. 최종 상태

```text
a[0] = 10
a[1] = 10
a[2] = 12
a[3] = 14
```

최종 출력:

```text
10 10 12 14
```

### 반드시 알아야 할 개념

구조체 안에 포인터 멤버가 있다고 해서 실제 배열 데이터가 구조체 안에 복사되는 것은 아닙니다.

이번 구조체:

```c
typedef struct {
    int *data;
    int size;
} Buffer;
```

에서 <code>data</code>는 외부 배열의 주소만 저장합니다.

따라서:

```c
b.data[i]
```

를 변경하면 원래 배열 <code>a</code>도 변경됩니다.

### 자주 하는 실수

<code>Buffer b = {a + 1, 3};</code>이 배열의 일부를 구조체 안으로 복사한다고 생각하면 안 됩니다.

저장되는 것은 <code>a[1]</code>의 주소입니다.

</details>

## 문제 4. 동적 2차원 배열과 배열 포인터

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *raw = malloc(6 * sizeof(int));

    if (raw == NULL)
        return 1;

    int (*p)[3] = (int (*)[3])raw;

    for (int i = 0; i < 6; i++)
        raw[i] = i + 1;

    p[1][1] += p[0][2];

    printf("%d %d %d\n",
           p[0][2],
           p[1][1],
           *(*(p + 1) + 2));

    free(raw);

    return 0;
}
```

① `3 5 6`  
② `3 8 6`  
③ `2 8 5`  
④ `3 8 5`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>3 8 6</code></strong>입니다.</p>

### 1. 동적 메모리 할당

```c
int *raw = malloc(6 * sizeof(int));
```

정수 6개가 연속으로 들어갈 공간을 확보합니다.

반복문 실행 후:

```text
raw[0] = 1
raw[1] = 2
raw[2] = 3
raw[3] = 4
raw[4] = 5
raw[5] = 6
```

### 2. 배열 포인터로 해석

```c
int (*p)[3] = (int (*)[3])raw;
```

<code>p</code>는 정수 3개짜리 배열을 가리키는 포인터입니다.

같은 메모리를 다음처럼 2행 3열로 해석할 수 있습니다.

```text
p[0] = {1, 2, 3}
p[1] = {4, 5, 6}
```

주소 관계는:

```text
p     → raw[0]
p + 1 → raw[3]
```

입니다.

### 3. 값 변경

```c
p[1][1] += p[0][2];
```

먼저:

```text
p[1][1] = 5
p[0][2] = 3
```

따라서:

```text
p[1][1] = 5 + 3 = 8
```

실제 <code>raw[4]</code>도 같은 메모리이므로 8로 바뀝니다.

현재 배열 형태:

```text
p[0] = {1, 2, 3}
p[1] = {4, 8, 6}
```

### 4. 첫 번째 출력값

```text
p[0][2] = 3
```

### 5. 두 번째 출력값

```text
p[1][1] = 8
```

### 6. 세 번째 출력값

```c
*(*(p + 1) + 2)
```

먼저:

```text
p + 1 → 두 번째 행
```

그다음 두 칸 이동하므로:

```text
p[1][2] = 6
```

### 7. 최종 출력

```text
3 8 6
```

### 반드시 알아야 할 개념

동적 메모리는 본질적으로 연속된 바이트 공간입니다.

어떤 포인터 자료형으로 해석하느냐에 따라 접근 단위가 달라집니다.

이번 문제에서:

```c
int (*p)[3]
```

로 해석했기 때문에:

```text
p + 1
```

은 정수 한 개가 아니라 정수 3개짜리 한 행만큼 이동합니다.

### 자주 하는 실수

<code>p + 1</code>을 <code>raw + 1</code>과 같은 이동으로 보면 안 됩니다.

```text
raw + 1 → 정수 1개 이동
p + 1   → 정수 3개 이동
```

입니다.

</details>

## 문제 5. 구조체 안의 함수 포인터

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef struct {
    int value;
    int (*op)(int, int);
} Task;

int add(int a, int b)
{
    return a + b;
}

int mul(int a, int b)
{
    return a * b;
}

int main(void)
{
    Task t[2] = {
        {3, add},
        {4, mul}
    };

    int x = t[0].op(t[0].value, 2);
    int y = t[1].op(x, t[1].value);

    printf("%d %d\n", x, y);

    return 0;
}
```

① `5 20`  
② `6 24`  
③ `5 16`  
④ `7 28`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>5 20</code></strong>입니다.</p>

### 1. 구조체 배열 상태

첫 번째 구조체:

```text
t[0].value = 3
t[0].op    → add
```

두 번째 구조체:

```text
t[1].value = 4
t[1].op    → mul
```

### 2. 첫 번째 함수 호출

```c
int x = t[0].op(t[0].value, 2);
```

<code>t[0].op</code>는 <code>add</code>를 가리킵니다.

따라서 실제 호출은:

```c
add(3, 2)
```

입니다.

결과:

```text
x = 5
```

### 3. 두 번째 함수 호출

```c
int y = t[1].op(x, t[1].value);
```

<code>t[1].op</code>는 <code>mul</code>을 가리킵니다.

현재:

```text
x = 5
t[1].value = 4
```

따라서 실제 호출은:

```c
mul(5, 4)
```

입니다.

결과:

```text
y = 20
```

### 4. 최종 출력

```text
5 20
```

### 반드시 알아야 할 개념

구조체 멤버로 함수 포인터를 저장할 수 있습니다.

이를 이용하면 각 구조체마다 서로 다른 동작을 연결할 수 있습니다.

이번 구조체:

```c
typedef struct {
    int value;
    int (*op)(int, int);
} Task;
```

에서 <code>op</code>는 정수 두 개를 받아 정수를 반환하는 함수의 주소입니다.

### 자주 하는 실수

<code>t[0].op</code>와 <code>t[1].op</code>가 같은 함수를 가리킨다고 가정하면 안 됩니다.

구조체 각 원소는 서로 다른 함수 주소를 저장할 수 있습니다.

</details>

## 문제 6. 문자열 복사 함수 직접 추적

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

char *copy_text(char *dst, const char *src)
{
    char *start = dst;

    while ((*dst++ = *src++) != '\0')
        ;

    return start;
}

int main(void)
{
    char src[] = "CODE";
    char dst[10];

    char *p = copy_text(dst, src);

    p[1] = 'A';

    printf("%s %c\n", dst, p[2]);

    return 0;
}
```

① `CODE D`  
② `CADE D`  
③ `CADE A`  
④ `CODE A`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>CADE D</code></strong>입니다.</p>

### 1. 주의

이 문제의 보기들은 의도적으로 동일하게 보이도록 두지 않는 것이 좋지만, 핵심은 직접 결과를 계산하는 것입니다.

실제 출력값을 추적하겠습니다.

### 2. 함수 시작 상태

원본 문자열:

```text
src = C O D E \0
```

<code>dst</code>는 아직 초기화되지 않은 배열입니다.

함수 호출:

```c
copy_text(dst, src)
```

함수 내부에서:

```c
char *start = dst;
```

따라서 <code>start</code>는 목적지 배열의 처음 주소를 기억합니다.

```text
start → dst[0]
dst   → dst[0]
src   → 'C'
```

### 3. while 조건의 의미

```c
(*dst++ = *src++) != '\0'
```

한 번 반복할 때:

1. 현재 <code>src</code> 문자를 읽습니다.
2. 현재 <code>dst</code> 위치에 복사합니다.
3. <code>src</code>와 <code>dst</code>를 각각 한 칸 이동합니다.
4. 방금 복사한 문자가 <code>\0</code>인지 확인합니다.

### 4. 문자 복사 과정

첫 번째:

```text
dst[0] = 'C'
```

두 번째:

```text
dst[1] = 'O'
```

세 번째:

```text
dst[2] = 'D'
```

네 번째:

```text
dst[3] = 'E'
```

다섯 번째:

```text
dst[4] = '\0'
```

종료 문자까지 복사한 뒤 반복문이 끝납니다.

따라서:

```text
dst = "CODE"
```

입니다.

### 5. 반환값

```c
return start;
```

<code>dst</code> 포인터는 복사하면서 계속 증가했지만 <code>start</code>는 처음 주소를 그대로 기억합니다.

따라서:

```text
p → dst[0]
```

입니다.

### 6. 문자 변경

```c
p[1] = 'A';
```

<code>p[1]</code>은 <code>dst[1]</code>입니다.

원래:

```text
C O D E
```

였으므로 <code>O</code>가 <code>A</code>로 바뀝니다.

```text
dst = "CADE"
```

### 7. 출력

```c
printf("%s %c\n", dst, p[2]);
```

첫 번째:

```text
dst → "CADE"
```

두 번째:

```text
p[2] = dst[2] = 'D'
```

따라서:

```text
CADE D
```

### 반드시 알아야 할 개념

문자열 복사에서는 마지막 종료 문자 <code>\0</code>까지 반드시 복사해야 합니다.

또한 후위 증가가 포함된:

```c
*dst++
```

는:

```c
*(dst++)
```

로 해석됩니다.

즉 현재 위치를 사용한 뒤 포인터를 증가시킵니다.

### 자주 하는 실수

복사 대상 문자만 생각하고 종료 문자 <code>\0</code> 복사를 빼먹으면 문자열이 정상적으로 끝나지 않습니다.

</details>

## 문제 7. 지역 변수 주소 반환의 문제점

다음 코드에 대한 설명으로 가장 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int *make_value(void)
{
    int x = 100;

    return &x;
}

int main(void)
{
    int *p = make_value();

    printf("%d\n", *p);

    return 0;
}
```

① 항상 `100`을 출력한다.  
② 컴파일 오류가 반드시 발생한다.  
③ 함수가 끝난 뒤 유효하지 않은 지역 변수 주소를 사용한다.  
④ `p`는 자동으로 `NULL`이 된다.

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③</strong>입니다.</p>

### 1. 함수 내부 상태

```c
int x = 100;
```

<code>x</code>는 <code>make_value</code> 함수의 일반 지역 변수입니다.

자동 저장 기간을 가지므로 함수가 실행되는 동안에만 유효합니다.

### 2. 주소 반환

```c
return &x;
```

함수는 <code>x</code>가 있던 주소를 반환하려 합니다.

호출 순간에는 실제 주소값이 존재할 수 있습니다.

### 3. 함수 종료

문제는 함수가 끝나는 시점입니다.

```text
make_value 종료
→ 지역 변수 x의 수명 종료
```

따라서 반환된 주소가 더 이상 유효한 객체를 가리키지 않습니다.

### 4. main에서 포인터 사용

```c
int *p = make_value();
```

<code>p</code>에는 어떤 주소값이 들어 있을 수 있지만 그 주소의 <code>x</code> 객체는 이미 수명이 끝났습니다.

그 후:

```c
*p
```

로 접근하면 유효하지 않은 메모리를 역참조하게 됩니다.

### 5. 왜 100이라고 단정할 수 없는가

실행 직후 우연히 메모리에 100이 남아 있을 수도 있습니다.

하지만 그것은 보장된 결과가 아닙니다.

따라서:

```text
항상 100 출력
```

이라고 판단할 수 없습니다.

### 6. 안전한 방법

예를 들어 호출자가 메모리를 제공하게 만들 수 있습니다.

```c
void make_value(int *p)
{
    *p = 100;
}
```

또는 동적 메모리를 사용하고 호출자가 나중에 해제하게 만들 수도 있습니다.

### 반드시 알아야 할 개념

포인터를 반환할 때 가장 중요한 질문은:

```text
이 주소가 함수 종료 후에도 유효한가?
```

입니다.

- 호출자가 가진 배열 주소 → 가능
- 전역 변수 주소 → 가능
- 정적 지역 변수 주소 → 가능
- 일반 지역 변수 주소 → 함수 종료 후 유효하지 않음

### 자주 하는 실수

컴파일이 성공했다는 이유로 안전한 코드라고 생각하면 안 됩니다.

컴파일러가 경고를 줄 수는 있지만 반드시 컴파일 오류가 발생하는 것은 아닙니다.

</details>

## 문제 8. 배열 포인터를 함수 인자로 전달

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

void change(int (*a)[3], int rows)
{
    for (int i = 0; i < rows; i++) {
        a[i][0] += a[i][2];
        a[i][1] *= 2;
    }
}

int main(void)
{
    int a[2][3] = {
        {1, 2, 3},
        {4, 5, 6}
    };

    change(a, 2);

    printf("%d %d %d %d\n",
           a[0][0],
           a[0][1],
           a[1][0],
           a[1][1]);

    return 0;
}
```

① `4 4 10 10`  
② `4 2 10 5`  
③ `3 4 6 10`  
④ `4 4 10 5`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>4 4 10 10</code></strong>입니다.</p>

### 1. 실행 전 2차원 배열

```text
a[0] = {1, 2, 3}
a[1] = {4, 5, 6}
```

### 2. 함수 매개변수

```c
void change(int (*a)[3], int rows)
```

<code>a</code>는 정수 3개짜리 배열 한 행을 가리키는 포인터입니다.

따라서:

```text
a[0] → 첫 번째 행
a[1] → 두 번째 행
```

입니다.

### 3. 첫 번째 행 처리

```text
i = 0
```

첫 번째 문장:

```c
a[0][0] += a[0][2];
```

```text
a[0][0] = 1
a[0][2] = 3
```

따라서:

```text
a[0][0] = 4
```

두 번째 문장:

```c
a[0][1] *= 2;
```

```text
a[0][1] = 2 × 2 = 4
```

첫 행은:

```text
{4, 4, 3}
```

이 됩니다.

### 4. 두 번째 행 처리

```text
i = 1
```

첫 번째 문장:

```text
a[1][0] = 4 + 6 = 10
```

두 번째 문장:

```text
a[1][1] = 5 × 2 = 10
```

두 번째 행:

```text
{10, 10, 6}
```

### 5. 최종 배열

```text
a[0] = {4, 4, 3}
a[1] = {10, 10, 6}
```

최종 출력:

```text
4 4 10 10
```

### 반드시 알아야 할 개념

2차원 배열을 함수에 전달할 때는 두 번째 차원의 크기를 알아야 포인터 이동 단위를 계산할 수 있습니다.

```c
int (*a)[3]
```

에서:

```text
a + 1
```

은 정수 3개짜리 한 행 전체를 건너뜁니다.

### 자주 하는 실수

함수 인자 <code>a</code>를 일반 <code>int *</code>와 같은 방식으로 생각하면 안 됩니다.

자료형이 다르기 때문에 포인터 이동 단위도 다릅니다.

</details>

## 문제 9. 비트 마스크로 일부 비트 갱신

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    unsigned int x = 0xA5;

    x &= ~(0x0F);
    x |= 0x09;

    printf("0x%X\n", x);

    return 0;
}
```

① `0xA9`  
② `0x09`  
③ `0xAF`  
④ `0xA5`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>0xA9</code></strong>입니다.</p>

### 1. 초기값

```text
x = 0xA5
```

8비트로 보면:

```text
1010 0101
```

### 2. 하위 4비트 지우기

```c
x &= ~(0x0F);
```

<code>0x0F</code>는:

```text
0000 1111
```

입니다.

이를 반전하면 하위 4비트가 0이 되는 마스크로 볼 수 있습니다.

8비트 형태로 핵심 부분만 보면:

```text
1111 0000
```

AND:

```text
1010 0101
1111 0000
---------
1010 0000
```

따라서:

```text
x = 0xA0
```

### 3. 새로운 하위 비트 설정

```c
x |= 0x09;
```

<code>0x09</code>는:

```text
0000 1001
```

입니다.

OR:

```text
1010 0000
0000 1001
---------
1010 1001
```

따라서:

```text
x = 0xA9
```

### 4. 최종 출력

```text
0xA9
```

### 반드시 알아야 할 개념

특정 비트 구간을 새로운 값으로 바꿀 때는 보통 두 단계로 처리합니다.

1. 기존 비트를 0으로 지웁니다.
2. 원하는 비트를 OR로 설정합니다.

이번 문제는 하위 4비트를:

```text
0101
```

에서:

```text
1001
```

로 바꾸는 과정입니다.

### 자주 하는 실수

바로 OR만 하면 기존에 1이었던 비트를 0으로 만들 수 없습니다.

따라서 새로운 값을 덮어쓸 때는 먼저 해당 영역을 마스크로 지우는 과정이 필요합니다.

</details>

## 문제 10. 문자 포인터 배열과 이중 포인터 교환

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

void swap_text(const char **a, const char **b)
{
    const char *tmp = *a;
    *a = *b;
    *b = tmp;
}

int main(void)
{
    const char *s[] = {
        "RED",
        "GREEN",
        "BLUE"
    };

    swap_text(&s[0], &s[2]);

    const char **p = s + 1;

    printf("%s %s %c\n",
           s[0],
           s[2],
           (*p)[2]);

    return 0;
}
```

① `BLUE RED E`  
② `RED BLUE E`  
③ `BLUE GREEN E`  
④ `BLUE RED U`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>BLUE RED E</code></strong>입니다.</p>

### 1. 실행 전 문자 포인터 배열

```text
s[0] → "RED"
s[1] → "GREEN"
s[2] → "BLUE"
```

문자열 자체를 배열 안에 저장하는 것이 아니라 문자열의 시작 주소를 저장하고 있습니다.

### 2. 함수 호출

```c
swap_text(&s[0], &s[2]);
```

함수 내부에서는:

```text
a → s[0]
b → s[2]
```

입니다.

### 3. 임시 포인터 저장

```c
const char *tmp = *a;
```

현재:

```text
*a = s[0] → "RED"
```

따라서:

```text
tmp → "RED"
```

### 4. 첫 번째 포인터 변경

```c
*a = *b;
```

현재:

```text
*b = s[2] → "BLUE"
```

따라서:

```text
s[0] → "BLUE"
```

가 됩니다.

### 5. 두 번째 포인터 변경

```c
*b = tmp;
```

따라서:

```text
s[2] → "RED"
```

최종 문자 포인터 배열:

```text
s[0] → "BLUE"
s[1] → "GREEN"
s[2] → "RED"
```

### 6. 이중 포인터 p 설정

```c
const char **p = s + 1;
```

따라서:

```text
p → s[1] → "GREEN"
```

입니다.

### 7. 첫 번째 출력값

```text
s[0] → "BLUE"
```

따라서:

```text
BLUE
```

### 8. 두 번째 출력값

```text
s[2] → "RED"
```

따라서:

```text
RED
```

### 9. 세 번째 출력값

```c
(*p)[2]
```

<code>*p</code>는:

```text
"GREEN"
```

입니다.

문자열 인덱스:

```text
인덱스   0   1   2   3   4
문자     G   R   E   E   N
```

따라서:

```text
(*p)[2] = E
```

### 10. 최종 출력

```text
BLUE RED E
```

### 반드시 알아야 할 개념

문자 포인터 배열에서 문자열을 교환할 때 문자열 내용을 하나씩 복사할 필요가 없습니다.

각 배열 원소가 가지고 있는 문자열의 시작 주소만 교환하면 됩니다.

이번 함수:

```c
void swap_text(const char **a, const char **b)
```

는 문자 포인터 자체를 바꾸기 위해 문자 포인터의 주소를 받습니다.

### 자주 하는 실수

<code>s[0]</code>과 <code>s[2]</code>의 문자열 내용이 메모리에서 서로 복사된다고 생각하면 안 됩니다.

교환되는 것은 문자열 데이터가 아니라 **문자열을 가리키는 포인터 값**입니다.

</details>

## 잘 놓치는 핵심

### 1. 포인터 단계가 늘어날수록 한 단계씩 역참조한다

```text
ppp → pp → p → 값
```

형태로 그리는 것이 가장 안전합니다.

### 2. 포인터 반환 함수는 주소의 수명을 확인한다

반환된 주소가 함수 종료 후에도 유효한 메모리를 가리켜야 합니다.

### 3. 구조체 내부 포인터는 외부 메모리를 가리킬 수 있다

구조체 안에 배열 내용이 복사되는 것이 아니라 주소만 저장될 수 있습니다.

### 4. 동적 메모리도 배열 포인터로 해석할 수 있다

자료형을 어떻게 지정하느냐에 따라 포인터의 이동 단위가 달라집니다.

### 5. 함수 포인터는 구조체 멤버가 될 수 있다

구조체마다 서로 다른 동작을 연결할 수 있습니다.

### 6. 문자열 복사는 종료 문자까지 포함한다

문자열은 마지막 <code>\0</code>까지 복사해야 정상적으로 끝납니다.

### 7. 일반 지역 변수 주소를 반환하면 안 된다

함수 종료와 함께 지역 변수의 수명이 끝납니다.

### 8. 2차원 배열 함수 인자는 행의 크기를 알아야 한다

배열 포인터의 이동 단위를 결정하기 위해 열 크기가 필요합니다.

### 9. 비트 값을 덮어쓸 때는 지운 뒤 설정한다

기존 비트를 먼저 마스크로 0으로 만든 뒤 원하는 값을 OR합니다.

### 10. 포인터 배열의 교환은 데이터가 아니라 주소를 바꾼다

문자열 전체를 복사하지 않고 문자열 시작 주소만 교환할 수 있습니다.

## 시험·면접에서 바로 보는 포인트

- 삼중 포인터는 <code>*</code>를 한 단계씩 제거하며 읽습니다.
- 포인터를 반환하면 해당 객체의 수명이 언제 끝나는지 확인합니다.
- 구조체 내부 포인터는 실제 데이터의 소유 위치를 확인합니다.
- 동적 메모리를 배열 포인터로 사용할 때 행 크기를 확인합니다.
- 함수 포인터가 구조체 안에 들어가면 멤버별로 가리키는 함수를 먼저 정리합니다.
- 문자열 복사 루프에서는 종료 문자까지 복사되는지 확인합니다.
- 지역 변수 주소 반환은 실행 결과를 계산하기 전에 잘못된 코드임을 판별합니다.
- 비트 필드 변경은 `지우기 → 설정하기` 순서를 기억합니다.
