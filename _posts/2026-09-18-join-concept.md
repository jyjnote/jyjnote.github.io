조인은 두 개 이상의 표에서 조건에 맞는 행을 연결해 하나의 조회 결과를 만드는 연산입니다. 직원 표의 부서번호와 부서 표의 부서번호를 연결하면 직원 이름과 부서 이름을 함께 볼 수 있습니다.

<blockquote class="prompt-info">
<p>조인은 “어떤 행끼리 연결할 것인가”와 “연결되지 않은 행도 남길 것인가”를 정하는 작업입니다.</p>
</blockquote>

<mark>조건은 연결 대상을 정하고, 조인 종류는 연결되지 않은 행의 처리 방법을 정합니다.</mark>

<details>
<summary>한 줄로</summary>

흩어진 정보를 연결하되, 짝이 없는 행을 남길지는 조인 종류에 따라 결정합니다.

</details>

## 1. 핵심 예시 — 직원 이름 옆에 부서 이름 붙이기

**직원 표**

| 직원번호 | 이름 | 부서번호 |
| --- | --- | --- |
| 1 | 민수 | 10 |
| 2 | 지연 | 10 |
| 3 | 현우 | 20 |
| 4 | 수진 | NULL |

**부서 표**

| 부서번호 | 부서명 |
| --- | --- |
| 10 | 개발부 |
| 20 | 영업부 |
| 30 | 인사부 |

직원 표에는 부서 이름이 없습니다. 부서번호가 같은 행끼리 연결하면 다음 정보를 얻습니다.

| 이름 | 부서명 |
| --- | --- |
| 민수 | 개발부 |
| 지연 | 개발부 |
| 현우 | 영업부 |

민수와 지연은 같은 개발부 행에 각각 연결됩니다. 부서에 배정되지 않은 수진과 직원이 없는 인사부는 이 결과에 없습니다.

이처럼 **양쪽에서 조건을 만족하는 짝이 있는 행만 조회하는 방식이 내부 조인**입니다.

## 2. 왜 필요한가

직원마다 부서 이름과 부서 전화번호를 반복해서 저장하면 같은 정보가 여러 행에 중복됩니다. 부서 이름이 바뀔 때 수정할 곳도 많아집니다.

직원 정보와 부서 정보를 별도 표로 관리하고, 조회할 때 부서번호로 연결하면 정보를 함께 사용할 수 있습니다.

| 상황 | 연결하는 표 | 연결 기준 |
| --- | --- | --- |
| 직원의 부서 확인 | 직원 + 부서 | 부서번호 |
| 주문자의 이름 확인 | 주문 + 고객 | 고객번호 |
| 수강생의 과목명 확인 | 수강신청 + 과목 | 과목번호 |

<mark>저장은 나누고, 필요한 정보를 조회할 때 연결합니다.</mark>

## 3. 작동 방식 — 조건과 보존 대상을 나누어 보기

다음은 내부 조인의 기본 형태입니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
INNER JOIN 부서
ON 직원.부서번호 = 부서.부서번호;
```

| 구문 | 역할 |
| --- | --- |
| SELECT | 결과에 보여 줄 열 선택 |
| FROM 직원 | 왼쪽 입력 표 지정 |
| INNER JOIN 부서 | 오른쪽 입력 표와 연결 방식 지정 |
| ON | 어떤 행끼리 짝을 이룰지 조건 지정 |

**첫째, 연결 조건을 봅니다.** 직원의 부서번호와 부서의 부서번호가 같은지 확인합니다.

**둘째, 짝이 생기는 행을 찾습니다.** 민수와 지연은 개발부에, 현우는 영업부에 연결됩니다.

**셋째, 짝이 없는 행의 처리 방법을 봅니다.** 내부 조인은 수진과 인사부를 결과에 넣지 않습니다.

여기서 왼쪽·오른쪽은 화면에 놓인 표의 위치가 아니라 **조인 구문에서 입력 표를 적은 순서**입니다.

<blockquote class="prompt-info">
<p>이 설명은 결과를 이해하기 위한 논리적 관점입니다. 실제 실행은 데이터베이스가 실행 계획에 따라 처리합니다. 조인만으로 결과 행의 표시 순서는 보장되지 않습니다.</p>
</blockquote>

## 4. 주요 개념 — 조인 종류별로 무엇을 남기는가

### 4.1. 내부 조인 — 짝이 있는 행만

내부 조인은 연결 조건을 만족하는 행의 조합만 남깁니다. 일반적인 `JOIN`은 `INNER JOIN`을 뜻합니다.

앞의 직원·부서 예시에서는 민수, 지연, 현우의 **3행**이 나옵니다.

### 4.2. 왼쪽 외부 조인 — 왼쪽 행을 모두 보존

왼쪽 외부 조인은 왼쪽 표의 모든 행을 남깁니다. 오른쪽에서 연결할 행이 없으면 오른쪽 열을 `NULL`로 채웁니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
LEFT JOIN 부서
ON 직원.부서번호 = 부서.부서번호;
```

| 이름 | 부서명 |
| --- | --- |
| 민수 | 개발부 |
| 지연 | 개발부 |
| 현우 | 영업부 |
| 수진 | NULL |

**부서 배정 여부와 관계없이 모든 직원을 조회**할 때 적합합니다. 직원이 없는 인사부는 오른쪽 표에만 있으므로 나오지 않습니다.

### 4.3. 오른쪽 외부 조인 — 오른쪽 행을 모두 보존

오른쪽 외부 조인은 오른쪽 표의 모든 행을 남깁니다. 왼쪽에서 연결할 행이 없으면 왼쪽 열을 `NULL`로 채웁니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
RIGHT JOIN 부서
ON 직원.부서번호 = 부서.부서번호;
```

| 이름 | 부서명 |
| --- | --- |
| 민수 | 개발부 |
| 지연 | 개발부 |
| 현우 | 영업부 |
| NULL | 인사부 |

개발부 직원이 두 명이므로 개발부는 두 행에 나타납니다. **모든 부서를 보존한다는 말은 부서마다 정확히 한 행이 나온다는 뜻이 아닙니다.**

표의 순서를 바꾸면 같은 연결을 왼쪽 외부 조인으로 표현할 수 있습니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 부서
LEFT JOIN 직원
ON 부서.부서번호 = 직원.부서번호;
```

### 4.4. 완전 외부 조인 — 양쪽 행을 모두 보존

완전 외부 조인은 조건에 맞는 행을 연결하고, 양쪽에서 짝을 찾지 못한 행도 남깁니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
FULL OUTER JOIN 부서
ON 직원.부서번호 = 부서.부서번호;
```

| 이름 | 부서명 |
| --- | --- |
| 민수 | 개발부 |
| 지연 | 개발부 |
| 현우 | 영업부 |
| 수진 | NULL |
| NULL | 인사부 |

**연결된 3행 + 직원 쪽의 미연결 1행 + 부서 쪽의 미연결 1행 = 5행**입니다.

외부 조인에서 `OUTER`는 생략할 수 있습니다. 예를 들어 `LEFT OUTER JOIN`과 `LEFT JOIN`은 같은 종류입니다.

<blockquote class="prompt-warning">
<p>조인 구문의 지원 범위는 데이터베이스에 따라 다릅니다. 개념을 익힌 뒤 실제 사용하는 데이터베이스의 문법을 확인합니다.</p>
</blockquote>

### 4.5. 교차 조인 — 가능한 모든 행 조합

교차 조인은 각 직원 행을 모든 부서 행과 조합합니다. 별도의 연결 조건을 사용하지 않습니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
CROSS JOIN 부서;
```

직원 4행과 부서 3행의 모든 조합이므로 **4 × 3 = 12행**입니다. 민수 한 명에 대해서도 개발부·영업부·인사부의 세 조합이 만들어집니다.

### 4.6. 자체 조인 — 같은 표를 서로 다른 역할로 연결

자체 조인은 같은 표를 두 번 참조하는 방식입니다. 별도의 조인 키워드가 아니라 내부 조인이나 외부 조인으로 구현합니다.

직원 표에 다음 정보가 있다고 가정합니다.

| 직원번호 | 이름 | 상사번호 |
| --- | --- | --- |
| 1 | 민수 | NULL |
| 2 | 지연 | 1 |
| 3 | 현우 | 1 |

```sql
SELECT 사원.이름 AS 사원이름, 상사.이름 AS 상사이름
FROM 직원 사원
LEFT JOIN 직원 상사
ON 사원.상사번호 = 상사.직원번호;
```

`사원`과 `상사`는 같은 직원 표를 구분하기 위한 별칭입니다. 지연과 현우의 상사는 민수이며, 민수의 상사 이름은 `NULL`로 나옵니다.

### 4.7. 동등·비동등·자연 조인 — 분류 기준이 다르다

| 개념 | 분류 기준 | 핵심 |
| --- | --- | --- |
| 내부·외부 조인 | 미연결 행의 보존 여부 | 짝이 없는 행을 남기는가 |
| 동등 조인 | 연결 조건 | 등호로 비교하는가 |
| 비동등 조인 | 연결 조건 | 범위·대소 등 등호 이외의 조건인가 |
| 자연 조인 | 조건 지정 방식 | 이름이 같은 모든 열을 자동으로 비교 |
| 자체 조인 | 입력 표 | 같은 표를 서로 다른 역할로 참조하는가 |

**동등 조인과 내부 조인은 같은 뜻이 아닙니다.** 등호 조건을 사용하는 외부 조인도 가능합니다.

비동등 조인은 급여가 어느 급여등급의 범위에 들어가는지 연결할 때 사용할 수 있습니다.

```sql
SELECT 직원.이름, 급여등급.등급
FROM 직원
INNER JOIN 급여등급
ON 직원.급여 BETWEEN 급여등급.최저급여 AND 급여등급.최고급여;
```

자연 조인은 이름이 같은 모든 열을 연결 기준으로 사용합니다. 같은 이름의 열이 추가되면 조건이 달라질 수 있으므로 기준을 명시하는 편이 이해하기 쉽습니다.

양쪽 연결 열의 이름이 같다면 `USING (부서번호)`로 동등 조건을 지정할 수도 있습니다. 이때 공통 연결 열은 결과에서 하나로 합쳐집니다.

## 5. 장점과 주의할 점

| 구분 | 내용 |
| --- | --- |
| 장점 | 나누어 저장한 정보를 한 번에 조회 가능 |
| 장점 | 직원·부서처럼 서로 관련된 정보를 함께 활용 |
| 주의 | 조건을 잘못 쓰면 원하지 않는 행이 연결됨 |
| 주의 | 여러 짝이 연결되면 결과 행 수가 증가함 |
| 주의 | 큰 표를 연결할 때는 조건·인덱스·실행 계획 검토 필요 |

조인 결과를 조회하는 것만으로 원본 표의 행이 수정되지는 않습니다. 조회 결과와 저장된 표는 구분해야 합니다.

## 6. 다른 개념과 비교 — 연결과 행 이어 붙이기

| 구분 | 조인 | UNION 계열 |
| --- | --- | --- |
| 결합 방식 | 행의 조합을 만들어 양쪽 정보를 연결 | 여러 조회 결과의 행을 이어 붙임 |
| 필요한 기준 | 일반적으로 연결 조건 사용 | 대응하는 열 수와 자료형의 호환성 |
| 예시 | 직원 이름 옆에 부서 이름 연결 | 올해 주문 행 아래에 작년 주문 행 추가 |
| 중복 처리 | 일반 조회에서는 같은 결과 값도 여러 행 가능 | UNION은 중복 제거, UNION ALL은 중복 유지 |

<mark>조인은 관련 정보를 연결하고, 합집합 계열은 조회 결과의 행을 이어 붙입니다.</mark>

## 잘 놓치는 핵심

### 1. 한 행에 짝이 여러 개면 결과도 여러 행이다

왼쪽 연결값 10이 2행, 오른쪽 연결값 10이 3행이라면 그 값에서는 **2 × 3 = 6개의 행 조합**이 나옵니다.

따라서 내부 조인의 결과 행 수가 항상 더 작은 원본 표의 행 수 이하인 것은 아닙니다. 외부 조인도 보존하는 표의 행 수보다 결과가 많을 수 있습니다.

### 2. NULL은 0이나 빈 문자열이 아니다

`NULL`은 값이 없거나 알 수 없음을 나타냅니다. 일반적인 등호 비교에서 `NULL = NULL`은 참이 아니므로 두 행을 짝으로 연결하지 않습니다.

결측 여부는 `= NULL`이 아니라 `IS NULL`로 확인합니다.

### 3. 연결 조건과 조회 조건을 옮기면 결과가 달라질 수 있다

다음은 모든 직원을 남기고, 개발부에 해당하는 정보만 연결합니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
LEFT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
AND 부서.부서명 = '개발부';
```

민수·지연은 개발부로 연결됩니다. 현우·수진도 남지만 부서명은 `NULL`입니다. 결과는 **4행**입니다.

반면 다음은 조인 결과에서 부서명이 개발부인 행만 남깁니다.

```sql
SELECT 직원.이름, 부서.부서명
FROM 직원
LEFT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
WHERE 부서.부서명 = '개발부';
```

민수·지연의 **2행**만 남습니다. 외부 조인 뒤에 오른쪽 열을 이처럼 제한하면 짝이 없어 보존했던 행이 걸러질 수 있습니다.

### 4. 기본키·외래키가 있어야만 조인할 수 있는 것은 아니다

기본키와 외래키는 표 사이의 관계와 데이터 무결성을 관리하는 데 중요합니다. 하지만 조인 자체는 선언된 키가 없어도 비교 조건을 지정해 수행할 수 있습니다.

연결 열의 이름도 반드시 같을 필요는 없습니다. 어떤 열끼리 비교할지 `ON`에서 명시하면 됩니다.

### 5. 벤다이어그램만으로 결과 행 수를 판단하면 안 된다

벤다이어그램은 어느 쪽의 미연결 행을 보존하는지 기억하는 데 도움이 됩니다. 하지만 같은 연결값이 여러 행에 있을 때 생기는 조합 수까지 보여 주지는 못합니다.

**행 수는 같은 연결값별로 짝이 몇 개 생기는지 확인합니다.**

## 시험·면접

### 핵심 암기 포인트

| 종류 | 기억할 말 | 기본 예시의 행 수 |
| --- | --- | --- |
| 내부 조인 | 짝이 있는 행만 | 3 |
| 왼쪽 외부 조인 | 왼쪽 행 모두 보존 | 4 |
| 오른쪽 외부 조인 | 오른쪽 행 모두 보존 | 4 |
| 완전 외부 조인 | 양쪽 행 모두 보존 | 5 |
| 교차 조인 | 가능한 모든 행 조합 | 12 |
| 자체 조인 | 같은 표를 역할별로 연결 | 조건과 보존 방식에 따라 달라짐 |

### 면접에서 바로 말하기

“조인은 여러 표의 행을 조건에 따라 연결하는 연산입니다. 내부 조인은 조건에 맞는 행만 조회하고, 외부 조인은 지정한 쪽의 미연결 행도 남깁니다. 미연결 상대의 열은 결측값으로 채워집니다.”

### 시험 함정 정리

- 왼쪽 외부 조인이라고 해서 오른쪽의 모든 행도 남는 것은 아닙니다.
- 등호 조건을 사용한다고 무조건 내부 조인인 것은 아닙니다.
- 연결값이 중복되면 결과 행 수가 원본보다 많아질 수 있습니다.
- 자체 조인은 같은 표를 참조하는 방식이며 내부·외부 조인 모두 가능합니다.
- 표시 순서를 정하려면 별도의 정렬 조건이 필요합니다.

## 예시로 한 바퀴 — 부서가 없는 직원 찾기

직원 표의 부서번호는 결측이거나 부서 표에 존재하는 번호라고 가정합니다. 부서 표의 부서번호는 기본키입니다.

**첫째, 모든 직원을 남깁니다.** 직원 표를 왼쪽에 놓고 왼쪽 외부 조인을 사용합니다.

**둘째, 부서번호가 같은 행을 연결합니다.** 부서가 배정된 직원에게 부서 정보가 붙습니다.

**셋째, 연결되지 않은 직원을 찾습니다.** 오른쪽 기본키가 결측인지 확인합니다.

```sql
SELECT 직원.이름
FROM 직원
LEFT JOIN 부서
ON 직원.부서번호 = 부서.부서번호
WHERE 부서.부서번호 IS NULL;
```

기본 예시의 결과는 **수진**입니다. 실제 부서 행에서는 결측일 수 없는 기본키를 검사하므로 연결 실패를 구분할 수 있습니다.

<blockquote class="prompt-warning">
<p>직원의 부서번호가 잘못된 번호여도 위 조회에 포함됩니다. 이 조회의 정확한 의미는 “부서 표에서 연결할 행을 찾지 못한 직원”입니다.</p>
</blockquote>

## 객관식 문제

### 문제 1. 내부 조인의 설명으로 옳은 것은?

① 왼쪽 표의 모든 행을 무조건 남긴다.  
② 연결 조건을 만족하는 행의 조합만 남긴다.  
③ 양쪽 표의 모든 행을 무조건 남긴다.  
④ 연결 조건과 관계없이 모든 조합을 만든다.  

<details>
<summary>정답과 해설</summary>

**②**. ①은 왼쪽 외부 조인, ③은 완전 외부 조인, ④는 교차 조인의 설명입니다.

</details>

### 문제 2. 기본 직원·부서 표를 왼쪽 외부 조인하면 몇 행인가?

직원을 왼쪽에 놓고 부서번호의 등호 조건을 사용합니다.

① 3행  
② 4행  
③ 5행  
④ 12행  

<details>
<summary>정답과 해설</summary>

**②**. 민수·지연·현우의 연결된 3행에 수진의 미연결 1행을 더합니다. 인사부는 보존 대상이 아닙니다.

</details>

### 문제 3. 같은 연결값이 왼쪽 2행, 오른쪽 3행에 있다면?

그 값만 등호 조건으로 내부 조인합니다.

① 2행  
② 3행  
③ 5행  
④ 6행  

<details>
<summary>정답과 해설</summary>

**④**. 왼쪽 각 행이 오른쪽 세 행과 연결됩니다. 두 행 각각 세 짝이 생겨 총 6행입니다.

</details>

### 문제 4. 기본 직원·부서 표의 완전 외부 조인 결과는?

부서번호의 등호 조건으로 연결합니다.

① 3행  
② 4행  
③ 5행  
④ 7행  

<details>
<summary>정답과 해설</summary>

**③**. 연결된 3행, 수진 1행, 직원이 없는 인사부 1행을 남겨 총 5행입니다. 원본 행 수를 단순히 더하지 않습니다.

</details>

### 문제 5. 왼쪽 외부 조인 뒤 개발부 조건을 WHERE에 넣으면?

기본 예시에서 `WHERE 부서.부서명 = '개발부'`를 적용합니다.

① 네 직원이 모두 남는다.  
② 현우와 수진만 남는다.  
③ 직원 없는 인사부도 남는다.  
④ 민수와 지연만 남는다.  

<details>
<summary>정답과 해설</summary>

**④**. 조회 조건을 만족하는 두 행만 남습니다. 수진의 부서명은 결측이므로 개발부라는 조건을 만족하지 않습니다.

</details>

### 문제 6. 조인에 대한 설명으로 옳은 것은?

① 자체 조인은 반드시 내부 조인으로만 구현한다.  
② 동등 조인과 내부 조인은 항상 같은 뜻이다.  
③ 기본키·외래키가 선언되지 않아도 조건으로 조인할 수 있다.  
④ 교차 조인의 행 수는 두 표의 행 수를 더한 값이다.  

<details>
<summary>정답과 해설</summary>

**③**. 자체 조인은 외부 조인도 가능합니다. 동등은 조건의 분류이고 내부는 보존 방식의 분류입니다. 교차 조인은 두 표의 행 수를 곱합니다.

</details>
