IP 주소는 네트워크에서 장치를 구분하기 위한 주소입니다.  
시험에서는 주소 자체보다 <mark>이 주소가 어느 네트워크에 속하는지, 목적지까지 어떤 순서로 전달되는지</mark>를 묻는 경우가 많습니다.

<blockquote class="prompt-info">
<p>한 줄: 목적지가 같은 네트워크면 직접 보내고, 다른 네트워크면 기본 게이트웨이로 보냅니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

내 주소와 목적지 주소를 서브넷 마스크로 비교하고, 같은 네트워크면 직접 전달하고, 다르면 기본 게이트웨이를 통해 라우터가 다음 경로를 결정합니다.

</details>

## 1. 가장 먼저 외워야 할 주소 종류

정보처리기사와 직업기초능력시험에서는 다음 주소를 우선 구분할 수 있어야 합니다.

| 구분 | 주소 범위 또는 예시 | 핵심 의미 |
| --- | --- | --- |
| 공인 주소 | 인터넷에서 사용하는 주소 | 외부 인터넷에서 식별 가능 |
| 사설 주소 | 10.0.0.0 대역 | 내부 네트워크용 |
| 사설 주소 | 172.16.0.0 ~ 172.31.255.255 | 내부 네트워크용 |
| 사설 주소 | 192.168.0.0 대역 | 내부 네트워크용 |
| 자동 사설 주소 | 169.254.0.0 대역 | 자동 주소 할당 실패 시 임시 사용 |
| 루프백 주소 | 127.0.0.1 | 자기 자신을 가리킴 |
| 제한 브로드캐스트 | 255.255.255.255 | 같은 네트워크 전체에 전달 |
| 미지정 주소 | 0.0.0.0 | 아직 주소가 없거나 모든 주소를 의미 |

<mark>시험에서는 사설 주소 3개 대역을 가장 먼저 구분해야 합니다.</mark>

### 사설 주소 암기

```text
10으로 시작하면 사설 주소 가능
172.16 ~ 172.31이면 사설 주소
192.168로 시작하면 사설 주소
```

<blockquote class="prompt-warning">
<p>172로 시작한다고 전부 사설 주소가 아닙니다. 172.16부터 172.31까지만 사설 주소입니다.</p>
</blockquote>

## 2. IP 주소를 받으면 무엇부터 확인하는가

문제에서 다음과 같이 주어졌다고 봅니다.

```text
내 컴퓨터 주소: 192.168.10.25
서브넷 마스크: 255.255.255.0
기본 게이트웨이: 192.168.10.1
목적지 주소: 192.168.10.80
```

가장 먼저 해야 하는 일은 <mark>내 주소와 목적지 주소가 같은 네트워크에 속하는지 확인하는 것</mark>입니다.

서브넷 마스크가 255.255.255.0이면 앞의 세 구간이 네트워크 부분이라고 보면 됩니다.

```text
내 주소      192.168.10.25
목적지 주소  192.168.10.80

앞 세 구간   192.168.10
```

둘 다 같은 네트워크입니다.

따라서 기본 게이트웨이를 거치지 않고 목적지 장치로 직접 전달합니다.

## 3. 같은 네트워크인지 판단하는 법

핵심은 주소와 서브넷 마스크를 이용해 네트워크 주소를 구하는 것입니다.

서브넷 마스크가 255인 부분은 네트워크 부분이고, 0인 부분은 장치 부분이라고 생각하면 됩니다.

```text
주소:          192.168.10.25
서브넷 마스크: 255.255.255.0
네트워크 주소: 192.168.10.0
```

목적지 주소도 같은 방식으로 계산합니다.

```text
목적지 주소:   192.168.10.80
서브넷 마스크: 255.255.255.0
네트워크 주소: 192.168.10.0
```

네트워크 주소가 같습니다.

따라서 같은 네트워크입니다.

<blockquote class="prompt-info">
<p>네트워크 주소가 같으면 직접 전달, 다르면 기본 게이트웨이로 전달합니다.</p>
</blockquote>

## 4. 목적지가 다른 네트워크라면

이번에는 목적지 주소가 다음과 같다고 봅니다.

```text
내 컴퓨터 주소: 192.168.10.25
서브넷 마스크: 255.255.255.0
기본 게이트웨이: 192.168.10.1
목적지 주소: 192.168.20.80
```

내 네트워크 주소는 다음과 같습니다.

```text
192.168.10.0
```

목적지 네트워크 주소는 다음과 같습니다.

```text
192.168.20.0
```

서로 다릅니다.

따라서 내 컴퓨터는 목적지 장치에 바로 보내지 않습니다.

먼저 기본 게이트웨이인 192.168.10.1로 보냅니다.

그 이후에는 라우터가 목적지 네트워크로 가는 경로를 결정합니다.

### 전체 흐름

```text
내 컴퓨터
→ 같은 네트워크인지 확인
→ 다른 네트워크임
→ 기본 게이트웨이로 전달
→ 라우터가 경로 선택
→ 다음 라우터 또는 목적지 네트워크로 전달
→ 최종 목적지 도착
```

## 5. 기본 게이트웨이가 하는 일

기본 게이트웨이는 <mark>다른 네트워크로 나갈 때 처음 전달하는 라우터의 주소</mark>입니다.

예를 들어 집에서 인터넷을 사용할 때 공유기가 기본 게이트웨이 역할을 하는 경우가 많습니다.

```text
내 컴퓨터: 192.168.0.10
공유기:    192.168.0.1
인터넷 서버: 8.8.8.8
```

8.8.8.8은 내 네트워크에 있지 않습니다.

따라서 다음과 같이 전달됩니다.

```text
192.168.0.10
→ 192.168.0.1
→ 인터넷 구간
→ 목적지 서버
```

<blockquote class="prompt-warning">
<p>기본 게이트웨이는 최종 목적지가 아닙니다. 다른 네트워크로 나가기 위해 처음 거치는 장치입니다.</p>
</blockquote>

## 6. 목적지까지 최종적으로 어디로 도착하는가

시험에서는 다음과 같은 형태로 많이 묻습니다.

```text
출발지: 192.168.10.20
목적지: 10.0.0.50
서브넷 마스크: 255.255.255.0
기본 게이트웨이: 192.168.10.1
```

출발지는 목적지가 다른 네트워크에 있다는 것을 확인합니다.

따라서 먼저 기본 게이트웨이로 보냅니다.

하지만 데이터의 <mark>최종 목적지 주소는 처음부터 끝까지 10.0.0.50</mark>입니다.

즉, 라우터는 중간 전달자입니다.

```text
최종 목적지 주소: 10.0.0.50
첫 전달 대상: 192.168.10.1
```

이 두 개를 구분해야 합니다.

## 7. IP 주소와 물리 주소는 다르다

같은 네트워크 안에서 실제 장치에 전달하려면 물리 주소가 필요합니다.

그래서 주소 결정 프로토콜을 사용합니다.

### 같은 네트워크일 때

```text
내 컴퓨터
→ 목적지 IP 주소 확인
→ 목적지 물리 주소 확인 요청
→ 목적지 장치가 자기 물리 주소 응답
→ 해당 장치로 전달
```

### 다른 네트워크일 때

중요한 점은 목적지 장치의 물리 주소를 구하는 것이 아니라 <mark>기본 게이트웨이의 물리 주소를 구한다는 것</mark>입니다.

```text
최종 목적지 IP 주소: 외부 서버 주소
현재 전달할 물리 주소: 기본 게이트웨이의 물리 주소
```

<blockquote class="prompt-danger">
<p>다른 네트워크로 보낼 때 처음 프레임의 물리 주소는 외부 서버가 아니라 기본 게이트웨이의 물리 주소입니다.</p>
</blockquote>

## 8. 새 IP 주소를 자동으로 할당받는 과정

컴퓨터가 네트워크에 처음 연결되면 아직 자기 주소가 없을 수 있습니다.

이때 주소 자동 할당 서버를 이용합니다.

일반적으로 다음 4단계로 진행됩니다.

| 순서 | 단계 | 의미 |
| --- | --- | --- |
| 1 | 발견 | 사용 가능한 주소 자동 할당 서버를 찾음 |
| 2 | 제안 | 서버가 사용 가능한 주소를 제안 |
| 3 | 요청 | 장치가 해당 주소 사용을 요청 |
| 4 | 승인 | 서버가 주소 사용을 승인 |

시험에서는 이 순서를 그대로 묻는 경우가 많습니다.

```text
발견
→ 제안
→ 요청
→ 승인
```

<mark>주소가 필요한 장치는 먼저 서버를 찾고, 서버가 주소를 제안하면 장치가 요청한 뒤 최종 승인받습니다.</mark>

## 9. 주소 자동 할당에 실패하면

주소 자동 할당 서버에서 주소를 받지 못하면 일부 운영체제는 자동 사설 주소를 사용합니다.

대표 대역은 다음과 같습니다.

```text
169.254.0.0 대역
```

이 주소가 보인다면 다음 상황을 의심할 수 있습니다.

- 주소 자동 할당 서버와 통신하지 못함
- 공유기 또는 네트워크 연결 문제
- 네트워크 설정 이상

<blockquote class="prompt-warning">
<p>169.254로 시작하는 주소가 잡혔다면 정상적인 사설 주소를 받은 것이 아니라 자동 할당 실패 상황일 가능성이 높습니다.</p>
</blockquote>

## 10. 사설 주소로 인터넷에 접속하는 방법

사설 주소는 인터넷에서 그대로 사용할 수 없습니다.

그래서 공유기나 라우터가 내부 주소를 공인 주소로 변환합니다.

예시는 다음과 같습니다.

```text
내 컴퓨터: 192.168.0.10
공유기 내부 주소: 192.168.0.1
공유기 공인 주소: 203.0.113.10
```

인터넷으로 나갈 때 공유기는 내부 주소를 공인 주소로 변환합니다.

```text
192.168.0.10
→ 공유기
→ 공인 주소로 변환
→ 인터넷
```

돌아오는 데이터는 공유기가 다시 내부 장치에 전달합니다.

<mark>사설 주소를 사용하는 장치가 인터넷에 접속하려면 주소 변환 과정이 필요합니다.</mark>

## 11. 네트워크 주소와 브로드캐스트 주소

주소 하나를 받았다고 해서 모든 주소를 장치에 할당할 수 있는 것은 아닙니다.

예를 들어 다음 네트워크를 봅니다.

```text
192.168.10.0 /24
```

이 경우 주소 범위는 다음과 같습니다.

| 구분 | 주소 |
| --- | --- |
| 네트워크 주소 | 192.168.10.0 |
| 첫 사용 가능 주소 | 192.168.10.1 |
| 마지막 사용 가능 주소 | 192.168.10.254 |
| 브로드캐스트 주소 | 192.168.10.255 |

따라서 일반 장치에 할당 가능한 주소는 192.168.10.1부터 192.168.10.254까지입니다.

<blockquote class="prompt-warning">
<p>네트워크 주소와 브로드캐스트 주소는 일반 장치에 할당하지 않습니다.</p>
</blockquote>

## 12. 가장 적절한 IP 주소 고르기

시험에서는 특정 네트워크에 사용할 수 있는 주소를 고르라고 할 수 있습니다.

예를 들어 다음 조건을 봅니다.

```text
네트워크: 192.168.20.0 /24
```

선택지가 다음과 같다고 봅니다.

```text
① 192.168.20.0
② 192.168.20.25
③ 192.168.20.255
④ 192.168.21.25
```

판단은 다음 순서로 합니다.

1. 같은 네트워크에 속하는가
2. 네트워크 주소가 아닌가
3. 브로드캐스트 주소가 아닌가
4. 이미 사용 중인 주소가 아닌가

따라서 가장 적절한 주소는 192.168.20.25입니다.

## 13. 서브넷 마스크를 이용한 빠른 판단

다음 형태는 매우 자주 나옵니다.

```text
주소: 192.168.1.130
서브넷 마스크: 255.255.255.128
```

마지막 구간에서 블록 크기를 구합니다.

```text
256 - 128 = 128
```

따라서 네트워크 구간은 다음과 같습니다.

```text
0 ~ 127
128 ~ 255
```

130은 두 번째 구간에 들어갑니다.

따라서 네트워크 주소는 다음과 같습니다.

```text
192.168.1.128
```

브로드캐스트 주소는 다음과 같습니다.

```text
192.168.1.255
```

사용 가능한 장치 주소는 다음과 같습니다.

```text
192.168.1.129 ~ 192.168.1.254
```

<mark>255.255.255.128이 나오면 마지막 구간을 128개씩 나눈다고 생각하면 빠릅니다.</mark>

## 14. 자주 나오는 서브넷 마스크 블록 크기

| 서브넷 마스크 마지막 값 | 블록 크기 | 한 구간 주소 수 |
| --- | --- | --- |
| 0 | 256 | 256 |
| 128 | 128 | 128 |
| 192 | 64 | 64 |
| 224 | 32 | 32 |
| 240 | 16 | 16 |
| 248 | 8 | 8 |
| 252 | 4 | 4 |

시험에서는 다음 계산만 기억하면 됩니다.

```text
블록 크기 = 256 - 서브넷 마스크 값
```

예를 들어 255.255.255.224라면 다음과 같습니다.

```text
256 - 224 = 32
```

따라서 구간은 다음과 같습니다.

```text
0 ~ 31
32 ~ 63
64 ~ 95
96 ~ 127
128 ~ 159
160 ~ 191
192 ~ 223
224 ~ 255
```

## 15. 주소를 보고 바로 판단하는 연습

### 예시 1

```text
내 주소: 192.168.1.10
목적지: 192.168.1.200
서브넷 마스크: 255.255.255.0
```

같은 네트워크입니다.

따라서 목적지 장치로 직접 전달합니다.

### 예시 2

```text
내 주소: 192.168.1.10
목적지: 192.168.2.20
서브넷 마스크: 255.255.255.0
기본 게이트웨이: 192.168.1.1
```

다른 네트워크입니다.

따라서 기본 게이트웨이 192.168.1.1로 먼저 전달합니다.

### 예시 3

```text
내 주소: 169.254.15.20
```

주소 자동 할당에 실패했을 가능성이 높습니다.

### 예시 4

```text
목적지: 127.0.0.1
```

자기 자신을 가리킵니다.

### 예시 5

```text
네트워크: 10.10.10.0 /24
후보 주소: 10.10.10.255
```

브로드캐스트 주소이므로 일반 장치에 할당할 수 없습니다.

## 16. 도메인 이름을 입력하면 실제로 일어나는 일

웹 주소를 입력했다고 해서 바로 서버에 전달되는 것은 아닙니다.

먼저 이름을 IP 주소로 바꿔야 합니다.

전체 흐름은 다음과 같습니다.

```text
도메인 이름 입력
→ 이름을 IP 주소로 변환
→ 목적지 IP 주소 확인
→ 같은 네트워크인지 판단
→ 다르면 기본 게이트웨이로 전달
→ 라우터들이 경로 선택
→ 목적지 서버 도착
```

즉, 이름 변환 기능은 목적지 주소를 찾는 역할이고, 라우팅은 그 주소까지 가는 길을 결정하는 역할입니다.

## 17. 라우터는 무엇을 보고 경로를 결정하는가

라우터는 목적지 주소를 보고 라우팅 테이블에서 가장 적절한 경로를 찾습니다.

라우팅 테이블에는 일반적으로 다음 정보가 들어 있습니다.

- 목적지 네트워크
- 서브넷 정보
- 다음 전달 지점
- 출구 인터페이스
- 경로 우선순위 정보

시험에서는 <mark>목적지 네트워크와 가장 구체적으로 일치하는 경로를 선택한다</mark>는 점이 중요합니다.

예를 들어 다음 두 경로가 있다고 봅니다.

```text
10.0.0.0 /8
10.10.0.0 /16
```

목적지가 10.10.20.30이라면 두 경로에 모두 포함됩니다.

하지만 10.10.0.0 /16이 더 구체적인 경로입니다.

따라서 더 구체적인 경로를 선택합니다.

## 18. 기본 경로

라우팅 테이블에서 목적지와 일치하는 경로를 찾지 못하면 기본 경로를 사용할 수 있습니다.

대표적인 표현은 다음과 같습니다.

```text
0.0.0.0 /0
```

의미는 다음과 같습니다.

```text
정확히 맞는 경로가 없으면 이쪽으로 보낸다
```

가정용 공유기의 기본 인터넷 경로에서 자주 볼 수 있습니다.

## 19. 잘 놓치는 핵심

### 1. 같은 네트워크라면 기본 게이트웨이를 거치지 않는다

같은 네트워크의 장치끼리는 직접 전달합니다.

### 2. 다른 네트워크라면 처음에는 기본 게이트웨이로 보낸다

최종 목적지 주소는 외부 서버 주소 그대로 유지됩니다.

### 3. 다른 네트워크로 보낼 때 처음 필요한 물리 주소는 게이트웨이의 물리 주소이다

외부 서버의 물리 주소를 직접 알아내는 것이 아닙니다.

### 4. 169.254는 자동 주소 할당 실패 상황을 의심한다

정상적으로 주소를 받은 상황과 구분합니다.

### 5. 네트워크 주소와 브로드캐스트 주소는 장치에 할당할 수 없다

주소 범위만 보고 무조건 할당 가능하다고 판단하면 안 됩니다.

### 6. 172 사설 주소 범위는 172.16부터 172.31까지이다

172 전체가 사설 주소가 아닙니다.

## 20. 시험·면접에서 바로 쓰는 판단 순서

문제에 주소가 여러 개 나오면 다음 순서로 봅니다.

```text
1. 내 IP 주소 확인
2. 서브넷 마스크 확인
3. 내 네트워크 주소 계산
4. 목적지 네트워크 주소 계산
5. 둘이 같은지 비교
6. 같으면 직접 전달
7. 다르면 기본 게이트웨이로 전달
8. 라우터가 목적지 경로 선택
9. 최종 목적지 도착
```

주소를 새로 받아야 한다면 다음 순서입니다.

```text
1. 주소 자동 할당 서버 탐색
2. 주소 제안 받기
3. 해당 주소 사용 요청
4. 서버 승인
5. 주소와 서브넷 마스크, 게이트웨이 정보 사용
```

## 21. 시험 함정 정리

| 함정 | 올바른 판단 |
| --- | --- |
| 172로 시작하면 모두 사설 주소 | 172.16 ~ 172.31만 사설 주소 |
| 다른 네트워크의 목적지로 바로 전달 | 기본 게이트웨이로 먼저 전달 |
| 게이트웨이가 최종 목적지 | 게이트웨이는 중간 전달 장치 |
| 169.254는 정상 사설 주소 할당 | 자동 할당 실패 시 나타날 수 있음 |
| 192.168.1.0을 장치에 할당 | /24라면 네트워크 주소이므로 불가 |
| 192.168.1.255를 장치에 할당 | /24라면 브로드캐스트 주소이므로 불가 |
| 사설 주소가 인터넷에서 그대로 사용 | 공인 주소 변환 과정 필요 |

## 22. 예시로 한 바퀴

다음 조건을 봅니다.

```text
컴퓨터 주소: 192.168.50.20
서브넷 마스크: 255.255.255.0
기본 게이트웨이: 192.168.50.1
웹 서버 주소: 203.0.113.30
```

첫째, 컴퓨터의 네트워크 주소는 192.168.50.0입니다.

둘째, 웹 서버는 다른 네트워크에 있습니다.

셋째, 컴퓨터는 기본 게이트웨이 192.168.50.1의 물리 주소를 확인합니다.

넷째, 데이터는 게이트웨이로 전달됩니다.

다섯째, 공유기나 라우터는 필요한 경우 사설 주소를 공인 주소로 변환합니다.

여섯째, 라우팅 경로를 따라 여러 라우터를 통과합니다.

일곱째, 최종적으로 목적지 IP 주소인 203.0.113.30에 도착합니다.

<mark>처음 전달 대상과 최종 목적지는 다를 수 있다는 점이 핵심입니다.</mark>
