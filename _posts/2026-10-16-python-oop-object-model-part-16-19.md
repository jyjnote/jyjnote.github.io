## 16부. 클래스·인스턴스·메서드

### 16.1. 클래스 정의·본문 실행·인스턴스 생성

**클래스**는 객체의 종류를 정의하고, **인스턴스**는 그 클래스에 속하는 개별 객체입니다. 클래스 자체도 객체입니다. 클래스 정의문을 실행할 때 본문이 실행되고, 본문의 `def`는 함수 객체를 만듭니다. 그 메서드의 본문까지 즉시 실행하는 것은 아닙니다.[^classes][^compound]

```python
기록 = []

class 회원:
    기록.append("클래스 본문")

    def __init__(self, 이름):
        기록.append("초기화")
        self.이름 = 이름

print(기록)                  # 출력: ['클래스 본문']
첫째 = 회원("가람")
둘째 = 회원("나래")
print(기록)                  # 출력: ['클래스 본문', '초기화', '초기화']
print(첫째.이름, 둘째.이름)   # 출력: 가람 나래
print(type(첫째) is 회원)     # 출력: True
print(type(회원) is type)     # 출력: True
```

클래스 본문은 **정의문을 실행할 때마다** 실행됩니다. 함수 안에서 클래스를 정의하고 그 함수를 두 번 호출하면, 클래스도 두 번 새로 정의될 수 있습니다. 따라서 “프로그램 전체에서 무조건 한 번 실행된다”라고 외우지 않습니다.

클래스가 유용한 이유는 서로 연결된 상태와 동작을 같은 대상에 묶을 수 있기 때문입니다. 다만 상태가 필요 없는 단순 계산은 함수만으로도 충분합니다. 모든 함수를 클래스로 감쌀 필요는 없습니다.

### 16.2. 객체 생성과 초기화: `__new__`와 `__init__`

일반적인 클래스 호출에서 `__new__`는 반환할 인스턴스를 만들고, `__init__`는 만들어진 인스턴스의 상태를 초기화합니다. 호출을 조정하는 상위 단계는 메타클래스의 `__call__`입니다.[^datamodel]

```python
class 상품:
    def __new__(cls, 이름):
        print("생성")
        return super().__new__(cls)

    def __init__(self, 이름):
        print("초기화")
        self.이름 = 이름

대상 = 상품("연필")
# 출력: 생성
# 출력: 초기화
print(대상.이름)  # 출력: 연필
```

| 구분 | `__new__` | `__init__` |
| --- | --- | --- |
| 중심 역할 | 생성할 객체를 반환 | 받은 객체의 상태를 초기화 |
| 첫 번째 인자 | 요청한 클래스 | 초기화할 인스턴스 |
| 반환 | 보통 요청한 클래스의 인스턴스 | 반드시 `None` |
| 주된 사용 | 불변 타입의 생성 방식 조정 등 | 일반적인 속성 초기화 |

`__new__`가 요청한 클래스의 인스턴스가 아닌 객체를 반환하면, 그 클래스 호출은 해당 객체에 `__init__`를 적용하지 않습니다. `__init__`에서 다른 객체를 반환하려 하면 오류입니다.[^datamodel]

```python
class 다른값반환:
    def __new__(cls):
        return 7

    def __init__(self):
        raise AssertionError("이 예제에서는 실행되지 않습니다.")

print(다른값반환())  # 출력: 7

class 잘못된초기화:
    def __init__(self):
        return 7

try:
    잘못된초기화()
except TypeError:
    print("초기화는 다른 값을 반환할 수 없음")
    # 출력: 초기화는 다른 값을 반환할 수 없음
```

<blockquote class="prompt-warning">
<p>“생성자”라는 표현을 넓게 쓰더라도, 시험에서는 객체 생성과 초기화를 나누어 답합니다. 일반적인 초기화만 필요하면 __new__를 직접 작성하지 않아도 됩니다.</p>
</blockquote>

### 16.3. `self`·`cls`의 관례와 메서드 바인딩

`self`와 `cls`는 예약어가 아니라 관례적인 매개변수 이름입니다. 일반 메서드를 인스턴스를 통해 조회하면, 원래 함수와 해당 인스턴스가 연결된 **바운드 메서드**를 얻습니다.[^classes][^descriptor]

```python
class 계산기:
    def 두배(self, 수):
        return 수 * 2

대상 = 계산기()
연결된메서드 = 대상.두배

print(연결된메서드(4))                    # 출력: 8
print(계산기.두배(대상, 4))               # 출력: 8
print(연결된메서드.__self__ is 대상)       # 출력: True
print(연결된메서드.__func__ is 계산기.두배)  # 출력: True
```

이 예제에서 `대상.두배(4)`는 `계산기.두배(대상, 4)`와 같은 계산을 합니다. 사용자가 `self`를 별도로 적지 않아도 메서드 호출이 연결된 인스턴스를 첫 인자로 전달합니다.

반대로 일반 함수를 **인스턴스 사전에 직접 저장**하면, 클래스에 저장한 함수처럼 자동으로 인스턴스가 연결되지는 않습니다. 함수의 위치와 조회 경로가 중요합니다.[^descriptor]

```python
class 도구:
    pass

def 인사(이름):
    return f"안녕, {이름}"

대상 = 도구()
대상.인사 = 인사
print(대상.인사("가람"))  # 출력: 안녕, 가람
```

### 16.4. 인스턴스 속성·클래스 속성·공유 상태

인스턴스 속성은 보통 각 인스턴스의 상태를 담습니다. 클래스 속성은 클래스에 저장되며, 인스턴스 조회에서도 상속·속성 규칙에 따라 사용됩니다. 클래스에 둔 리스트 하나를 여러 인스턴스가 공유할 수 있습니다.[^classes]

```python
class 장바구니:
    품목 = []
    종류 = "기본"

첫째 = 장바구니()
둘째 = 장바구니()
첫째.품목.append("연필")
첫째.종류 = "특별"

print(둘째.품목)                  # 출력: ['연필']
print(첫째.품목 is 둘째.품목)      # 출력: True
print(첫째.종류, 둘째.종류)        # 출력: 특별 기본
print(장바구니.종류)              # 출력: 기본
print("품목" in 첫째.__dict__)     # 출력: False
print("종류" in 첫째.__dict__)     # 출력: True
```

`append`는 찾아낸 리스트를 변경합니다. 반면 이 예제의 `첫째.종류 = "특별"`은 첫째 인스턴스에 같은 이름의 속성을 만들어 클래스 속성을 가립니다.

**위 설명은 일반 속성에 대한 규칙입니다.** `property` 같은 데이터 디스크립터가 있으면 대입이 설정 메서드로 전달될 수 있습니다. “인스턴스 속성이 언제나 우선한다”는 일반화는 19부에서 수정합니다.[^descriptor]

```python
class 장바구니:
    def __init__(self):
        self.품목 = []

첫째 = 장바구니()
둘째 = 장바구니()
첫째.품목.append("연필")

print(첫째.품목, 둘째.품목)        # 출력: ['연필'] []
print(첫째.품목 is 둘째.품목)      # 출력: False
```

개별 목록이 필요하면 초기화할 때 각각 만듭니다. 공통 설정·상수처럼 의도적으로 공유할 값은 클래스에 둘 수 있습니다.

### 16.5. 인스턴스 메서드·클래스 메서드·정적 메서드

세 종류의 차이는 **자동으로 연결하는 첫 인자**입니다. 클래스 메서드는 호출 경로의 클래스를 연결하고, 정적 메서드는 인스턴스나 클래스를 자동 인자로 추가하지 않습니다.[^builtins][^descriptor]

| 종류 | 자동 연결 | 대표 용도 | 일반적인 선언 |
| --- | --- | --- | --- |
| 인스턴스 메서드 | 인스턴스 | 개별 객체 상태 처리 | `def 이름(self, ...)` |
| 클래스 메서드 | 클래스 | 다른 형식에서 객체를 만드는 대체 생성 경로 | `@classmethod` |
| 정적 메서드 | 없음 | 클래스와 관련되지만 상태가 필요 없는 계산 | `@staticmethod` |

```python
class 회원:
    def __init__(self, 이름):
        self.이름 = 이름

    def 소개(self):
        return self.이름

    @classmethod
    def 문자열에서(cls, 원문):
        return cls(원문.strip())

    @staticmethod
    def 이름검사(이름):
        return bool(이름.strip())

class 우수회원(회원):
    pass

대상 = 우수회원.문자열에서(" 가람 ")
print(type(대상).__name__)        # 출력: 우수회원
print(대상.소개())               # 출력: 가람
print(회원.이름검사("   "))      # 출력: False
print(대상.문자열에서.__self__ is 우수회원)  # 출력: True
```

`문자열에서`가 `회원(...)`을 고정 호출하지 않고 `cls(...)`를 사용하므로, 이 상속 구조에서는 하위 클래스의 객체를 만듭니다. 하위 클래스가 생성 인자 규약을 바꾸면 그 호환성도 확인해야 합니다.

정적 메서드는 일반 함수로 분리해도 되는 경우가 많습니다. 클래스 안에 둔다는 이유만으로 특별한 성능이나 접근 권한이 생기지는 않습니다.

### 16.6. 공개·비공개 관례와 이름 맹글링

앞에 밑줄 하나를 둔 이름은 내부 구현이라는 관례입니다. 앞에 밑줄 두 개를 붙이고 뒤에는 두 개 미만인 이름은 클래스 내부에서 이름이 변환될 수 있습니다. 이를 **이름 맹글링**이라고 합니다.[^classes]

| 이름 형태 | 의미 | 주의 |
| --- | --- | --- |
| `이름` | 일반적으로 공개하는 속성 | 사용 규약을 따름 |
| `_이름` | 비공개로 취급하자는 관례 | 언어가 외부 접근을 차단하지 않음 |
| `__이름` | 클래스 이름을 포함한 형태로 변환 | 상속 과정의 이름 충돌 방지가 목적 |
| `__이름__` | 특수 이름 형태 | 앞의 이름 맹글링 규칙과 다름 |

```python
class 문서:
    def __init__(self):
        self.__내용 = "원문"

class 보고서(문서):
    def __init__(self):
        super().__init__()
        self.__내용 = "요약"

대상 = 보고서()
print(대상._문서__내용)       # 출력: 원문
print(대상._보고서__내용)     # 출력: 요약
print(hasattr(대상, "__내용"))  # 출력: False
```

상위 클래스의 `__내용`과 하위 클래스의 `__내용`은 서로 다른 이름으로 바뀝니다. 문자열로 전달한 `getattr(대상, "__내용")`에 같은 변환이 자동 적용되는 것은 아닙니다.[^classes]

<mark>이름 맹글링은 보안 경계가 아닙니다. 내부 값을 숨기는 암호화나 접근 권한 검사로 설명하지 않습니다.</mark>

### 16.7. 데이터 클래스·필드·기본값 생성 함수

데이터 클래스는 선언한 필드를 바탕으로 초기화·표현·동등성 비교 등의 코드를 생성하는 클래스입니다. 기본 설정에서는 `__init__`·`__repr__`·`__eq__`를 생성할 수 있습니다. 이미 정의한 메서드와 옵션에 따라 실제 생성 여부는 달라집니다.[^dataclasses][^dataclasspep]

```python
from dataclasses import dataclass, field, fields
from typing import ClassVar

@dataclass
class 회원:
    구분: ClassVar[str] = "일반"
    이름: str
    관심사: list[str] = field(default_factory=list)

첫째 = 회원("가람")
둘째 = 회원("나래")
첫째.관심사.append("통계")

print(첫째)                       # 출력: 회원(이름='가람', 관심사=['통계'])
print(둘째.관심사)                # 출력: []
print([항목.name for 항목 in fields(회원)])  # 출력: ['이름', '관심사']
print(회원.구분)                  # 출력: 일반
```

`default_factory=list`는 기본값이 필요할 때 호출할 함수를 지정합니다. `list()`로 만든 같은 리스트를 기본값에 넣는 방식과 다릅니다. 생성 함수는 일반적으로 인자 없이 호출할 수 있어야 합니다.[^dataclasses]

| 도구 | 역할 | 주의 |
| --- | --- | --- |
| `field(default_factory=...)` | 기본값이 필요할 때 값을 생성 | 함수 자체를 전달 |
| `field(init=False)` | 생성 인자에서 제외 | 값 마련 방식은 별도로 확인 |
| `field(repr=False)` | 자동 표현에서 제외 | 비밀정보 접근 자체를 막지는 않음 |
| `field(compare=False)` | 자동 동등성·순서 비교에서 제외 | 객체의 의미와 맞는지 확인 |
| `ClassVar` | 데이터 클래스 필드에서 제외 | 클래스 수준 값 표시 |
| `InitVar` | 초기화 전용 인자 | 일반 저장 필드와 구별 |
| `__post_init__` | 자동 초기화 뒤 추가 계산·검증 | 직접 만든 초기화에서는 호출을 따로 판단 |

```python
from dataclasses import dataclass, field

@dataclass
class 직사각형:
    가로: int
    세로: int
    넓이: int = field(init=False)

    def __post_init__(self):
        if self.가로 < 0 or self.세로 < 0:
            raise ValueError("길이는 음수일 수 없습니다.")
        self.넓이 = self.가로 * self.세로

print(직사각형(3, 4).넓이)  # 출력: 12
```

데이터 클래스의 타입 주석은 자동적인 실행 중 타입 검사가 아닙니다. 필드 선언과 값 검증을 구별합니다. 자동 `__init__`는 일반 상위 클래스의 `__init__`를 임의로 호출하지 않으므로 필요한 초기화는 명시적으로 연결합니다.[^dataclasses][^typing]

파이썬 3.13의 데이터 클래스는 해시 불가능한 기본값을 변경 가능한 기본값의 근사 지표로 사용하여 거부합니다. 이것이 모든 변경 가능성을 완벽하게 판별한다는 뜻은 아닙니다.[^dataclasses]

### 16.8. 데이터 클래스의 비교·해시·동결·슬롯

자동 비교는 기본적으로 **같은 구체 타입의 인스턴스**끼리 필드를 비교합니다. `order=True`이면 필드 순서에 따른 순서 비교 메서드도 생성합니다. `frozen=True`는 일반적인 필드 재대입을 막지만 내부 객체까지 재귀적으로 얼리지는 않습니다.[^dataclasses]

```python
from dataclasses import dataclass, field, FrozenInstanceError

@dataclass(frozen=True)
class 기록:
    점수: list[int] = field(default_factory=list)

대상 = 기록()
대상.점수.append(90)
print(대상.점수)  # 출력: [90]

try:
    대상.점수 = []
except FrozenInstanceError:
    print("필드 재대입 금지")  # 출력: 필드 재대입 금지

try:
    hash(대상)
except TypeError:
    print("리스트 필드는 해시할 수 없음")  # 출력: 리스트 필드는 해시할 수 없음
```

자동 해시 규칙은 명시적인 `__hash__`가 없고 `unsafe_hash=False`인 기본 상황에서 다음과 같습니다.[^dataclasses]

| `eq` | `frozen` | 기본 해시 처리 |
| --- | --- | --- |
| `True` | `True` | 필드 기반 해시 메서드 생성 |
| `True` | `False` | `__hash__ = None`으로 해시 불가능 표시 |
| `False` | 어느 쪽이든 | 기존·상속 해시 정책을 유지 |

해시 메서드가 생성되어도 **해시에 참여하는 필드가 실제로 해시 가능해야** 호출이 성공합니다. `unsafe_hash=True`는 안전성을 보장하는 옵션이 아니라 강제로 해시 생성을 요청하는 옵션입니다.

```python
from dataclasses import dataclass, replace

@dataclass(frozen=True, order=True, slots=True)
class 좌표:
    가로: int
    세로: int

첫째 = 좌표(1, 2)
둘째 = replace(첫째, 세로=3)
print(첫째 == 좌표(1, 2))        # 출력: True
print(첫째 < 둘째)              # 출력: True
print(hash(첫째) == hash(좌표(1, 2)))  # 출력: True
print(hasattr(첫째, "__dict__"))  # 출력: False
```

| 비교 항목 | 일반 클래스 | 데이터 클래스 |
| --- | --- | --- |
| 초기화·표현 | 필요에 따라 직접 작성 | 필드를 바탕으로 생성 가능 |
| 기본 동등성 | 그대로 두면 정체성 중심 | 기본적으로 같은 타입의 필드 비교 |
| 입력 검증 | 직접 설계 | 역시 직접 설계 |
| 불변성 | 직접 설계 | 동결 옵션은 얕은 쓰기 제한 |
| 저장 공간 | 속성 구조에 따라 달라짐 | 슬롯 옵션을 선택 가능 |
| 적합한 대상 | 다양한 상태·행동 | 이름 있는 자료 묶음을 중심으로 한 객체 |

`asdict`는 단순한 얕은 사전 뷰가 아닙니다. 중첩 데이터 클래스·컨테이너를 재귀적으로 변환하고 그 외 객체는 깊은 복사 규칙을 사용합니다. `replace`는 기존 객체의 제자리 변경이 아니라 초기화 과정을 거쳐 새 객체를 만듭니다.[^dataclasses]

<blockquote class="prompt-warning">
<p>파이썬 3.13에서 데이터 클래스의 slots=True는 원래 클래스 대신 새 클래스를 반환합니다. 인자 없는 super()나 인자가 필요한 상위 __init_subclass__와 결합할 때 제약이 있으므로 일반 클래스의 슬롯과 완전히 같다고 보지 않습니다.</p>
</blockquote>

## 17부. 상속·다형성·객체 설계

### 17.1. 단일 상속·재정의·부모 기능 확장

상속은 기존 클래스의 속성과 동작을 탐색할 수 있는 관계를 만듭니다. 하위 클래스가 같은 이름의 메서드를 정의하면 **재정의**합니다. 상위 메서드가 다른 메서드를 호출할 때에도 실제 인스턴스의 동작이 사용될 수 있습니다.[^classes]

```python
class 문서:
    def 제목(self):
        return "기본 제목"

    def 출력문(self):
        return f"문서: {self.제목()}"

class 보고서(문서):
    def 제목(self):
        return "분석 결과"

대상 = 보고서()
print(대상.출력문())              # 출력: 문서: 분석 결과
print(isinstance(대상, 문서))     # 출력: True
print(issubclass(보고서, 문서))   # 출력: True
print(type(대상) is 문서)         # 출력: False
```

상위 클래스에 정의한 `출력문`이라도 `self`는 보고서 인스턴스입니다. 따라서 `self.제목()`은 보고서의 재정의된 메서드를 사용합니다.

하위 클래스가 `__init__`를 새로 정의하면 상위의 초기화가 자동으로 추가 실행되지는 않습니다. 필요한 경우 `super().__init__(...)`로 연결합니다. 반대로 하위가 초기화를 정의하지 않으면 상속된 초기화가 사용될 수 있습니다.[^datamodel]

### 17.2. 다중 상속·믹스인·다이아몬드 구조

**다중 상속**은 여러 기반 클래스를 두는 구조입니다. **믹스인**은 특정 기능을 보태기 위해 설계한 작은 기반 클래스를 뜻하는 설계 관례이며, 별도의 예약어는 아닙니다.[^classes][^abc]

```python
class 이름표기능:
    def 이름표(self):
        return f"[{self.이름}]"

class 회원:
    def __init__(self, 이름):
        self.이름 = 이름

class 표시회원(이름표기능, 회원):
    pass

print(표시회원("가람").이름표())  # 출력: [가람]
```

이 믹스인은 사용 대상이 `이름` 속성을 제공한다고 가정합니다. 믹스인의 의존 속성과 메서드를 작게 유지해야 결합 조건을 이해하기 쉽습니다.

공통 조상을 두 경로로 상속하면 다이아몬드 구조가 됩니다. 이때 탐색 순서를 단순한 “왼쪽 부모를 끝까지 찾은 다음 오른쪽 부모”로만 계산하면 틀릴 수 있습니다.[^mro]

```text
        공통
       /    \
     왼쪽  오른쪽
       \    /
        최종
```

### 17.3. 메서드 탐색 순서와 일관된 선형화

파이썬의 기본 클래스 체계는 여러 상속 경로를 일관된 한 줄의 탐색 순서로 정리합니다. 이를 **메서드 탐색 순서**라고 하며 `__mro__`에서 확인할 수 있습니다. 기본 선형화 방식은 `C3`입니다.[^mro]

```python
class 공통:
    def 값(self):
        return "공통"

class 왼쪽(공통):
    pass

class 오른쪽(공통):
    def 값(self):
        return "오른쪽"

class 최종(왼쪽, 오른쪽):
    pass

print([종류.__name__ for 종류 in 최종.__mro__])
# 출력: ['최종', '왼쪽', '오른쪽', '공통', 'object']
print(최종().값())  # 출력: 오른쪽
```

왼쪽에서 `값`을 찾지 못했다고 곧바로 공통까지 내려가지 않습니다. 전체 순서에서 오른쪽이 공통보다 먼저이므로 오른쪽의 메서드가 선택됩니다.

| 지켜야 하는 성질 | 뜻 |
| --- | --- |
| 하위 우선 | 하위 클래스가 상위보다 앞에 옴 |
| 지역 순서 유지 | 선언한 기반 클래스들의 선후관계를 존중 |
| 단조성 | 기존 상속에서 정한 선후관계를 하위 확장이 뒤집지 않음 |
| 일관성 | 모두 만족할 순서가 없으면 클래스 생성 실패 |

```python
class 첫째:
    pass

class 둘째:
    pass

class 앞순서(첫째, 둘째):
    pass

class 뒷순서(둘째, 첫째):
    pass

try:
    class 충돌(앞순서, 뒷순서):
        pass
except TypeError:
    print("탐색 순서 충돌")  # 출력: 탐색 순서 충돌
```

첫째가 둘째보다 앞서야 한다는 요구와 뒤서야 한다는 요구가 충돌합니다. 파이썬은 임의의 한쪽을 고르지 않고 클래스 생성을 거부합니다.[^mro]

### 17.4. `super`와 협력적 다중 상속

`super()`는 직접 부모를 가리키는 고정 별칭이 아닙니다. 일반적인 인스턴스 메서드에서는 **실제 인스턴스의 탐색 순서에서, 그 메서드가 정의된 기준 클래스 다음부터 조회**하도록 돕습니다.[^builtins][^mro]

```python
class 공통:
    def 처리(self):
        return ["공통"]

class 왼쪽(공통):
    def 처리(self):
        return ["왼쪽"] + super().처리()

class 오른쪽(공통):
    def 처리(self):
        return ["오른쪽"] + super().처리()

class 최종(왼쪽, 오른쪽):
    def 처리(self):
        return ["최종"] + super().처리()

print(왼쪽().처리())  # 출력: ['왼쪽', '공통']
print(최종().처리())  # 출력: ['최종', '왼쪽', '오른쪽', '공통']
```

같은 왼쪽 메서드의 `super()`라도 왼쪽 인스턴스에서는 공통으로 이어지고, 최종 인스턴스에서는 오른쪽으로 이어집니다. **메서드를 정의한 기준 클래스와 실제 대상의 전체 순서**를 함께 봐야 합니다.

협력적 상속에서는 각 참여 메서드가 필요한 일을 수행한 뒤 다음 메서드로 연결합니다. 다음 호출을 생략하면 그 지점에서 연결이 끊깁니다. 탐색 순서가 있다고 모든 메서드가 저절로 실행되는 것은 아닙니다.

| 설계 조건 | 이유 |
| --- | --- |
| 각 단계가 다음 메서드를 한 번 호출 | 누락·중복 실행을 줄임 |
| 서로 호환되는 인자 규약 사용 | 중간 클래스가 바뀌어도 연결 유지 |
| 생성 인자는 각 단계가 필요한 것만 소비 | 나머지를 다음 단계에 전달 가능 |
| 마지막 단계의 종료 규약 마련 | 없는 메서드까지 무조건 호출하지 않음 |

인자 없는 `super()`는 일반적인 메서드 문맥을 전제로 합니다. 중첩 함수 등에서 같은 방식으로 작동한다고 가정하지 않습니다. 특정 기반 클래스를 직접 호출하는 방식과 협력적 연결을 무분별하게 섞으면 중복 초기화가 생길 수 있습니다.[^builtins]

### 17.5. 덕 타이핑: 상속보다 지원하는 동작

**덕 타이핑**은 특정 상속 관계를 요구하기보다, 필요한 동작을 실제로 제공하는 객체를 사용하는 접근입니다. 같은 이름만 있는 것으로 충분하지 않고 입력·결과·부작용의 의미도 맞아야 합니다.[^classes][^protocol]

```python
class 문자열저장소:
    def 읽기(self):
        return "문자열 자료"

class 목록저장소:
    def 읽기(self):
        return "목록 자료"

def 가져오기(저장소):
    return 저장소.읽기()

print(가져오기(문자열저장소()))  # 출력: 문자열 자료
print(가져오기(목록저장소()))    # 출력: 목록 자료
```

두 클래스가 같은 사용자 정의 상위 클래스를 상속하지 않아도 `가져오기`에 사용할 수 있습니다. 이 함수가 의존하는 것은 “읽기 동작을 지원하고 기대한 결과를 준다”는 규약입니다.

타입 검사가 무조건 나쁘다는 뜻은 아닙니다. 값의 허용 범위를 제한하거나 잘못된 입력을 초기에 거부해야 할 때는 명시적 검사가 필요합니다. 덕 타이핑과 입력 검증은 서로 다른 판단입니다.

### 17.6. 추상 기반 클래스·구조적 규약의 차이

**추상 기반 클래스**는 상속 체계에서 구현할 동작을 선언할 수 있습니다. 추상 메서드가 남은 일반 하위 클래스는 인스턴스를 만들 수 없습니다. 추상 메서드에도 본문을 둘 수 있습니다.[^abc]

```python
from abc import ABC, abstractmethod

class 저장소(ABC):
    @abstractmethod
    def 읽기(self):
        raise NotImplementedError

class 파일저장소(저장소):
    def 읽기(self):
        return "완료"

try:
    저장소()
except TypeError:
    print("추상 클래스 직접 생성 불가")
    # 출력: 추상 클래스 직접 생성 불가

print(파일저장소().읽기())  # 출력: 완료
```

`Protocol`은 정적 타입 검사에 구조적 규약을 표현하는 도구입니다. 명시적으로 상속하지 않아도 필요한 멤버와 타입 규약을 만족하면 검사 도구가 호환 대상으로 판단할 수 있습니다.[^protocol][^typing]

```python
from typing import Protocol

class 읽기규약(Protocol):
    def 읽기(self) -> str:
        ...

class 메모리저장소:
    def 읽기(self) -> str:
        return "저장된 자료"

def 불러오기(대상: 읽기규약) -> str:
    return 대상.읽기()

print(불러오기(메모리저장소()))  # 출력: 저장된 자료
```

| 방식 | 주로 확인하는 것 | 확인되는 시점·범위 |
| --- | --- | --- |
| 덕 타이핑 | 필요한 동작의 실제 지원 | 해당 동작을 사용할 때 |
| 추상 기반 클래스 | 선언한 추상 멤버의 구현 여부 | 일반 상속의 인스턴스 생성 시 제한 |
| 구조적 타입 규약 | 멤버 이름·호출 형태·타입 호환 | 정적 검사 도구가 분석 |
| 실행 중 규약 확인 | 멤버 존재 등 제한된 조건 | `runtime_checkable` 사용 시 |

**주의할 경계도 있습니다.** 추상 기반 클래스의 가상 하위 클래스 등록은 메서드를 상속시키지 않습니다. `runtime_checkable`을 붙인 규약의 실행 중 검사는 모든 인자 타입과 반환 타입을 검증하지 않습니다. 타입 주석만으로 잘못된 입력이 자동 차단되는 것도 아닙니다.[^abc][^typing]

`@abstractmethod`를 `@classmethod`·`@staticmethod`·`@property`와 함께 쓰면 일반적으로 추상 메서드 표시를 가장 안쪽에 둡니다.[^abc]

### 17.7. 상속과 합성·위임·책임 분리

**상속**은 기반 타입의 역할을 이어받는 관계이고, **합성**은 다른 객체를 구성 요소로 보유하는 관계입니다. **위임**은 일부 일을 그 객체에 맡기는 방식입니다. 아래는 출력을 맡길 객체를 전달받는 설계 예제입니다.

```python
class 화면출력:
    def 쓰기(self, 내용):
        return f"화면: {내용}"

class 기록출력:
    def 쓰기(self, 내용):
        return f"기록: {내용}"

class 알림:
    def __init__(self, 출력기):
        self.출력기 = 출력기

    def 보내기(self, 내용):
        return self.출력기.쓰기(내용)

print(알림(화면출력()).보내기("완료"))  # 출력: 화면: 완료
print(알림(기록출력()).보내기("완료"))  # 출력: 기록: 완료
```

알림은 화면출력의 한 종류가 아닙니다. 출력기를 사용하여 일을 수행합니다. 이런 관계에는 상속보다 합성이 뜻을 더 잘 드러냅니다.

| 선택 | 검토할 질문 | 주의할 비용 |
| --- | --- | --- |
| 상속 | 하위 객체를 상위 객체 대신 사용해도 약속이 유지되는가? | 기반 클래스의 변경에 결합될 수 있음 |
| 합성 | 다른 기능을 가진 객체가 필요하고 교체도 해야 하는가? | 위임 코드와 객체 연결이 필요 |
| 일반 함수 | 별도 상태나 수명 없이 입력을 결과로 바꾸는가? | 관련 상태가 흩어지지 않는지 확인 |

코드 재사용만을 이유로 상속하지 않습니다. 하위 타입이 상위 타입의 입력·출력·부작용 약속을 깨면, 이름상 상속되어도 대체 가능한 설계라고 보기 어렵습니다.

### 17.8. 재정의·연산자 오버로딩·함수 오버로딩

세 용어는 적용되는 대상이 다릅니다. 파이썬에서 같은 이름의 함수를 여러 번 정의하면 일반적으로 뒤의 바인딩이 앞의 바인딩을 가립니다. 인자 타입이나 개수로 여러 구현을 자동 보존하지 않습니다.[^compound][^typing]

```python
class 도구:
    def 처리(self, 값):
        return "한 인자"

    def 처리(self, 첫값, 둘째값):
        return 첫값 + 둘째값

print(도구().처리(2, 3))  # 출력: 5

try:
    도구().처리(2)
except TypeError:
    print("앞의 구현은 선택되지 않음")
    # 출력: 앞의 구현은 선택되지 않음
```

| 용어 | 의미 | 파이썬에서의 대표 방식 |
| --- | --- | --- |
| 메서드 재정의 | 하위가 상위의 같은 이름 동작을 대체 | 하위 클래스에 메서드 정의 |
| 연산자 오버로딩 | 객체가 연산 문법에 참여 | `__add__`·`__eq__` 등 |
| 여러 호출 형태 지원 | 하나의 이름이 여러 인자 형태를 받음 | 기본 인자·가변 인자·명시적 분기 |
| 타입별 실행 구현 선택 | 입력 타입에 따라 구현을 고름 | `singledispatch`·`singledispatchmethod` |
| 타입 검사용 오버로드 | 여러 호출 형태를 정적 검사에 설명 | `typing.overload`와 최종 실행 구현 |

`typing.overload` 선언은 실행 중 구현 선택기가 아닙니다. 실제 실행을 담당할 최종 구현이 필요합니다. 반면 단일 디스패치는 실행 중 타입을 기준으로 등록한 구현을 고릅니다.[^typing][^functools]

## 18부. 데이터 모델과 특수 메서드

### 18.1. 문법·내장 함수·사용자 객체를 연결하는 규약

**특수 메서드**는 파이썬의 문법이나 내장 함수가 사용할 동작을 정의하는 약속된 이름입니다. 임의의 새 연산자를 만드는 기능은 아니며, 이미 정해진 문법에 사용자 객체를 참여시킵니다.[^datamodel]

| 사용 문법 | 중심 규약 | 담당하는 동작 |
| --- | --- | --- |
| `repr(대상)` | `__repr__` | 개발·관찰용 표현 |
| `str(대상)` | `__str__` | 읽기 쉬운 표현 |
| `format(대상, 형식)` | `__format__` | 서식 적용 |
| `len(대상)` | `__len__` | 길이 |
| `bool(대상)` | `__bool__`·`__len__` | 참·거짓 판정 |
| `값 in 대상` | `__contains__` 등 | 포함 여부 |
| `대상[키]` | `__getitem__` | 항목 조회 |
| `iter(대상)` | `__iter__` 등 | 반복자 제공 |
| `왼쪽 + 오른쪽` | `__add__`·`__radd__` | 덧셈 규약 |
| `대상 += 값` | `__iadd__` 등 | 증강 대입 규약 |
| `대상(...)` | `__call__` | 함수처럼 호출 |
| `hash(대상)` | `__hash__` | 해시값 계산 |

이 표는 연결 지점을 요약한 것입니다. 대체 경로·반사 연산·하위 타입 우선순위가 있으므로, 문법이 항상 해당 메서드 하나의 직접 호출과 완전히 같지는 않습니다.

반복·자원 관리·비동기·복사에도 관련 규약이 있습니다. `__enter__`·`__exit__`는 다음 편, `__await__`와 비동기 규약은 비동기편, `__del__`과 객체 수명은 메모리편에서 연결합니다.[^datamodel]

### 18.2. 문자열 표현과 형식 지정

`__repr__`는 객체를 구별할 수 있는 정보 중심 표현이고, `__str__`는 사용자가 읽기 쉬운 표현입니다. `__format__`은 서식 문자열을 해석합니다. 세 메서드 모두 문자열을 반환해야 합니다.[^datamodel]

```python
class 가격:
    def __init__(self, 값):
        self.값 = 값

    def __repr__(self):
        return f"가격(값={self.값!r})"

    def __str__(self):
        return f"{self.값}원"

    def __format__(self, 형식):
        return format(self.값, 형식) + "원"

대상 = 가격(12345)
print(repr(대상))       # 출력: 가격(값=12345)
print(str(대상))        # 출력: 12345원
print(f"{대상:,}")      # 출력: 12,345원
print([대상])           # 출력: [가격(값=12345)]
```

리스트 같은 내장 컨테이너는 원소를 표현할 때 보통 원소의 `repr`를 사용합니다. 따라서 객체 하나를 출력한 모습과 그 객체를 리스트에 넣고 출력한 모습이 다를 수 있습니다.

`__str__`를 따로 정의하지 않으면 기본 경로에서 `__repr__`를 사용합니다. 반대로 `__str__`만 정의했다고 `repr`까지 같은 표현이 되는 것은 아닙니다.[^datamodel]

`repr`를 가능하면 객체를 이해하거나 재구성할 수 있는 형태로 작성하자는 권고는 있습니다. 그러나 **모든 객체의 `repr`를 실행하면 복원된다**는 보장은 없습니다. 출력 문자열을 신뢰하지 말고, 비밀정보도 포함하지 않습니다.

### 18.3. 길이·참 거짓·멤버십

참·거짓 판정은 `__bool__`를 우선 사용하고, 없으면 `__len__`를 사용합니다. 둘 다 없으면 일반적으로 참입니다. `__bool__`는 불리언을, `__len__`는 음수가 아닌 정수 길이를 반환해야 합니다.[^datamodel]

```python
class 대기목록:
    def __init__(self, 자료):
        self.자료 = list(자료)

    def __len__(self):
        return len(self.자료)

    def __contains__(self, 값):
        return 값 in self.자료

print(bool(대기목록([])))          # 출력: False
print(len(대기목록([1, 2])))       # 출력: 2
print(2 in 대기목록([1, 2]))       # 출력: True

class 항상참인목록(대기목록):
    def __bool__(self):
        return True

대상 = 항상참인목록([])
print(len(대상), bool(대상))        # 출력: 0 True
```

길이가 영이어도 직접 정의한 `__bool__`가 참을 반환하면 참으로 평가됩니다. 특수 메서드를 정의할 수 있다는 사실과 직관적인 설계라는 판단은 별개입니다.

| 동작 | 먼저 확인할 규약 | 없을 때의 대표 경로 |
| --- | --- | --- |
| 참·거짓 | `__bool__` | `__len__`, 둘 다 없으면 참 |
| 포함 여부 | `__contains__` | 반복 규약, 이후 옛 시퀀스 규약 |
| 반복 | `__iter__` | 정수 인덱스의 `__getitem__` |
| 역순 반복 | `__reversed__` | 길이와 인덱스 조회 |

옛 시퀀스 반복 규약은 영부터 순서대로 조회하고 `IndexError`로 종료를 알립니다. 특별한 메서드를 `None`으로 설정하여 동작을 명시적으로 막은 경우에는 위의 “미정의”와 같은 대체 규칙을 적용하지 않을 수 있습니다.[^datamodel]

### 18.4. 인덱싱·슬라이싱·항목 변경·사용자 컨테이너

`대상[키]`는 항목 조회 규약을 사용합니다. `대상[1:3]`처럼 슬라이스를 쓰면 `__getitem__`에 `slice` 객체가 전달됩니다. 음수 인덱스를 변환하거나 슬라이스 결과를 어떤 타입으로 반환할지는 구현에서 정해야 합니다.[^datamodel]

```python
class 점수표:
    def __init__(self, 자료):
        self._자료 = list(자료)

    def __len__(self):
        return len(self._자료)

    def __iter__(self):
        return iter(self._자료)

    def __getitem__(self, 키):
        결과 = self._자료[키]
        return type(self)(결과) if isinstance(키, slice) else 결과

    def __setitem__(self, 키, 값):
        self._자료[키] = 값

    def __delitem__(self, 키):
        del self._자료[키]

대상 = 점수표([10, 20, 30, 40])
print(대상[-1])              # 출력: 40
print(list(대상[1:3]))        # 출력: [20, 30]
print(type(대상[1:3]).__name__)  # 출력: 점수표
대상[0] = 99
대상[1:3] = [7, 8]
del 대상[-1]
print(list(대상))            # 출력: [99, 7, 8]
print(len(대상))             # 출력: 3
```

이 예제는 실제 저장을 리스트에 위임하므로 음수 인덱스·슬라이스·범위 오류도 리스트의 규칙을 따릅니다. 슬라이스 조회는 새 점수표를 만들지만 내부 원소까지 깊게 복사하는 설계는 아닙니다.

| 상황 | 일반적인 예외·계약 |
| --- | --- |
| 시퀀스의 범위 밖 인덱스 | `IndexError` |
| 매핑에서 없는 키 | `KeyError` |
| 허용하지 않는 키 타입 | `TypeError` |
| 컨테이너의 `__iter__` | 원소를 제공하는 반복자 반환 |
| 반복자의 `__iter__` | 보통 자기 자신 반환 |
| 반복자의 `__next__` | 다음 원소 또는 `StopIteration` |

시퀀스를 완성할 때는 `collections.abc.Sequence`·`MutableSequence`, 매핑에는 `Mapping`·`MutableMapping`을 검토할 수 있습니다. 각 추상 규약이 요구하는 최소 메서드와 제공하는 보조 메서드를 확인합니다.[^collectionsabc]

**항목 접근과 속성 접근도 다릅니다.** `대상["이름"]`은 항목 규약이고 `대상.이름`은 속성 규약입니다. 클래스 자체에 대괄호를 사용하는 타입 매개변수 표현은 `__class_getitem__` 등 별도 경로와 연결됩니다.[^datamodel]

### 18.5. 산술·반사·제자리 연산과 `NotImplemented`

이항 연산에는 왼쪽 메서드와 오른쪽의 반사 메서드가 참여할 수 있습니다. 지원하지 않는 상대 타입에는 `NotImplemented`를 반환하여 다른 연산 경로를 시도하도록 알립니다.[^datamodel]

```python
class 점수:
    def __init__(self, 값):
        self.값 = 값

    def __add__(self, 다른값):
        if type(다른값) is not int:
            return NotImplemented
        return 점수(self.값 + 다른값)

    def __radd__(self, 다른값):
        return self.__add__(다른값)

대상 = 점수(10)
print((대상 + 2).값)                      # 출력: 12
print((2 + 대상).값)                      # 출력: 12
print(대상.__add__("문자") is NotImplemented)  # 출력: True

try:
    대상 + "문자"
except TypeError:
    print("지원하지 않는 연산")  # 출력: 지원하지 않는 연산
```

이 예제는 정수와의 덧셈만 허용하며, 순서를 바꿔도 같은 계산을 할 수 있어 반사 메서드가 같은 구현을 사용합니다. 뺄셈·나눗셈처럼 순서가 중요한 연산은 무작정 같은 구현으로 연결하면 안 됩니다.

오른쪽 타입이 왼쪽 타입의 엄격한 하위 타입이고 다른 반사 구현을 제공하면, **오른쪽 반사 메서드가 먼저** 기회를 받을 수 있습니다. 따라서 “항상 왼쪽 메서드를 먼저 부른다”는 암기도 정확하지 않습니다.[^datamodel]

| 이름 | 의미 | 사용 방식 |
| --- | --- | --- |
| `NotImplemented` | 해당 피연산자 조합을 처리하지 않겠다는 표식 | 연산 메서드에서 반환 |
| `NotImplementedError` | 구현되지 않은 동작임을 알리는 예외 | 필요할 때 발생시킴 |
| `None` | 일반적인 값의 부재 표현 | 연산 미지원 표식을 대신하지 않음 |

`NotImplemented` 자체를 예외처럼 발생시키거나 일반적인 참·거짓 값으로 판정하지 않습니다. 필요하면 `결과 is NotImplemented`로 확인합니다.

증강 대입은 `__iadd__` 같은 메서드를 먼저 사용할 수 있습니다. 없거나 미지원이면 일반·반사 연산으로 넘어갑니다. 그 결과는 다시 대입 대상에 연결됩니다.[^datamodel]

```python
class 묶음:
    def __init__(self, 자료):
        self.자료 = list(자료)

    def __iadd__(self, 추가):
        self.자료.extend(추가)
        return self

대상 = 묶음([1])
별칭 = 대상
대상 += [2]
print(대상 is 별칭)  # 출력: True
print(별칭.자료)     # 출력: [1, 2]
```

`__iadd__`는 반드시 같은 객체를 반환해야 하는 것은 아닙니다. 다른 객체를 반환하면 대입 대상은 그 새 결과로 연결됩니다. 위 예제에서는 제자리 변경을 의도하므로 `self`를 반환했습니다.

### 18.6. 비교·해시·정렬 가능한 객체의 계약

동등성은 객체의 의미가 같은지, 동일성은 같은 객체인지를 묻습니다. `__eq__`는 동등성을 정의하지만 `is`의 의미를 바꾸지 못합니다. 순서 비교와 해시는 각각 별도의 계약입니다.[^datamodel]

```python
class 회원:
    def __init__(self, 번호):
        self.번호 = 번호

    def __eq__(self, 다른회원):
        if type(다른회원) is not type(self):
            return NotImplemented
        return self.번호 == 다른회원.번호

첫째 = 회원(1)
둘째 = 회원(1)
print(첫째 == 둘째)  # 출력: True
print(첫째 is 둘째)  # 출력: False

try:
    hash(첫째)
except TypeError:
    print("동등성만 정의하여 해시 불가능")
    # 출력: 동등성만 정의하여 해시 불가능
```

클래스가 `__eq__`를 새로 정의하고 적절한 `__hash__`를 별도로 두지 않으면, 파이썬은 기본적으로 해시 불가능한 것으로 처리합니다. 필드 기반 동등성을 쓰면서 정체성 기반 해시를 그대로 사용하면 계약을 깨뜨릴 수 있기 때문입니다.[^datamodel]

| 반드시 구별할 명제 | 판단 |
| --- | --- |
| 같은 것으로 비교되는 두 해시 가능 객체는 해시값도 같아야 함 | 맞음 |
| 해시값이 같으면 반드시 같은 값의 객체임 | 틀림, 충돌 가능 |
| 객체가 존재하는 동안 해시값은 안정적으로 유지되어야 함 | 맞음 |
| 값 기반 해시의 재료가 바뀌어도 사전 키로 안전함 | 틀림 |
| 모든 변경 가능한 객체는 해시 불가능함 | 틀림, 정체성 기반 사용자 객체 등 구별 |

양쪽 동등성 메서드가 모두 미지원을 반환하면 `==`는 동일성으로, `!=`는 그 반대로 최종 판정합니다. 반면 적절한 순서 비교 구현이 없으면 `<` 같은 연산은 오류가 납니다.[^datamodel]

```python
from functools import total_ordering

@total_ordering
class 등급:
    def __init__(self, 점수):
        self.점수 = 점수

    def __eq__(self, 다른등급):
        if type(다른등급) is not type(self):
            return NotImplemented
        return self.점수 == 다른등급.점수

    def __lt__(self, 다른등급):
        if type(다른등급) is not type(self):
            return NotImplemented
        return self.점수 < 다른등급.점수

print(등급(80) <= 등급(90))  # 출력: True
print([대상.점수 for 대상 in sorted([등급(90), 등급(70)])])
# 출력: [70, 90]
```

`total_ordering`은 동등성과 하나 이상의 순서 메서드를 바탕으로 나머지 순서 연산을 보완합니다. 정렬 한 번만 필요하면 `sorted(자료, key=...)`가 클래스 전체의 순서 의미를 정의하는 것보다 단순할 수 있습니다.[^functools]

비교의 반사 짝은 `<`와 `>`, `<=`와 `>=`입니다. `__rlt__`라는 이름으로 정의하는 방식이 아닙니다. 한 순서 메서드를 작성했다고 다른 모든 비교가 저절로 같은 논리로 완성되는 것도 아닙니다.[^datamodel]

### 18.7. 호출 가능한 객체·수치 변환·인덱스 변환

클래스에 `__call__`을 정의하면 인스턴스를 함수처럼 호출할 수 있습니다. 함수와 달리 상태를 명시적인 속성으로 유지하는 호출 대상을 만들 수 있습니다.[^datamodel]

```python
class 누적기:
    def __init__(self):
        self.합계 = 0

    def __call__(self, 수):
        self.합계 += 수
        return self.합계

대상 = 누적기()
print(callable(대상))  # 출력: True
print(대상(3))        # 출력: 3
print(대상(4))        # 출력: 7
```

`callable`이 참이라고 모든 인자 조합의 호출이 성공한다는 뜻은 아닙니다. 호출 규약은 있어도 인자 개수나 본문의 계산 때문에 예외가 발생할 수 있습니다.[^builtins]

**정수 변환과 인덱스 사용도 다릅니다.** `__int__`는 정수로 변환하는 규약이고, `__index__`는 객체가 정수 인덱스 역할을 할 수 있음을 표현합니다.[^datamodel]

```python
class 정수변환:
    def __int__(self):
        return 2

class 위치:
    def __index__(self):
        return 2

자료 = ["첫째", "둘째", "셋째"]
print(int(정수변환()))  # 출력: 2

try:
    자료[정수변환()]
except TypeError:
    print("정수 변환만으로 인덱스가 되지는 않음")
    # 출력: 정수 변환만으로 인덱스가 되지는 않음

print(자료[위치()])     # 출력: 셋째
print(bin(위치()))      # 출력: 0b10
```

`__float__`·`__complex__`·`__bytes__`·`__round__` 등도 각 변환·연산 규약에 대응합니다. 대응 메서드는 요구되는 반환 타입을 지켜야 하며, 표면상 비슷한 변환을 하나의 규칙으로 뭉뚱그리지 않습니다.[^datamodel]

### 18.8. 암묵적인 특수 메서드 탐색과 일반 속성 조회

일반 속성 조회와 내장 문법의 특수 메서드 탐색은 다릅니다. 사용자 클래스의 특수 동작은 일반적으로 인스턴스 사전이 아니라 **그 인스턴스의 타입에 정의**해야 안정적으로 적용됩니다.[^datamodel]

```python
class 상자:
    pass

대상 = 상자()
대상.__len__ = lambda: 99
print(대상.__len__())  # 출력: 99

try:
    len(대상)
except TypeError:
    print("타입에 길이 규약이 없음")
    # 출력: 타입에 길이 규약이 없음

상자.__len__ = lambda self: 3
print(len(대상))       # 출력: 3
print(대상.__len__())  # 출력: 99
```

직접 쓴 `대상.__len__()`은 일반적인 속성 조회를 거칩니다. `len(대상)`은 타입에 정의된 특수 동작을 사용하므로 결과가 다를 수 있습니다.

암묵적인 특수 메서드 탐색은 사용자 정의 `__getattribute__`도 일반적으로 우회합니다. 따라서 “모든 동작을 `__getattribute__` 하나에서 가로챌 수 있다”는 설명은 틀립니다.[^datamodel]

<blockquote class="prompt-warning">
<p>“len은 __len__을 호출한다”는 입문 설명에는 조회 경로가 생략되어 있습니다. 실제 문제에서는 메서드를 클래스에 넣었는지 인스턴스에 넣었는지까지 확인합니다.</p>
</blockquote>

<summary>18부 한 줄 요약</summary>

특수 메서드는 내장 문법에 참여하는 계약입니다. 이름만 맞추지 말고 반환 타입·대체 경로·비교와 해시의 일관성도 지킵니다.

</details>

## 19부. 속성 접근·디스크립터·메타클래스

### 19.1. 속성 조회·설정·삭제

`getattr`·`setattr`·`delattr`는 문자열로 속성 이름을 지정할 때 사용합니다. 점을 이용한 접근처럼 속성 규약을 거치므로, 항상 내부 사전을 직접 읽고 쓰는 함수라고 생각하면 안 됩니다.[^builtins]

```python
class 설정:
    pass

대상 = 설정()
setattr(대상, "지역", "광주")
print(getattr(대상, "지역"))          # 출력: 광주
print(getattr(대상, "언어", "한국어"))  # 출력: 한국어
print(hasattr(대상, "지역"))         # 출력: True
delattr(대상, "지역")
print(hasattr(대상, "지역"))         # 출력: False
```

| 도구 | 역할 | 주의 |
| --- | --- | --- |
| `getattr(대상, 이름)` | 속성 조회 | 속성이 없으면 보통 `AttributeError` |
| `getattr(대상, 이름, 기본값)` | 조회 실패 시 기본값 사용 | 모든 종류의 예외를 없애지는 않음 |
| `setattr(대상, 이름, 값)` | 속성 설정 | 설정 규약·검증이 실행될 수 있음 |
| `delattr(대상, 이름)` | 속성 삭제 | 삭제 규약이 실행될 수 있음 |
| `hasattr(대상, 이름)` | 조회가 `AttributeError` 없이 성공하는지 확인 | 실제 조회이므로 부작용 가능 |
| `vars(대상)` | 해당 객체의 `__dict__`를 구함 | 없는 객체에서는 사용할 수 없음 |
| `dir(대상)` | 탐색에 유용한 이름 목록 제공 | 모든 동적 속성의 완전한 목록은 아님 |

`hasattr`는 단순히 사전에 키가 있는지만 보는 검사가 아닙니다. 속성 계산 중 발생한 `AttributeError`도 속성이 없다는 결과로 보일 수 있습니다. 다른 예외는 일반적으로 전파됩니다.[^builtins]

### 19.2. `__getattribute__`와 `__getattr__`

`__getattribute__`는 일반 속성 조회의 기본 진입점입니다. `__getattr__`는 그 조회가 `AttributeError`로 실패했을 때 점 접근이나 `getattr` 경로에서 사용하는 보완 동작입니다.[^datamodel][^descriptor]

```python
기록 = []

class 설정:
    def __init__(self):
        self.이름 = "가람"

    def __getattribute__(self, 이름):
        기록.append(이름)
        return object.__getattribute__(self, 이름)

    def __getattr__(self, 이름):
        if 이름 == "별칭":
            return "기본 별칭"
        raise AttributeError(이름)

대상 = 설정()
print(대상.이름)                       # 출력: 가람
print(대상.별칭)                       # 출력: 기본 별칭
print(getattr(대상, "주소", "없음"))    # 출력: 없음
print(기록)                           # 출력: ['이름', '별칭', '주소']
```

| 구분 | `__getattribute__` | `__getattr__` |
| --- | --- | --- |
| 실행 조건 | 일반 속성 조회 | 앞의 조회가 `AttributeError`로 실패 |
| 주된 목적 | 전체 조회 정책 변경·관찰 | 동적 속성 제공·선택적 위임 |
| 위험 | 잘못 조회하면 무한 재귀 | 오타까지 정상 속성처럼 숨길 수 있음 |
| 기본 동작 보존 | 기본 구현으로 위임 | 모르는 이름에는 `AttributeError` |

`__getattribute__` 내부에서 `self.어떤속성`을 무심코 읽으면 다시 같은 메서드로 들어갈 수 있습니다. `object.__getattribute__(self, 이름)` 또는 적절한 `super().__getattribute__(이름)`로 기본 조회를 이어갑니다.

`object.__getattribute__`를 직접 호출한 것은 점 접근의 전체 처리와 같지 않습니다. 직접 호출이 실패했다고 `__getattr__`가 그 내부에서 자동 실행되지는 않습니다. 또한 내장 문법의 특수 메서드 탐색은 이 일반 조회를 우회할 수 있습니다.[^descriptor][^datamodel]

`__setattr__`·`__delattr__`를 재정의할 때도 같은 재귀 문제를 주의합니다. 저장이 필요한 경우 기본 구현으로 적절히 위임해야 합니다.[^datamodel]

### 19.3. 디스크립터 규약: 조회·설정·삭제

**디스크립터**는 클래스 속성으로 배치되어 다른 인스턴스의 속성 접근을 관리하는 객체입니다. 그 타입에 `__get__`·`__set__`·`__delete__` 중 하나 이상을 정의합니다. 검증이나 계산을 여러 속성에 재사용할 수 있습니다.[^descriptor]

```python
class 점수항목:
    def __set_name__(self, 소유클래스, 이름):
        self.저장이름 = "_" + 이름

    def __get__(self, 대상, 소유클래스=None):
        if 대상 is None:
            return self
        return getattr(대상, self.저장이름)

    def __set__(self, 대상, 값):
        if type(값) is not int:
            raise TypeError("점수는 정수여야 합니다.")
        if not 0 <= 값 <= 100:
            raise ValueError("점수는 영부터 백 사이여야 합니다.")
        setattr(대상, self.저장이름, 값)

    def __delete__(self, 대상):
        delattr(대상, self.저장이름)

class 성적:
    점수 = 점수항목()

첫째 = 성적()
둘째 = 성적()
첫째.점수 = 80
둘째.점수 = 90
print(첫째.점수, 둘째.점수)     # 출력: 80 90
print(성적.점수.저장이름)       # 출력: _점수

try:
    첫째.점수 = 120
except ValueError:
    print("범위 검증 실패")    # 출력: 범위 검증 실패

del 첫째.점수
print(hasattr(첫째, "점수"))   # 출력: False
```

| 구성 | 이 예제의 의미 |
| --- | --- |
| `성적.점수` | 클래스에 공유된 디스크립터 객체 |
| 디스크립터의 `self` | 점수 규약을 관리하는 객체 |
| 디스크립터의 `대상` | 실제 성적 인스턴스 |
| `첫째._점수` | 첫째 인스턴스의 저장 값 |
| `__set_name__` | 자신이 어떤 이름으로 배치되었는지 통지받음 |

규약 객체는 공유되지만 실제 값은 각 대상 인스턴스에 저장했습니다. 디스크립터의 `self.값`에 모든 사용자 값을 저장하면 인스턴스끼리 값이 섞일 수 있습니다.

클래스에서 조회할 때는 `대상` 인자로 `None`이 전달되는 일반 경로가 있습니다. 위 예제는 그때 디스크립터 자신을 반환합니다. 이 반환 정책은 구현자가 정한 것이며 모든 디스크립터에 강제되는 결과는 아닙니다.[^descriptor]

인스턴스 사전에 디스크립터 객체를 넣기만 하면 자동 속성 관리가 활성화되지는 않습니다. **그 규약 객체가 어느 위치에서 발견되는지**가 중요합니다.

### 19.4. 데이터·비데이터 디스크립터와 우선순위

설정이나 삭제 규약을 제공하면 데이터 디스크립터로 분류합니다. 조회 규약만 제공하는 디스크립터는 비데이터 디스크립터입니다. 일반 함수는 비데이터 디스크립터이며, `property`는 데이터 디스크립터입니다.[^descriptor]

기본 인스턴스 조회는 먼저 클래스의 탐색 순서에서 **해당 이름의 첫 후보**를 찾고 그 후보의 종류를 검사합니다. 그다음 다음 우선순위를 적용합니다.

| 우선순위 | 후보 | 설명 |
| --- | --- | --- |
| 1 | 읽기 규약이 있는 데이터 디스크립터 | 인스턴스 사전의 같은 이름보다 우선 |
| 2 | 인스턴스 사전의 속성 | 일반 메서드나 클래스 속성을 가릴 수 있음 |
| 3 | 비데이터 디스크립터 | 인스턴스에 같은 이름이 없으면 조회 규약 실행 |
| 4 | 일반 클래스 속성 | 찾은 값을 사용 |
| 5 | 조회 실패 뒤의 `__getattr__` | 정의되어 있다면 보완 조회 |

이 표는 기본 `object.__getattribute__`와 일반적인 점 접근을 전제로 합니다. 읽기 메서드 없이 설정·삭제만 있는 특수 사례를 첫 번째 줄의 읽기 규칙과 동일시하지 않습니다.[^descriptor]

```python
class 데이터항목:
    def __get__(self, 대상, 소유클래스=None):
        return "규약값"

    def __set__(self, 대상, 값):
        대상._저장값 = 값

class 비데이터항목:
    def __get__(self, 대상, 소유클래스=None):
        return "계산값"

class 자료:
    첫째 = 데이터항목()
    둘째 = 비데이터항목()

대상 = 자료()
대상.__dict__["첫째"] = "직접값"
대상.__dict__["둘째"] = "직접값"
print(대상.첫째)  # 출력: 규약값
print(대상.둘째)  # 출력: 직접값
```

첫째는 데이터 디스크립터이므로 인스턴스 사전에 같은 이름을 넣어도 규약이 우선합니다. 둘째는 비데이터 디스크립터이므로 인스턴스 값이 가립니다.

**상속 전체에서 모든 데이터 디스크립터를 먼저 모으는 것은 아닙니다.** 하위 클래스가 같은 이름의 일반 속성을 먼저 제공하면 상위의 디스크립터를 가릴 수 있습니다.[^descriptor]

```python
class 상위:
    @property
    def 값(self):
        return 100

class 하위(상위):
    값 = 3

대상 = 하위()
대상.__dict__["값"] = 7
print(대상.값)  # 출력: 7
```

상위의 읽기 전용 속성이 모든 하위 정의보다 무조건 우선하는 것이 아닙니다. **탐색 순서에서 후보 선택 → 후보 종류에 따른 우선순위**로 나누어 판단합니다.

### 19.5. `property`·메서드 바인딩·`cached_property`

`property`는 속성처럼 사용하는 조회·설정·삭제 동작을 정의합니다. 공개 접근 이름은 유지하면서 내부 검증과 저장 방식을 바꿀 수 있습니다.[^builtins][^descriptor]

```python
class 점수:
    def __init__(self, 값):
        self.값 = 값

    @property
    def 값(self):
        return self._값

    @값.setter
    def 값(self, 새값):
        if type(새값) is not int:
            raise TypeError("정수가 필요합니다.")
        if not 0 <= 새값 <= 100:
            raise ValueError("점수 범위를 벗어났습니다.")
        self._값 = 새값

대상 = 점수(80)
대상.값 = 95
print(대상.값)  # 출력: 95

try:
    대상.값 = -1
except ValueError:
    print("잘못된 점수 차단")  # 출력: 잘못된 점수 차단
```

설정 메서드가 없는 읽기 전용 `property`도 데이터 디스크립터입니다. 일반적인 같은 이름 대입을 허용하는 비데이터 디스크립터로 바뀌지 않습니다. 대신 설정 시 `AttributeError`를 발생시킵니다.[^descriptor]

함수가 메서드로 연결되는 것도 디스크립터 규약입니다. 클래스에 저장된 함수의 `__get__`가 인스턴스와 함수를 연결합니다. `classmethod`는 클래스를 연결하고 `staticmethod`는 자동 연결을 막는 형태로 동작합니다.[^descriptor]

`cached_property`는 계산한 결과를 같은 이름의 인스턴스 속성으로 저장합니다. 이후에는 그 값이 조회되며, 삭제하면 다시 계산할 수 있습니다.[^functools]

```python
from functools import cached_property

class 자료:
    def __init__(self):
        self.수들 = [1, 2, 3]
        self.계산횟수 = 0

    @cached_property
    def 합계(self):
        self.계산횟수 += 1
        return sum(self.수들)

대상 = 자료()
print(대상.합계, 대상.합계, 대상.계산횟수)  # 출력: 6 6 1
대상.수들.append(4)
print(대상.합계)                         # 출력: 6
del 대상.합계
print(대상.합계, 대상.계산횟수)           # 출력: 10 2
```

| 구분 | `property` | `cached_property` |
| --- | --- | --- |
| 일반적인 조회 | 조회 함수를 실행 | 저장된 값이 있으면 그 값 사용 |
| 같은 이름의 일반 대입 | 설정 메서드가 필요 | 저장 값을 덮을 수 있음 |
| 계산 재사용 | 구현자가 따로 설계 | 인스턴스 속성으로 저장 |
| 원본 상태 변경 | 다음 조회에서 새 계산 가능 | 캐시가 자동 무효화되지는 않음 |
| 인스턴스 사전 필요 | 구현 방식에 따라 다름 | 쓰기 가능한 인스턴스 사전 필요 |

파이썬 3.13의 `cached_property`는 여러 스레드가 동시에 접근할 때 계산이 정확히 한 번이라는 보장을 제공하지 않습니다. 한 번의 계산이 중요한 경우에는 별도 동기화가 필요합니다. 위 출력 예제는 순차 실행입니다.[^functools]

### 19.6. `__dict__`·`__slots__`와 저장 구조

일반적인 사용자 인스턴스는 `__dict__`에 속성을 저장할 수 있지만, 모든 객체가 이 사전을 가지는 것은 아닙니다. `__slots__`는 슬롯 이름을 선언하여 별도 속성 저장 구조를 사용하도록 합니다.[^datamodel]

```python
class 회원:
    __slots__ = ("이름",)

    def __init__(self, 이름):
        self.이름 = 이름

대상 = 회원("가람")
대상.이름 = "나래"
print(대상.이름)                  # 출력: 나래
print(hasattr(대상, "__dict__"))  # 출력: False

try:
    대상.지역 = "광주"
except AttributeError:
    print("선언하지 않은 속성 추가 불가")
    # 출력: 선언하지 않은 속성 추가 불가

class 확장회원(회원):
    pass

확장 = 확장회원("다온")
확장.지역 = "광주"
print(hasattr(확장, "__dict__"))  # 출력: True
print(확장.지역)                  # 출력: 광주
```

슬롯의 이름이 고정되어도 그 슬롯에 저장한 값은 변경할 수 있습니다. 슬롯은 객체를 불변으로 만드는 문법이 아닙니다.

| 상황 | 결과·설계 포인트 |
| --- | --- |
| 슬롯만 있고 사전이 없는 인스턴스 | 임의의 새 속성 추가 제한 |
| 슬롯에 `__dict__` 포함 | 동적 속성 저장도 허용 |
| 슬롯에 `__weakref__` 포함 | 필요한 경우 약한 참조 지원 |
| 상위에서 이미 사전을 제공 | 하위의 슬롯으로 그 사전을 없애지 못함 |
| 하위가 슬롯을 선언하지 않음 | 보통 사전이 다시 생김 |
| 하위가 `__slots__ = ()` 선언 | 새 슬롯·사전을 추가하지 않는 의도 |
| 여러 부모가 비어 있지 않은 슬롯 저장 구조 제공 | 다중 상속 제약·충돌 가능 |

슬롯은 클래스 수준의 디스크립터로 구현됩니다. 같은 이름의 클래스 기본값을 동시에 선언하거나 상위 슬롯을 중복 선언하는 방식은 피합니다. 저장·상속 규칙을 확인해야 합니다.[^datamodel]

클래스의 `__dict__`는 보통 읽기 전용 프록시입니다. 이것은 **클래스 자체가 불변**이라는 뜻이 아닙니다. 일반적인 사용자 클래스에서는 `클래스.속성 = 값`으로 클래스 속성을 설정할 수 있습니다.[^datamodel]

슬롯은 인스턴스가 매우 많을 때 메모리를 줄일 가능성이 있지만, 절감 폭은 구현·속성 개수·상속 구조 등에 따라 다릅니다. 일반 객체에도 무조건 적용하기보다 실제 사용량과 호환성을 확인합니다.

### 19.7. 클래스 생성 절차와 메타클래스

**메타클래스**는 클래스 객체의 타입입니다. 일반적인 인스턴스를 클래스가 만들듯, 클래스 객체는 보통 `type` 또는 그 하위 메타클래스가 만듭니다.[^datamodel][^metaclass]

```python
간단형 = type("간단형", (), {"값": 7})
대상 = 간단형()

print(대상.값)                    # 출력: 7
print(type(대상) is 간단형)       # 출력: True
print(type(간단형) is type)       # 출력: True
print(isinstance(간단형, type))   # 출력: True
```

`type(대상)`은 타입을 조회하고, 세 인자를 받는 `type(이름, 기반클래스들, 이름공간)`은 클래스를 만드는 용도로 사용할 수 있습니다. 복잡한 클래스 생성에서는 기반 클래스 해석 등 클래스 정의문이 수행하는 추가 단계도 구별합니다.[^builtins][^datamodel]

| 단계 | 기본 클래스 생성 과정 |
| --- | --- |
| 1 | 기반 클래스 후보를 해석 |
| 2 | 호환되는 메타클래스를 선택 |
| 3 | `__prepare__` 등으로 클래스 이름 공간 준비 |
| 4 | 클래스 본문 실행 |
| 5 | 메타클래스를 호출하여 클래스 객체 구성 |
| 6 | 클래스 데코레이터 적용 |
| 7 | 최종 결과를 클래스 이름에 연결 |

다음 예제는 **클래스를 만드는 과정**과 **그 클래스로 인스턴스를 만드는 과정**을 구별합니다.[^metaclass][^datamodel]

```python
기록 = []

class 구성기(type):
    @classmethod
    def __prepare__(메타클래스, 이름, 기반, **추가):
        기록.append("이름 공간 준비")
        return {}

    def __new__(메타클래스, 이름, 기반, 이름공간, **추가):
        기록.append("클래스 생성")
        return super().__new__(메타클래스, 이름, 기반, 이름공간, **추가)

    def __init__(cls, 이름, 기반, 이름공간, **추가):
        기록.append("클래스 초기화")
        super().__init__(이름, 기반, 이름공간, **추가)

    def __call__(cls, *인자, **키워드):
        기록.append("인스턴스 호출")
        return super().__call__(*인자, **키워드)

class 대상(metaclass=구성기):
    기록.append("클래스 본문")

    def __new__(cls):
        기록.append("인스턴스 생성")
        return super().__new__(cls)

    def __init__(self):
        기록.append("인스턴스 초기화")

print(기록)
# 출력: ['이름 공간 준비', '클래스 본문', '클래스 생성', '클래스 초기화']
기록.clear()
인스턴스 = 대상()
print(기록)
# 출력: ['인스턴스 호출', '인스턴스 생성', '인스턴스 초기화']
```

같은 `__new__`·`__init__`라는 이름이라도 메타클래스에 정의했는지 일반 클래스에 정의했는지에 따라 구성하는 대상이 다릅니다. 메타클래스의 `__call__`을 재정의하면 일반 인스턴스 구성 경로도 바꿀 수 있습니다.

메타클래스에서 이름 공간을 복사·수정할 때는 `__classcell__` 같은 내부 연결 정보를 임의로 제거하지 않습니다. 인자 없는 `super()` 등의 정상 동작에 필요한 정보가 전달되어야 합니다.[^datamodel]

### 19.8. 클래스 데코레이터·생성 훅·메타클래스 선택

클래스 생성에 개입하려고 항상 메타클래스부터 만들 필요는 없습니다. 한 클래스의 후처리에는 클래스 데코레이터, 하위 클래스 등록에는 `__init_subclass__`, 속성 이름 통지에는 `__set_name__`을 검토합니다.[^hooks]

```python
등록부 = {}

def 설명추가(클래스):
    클래스.설명 = "등록된 처리기"
    return 클래스

class 처리기:
    def __init_subclass__(cls, *, 식별자=None, **추가):
        super().__init_subclass__(**추가)
        if 식별자 is not None:
            등록부[식별자] = cls

@설명추가
class 문자처리기(처리기, 식별자="문자"):
    pass

print(등록부["문자"] is 문자처리기)  # 출력: True
print(문자처리기.설명)              # 출력: 등록된 처리기
```

`__init_subclass__`는 하위 클래스가 정의될 때 사용되며 그 하위 클래스가 `cls`로 전달됩니다. 인스턴스를 만들 때마다 호출하는 초기화 메서드가 아닙니다. 일반 메서드 형태로 정의해도 이 규약은 자동으로 클래스 메서드처럼 처리합니다.[^hooks][^datamodel]

| 도구 | 개입하는 대상·시점 | 적합한 예 |
| --- | --- | --- |
| 클래스 데코레이터 | 생성된 특정 클래스 | 속성 추가·등록·검증·교체 |
| `__init_subclass__` | 새로운 하위 클래스 | 구현 등록·하위 정의의 조건 확인 |
| `__set_name__` | 클래스에 배치된 이름 있는 객체 | 저장 이름·표시 이름 확보 |
| 메타클래스 | 이름 공간 준비·클래스 구성·클래스 동작 | 더 넓은 생성 정책·프레임워크 |

기본 `type.__new__` 경로에서는 클래스 객체를 만든 뒤, 이름 공간의 `__set_name__` 통지를 처리하고, 탐색 순서의 바로 다음 기반 클래스에서 `__init_subclass__`를 호출합니다. 여러 기반 클래스의 훅을 모두 이어가려면 협력적인 `super` 연결이 필요합니다.[^datamodel]

```text
이름 공간 준비
→ 클래스 본문 실행
→ 메타클래스의 클래스 생성
  → 기본 클래스 생성 내부에서 이름 통지
  → 하위 클래스 초기화 훅
→ 메타클래스의 클래스 초기화
→ 클래스 데코레이터 적용
→ 최종 이름 바인딩
```

`__set_name__`는 디스크립터에만 한정된 전용 메서드는 아닙니다. 이 훅을 제공하는 클래스 속성 객체가 통지를 받을 수 있습니다. 클래스 생성 후 `클래스.항목 = 규약객체`로 추가하면 자동 통지가 없으므로 필요한 경우 `규약객체.__set_name__(클래스, "항목")`를 직접 호출합니다.[^hooks]

클래스 데코레이터가 다른 객체를 반환하면 최종 클래스 이름은 그 반환값에 연결됩니다. 이때 생성 훅이 먼저 관찰했던 원래 클래스와 최종 이름의 대상이 달라질 수 있습니다.[^compound][^datamodel]

여러 기반 클래스가 서로 다른 메타클래스를 사용하면 메타클래스 충돌이 발생할 수 있습니다. 일반적인 클래스형 메타클래스 선택에서는 모든 후보의 하위 타입이 되는 호환 후보가 필요합니다. 단순한 등록 기능이면 생성 훅을 사용하여 이런 결합을 줄일 수 있습니다.[^datamodel][^hooks]

<blockquote class="prompt-info">
<p>설계할 때는 일반 함수·합성·클래스 데코레이터·생성 훅으로 충분한지 먼저 봅니다. 메타클래스를 이해하는 것과 모든 문제에 메타클래스를 사용하는 것은 다릅니다.</p>

## 잘 놓치는 핵심

### 1. 클래스 본문 실행과 인스턴스 초기화는 다릅니다

클래스 본문은 정의문을 실행할 때, 일반적인 인스턴스 초기화는 클래스를 호출하여 인스턴스를 구성할 때 일어납니다. 클래스 안의 메서드 정의와 그 메서드 본문 실행도 나눕니다.[^classes]

### 2. 인스턴스로 조회했다고 인스턴스에 저장된 값은 아닙니다

클래스 리스트를 조회한 뒤 내부를 변경하면 다른 객체에서도 보일 수 있습니다. 일반 속성의 재대입과 공유 객체의 변경을 구별합니다. 데이터 디스크립터가 있으면 대입 경로도 달라집니다.[^classes][^descriptor]

### 3. `super`는 탐색의 다음을 뜻합니다

메서드를 정의한 클래스와 실제 대상의 탐색 순서를 함께 확인합니다. 다음 메서드를 호출하지 않으면 뒤에 있는 클래스들의 동작이 자동으로 실행되지는 않습니다.[^builtins][^mro]

### 4. 데이터 클래스가 검증과 깊은 불변성을 대신하지 않습니다

타입 주석은 자동 검증이 아닙니다. 동결 옵션은 내부 리스트까지 얼리지 않습니다. 해시 메서드가 생성되어도 참여 필드가 해시 불가능하면 실패합니다.[^dataclasses][^typing]

### 5. 동등성과 해시는 함께 설계합니다

같은 것으로 비교되는 해시 가능 객체는 같은 해시값을 가져야 합니다. 값 기반 해시의 재료를 변경하지 않습니다. 해시 충돌은 동등성의 증거가 아닙니다.[^datamodel]

### 6. 속성 이름이 같아도 조회 규칙이 다를 수 있습니다

일반 메서드는 인스턴스 속성으로 가릴 수 있지만, 읽기 규약이 있는 데이터 디스크립터는 인스턴스 사전보다 먼저 처리됩니다. 먼저 탐색 순서의 후보를 정한다는 조건도 기억합니다.[^descriptor]

### 7. `len(대상)`과 `대상.__len__()`은 동일한 조회가 아닙니다

암묵적 특수 메서드 호출은 타입의 규약을 사용합니다. 인스턴스에 함수 하나를 넣었다고 내장 문법의 동작이 바뀌지는 않습니다.[^datamodel]

### 8. 속성 제어와 보안·불변성을 혼동하지 않습니다

밑줄은 접근 관례이고, 슬롯은 저장 구조이며, 읽기 전용 속성은 접근 규약입니다. 각각이 이름만으로 완전한 정보 은닉이나 재귀적 불변성을 제공하는 것은 아닙니다.[^classes][^datamodel][^descriptor]

## 예시로 한 바퀴: 성적 명부 만들기

다음 예제는 값 검증을 가진 성적 객체와, 여러 성적을 다루는 읽기 중심 컨테이너를 분리합니다. 데이터 클래스·합성·시퀀스 규약·클래스 메서드·계산 속성을 함께 사용합니다.

```python
from collections.abc import Sequence
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class 성적:
    이름: str
    점수: int

    def __post_init__(self):
        if not isinstance(self.이름, str) or not self.이름.strip():
            raise ValueError("이름이 필요합니다.")
        if type(self.점수) is not int:
            raise TypeError("점수는 정수여야 합니다.")
        if not 0 <= self.점수 <= 100:
            raise ValueError("점수 범위를 확인하세요.")

class 성적부(Sequence):
    def __init__(self, 자료):
        self._자료 = tuple(자료)
        if not all(isinstance(항목, 성적) for 항목 in self._자료):
            raise TypeError("성적 객체만 저장합니다.")

    @classmethod
    def 행에서(cls, 행들):
        return cls(성적(이름, 점수) for 이름, 점수 in 행들)

    def __len__(self):
        return len(self._자료)

    def __getitem__(self, 키):
        결과 = self._자료[키]
        return type(self)(결과) if isinstance(키, slice) else 결과

    @property
    def 평균(self):
        if not self._자료:
            return 0.0
        return sum(항목.점수 for 항목 in self._자료) / len(self._자료)

명부 = 성적부.행에서([("가람", 80), ("나래", 90), ("다온", 70)])
print(명부[0].이름)                      # 출력: 가람
print([항목.이름 for 항목 in 명부[1:]])   # 출력: ['나래', '다온']
print(len(명부), 명부.평균)               # 출력: 3 80.0
print([항목.이름 for 항목 in sorted(명부, key=lambda 항목: 항목.점수, reverse=True)])
# 출력: ['나래', '가람', '다온']
print(성적부([]).평균)                   # 출력: 0.0

try:
    성적("잘못된 입력", 120)
except ValueError:
    print("생성 단계에서 범위 오류 확인")
    # 출력: 생성 단계에서 범위 오류 확인
```

| 구성 | 사용한 개념 | 이 예제의 판단 |
| --- | --- | --- |
| `성적` | 데이터 클래스 | 이름과 점수를 함께 다룸 |
| `__post_init__` | 생성 후 검증 | 타입 주석과 실제 검증을 분리 |
| `frozen=True` | 일반 필드 재대입 제한 | 필드는 문자열·정수로 구성 |
| `성적부._자료` | 합성 | 성적부가 여러 성적을 보유 |
| `Sequence` | 추상 컨테이너 규약 | 길이·항목 조회를 구현하고 반복 보조를 활용 |
| `행에서` | 클래스 메서드 | 다른 입력 형태에서 객체를 구성 |
| `평균` | 계산 속성 | 조회할 때 결과를 계산 |
| `sorted`의 기준 함수 | 함수형 정렬 | 성적 객체 전체에 순서 비교를 강요하지 않음 |

시퀀스가 제공하는 보조 동작과 데이터 클래스의 생성 규칙은 공식 규약에 따릅니다.[^collectionsabc][^dataclasses]

빈 명부의 평균을 `0.0`으로 반환한 것은 **이 예제에서 정한 처리 정책**입니다. 수학적으로 빈 자료의 평균이 영이라는 의미는 아닙니다. 실제 서비스라면 값 없음이나 예외를 사용하는 정책도 검토합니다.

이 클래스는 공개 항목 변경 메서드를 제공하지 않는 읽기 중심 설계입니다. 내부 속성까지 악의적 변경으로부터 완전히 보호하는 보안·불변 장치를 구현한 것은 아닙니다.

## 객관식 문제

각 문제는 네 선택지 중 하나가 정답입니다. 코드의 클래스는 다른 문제와 무관하게 새로 정의합니다.

### 문제 1. 클래스 속성과 공유 리스트

다음 코드의 출력으로 옳은 것은?

```python
class 기록:
    횟수 = 0
    내역 = []

첫째 = 기록()
둘째 = 기록()
```

## 정리
