`ORDER BY`는 **SELECT 조회 결과를 특정 Column 기준으로 정렬하는 절**입니다.

오름차순과 내림차순을 지정할 수 있고, 여러 Column을 순서대로 정렬 기준으로 사용할 수도 있습니다.

## 가장 먼저 기본 구조

ORDER BY의 기본 형태는 다음과 같습니다.

```sql
SELECT Column
FROM Table
ORDER BY Column;
```

예를 들어 급여가 낮은 직원부터 조회합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
ORDER BY SALARY;
```

기본 정렬은 오름차순입니다.

```text
작은 값
↓
큰 값
```

<mark>ORDER BY는 조회 결과의 Row 순서를 바꾸는 절입니다.</mark>

## ASC · 오름차순

`ASC`는 Ascending의 의미로 오름차순입니다.

숫자는 작은 값부터 큰 값 순서로 정렬됩니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
ORDER BY SALARY ASC;
```

예를 들면 다음과 같습니다.

```text
2890
2980
3070
3160
3250
```

`ASC`는 기본값이므로 생략할 수 있습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
ORDER BY SALARY;
```

위 두 SQL은 같은 정렬 방향입니다.

## DESC · 내림차순

`DESC`는 Descending의 의미로 내림차순입니다.

숫자는 큰 값부터 작은 값 순서로 정렬됩니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
ORDER BY SALARY DESC;
```

예를 들면 다음과 같습니다.

```text
3250
3160
3070
2980
2890
```

정리하면 다음과 같습니다.

```text
ASC
→ 오름차순

DESC
→ 내림차순
```




## 여러 Column으로 정렬

ORDER BY에는 여러 Column을 지정할 수 있습니다.

```sql
SELECT EMP_NAME, DEPT_ID, SALARY
FROM EMPLOYEE
ORDER BY DEPT_ID ASC, SALARY DESC;
```

정렬 기준은 왼쪽부터 적용합니다.

```text
1순위
→ DEPT_ID ASC

2순위
→ SALARY DESC
```

즉 먼저 부서 번호로 정렬하고, 같은 부서 안에서는 급여가 높은 순서로 정렬합니다.

<mark>여러 정렬 기준에서는 왼쪽 Column이 우선순위가 더 높습니다.</mark>


## SELECT에 없는 Column과 Alias로 정렬

DBMS와 쿼리 형태에 따라 SELECT에 표시하지 않은 Column을 ORDER BY에 사용할 수 있는 경우가 있습니다.

```sql
SELECT EMP_NAME
FROM EMPLOYEE
ORDER BY SALARY DESC;
```

Alias도 정렬 기준으로 사용할 수 있는 경우가 많습니다.

```sql
SELECT
    EMP_NAME,
    SALARY AS PAY
FROM EMPLOYEE
ORDER BY PAY DESC;
```

다만 DISTINCT 등과 함께 사용할 때는 DBMS별 제한을 확인해야 합니다.


## WHERE와 ORDER BY

WHERE로 Row를 먼저 고른 뒤 결과를 정렬할 수 있습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY >= 3000
ORDER BY SALARY DESC;
```

논리적으로 다음처럼 이해할 수 있습니다.

```text
FROM
→ EMPLOYEE 선택

WHERE
→ SALARY >= 3000인 Row 선택

SELECT
→ 결과 Column 결정

ORDER BY
→ 결과 정렬
```

## DISTINCT와 ORDER BY

DISTINCT로 중복을 제거한 결과도 정렬할 수 있습니다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE
ORDER BY DEPT_ID ASC;
```

핵심 역할은 다릅니다.

```text
DISTINCT
→ 중복 제거

ORDER BY
→ 정렬
```

DISTINCT 자체는 정렬을 보장하지 않습니다.

정렬된 결과가 필요하면 ORDER BY를 명시합니다.

## ORDER BY를 쓰지 않으면

ORDER BY가 없는 SELECT 결과의 Row 순서는 보장된다고 생각하면 안 됩니다.

```sql
SELECT EMP_NAME
FROM EMPLOYEE;
```

현재 우연히 특정 순서로 보이더라도 항상 같은 순서가 유지된다고 기대하면 안 됩니다.

정해진 순서가 필요하다면 ORDER BY를 사용합니다.

<blockquote class="prompt-warning">
<p>조회 결과의 순서가 중요하다면 ORDER BY를 명시해야 합니다.</p>
</blockquote>

## NULL과 정렬

정렬 대상 Column에 NULL이 있을 수 있습니다.

NULL이 앞에 오는지 뒤에 오는지는 DBMS와 정렬 방향, 지원 문법에 따라 차이가 있을 수 있습니다.

따라서 NULL의 정확한 위치가 중요하다면 사용하는 DBMS의 정렬 규칙을 확인해야 합니다.

핵심은 다음과 같습니다.

```text
NULL 정렬 위치
→ DBMS별 차이 가능
```

## 작성 순서와 논리적 처리

작성은 다음과 같습니다.

```text
SELECT
FROM
WHERE
ORDER BY
```

논리적으로는 다음처럼 이해하면 쉽습니다.

```text
FROM → 대상 Table
WHERE → Row 필터링
SELECT → 결과 생성
DISTINCT → 중복 제거
ORDER BY → 결과 정렬
```

## 잘 놓치는 핵심

### 1. ORDER BY는 정렬이다

```text
ORDER BY
→ 조회 결과 순서 지정
```

### 2. 기본값은 ASC다

```sql
ORDER BY SALARY;
```

는 기본적으로

```sql
ORDER BY SALARY ASC;
```

와 같은 방향입니다.

### 3. DESC는 내림차순이다

```text
큰 값
↓
작은 값
```

### 4. 여러 Column에서는 왼쪽부터 적용한다

```sql
ORDER BY DEPT_ID ASC, SALARY DESC;
```

`DEPT_ID`가 1순위입니다.

### 5. DISTINCT와 역할이 다르다

```text
DISTINCT → 중복 제거
ORDER BY → 정렬
```

### 6. 정렬이 필요하면 ORDER BY를 명시한다

ORDER BY가 없는 결과 순서를 믿으면 안 됩니다.

## 시험·면접

### 핵심 암기

```text
ORDER BY
= 조회 결과 정렬
```

### 방향

```text
ASC
→ 오름차순
→ 기본값

DESC
→ 내림차순
```

### 여러 Column

```sql
ORDER BY A ASC, B DESC;
```

```text
A
→ 1순위

B
→ A가 같은 경우 2순위
```

### 시험 함정 1

ASC는 생략할 수 있습니다.

```sql
ORDER BY SALARY;
```

는 기본적으로 오름차순입니다.

### 시험 함정 2

DISTINCT는 자동 정렬 기능이 아닙니다.

### 시험 함정 3

여러 Column 정렬에서는 왼쪽에 적은 기준이 먼저 적용됩니다.

### 면접에서 짧게 답한다면

ORDER BY는 SELECT 조회 결과를 특정 Column 기준으로 정렬하는 절입니다.

ASC는 오름차순이고 기본값이며, DESC는 내림차순입니다. 여러 Column을 지정하면 왼쪽부터 우선순위에 따라 정렬합니다.
