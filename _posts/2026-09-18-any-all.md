복잡한 SQL도 괄호 안쪽 결과부터 작게 나누어 보면 이해하기 쉽습니다.

## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > ALL (
    SELECT SALARY
    FROM EMPLOYEE
    WHERE DEPT_ID = 20
);
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>ANY는 하나 이상 만족하면 되고 ALL은 모든 값에 대해 조건을 만족해야 합니다.</mark>

### 규칙 1. ANY는 서브쿼리 결과 중 하나 이상과 비교 조건을 만족하면 참이다.

이 문장은 `ANY · ALL` 문제를 풀 때 핵심 기준입니다.

```text
질문 1 → Subquery 또는 집합 결과가 무엇인가
질문 2 → 바깥 Query가 그 결과를 어떻게 사용하는가
질문 3 → Row 수와 Column 수가 연산자에 맞는가
질문 4 → NULL과 중복은 결과에 어떤 영향을 주는가
```

문법을 바로 계산하기보다 안쪽 결과를 작은 표로 먼저 적으면 실수가 줄어듭니다.

## ANY의 의미

다음 집합과 비교한다고 해봅시다.

```text
10
20
30
```

`25 > ANY (...)`는 적어도 하나의 값보다 크면 됩니다.

25는 10보다 크므로 참입니다.

```text
ANY
→ 하나라도 만족하면 참
```

## ALL의 의미

같은 집합에서 `25 > ALL (...)`을 봅니다.

25는 30보다 크지 않습니다.

따라서 거짓입니다.

```text
ALL
→ 모든 값에 대해 만족해야 참
```

## > ANY 해석

다음 집합이 있다고 해봅시다.

```text
100
200
300
```

`X > ANY`는 적어도 하나보다 크면 됩니다.

NULL이 없고 집합이 비어 있지 않다는 단순 조건에서는 최소값보다 큰지와 연결해서 생각할 수 있습니다.

하지만 NULL과 빈 집합이 있으면 단순 MIN 치환과 의미가 달라질 수 있으므로 주의합니다.

## > ALL 해석

`X > ALL`은 모든 값보다 커야 합니다.

NULL이 없고 집합이 비어 있지 않은 단순 조건에서는 최대값보다 큰지와 연결해 생각할 수 있습니다.

```text
X > ALL(values)
→ X가 모든 값보다 큼
```

시험에서는 가장 큰 값과 비교하는 사고가 빠릅니다.

## = ANY와 IN

다음 두 표현은 표준 SQL 의미에서 유사합니다.

```sql
X = ANY (subquery)
```

```sql
X IN (subquery)
```

둘 다 후보 중 하나와 같은지를 확인합니다.

다만 실제 지원 문법과 NULL 처리 세부는 DBMS를 확인합니다.

## < ALL과 최대·최소

`X < ALL(values)`는 모든 값보다 작아야 합니다.

단순한 숫자 집합에서는 최소값보다 작은지 생각하면 쉽습니다.

```text
X < ALL
→ X가 가장 작은 기준보다도 작아야 함
```

## 빈 집합

표준 SQL의 논리에서 비교할 대상이 하나도 없을 때 ANY와 ALL은 다르게 해석될 수 있습니다.

```text
ANY
→ 만족시키는 값이 하나도 없으므로 거짓

ALL
→ 위반하는 값이 하나도 없으므로 참
```

DBMS 문법 지원과 실제 동작은 확인해야 합니다.

## SQLite 주의

현재 실습 DB가 SQLite라면 일반적인 다음 문법은 사용할 수 없습니다.

```sql
SALARY > ALL (SELECT ...)
```

SQLite에서는 MAX, MIN, EXISTS, NOT EXISTS 등을 이용해 목적에 맞게 다시 작성할 수 있습니다.

예를 들어 모든 급여보다 큰지를 단순한 NULL 없는 집합에서 확인한다면 MAX를 이용한 비교를 생각할 수 있습니다.

```sql
SALARY > (
    SELECT MAX(SALARY)
    FROM EMPLOYEE
    WHERE DEPT_ID = 20
)
```

단, 빈 집합과 NULL까지 포함한 표준 ALL의 의미와 완전히 동일하다고 단정하면 안 됩니다.

## 시험·면접

### 핵심 암기

```text
ANY = 하나 이상 / ALL = 모두
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

``> ALL`은 일반적으로 모든 값보다 큰지를 확인한다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

ANY와 ALL은 여러 Row를 반환하는 서브쿼리 결과와 비교 연산자를 결합할 때 사용하는 표준 SQL 연산자입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > ALL (
    SELECT SALARY
    FROM EMPLOYEE
    WHERE DEPT_ID = 20
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.

```text
1. 안쪽 SELECT 또는 첫 번째 SELECT 결과를 적는다.
2. Row 수와 Column 수를 확인한다.
3. NULL이 포함되는지 본다.
4. 중복을 유지하는지 제거하는지 본다.
5. 바깥 연산자 또는 집합 연산을 적용한다.
```

이번 연습의 핵심 문장은 다음입니다.

```text
ANY는 서브쿼리 결과 중 하나 이상과 비교 조건을 만족하면 참이다.
```

이 과정을 반복하면 긴 SQL도 작은 결과 집합 여러 개로 나누어 읽을 수 있습니다.

객관식에서는 실제 값을 두세 개만 넣어도 `항상`, `모두`, `하나 이상`, `존재` 같은 표현의 차이를 빠르게 확인할 수 있습니다.
