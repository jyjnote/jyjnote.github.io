## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

## 한 값이라는 의미

Scalar는 하나의 값을 의미합니다.

```text
3000
'서울'
2026-09-18
```

따라서 Scalar Subquery도 바깥 Query가 하나의 값으로 사용할 수 있는 결과를 만드는 것이 핵심입니다.

```sql
SELECT AVG(SALARY)
FROM EMPLOYEE;
```

AVG 결과는 한 값이므로 Scalar Subquery에 자연스럽습니다.

## WHERE에서 비교

평균 급여보다 높은 직원을 찾습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

바깥 Query 입장에서는 괄호 부분이 하나의 숫자처럼 사용됩니다.

## SELECT 절에서 사용

각 직원 옆에 전체 평균을 표시할 수 있습니다.

```sql
SELECT
    EMP_NAME,
    SALARY,
    (SELECT AVG(SALARY) FROM EMPLOYEE) AS AVG_SALARY
FROM EMPLOYEE;
```

서브쿼리 결과 한 값이 각 결과 Row에 붙습니다.

## 집계 함수와 조합

다음 집계 함수들은 보통 한 Row를 반환하므로 Scalar Subquery에서 자주 보입니다.

- COUNT
- SUM
- AVG
- MIN
- MAX

예를 들어 최고 급여와 같은 직원을 찾습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY = (
    SELECT MAX(SALARY)
    FROM EMPLOYEE
);
```

## 0 Row 결과

조건에 맞는 Row가 하나도 없으면 Scalar Subquery가 NULL로 해석되는 DBMS가 많습니다.

예를 들어 존재하지 않는 부서에서 한 값을 찾는 경우입니다.

```sql
SELECT (
    SELECT DEPT_NAME
    FROM DEPARTMENT
    WHERE DEPT_ID = 999
);
```

실제 반환 규칙은 DBMS를 확인해야 합니다.

## 여러 Row 반환 주의

Scalar Subquery는 하나의 값을 기대합니다.

```sql
SELECT DEPT_NAME
FROM DEPARTMENT;
```

이 Query가 여러 Row를 반환한다면 Scalar 자리에 쓰는 것은 위험합니다.

일부 DBMS는 오류를 내고, SQLite는 Scalar Subquery에서 첫 번째 Row를 사용할 수 있습니다.

따라서 일반적인 SQL 작성에서는 한 Row가 보장되도록 조건이나 집계를 설계하는 것이 안전합니다.

## SQLite에서의 주의

현재 실습 DB가 SQLite라면 Scalar Subquery의 세부 동작을 따로 기억할 필요가 있습니다.

SQLite에서는 여러 Row가 나온 Scalar Subquery에서 첫 번째 Row를 사용할 수 있습니다.

하지만 다른 DBMS에서는 오류가 날 수 있으므로 이 동작에 의존하는 SQL은 이식성이 낮습니다.

## Scalar와 Multi-row 비교

| 구분 | Scalar Subquery | Multi-row Subquery |
| --- | --- | --- |
| 대표 결과 | 한 값 | 여러 Row |
| 대표 연산자 | =, >, < | IN, EXISTS, ANY, ALL |
| 핵심 | 단일 값 비교 | 집합과 비교 |

먼저 결과 Row 수를 예상하면 연산자 선택이 쉬워집니다.

## 시험·면접

### 핵심 암기

```text
Scalar Subquery = 한 값처럼 사용하는 Subquery
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

`여러 Row가 반환될 때의 동작은 DBMS마다 차이가 있으므로 한 값이 되도록 설계한다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

Scalar Subquery(스칼라 서브쿼리)는 하나의 값처럼 사용되는 서브쿼리입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
