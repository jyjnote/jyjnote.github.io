Correlated Subquery(상관 서브쿼리)는 안쪽 Query가 바깥 Query의 Column을 참조하는 서브쿼리입니다.

복잡한 SQL도 괄호 안쪽 결과부터 작게 나누어 보면 이해하기 쉽습니다.

## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT E.EMP_NAME, E.SALARY
FROM EMPLOYEE E
WHERE E.SALARY > (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEE E2
    WHERE E2.DEPT_ID = E.DEPT_ID
);
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>상관 서브쿼리는 바깥 Query의 현재 Row 값을 안쪽 Query가 사용합니다.</mark>

### 규칙 1. 안쪽 Query가 바깥 Query의 별칭이나 Column을 참조한다.

```text
질문 1 → Subquery 또는 집합 결과가 무엇인가
질문 2 → 바깥 Query가 그 결과를 어떻게 사용하는가
질문 3 → Row 수와 Column 수가 연산자에 맞는가
```

## 바깥 Row를 참조한다

다음 부분이 핵심입니다.

```sql
WHERE E2.DEPT_ID = E.DEPT_ID
```

`E2`는 안쪽 Query의 EMPLOYEE입니다.

`E`는 바깥 Query의 EMPLOYEE입니다.

안쪽 Query가 바깥의 `E.DEPT_ID`를 사용하므로 상관 관계가 생깁니다.

## 부서 평균보다 높은 직원

각 직원마다 자신의 부서 평균과 비교합니다.

```sql
SELECT E.EMP_NAME, E.SALARY
FROM EMPLOYEE E
WHERE E.SALARY > (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEE E2
    WHERE E2.DEPT_ID = E.DEPT_ID
);
```

직원마다 `E.DEPT_ID`가 달라질 수 있으므로 비교 기준도 달라집니다.

## 논리적 실행 흐름

개념적으로 다음처럼 이해합니다.

```text
1. 바깥 Row 하나 선택
2. 그 Row의 값을 Subquery에 전달
3. Subquery 결과 계산
4. 바깥 조건 판단
5. 다음 바깥 Row
```

실제 DBMS는 최적화를 통해 다르게 실행할 수 있지만 학습 단계에서는 이 흐름이 직관적입니다.

## EXISTS와 결합

주문이 있는 고객을 찾습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

안쪽 Query가 바깥 `C.CUSTOMER_ID`를 참조합니다.

## NOT EXISTS와 결합

주문이 없는 고객을 찾습니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE NOT EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

각 고객마다 대응 주문의 존재 여부를 확인합니다.

## 독립 Subquery와 비교

독립 서브쿼리는 바깥 값을 사용하지 않습니다.

```sql
SELECT AVG(SALARY)
FROM EMPLOYEE;
```

상관 서브쿼리는 바깥 값을 사용합니다.

```sql
WHERE E2.DEPT_ID = E.DEPT_ID
```

이 차이가 가장 중요합니다.

## JOIN으로 바꾸기

일부 상관 서브쿼리는 JOIN이나 GROUP BY로 다시 작성할 수 있습니다.

하지만 무조건 JOIN이 빠르다고 단정할 수는 없습니다.

DBMS 최적화, Index, 데이터 크기에 따라 달라지므로 실행 계획을 봐야 합니다.

## 별칭의 중요성

같은 Table을 바깥과 안쪽에서 동시에 사용할 수 있으므로 별칭이 매우 중요합니다.

```text
E
→ 바깥 직원

E2
→ 비교 대상 직원
```

별칭을 명확히 쓰면 어떤 Query의 Column인지 쉽게 구분할 수 있습니다.

## 시험·면접

### 핵심 암기

```text
Correlated Subquery = Subquery가 Outer Query의 Column을 참조
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

`독립 서브쿼리와 달리 안쪽 Query만 떼어 실행하기 어려운 경우가 많다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

Correlated Subquery(상관 서브쿼리)는 안쪽 Query가 바깥 Query의 Column을 참조하는 서브쿼리입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT E.EMP_NAME, E.SALARY
FROM EMPLOYEE E
WHERE E.SALARY > (
    SELECT AVG(E2.SALARY)
    FROM EMPLOYEE E2
    WHERE E2.DEPT_ID = E.DEPT_ID
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
