## 핵심 예시

직원 데이터를 보고 싶다면 다음처럼 작성합니다.

```sql
SELECT *
FROM EMPLOYEE;
```

의미는 단순합니다.

```text
SELECT
→ 무엇을 볼 것인가

FROM EMPLOYEE
→ 어느 Table에서 가져올 것인가
```

<mark>SQL은 사람이 원하는 데이터 작업을 DBMS에 전달하는 명령 언어입니다.</mark>

## 왜 SQL이 필요한가

SQL은 데이터 조회·추가·수정·삭제뿐 아니라 Table 생성, 권한 설정, Transaction 제어까지 일정한 문법으로 표현하게 해줍니다.

## SQL과 DBMS의 관계

SQL은 명령 언어이고, DBMS는 SQL을 해석해 Database 작업을 수행하는 소프트웨어입니다.

```text
사용자 → SQL → DBMS → Database
```

## SQL의 큰 분류

SQL은 역할에 따라 다음처럼 구분합니다.

| 구분 | 역할 | 대표 명령 |
| --- | --- | --- |
| DDL | 구조 정의 | CREATE, ALTER, DROP |
| DML | 데이터 조작 | SELECT, INSERT, UPDATE, DELETE |
| DCL | 권한 제어 | GRANT, REVOKE |
| TCL | Transaction 제어 | COMMIT, ROLLBACK |

교재에 따라 `SELECT`를 DQL로 별도 분류하기도 합니다.

## DDL

DDL은 Data Definition Language입니다.

데이터베이스의 구조를 정의하거나 변경합니다.

```text
CREATE
ALTER
DROP
```

예를 들어 Table을 만듭니다.

```sql
CREATE TABLE TEST(
    ID INTEGER PRIMARY KEY,
    NAME TEXT
);
```

DDL은 실제 Row보다 Schema를 다루는 데 초점이 있습니다.

## DML

DML은 Data Manipulation Language입니다.

Table의 데이터를 조회하거나 변경합니다.

```text
SELECT
INSERT
UPDATE
DELETE
```

직원을 조회합니다.

```sql
SELECT *
FROM EMPLOYEE;
```

데이터를 추가할 수도 있습니다.

```sql
INSERT INTO EMPLOYEE(
    EMP_ID,
    EMP_NAME,
    DEPT_ID
)
VALUES (
    1051,
    '직원51',
    10
);
```

## DCL

DCL은 사용자 권한을 제어합니다.

```text
GRANT → 권한 부여
REVOKE → 권한 회수
```

## TCL

TCL은 Transaction의 결과를 제어합니다.

```text
COMMIT → 작업 확정
ROLLBACK → 작업 취소
```

## SELECT 기본 구조

SELECT의 기본 형태는 다음과 같습니다.

```sql
SELECT Column
FROM Table;
```

직원 이름만 조회합니다.

```sql
SELECT EMP_NAME
FROM EMPLOYEE;
```

여러 Column도 선택할 수 있습니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE;
```

모든 Column은 `*`로 표현합니다.

```sql
SELECT *
FROM EMPLOYEE;
```

## WHERE로 Row 선택

WHERE는 조건에 맞는 Row를 선택합니다.

```sql
SELECT EMP_ID, EMP_NAME, SALARY
FROM EMPLOYEE
WHERE DEPT_ID = 10;
```

다음처럼 기억하면 쉽습니다.

```text
FROM
→ Table 선택

SELECT
→ Column 선택

WHERE
→ Row 조건
```

## SQL은 선언형 언어다

SQL은 **처리 절차보다 원하는 결과를 표현하는 성격**이 강합니다.

예를 들어

```sql
SELECT EMP_NAME
FROM EMPLOYEE
WHERE SALARY >= 3000;
```

라고 작성합니다.

사용자는 원하는 결과를 선언합니다.

실제 검색 방법과 실행 순서는 DBMS가 실행 계획을 통해 결정합니다.

<mark>SQL에서는 어떻게 처리할지보다 무엇을 원하는지 표현하는 것이 핵심입니다.</mark>

## Table · Row · Column과 연결

| 개념 | SQL |
| --- | --- |
| Table | FROM |
| Column | SELECT |
| Row | WHERE 조건 |
| Schema | CREATE, ALTER |

```text
FROM → Table
SELECT → Column
WHERE → Row 조건
```




## DBMS마다 세부 문법은 다를 수 있다

SQL에는 공통적인 표준 문법이 있습니다.

하지만 DBMS마다 세부 기능에는 차이가 있습니다.

```text
MySQL
PostgreSQL
Oracle
SQL Server
SQLite
```

자료형, 함수, 날짜 처리, 자동 증가, 일부 제약조건 문법 등이 다를 수 있습니다.

<blockquote class="prompt-warning">
<p>SQL의 큰 원리는 공통적이지만 실제 실행 문법은 사용하는 DBMS를 함께 확인해야 합니다.</p>
</blockquote>


## 장점과 주의점

SQL은 짧은 문장으로 조회·변경·집계·정렬·Table 연결 같은 작업을 표현할 수 있습니다.

반면 같은 결과를 만드는 SQL이라도 Index, JOIN, 조건식, 데이터 양, 실행 계획에 따라 성능이 달라질 수 있습니다.

따라서 문법 이후에는 Query Optimization도 함께 공부해야 합니다.

## 잘 놓치는 핵심

### 1. SQL과 DBMS는 같은 것이 아니다

```text
SQL
→ 명령 언어

DBMS
→ SQL을 해석하고 Database를 관리하는 소프트웨어
```

### 2. SQL은 조회만 하는 언어가 아니다

구조 정의, 데이터 변경, 권한 제어, Transaction 제어까지 할 수 있습니다.

### 3. SELECT 분류는 교재마다 다를 수 있다

DML로 분류하기도 하고 DQL로 별도 구분하기도 합니다.

### 4. SQL은 선언형 성격이 강하다

사용자는 원하는 결과를 표현하고 구체적인 실행 방법은 DBMS가 결정합니다.

### 5. DBMS마다 세부 문법이 다를 수 있다

표준 SQL의 큰 틀은 비슷하지만 세부 기능에는 차이가 있습니다.

## 시험·면접

### 핵심 암기

```text
SQL
= 관계형 데이터베이스를 정의·조회·변경·제어하는 언어
```

### 큰 분류

```text
DDL
→ 구조 정의

DML
→ 데이터 조작

DCL
→ 권한 제어

TCL
→ Transaction 제어
```

### 대표 명령

```text
DDL → CREATE, ALTER, DROP
DML → SELECT, INSERT, UPDATE, DELETE
DCL → GRANT, REVOKE
TCL → COMMIT, ROLLBACK
```

### 시험 함정

다음 문장은 틀렸습니다.

```text
SQL은 데이터를 조회하는 SELECT만 의미한다.
```

SQL은 구조, 데이터, 권한, Transaction까지 다룰 수 있습니다.

### 면접에서 짧게 답한다면

SQL은 관계형 데이터베이스에서 데이터와 Schema를 정의하고 조회·추가·수정·삭제·제어하기 위한 언어입니다.

대표적으로 DDL, DML, DCL, TCL로 구분하며, 사용자가 원하는 결과를 선언하면 DBMS가 이를 해석하고 실행합니다.

## 예시로 한 바퀴

직원 이름과 급여를 조회합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE;
```

특정 부서 직원만 조회합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE DEPT_ID = 10;
```

새로운 Table 구조를 만듭니다.

```sql
CREATE TABLE TEST(
    ID INTEGER PRIMARY KEY,
    NAME TEXT
);
```

작업을 확정합니다.

```sql
COMMIT;
```

SQL 하나로 여러 종류의 데이터베이스 작업을 표현할 수 있습니다.
