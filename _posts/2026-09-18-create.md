`CREATE`는 <mark>데이터베이스 객체의 구조를 새로 만드는 DDL 명령어</mark>입니다.

가장 대표적으로 `CREATE TABLE`을 사용해 Table과 Column, 자료형, Key, 제약조건을 정의합니다.

<blockquote class="prompt-info">
<p>한 줄: CREATE는 데이터를 넣는 명령이 아니라 데이터가 저장될 구조를 만드는 명령입니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

`CREATE`는 Table 같은 데이터베이스 객체의 구조를 생성합니다.

</details>

## CREATE TABLE

`CREATE TABLE`은 새로운 Table의 Schema를 정의합니다.

### 입력 상태

아직 `DEPARTMENT` Table이 존재하지 않는다고 가정합니다.

| 객체 | 상태 |
| --- | --- |
| DEPARTMENT | 없음 |

```sql
CREATE TABLE DEPARTMENT(
    DEPT_ID INTEGER PRIMARY KEY,
    DEPT_NAME TEXT NOT NULL,
    REGION TEXT
);
```

### 결과 Table 구조

| Column | 자료형 | 제약조건 |
| --- | --- | --- |
| DEPT_ID | INTEGER | PRIMARY KEY |
| DEPT_NAME | TEXT | NOT NULL |
| REGION | TEXT | 없음 |

`CREATE TABLE`을 실행하면 Row가 자동으로 생기는 것이 아니라 데이터를 담을 구조가 만들어집니다.

## 기본 문법

```sql
CREATE TABLE Table명(
    Column명 자료형 제약조건,
    Column명 자료형 제약조건
);
```

예를 들어 직원 Table을 간단하게 만들면 다음과 같습니다.

### 입력 상태

| 객체 | 상태 |
| --- | --- |
| EMPLOYEE | 없음 |

```sql
CREATE TABLE EMPLOYEE(
    EMP_ID INTEGER PRIMARY KEY,
    EMP_NAME TEXT NOT NULL,
    DEPT_ID INTEGER,
    SALARY INTEGER
);
```

### 결과 Table 구조

| Column | 자료형 | 제약조건 |
| --- | --- | --- |
| EMP_ID | INTEGER | PRIMARY KEY |
| EMP_NAME | TEXT | NOT NULL |
| DEPT_ID | INTEGER | 없음 |
| SALARY | INTEGER | 없음 |

## CREATE와 제약조건

Table을 만들 때 Column과 함께 제약조건을 정의할 수 있습니다.

```sql
CREATE TABLE EMPLOYEE(
    EMP_ID INTEGER PRIMARY KEY,
    EMP_NAME TEXT NOT NULL,
    DEPT_ID INTEGER,
    SALARY INTEGER,
    FOREIGN KEY(DEPT_ID) REFERENCES DEPARTMENT(DEPT_ID)
);
```

### 결과 구조

| 항목 | 의미 |
| --- | --- |
| `PRIMARY KEY` | Row를 식별하는 기본 Key |
| `NOT NULL` | NULL 저장 금지 |
| `FOREIGN KEY` | 다른 Table의 Key 참조 |
| `REFERENCES` | 참조 대상 지정 |

이 예시에서 `EMPLOYEE.DEPT_ID`는 `DEPARTMENT.DEPT_ID`를 참조합니다.

## PRIMARY KEY

`PRIMARY KEY`는 각 Row를 구분하는 기본 Key입니다.

### 입력 상태

| 객체 | 상태 |
| --- | --- |
| PRODUCT | 없음 |

```sql
CREATE TABLE PRODUCT(
    PRODUCT_ID TEXT PRIMARY KEY,
    PRODUCT_NAME TEXT,
    PRICE INTEGER
);
```

### 결과 Table 구조

| Column | 자료형 | 제약조건 |
| --- | --- | --- |
| PRODUCT_ID | TEXT | PRIMARY KEY |
| PRODUCT_NAME | TEXT | 없음 |
| PRICE | INTEGER | 없음 |

`PRODUCT_ID`는 각 상품 Row를 식별하는 기준이 됩니다.

## 복합 PRIMARY KEY

두 개 이상의 Column을 묶어 하나의 Primary Key로 만들 수도 있습니다.

### 입력 상태

| 객체 | 상태 |
| --- | --- |
| ORDER_ITEM | 없음 |

```sql
CREATE TABLE ORDER_ITEM(
    ORDER_ID TEXT,
    PRODUCT_ID TEXT,
    QTY INTEGER,
    PRIMARY KEY(ORDER_ID, PRODUCT_ID)
);
```

### 결과 Table 구조

| Column | 역할 |
| --- | --- |
| ORDER_ID | 복합 Key 구성 |
| PRODUCT_ID | 복합 Key 구성 |
| QTY | 수량 |
| ORDER_ID + PRODUCT_ID | PRIMARY KEY |

즉 `ORDER_ID` 하나만이 아니라 두 Column의 조합이 Row를 식별합니다.

## CREATE VIEW와 CREATE INDEX

`CREATE`는 Table 외의 데이터베이스 객체에도 사용할 수 있습니다.

### VIEW 생성

```sql
CREATE VIEW VIP_CUSTOMER AS
SELECT *
FROM CUSTOMER
WHERE GRADE = 'VIP';
```

`VIP_CUSTOMER`라는 View가 만들어집니다.

### INDEX 생성

```sql
CREATE INDEX IDX_CUSTOMER_NAME
ON CUSTOMER(NAME);
```

`CUSTOMER.NAME`을 대상으로 Index 객체를 생성합니다.

이 글에서는 `CREATE TABLE`을 중심으로 기억하면 됩니다.

## CREATE와 INSERT 차이

두 명령은 역할이 완전히 다릅니다.

### CREATE

```sql
CREATE TABLE DEPARTMENT(
    DEPT_ID INTEGER PRIMARY KEY,
    DEPT_NAME TEXT NOT NULL
);
```

```text
구조 생성
→ Schema 정의
```

### INSERT

```sql
INSERT INTO DEPARTMENT
VALUES (10, '개발');
```

```text
실제 Row 추가
→ 데이터 변경
```

| 명령 | 역할 |
| --- | --- |
| CREATE | 구조 생성 |
| INSERT | Row 추가 |

## 잘 놓치는 핵심

### 1. CREATE는 DDL이다

```text
DDL
→ 데이터 구조 정의

CREATE
→ 구조 생성
```

### 2. CREATE TABLE만 있는 것은 아니다

`VIEW`, `INDEX` 같은 다른 객체도 생성할 수 있습니다.

### 3. CREATE는 Row를 자동으로 넣지 않는다

Table을 만든 뒤 실제 데이터가 필요하면 `INSERT`를 사용합니다.

### 4. 제약조건도 Schema의 일부다

`PRIMARY KEY`, `NOT NULL`, `FOREIGN KEY` 같은 규칙을 Table 생성 시 함께 정의할 수 있습니다.

## 시험·면접

### 핵심 암기

```text
CREATE
→ 생성
→ DDL
→ Schema 정의
```

```text
CREATE TABLE
→ Table 구조 생성
```

```text
PRIMARY KEY
→ Row 식별
```

```text
FOREIGN KEY
→ 다른 Table 참조
```

### 시험 함정

`CREATE TABLE`을 실행했다고 실제 데이터 Row까지 생성되는 것은 아닙니다.

또한 `CREATE`는 데이터를 추가하는 DML이 아니라 구조를 정의하는 DDL입니다.

### 면접 짧은 답변

`CREATE`는 Table, View, Index 같은 데이터베이스 객체를 생성하는 DDL 명령어입니다. `CREATE TABLE`에서는 Column의 이름과 자료형뿐 아니라 Primary Key, Not Null, Foreign Key 같은 제약조건도 함께 정의할 수 있습니다.

## 객관식 문제

### 문제 1 · CREATE

다음 중 `CREATE`의 역할로 가장 적절한 것은?

① 기존 Row 조회  
② 데이터베이스 객체의 구조 생성  
③ 기존 Row 수정  
④ 기존 Row 삭제

<details markdown="1">
<summary>정답</summary>

②

`CREATE`는 Table 같은 데이터베이스 객체의 구조를 생성하는 DDL입니다.

</details>

### 문제 2 · CREATE TABLE

다음 SQL을 실행한 직후에 대한 설명으로 옳은 것은?

```sql
CREATE TABLE DEPARTMENT(
    DEPT_ID INTEGER PRIMARY KEY,
    DEPT_NAME TEXT NOT NULL
);
```

① 개발 부서 Row가 자동으로 추가된다.  
② DEPARTMENT의 구조가 생성된다.  
③ 모든 기존 Table이 삭제된다.  
④ DEPT_ID 값이 자동으로 10이 된다.

<details markdown="1">
<summary>정답</summary>

②

Table의 Schema만 정의됩니다.

실제 Row를 넣으려면 별도로 `INSERT`해야 합니다.

</details>

### 문제 3 · PRIMARY KEY

다음에서 Primary Key는?

```sql
CREATE TABLE PRODUCT(
    PRODUCT_ID TEXT PRIMARY KEY,
    PRODUCT_NAME TEXT,
    PRICE INTEGER
);
```

① PRODUCT  
② PRODUCT_ID  
③ PRODUCT_NAME  
④ PRICE

<details markdown="1">
<summary>정답</summary>

②

`PRODUCT_ID`에 `PRIMARY KEY` 제약조건이 지정되어 있습니다.

</details>

### 문제 4 · 복합 Key

다음 SQL에 대한 설명으로 옳은 것은?

```sql
CREATE TABLE ORDER_ITEM(
    ORDER_ID TEXT,
    PRODUCT_ID TEXT,
    QTY INTEGER,
    PRIMARY KEY(ORDER_ID, PRODUCT_ID)
);
```

① ORDER_ID만 Primary Key다.  
② PRODUCT_ID만 Primary Key다.  
③ ORDER_ID와 PRODUCT_ID의 조합이 Primary Key다.  
④ QTY가 Primary Key다.

<details markdown="1">
<summary>정답</summary>

③

두 Column을 묶은 복합 Primary Key입니다.

</details>

### 문제 5 · CREATE와 INSERT

다음 중 올바른 연결은?

① CREATE → Row 추가  
② INSERT → Schema 생성  
③ CREATE → 구조 생성  
④ CREATE → Row 조회

<details markdown="1">
<summary>정답</summary>

③

`CREATE`는 구조를 만들고 `INSERT`는 실제 Row를 추가합니다.

</details>
