## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT EMP_NAME, DEPT_ID
FROM EMPLOYEE
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
);
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>다중 행 서브쿼리는 하나의 값이 아니라 여러 후보 값이나 Row 집합을 바깥 Query에 제공합니다.</mark>

```text
질문 1 → Subquery 또는 집합 결과가 무엇인가
질문 2 → 바깥 Query가 그 결과를 어떻게 사용하는가
질문 3 → Row 수와 Column 수가 연산자에 맞는가
```

## 여러 Row라는 의미

서브쿼리 결과가 다음과 같다고 해봅시다.

```text
10
20
50
```

이 결과는 하나의 숫자가 아니라 세 개의 후보 값 집합입니다.

따라서 바깥 Query도 집합과 비교할 수 있는 연산자를 사용해야 합니다.

## IN과 다중 행

서울에 있는 부서의 직원을 찾습니다.

```sql
SELECT EMP_NAME, DEPT_ID
FROM EMPLOYEE
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
);
```

안쪽 Query가 여러 부서 번호를 반환해도 IN이 각 값을 후보로 처리합니다.

## 단일 값 연산자 주의

다음처럼 서브쿼리가 여러 값을 반환할 수 있는데 `=`를 사용하면 일반적인 SQL에서는 문제가 됩니다.

```sql
WHERE DEPT_ID = (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
)
```

여러 Row 가능성이 있다면 IN 같은 다중 행 연산자를 검토합니다.

## EXISTS와 다중 행

EXISTS는 서브쿼리 결과의 실제 값보다 Row가 하나라도 있는지를 봅니다.

```sql
SELECT C.CUSTOMER_ID, C.NAME
FROM CUSTOMER C
WHERE EXISTS (
    SELECT 1
    FROM ORDERS O
    WHERE O.CUSTOMER_ID = C.CUSTOMER_ID
);
```

주문이 하나 이상 있는 고객을 찾습니다.

## ANY와 ALL

표준 SQL에서는 비교 연산자와 ANY, ALL을 결합할 수 있습니다.

```text
> ANY
→ 하나라도 기준보다 작으면 참이 될 수 있음

> ALL
→ 모든 기준보다 커야 참
```

DBMS 지원 여부를 확인해야 하며 SQLite는 일반적인 `> ANY (subquery)` 문법을 지원하지 않습니다.

## Multi-column 결과

서브쿼리가 여러 Column을 반환할 수도 있습니다.

```sql
SELECT DEPT_ID, SALARY
FROM EMPLOYEE;
```

이 경우 바깥 Query에서도 두 값을 하나의 Row 값으로 비교하는 문법이 필요할 수 있습니다.

지원 문법은 DBMS마다 차이가 있으므로 시험에서는 문제에서 제시한 문법을 따릅니다.

## 중복 결과

IN에서 서브쿼리 결과에 같은 값이 여러 번 있어도 포함 여부 판단 자체는 같습니다.

```text
10
10
20
```

`DEPT_ID IN (...)`에서는 10이 한 번 있든 여러 번 있든 10은 후보 값입니다.

다만 실제 서브쿼리 계산 비용과 다른 연산에서는 중복이 영향을 줄 수 있습니다.

## NULL 주의

다중 행 서브쿼리에서 NULL은 특히 `NOT IN`과 결합할 때 주의해야 합니다.

```text
NOT IN
+
서브쿼리 결과에 NULL
→ UNKNOWN 영향
```

미존재 여부를 찾는 문제에서는 NOT EXISTS가 더 안전한 경우가 많습니다.

## 시험·면접

### 핵심 암기

```text
Multi-row Subquery = 여러 Row를 반환하는 Subquery
```

### 시험 접근 순서

```text
1. 안쪽 Query 결과 확인
2. Row 수 확인
3. Column 수 확인
4. 연산자 의미 확인
5. NULL 확인
6. 중복 처리 확인
7. 바깥 Query 결과 판단
```

### 시험 함정

`NOT IN은 서브쿼리에 NULL이 있으면 결과가 예상과 달라질 수 있다.`와 관련된 문장은 특히 조건을 정확히 확인해야 합니다.

### 면접에서 짧게 답한다면

Multi-row Subquery(다중 행 서브쿼리)는 여러 Row를 반환하는 서브쿼리입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT EMP_NAME, DEPT_ID
FROM EMPLOYEE
WHERE DEPT_ID IN (
    SELECT DEPT_ID
    FROM DEPARTMENT
    WHERE REGION = '서울'
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
