문장을 **형태소 단위로 나누고 품사나 문법 기능을 분석하는 과정**입니다.  
한국어처럼 조사와 어미 변화가 많은 언어에서 특히 중요합니다.
<blockquote class="prompt-info">
  <p>Morphological Analysis = 문장을 의미나 문법 기능을 가진 최소 단위로 분석하는 과정입니다.</p>
</blockquote>

```text
나는 사과를 먹었다
→ 나 / 는 / 사과 / 를 / 먹 / 었 / 다
```
<mark>형태소 분석은 단순히 공백으로 자르는 것이 아니라, 단어 내부의 문법 구조까지 나눕니다.</mark>
<details>
<summary>한 줄로</summary>
한국어의 조사, 어미, 어간 등을 분리해서 문장 구조를 더 세밀하게 보는 작업입니다.
</details>

## 형태소란
형태소는 **의미나 문법 기능을 가지는 최소 단위**입니다.
```text
먹었다
→ 먹 / 었 / 다
```
- `먹`: 먹다의 의미
- `었`: 과거
- `다`: 종결
각 조각이 의미나 문법 기능을 가집니다.

## Tokenization과의 차이
Tokenization은 텍스트를 **처리 단위 Token으로 나누는 큰 개념**입니다.
```text
Tokenization
├─ 공백 기준
├─ 문자 기준
├─ Subword 기준
└─ 형태소 기준
```
형태소 분석은 언어학적 구조를 분석하고, 그 결과를 Token으로 사용할 수 있습니다.
<blockquote class="prompt-warning">
  <p>형태소 분석과 Tokenization은 같은 말이 아닙니다. 형태소 분석 결과를 Tokenization에 사용할 수 있는 관계입니다.</p>
</blockquote>

## 왜 한국어에서 중요한가
다음 표현을 보겠습니다.
```text
나는
나를
나도
나에게
```
공백 기준으로는 전부 다른 Token입니다.
형태소 분석:
```text
나 / 는
나 / 를
나 / 도
나 / 에게
```
공통된 `나`를 찾을 수 있습니다.
<mark>한국어는 조사와 어미가 단어에 붙기 때문에 공백만으로는 형태 구조를 충분히 반영하기 어렵습니다.</mark>

## 자립 형태소와 의존 형태소
**자립 형태소**는 혼자서 하나의 단어처럼 쓸 수 있습니다.
```text
나
사과
학교
사람
```
**의존 형태소**는 다른 형태소에 붙어야 합니다.
```text
는
를
었
다
```
예:
```text
나는
→ 나 + 는
```
`나`는 자립 형태소, `는`은 의존 형태소입니다.

## 실질 형태소와 형식 형태소
**실질 형태소**는 실제 의미를 전달합니다.
```text
사과
먹
학교
빠르
```
**형식 형태소**는 주로 문법 기능을 담당합니다.
```text
은
는
이
가
을
를
었
다
```
```text
사과를 먹었다
```
에서 `사과`, `먹`은 실질 의미가 크고 `를`, `었`, `다`는 문법 기능을 담당합니다.

## 어근과 접사
**어근(root)**은 단어의 중심 의미를 가집니다.
```text
먹이다
→ 먹
```
**접사(affix)**는 어근에 붙어 의미를 더합니다.
```text
풋사과
→ 풋 + 사과
```
```text
먹이다
→ 먹 + 이 + 다
```
접사는 위치에 따라 접두사와 접미사로 나눕니다.

## 어간과 어미
용언에서는 어간과 어미가 중요합니다.
```text
먹었다
먹는다
먹으면
```
공통 부분인 `먹`이 **어간**입니다.
```text
먹었다
→ 먹 / 었 / 다
```
- `먹`: 어간
- `었`: 선어말어미
- `다`: 종결어미
형태소 분석기는 이런 구조를 더 세밀하게 분석합니다.

## 품사 태깅
형태소를 나누고 **품사 태그**를 붙이는 작업을 함께 수행하는 경우가 많습니다.
```text
나는 사과를 먹었다
```
예:
```text
나/대명사
는/조사
사과/명사
를/조사
먹/동사
었/어미
다/어미
```
이를 **POS Tagging**이라고 합니다.
```text
POS = Part Of Speech
```
<blockquote class="prompt-info">
  <p>형태소 분석은 형태소 분리와 품사 판별을 함께 다루는 경우가 많습니다.</p>
</blockquote>

## 같은 문자열도 분석이 달라진다
```text
나는 학교에 간다
```
의 `나는`:
```text
나 / 는
대명사 / 조사
```
```text
하늘을 나는 새
```
의 `나는`:
```text
날 / 는
동사 / 어미
```
같은 표면형이라도 문맥에 따라 분석이 달라집니다.
<blockquote class="prompt-warning">
  <p>형태소 분석은 문자열만 자르는 작업이 아닙니다. 문맥에 따라 형태소와 품사가 달라질 수 있습니다.</p>
</blockquote>

## 형태소 분석의 모호성
하나의 문자열에 여러 분석 후보가 생길 수 있습니다.
예:
```text
나는
```
문맥에 따라
```text
나 + 는
```
일 수도 있고 `날다`의 활용형일 수도 있습니다.
분석기는 가능한 후보 중 문맥에 맞는 결과를 골라야 합니다.
이 때문에 분석기마다 결과가 조금씩 달라질 수 있습니다.

## 형태소 분석기
한국어 NLP에서 많이 접하는 분석기:
```text
MeCab
Okt
Komoran
Kkma
Hannanum
```
분석기마다
- 사전
- 품사 체계
- 속도
- 신조어 처리
- 사용자 사전
- 분석 규칙
이 다를 수 있습니다.
<mark>같은 문장을 넣어도 형태소 분석기마다 결과가 완전히 같지는 않을 수 있습니다.</mark>

## 사용자 사전
전문용어나 고유명사가 사전에 없으면 잘못 쪼개질 수 있습니다.
```text
ChatGPT
LangChain
금융위원회
다우오피스
```
필요하면 사용자 사전에 등록합니다.
```text
다우오피스
→ 하나의 명사로 등록
```
도메인 NLP에서 특히 중요할 수 있습니다.

## OOV와 형태소 분석
처음 보는 단어는 형태소 분석에서도 문제입니다.
```text
초거대언어모델
```
사전에 없다면 잘못 분리될 수 있습니다.
```text
OOV = Out Of Vocabulary
```
형태소 단위로 나누면 단어 전체를 하나의 Vocabulary 항목으로 보는 것보다 OOV를 줄이는 데 도움이 될 수 있습니다.

## 형태소와 Subword
둘 다 단어를 작은 조각으로 나눌 수 있지만 기준이 다릅니다.
| 방식 | 기준 |
| --- | --- |
| 형태소 | 언어학적 의미·문법 |
| Subword | 데이터의 문자열 패턴 |
예:
```text
먹었습니다
```
형태소 분석:
```text
먹 / 었 / 습니다
```
Subword Tokenizer는
```text
먹었 / 습 / 니다
```
처럼 다르게 나눌 수도 있습니다.
<blockquote class="prompt-warning">
  <p>Subword Token은 언어학적 형태소와 반드시 일치하지 않습니다.</p>
</blockquote>

## 언제 쓰나
전통적인 한국어 NLP에서 자주 사용합니다.
- 문서 분류
- 감성 분석
- 키워드 추출
- 검색
- 빈도 분석
- TF-IDF
- 명사 추출
예를 들어
```text
나는 사과를 먹었다
```
에서 명사만 뽑으면
```text
사과
```
같은 핵심 단어를 얻을 수 있습니다.

## 항상 필요한가
아닙니다.
현대 Transformer와 LLM에서는 별도 형태소 분석 없이 Subword Tokenizer가 원문을 직접 처리하는 경우가 많습니다.
```text
Raw Text
  ↓
Subword Tokenizer
  ↓
Token ID
  ↓
Transformer
```
<blockquote class="prompt-info">
  <p>전통 한국어 NLP에서는 형태소 분석이 중요했지만, 현대 LLM에서는 Subword Tokenizer가 직접 처리하는 경우가 많습니다.</p>
</blockquote>
다만 검색, 명사 추출, 키워드 분석, 언어학적 분석에서는 여전히 유용합니다.

## Python으로 보면
개념적으로 결과를 다음처럼 표현할 수 있습니다.
```python
result = [
    ("나", "대명사"),
    ("는", "조사"),
    ("사과", "명사"),
    ("를", "조사"),
    ("먹", "동사"),
    ("었", "어미"),
    ("다", "어미")
]
```
명사만 추출:
```python
nouns = [
    word for word, pos in result
    if pos == "명사"
]
```
결과:
```text
['사과']
```
실제 품사 태그 이름은 분석기마다 다를 수 있습니다.

## 전처리 흐름
지금까지의 흐름:
```text
Corpus
  ↓
Text Normalization
  ↓
Tokenization
  ↓
Morphological Analysis
  ↓
Stopword
  ↓
Stemming · Lemmatization
```
실제 구현에서는 형태소 분석 자체가 Tokenization을 포함할 수도 있습니다.

## 잘 놓치는 핵심
### 1. 형태소 ≠ 단어
단어보다 작은 단위일 수 있습니다.
### 2. Tokenization과 완전히 같은 개념이 아님
형태소 분석 결과를 Token으로 사용할 수 있습니다.
### 3. 조사와 어미도 형태소
실질 의미가 약해도 문법 기능을 가집니다.
### 4. 같은 문자열도 문맥에 따라 분석이 다름
`나는` 같은 표현이 대표적입니다.
### 5. 분석기마다 결과가 다를 수 있음
사전과 품사 체계가 다릅니다.
### 6. Subword ≠ 형태소
Subword는 문자열 패턴, 형태소는 언어학적 단위입니다.

## 시험·면접

  <p>단골: 형태소 정의, 자립·의존 형태소, 실질·형식 형태소, 어간·어미, 품사 태깅, 형태소와 Subword 차이.</p>
</blockquote>
자주 나오는 문장:
- 형태소는 의미나 문법 기능을 가지는 최소 단위다
- 한국어는 조사와 어미 때문에 형태소 분석이 중요하다
- 형태소 분석은 품사 태깅과 함께 사용된다
- 형태소 분석 결과는 분석기마다 다를 수 있다
- Subword와 형태소는 기준이 다르다
- 현대 LLM은 별도 형태소 분석 없이 Subword Tokenizer를 쓰기도 한다

## 예시로 한 바퀴
```text
학생들이 책을 읽었다
```
공백 기준:
```text
학생들이 / 책을 / 읽었다
```
형태소 기준의 한 예:
```text
학생 / 들 / 이 / 책 / 을 / 읽 / 었 / 다
```
역할:
```text
학생 → 명사
들   → 복수 표현
이   → 조사
책   → 명사
을   → 조사
읽   → 동사 어간
었   → 과거
다   → 종결
```
형태소 분석이 공백 분리보다 더 세밀한 이유입니다.
