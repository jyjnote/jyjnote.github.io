`NULL`은 **값이 없거나 알 수 없음을 나타내는 특별한 상태**입니다.

0이나 빈 문자열과 같은 일반 값이 아니므로 비교와 연산에서 따로 주의해야 합니다.

<blockquote class="prompt-info">
<p>한 줄: NULL은 0이나 빈 문자열이 아니라 값이 없거나 알 수 없는 상태입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

NULL = 값이 없거나 아직 알 수 없는 상태입니다.

</details>

이 글에서는 `EMPLOYEE.BONUS`를 중심으로 NULL을 봅니다.

## 가장 먼저 핵심

EMPLOYEE 일부를 단순화하면 다음과 같습니다.

| EMP_ID | EMP_NAME | BONUS |
| ---: | --- | ---: |
| 1001 | 직원1 | 200 |
| 1002 | 직원2 | 300 |
| 1003 | 직원3 | 400 |
| 1004 | 직원4 | NULL |
| 1005 | 직원5 | 100 |

직원4의 BONUS가 NULL이라면 다음 뜻으로 이해할 수 있습니다.

```text
보너스가 0이다
→ 아님

빈 문자열이다
→ 아님

보너스 값이 없거나 알 수 없다
→ NULL
```

<mark>NULL은 하나의 일반 값이 아니라 값의 부재 또는 미정 상태를 나타냅니다.</mark>

## NULL과 0은 다르다

숫자 Column에서 0은 실제 숫자 값입니다.

```text
BONUS = 0
→ 보너스가 0이라는 값이 존재
```

반면 NULL은 값 자체가 없는 상태입니다.

```text
BONUS = NULL
→ 보너스 값이 없거나 알 수 없음
```

따라서 둘은 완전히 다릅니다.

| 표현 | 의미 |
| --- | --- |
| 0 | 숫자 0 |
| NULL | 값 없음 또는 알 수 없음 |

## NULL과 빈 문자열도 다르다

문자열에서도 NULL과 빈 문자열은 구분해야 합니다.

```text
''
→ 길이가 0인 문자열

NULL
→ 값 자체가 없음
```

즉 다음은 같은 의미가 아닙니다.

```text
NAME = ''
NAME = NULL
```

DBMS에 따라 문자열 처리 세부 규칙은 다를 수 있지만 개념적으로 NULL과 빈 문자열은 구분합니다.

## NULL 찾기

NULL 여부는 일반 비교 연산자 `=`로 확인하지 않습니다.

다음처럼 작성합니다.

```sql
SELECT EMP_NAME
FROM EMPLOYEE
WHERE BONUS IS NULL;
```

NULL이 아닌 Row는 다음과 같습니다.

```sql
SELECT EMP_NAME, BONUS
FROM EMPLOYEE
WHERE BONUS IS NOT NULL;
```

```text
IS NULL
→ NULL 찾기

IS NOT NULL
→ NULL이 아닌 값 찾기
```

## 왜 = NULL을 사용하지 않는가

NULL은 일반 값처럼 같고 다름을 단순하게 판단하기 어렵습니다.

예를 들어

```text
알 수 없는 값
=
알 수 없는 값
```

이라고 해도 두 값이 실제로 같은지는 알 수 없습니다.

그래서 SQL에서는 NULL 비교를 일반적인 TRUE 또는 FALSE만으로 처리하지 않습니다.

이 때문에 NULL 여부는 `IS NULL`, `IS NOT NULL`을 사용합니다.

<blockquote class="prompt-warning">
<p>NULL은 = NULL 또는 <> NULL로 검사하지 않고 IS NULL 또는 IS NOT NULL을 사용합니다.</p>
</blockquote>

## NULL과 세 값 논리

SQL 조건식은 NULL 때문에 `TRUE`, `FALSE`, `UNKNOWN`을 생각해야 합니다.

```text
NULL > 100
→ UNKNOWN
```

WHERE에서는 TRUE인 Row가 선택되므로 UNKNOWN인 Row는 일반적으로 결과에 포함되지 않습니다.

## WHERE와 NULL

다음 SQL을 봅시다.

```sql
SELECT EMP_NAME, BONUS
FROM EMPLOYEE
WHERE BONUS > 100;
```

BONUS가 200이라면

```text
200 > 100
→ TRUE
```

이므로 결과에 포함됩니다.

BONUS가 NULL이라면

```text
NULL > 100
→ UNKNOWN
```

이므로 해당 조건으로는 선택되지 않습니다.

## NULL과 산술 연산

NULL이 포함된 산술 연산은 일반적으로 결과도 NULL이 됩니다.

예를 들어

```text
100 + NULL
→ NULL
```

처럼 생각하면 됩니다.

SQL 예시는 다음과 같습니다.

```sql
SELECT SALARY, BONUS, SALARY + BONUS
FROM EMPLOYEE;
```

BONUS가 NULL인 Row에서는 `SALARY + BONUS`도 NULL이 될 수 있습니다.

즉 NULL이 계산식 안으로 들어오면 결과를 확정할 수 없기 때문입니다.


## NOT NULL

`NOT NULL`은 Column에 NULL을 저장하지 못하도록 하는 제약조건입니다.

예를 들어

```sql
EMP_NAME TEXT NOT NULL
```

이면 EMP_NAME은 NULL이 될 수 없습니다.

```text
NULL
→ 값이 없는 상태

NOT NULL
→ NULL 저장 금지 제약
```

둘은 서로 다른 개념입니다.

## Primary Key · Foreign Key와 NULL

Primary Key는 NULL을 허용하지 않습니다.

```text
Primary Key
→ NULL 불가
→ 개체 무결성과 연결
```

Foreign Key는 Schema가 허용하면 NULL일 수 있습니다.

```text
Foreign Key = NULL
→ NULL 허용 Column이면 가능

Foreign Key = 존재하지 않는 값
→ 참조 무결성 위반
```

## NULL과 NOT NULL 제약 위반

`NOT NULL`이 설정된 Column에는 NULL을 저장할 수 없습니다.

```sql
DEPT_ID INTEGER NOT NULL
```

Foreign Key가 NULL인데 이 제약이 걸려 있다면 참조 무결성보다 `NOT NULL` 제약조건 위반으로 보는 것이 정확합니다.

```text
Foreign Key = NULL + NULL 허용
→ 가능

Foreign Key = NULL + NOT NULL
→ NOT NULL 제약 위반
```




## 잘 놓치는 핵심

### 1. NULL은 0이 아니다

```text
0
→ 실제 숫자 값

NULL
→ 값 없음 또는 알 수 없음
```

### 2. NULL은 빈 문자열이 아니다

```text
''
→ 빈 문자열

NULL
→ 값 자체가 없음
```

### 3. = NULL을 사용하지 않는다

```text
IS NULL
IS NOT NULL
```

을 사용합니다.

### 4. NULL이 연산에 들어가면 결과도 NULL이 될 수 있다

```text
100 + NULL
→ NULL
```

### 5. NOT NULL은 제약조건이다

NULL 자체와 `NOT NULL` 제약조건은 다른 개념입니다.

### 6. Primary Key는 NULL 불가다

개체 무결성과 연결됩니다.

## 시험·면접

### 핵심 암기

```text
NULL
= 값이 없거나 알 수 없는 상태
```

### NULL 검색

```sql
WHERE Column IS NULL;
```

```sql
WHERE Column IS NOT NULL;
```

### 시험 함정 1

다음은 올바른 NULL 검색 방법이 아닙니다.

```sql
WHERE BONUS = NULL;
```

다음처럼 작성합니다.

```sql
WHERE BONUS IS NULL;
```

### 시험 함정 2

```text
NULL
≠ 0
≠ 빈 문자열
```

입니다.

### 시험 함정 3

Foreign Key가 NULL이고 해당 Column이 NULL을 허용한다면 참조 무결성 위반이 아닐 수 있습니다.

하지만 `NOT NULL`이 설정되어 있다면 NOT NULL 제약조건 위반입니다.

### 면접에서 짧게 답한다면

NULL은 값이 0이라는 뜻이 아니라 값이 없거나 알 수 없는 상태를 의미합니다.

일반 비교 연산자로 직접 비교하지 않고 `IS NULL`과 `IS NOT NULL`을 사용하며, NULL이 포함된 비교나 연산에서는 UNKNOWN 또는 NULL 결과가 나타날 수 있습니다.
