## BCNF 기본 조건

Relation에 다음 함수 종속이 있다고 해봅시다.

```text
X → Y
```

이 종속이 비자명하다면 BCNF에서는 X가 Super Key여야 합니다.

```text
결정자
→ 반드시 Super Key
```

## 3NF보다 강하다

BCNF는 3NF보다 더 강한 조건입니다.

```text
BCNF
→ 3NF 만족

3NF
→ 항상 BCNF인 것은 아님
```

3NF는 종속되는 Attribute가 Prime Attribute인 경우 일부 예외를 허용하지만 BCNF는 결정자가 Super Key인지에 집중합니다.

## 구체적 예시

다음 Relation을 생각합니다.

```text
수강
학생 | 과목 | 교수
```

업무 규칙을 다음처럼 가정합니다.

```text
(학생, 과목) → 교수
교수 → 과목
```

한 교수는 하나의 과목만 담당한다고 가정한 것입니다.

## Candidate Key 찾기

`(학생, 과목)`은 모든 Attribute를 결정하므로 Candidate Key가 될 수 있습니다.

또 `교수 → 과목`이 있으므로

```text
(학생, 교수)
```

도 학생과 과목과 교수를 모두 결정할 수 있어 Candidate Key가 될 수 있습니다.

즉 Prime Attribute가 여러 개 존재합니다.

## 3NF는 만족 가능

함수 종속

```text
교수 → 과목
```

에서 `교수`는 Super Key가 아닙니다.

하지만 `과목`은 Candidate Key의 일부인 Prime Attribute입니다.

따라서 정확한 3NF 조건에서는 허용될 수 있습니다.

## BCNF 위반

같은 함수 종속을 BCNF 관점에서 보면

```text
교수 → 과목
```

결정자인 `교수`가 Super Key가 아닙니다.

따라서 BCNF를 위반합니다.

## BCNF 분해

다음처럼 분해할 수 있습니다.

```text
교수과목
교수 | 과목

학생교수
학생 | 교수
```

`교수 → 과목`이라는 사실을 교수과목 Relation으로 분리합니다.

## 분해 후 확인

교수과목에서는 `교수`가 Key가 됩니다.

```text
교수 → 과목
```

결정자가 Super Key입니다.

학생교수에서는 `(학생, 교수)`가 Key가 됩니다.

## BCNF 판단 순서

다음 순서로 풉니다.

```text
1. 모든 함수 종속을 적는다.
2. 각 함수 종속의 결정자를 확인한다.
3. 결정자가 Super Key인지 확인한다.
4. Super Key가 아닌 결정자가 하나라도 있으면 BCNF 위반
5. 해당 종속을 기준으로 분해한다.
```

## 3NF와 BCNF 비교

| 구분 | 3NF | BCNF |
| --- | --- | --- |
| 조건 | 결정자가 Super Key이거나 종속자가 Prime Attribute | 결정자는 반드시 Super Key |
| 강도 | 상대적으로 약함 | 더 강함 |
| 모든 BCNF | 3NF 만족 | 해당 |
| 모든 3NF | BCNF는 아님 | 해당 안 됨 |

시험에서는 이 포함 관계가 중요합니다.

## 주의

BCNF 분해는 중복과 이상을 더 줄일 수 있지만 함수 종속 보존 여부를 함께 검토해야 합니다.

정규화는 단순히 단계 숫자를 높이는 것이 목적이 아니라 데이터 무결성과 운영 편의의 균형을 맞추는 과정입니다.

## 다른 개념과 비교

### 비교 1. 3NF

```text
3NF
→ 일부 Prime Attribute 예외 허용
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

### 비교 2. BCNF

```text
BCNF
→ 모든 결정자 Super Key
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

### 비교 3. Candidate Key

```text
Candidate Key
→ 최소 Super Key
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

## 시험·면접

### 핵심 암기

```text
BCNF = 모든 결정자는 Super Key
```

### 시험 접근 순서

```text
1. Entity 또는 Relation 확인
2. Candidate Key 확인
3. 함수 종속 확인
4. 이상 현상 확인
5. 정규형 조건 확인
6. 필요한 분해 확인
```

### 시험 함정

현재 예시 데이터에서 값이 우연히 유일하다고 해서 함수 종속이나 Key가 자동으로 성립하는 것은 아닙니다.

Schema와 업무 규칙을 기준으로 판단해야 합니다.

### 면접에서 짧게 답한다면

BCNF는 모든 비자명한 함수 종속에서 결정자가 Super Key가 되도록 요구하는 정규형입니다.

정규화와 모델링에서는 Key와 함수 종속을 기준으로 중복과 이상 현상을 줄이는 방향으로 구조를 설계합니다.

## 예시로 한 바퀴

`BCNF` 문제를 만나면 작은 Relation부터 그립니다.

```text
Key
→ 결정되는 Attribute
→ 반복되는 사실
→ 발생 가능한 이상 현상
```

그다음 어떤 Attribute가 어떤 Key에 종속되는지 화살표로 표시합니다.

마지막으로 분해가 필요하다면 **같은 사실을 한 곳에서만 관리할 수 있도록** Relation을 나눕니다.
