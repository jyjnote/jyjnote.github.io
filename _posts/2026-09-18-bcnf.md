`BCNF`는 <mark>모든 함수적 종속에서 결정자가 후보 Key가 되도록 만든 정규형</mark>입니다.

제3정규형보다 더 엄격한 조건을 적용하며, 핵심은 **결정자가 후보 Key인지 확인하는 것**입니다.

<blockquote class="prompt-info">
<p>한 줄: BCNF에서는 무언가를 결정하는 Attribute가 반드시 후보 Key여야 합니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

모든 `A → B`에서 A가 후보 Key이면 BCNF를 만족합니다.

</details>

## BCNF의 핵심

함수적 종속이 다음과 같다고 가정합니다.

```text
A → B
```

BCNF에서는 왼쪽의 `A`, 즉 결정자가 후보 Key인지 확인합니다.

```text
결정자
→ 후보 Key
```

이면 문제가 없습니다.

반대로

```text
결정자
→ 후보 Key가 아님
```

이라면 BCNF를 위반할 수 있습니다.

## 3NF보다 더 엄격하다

제3정규형은 비주요 Attribute 사이의 이행 함수 종속을 제거하는 데 초점을 둡니다.

BCNF는 한 단계 더 나아가 모든 함수적 종속의 결정자를 검사합니다.

```text
3NF
→ 이행 함수 종속 제거
```

```text
BCNF
→ 모든 결정자가 후보 Key
```

따라서

```text
BCNF 만족
→ 3NF도 만족
```

하지만

```text
3NF 만족
→ BCNF도 반드시 만족
```

하는 것은 아닙니다.

## 대표 예시

다음 수강 관계를 생각해보겠습니다.

| 학생 | 과목 | 교수 |
| --- | --- | --- |
| 학생1 | 데이터베이스 | 교수1 |
| 학생1 | 운영체제 | 교수2 |
| 학생2 | 데이터베이스 | 교수1 |

다음 업무 규칙이 있다고 가정합니다.

```text
학생 + 과목
→ 교수
```

한 학생이 특정 과목을 들으면 담당 교수가 하나로 결정됩니다.

또한 교수 한 명은 하나의 과목만 담당한다고 가정합니다.

```text
교수
→ 과목
```

## 후보 Key 찾기

다음 함수적 종속을 봅니다.

```text
학생 + 과목
→ 교수
```

따라서 `학생 + 과목`은 하나의 후보 Key가 될 수 있습니다.

또한

```text
교수
→ 과목
```

이므로 `학생 + 교수`를 알면 과목도 결정할 수 있습니다.

```text
학생 + 교수
→ 과목
```

따라서 후보 Key는 다음처럼 볼 수 있습니다.

```text
학생 + 과목
학생 + 교수
```

## BCNF 위반 찾기

이제 각 함수적 종속의 결정자를 확인합니다.

### 첫 번째

```text
학생 + 과목
→ 교수
```

`학생 + 과목`은 후보 Key입니다.

```text
결정자
→ 후보 Key
→ 문제 없음
```

### 두 번째

```text
교수
→ 과목
```

하지만 `교수` 하나만으로는 학생까지 결정할 수 없습니다.

즉, 교수는 후보 Key가 아닙니다.

```text
교수
→ 결정자

교수
→ 후보 Key 아님
```

따라서 BCNF를 위반합니다.

<blockquote class="prompt-warning">
<p>BCNF 문제에서는 함수적 종속의 오른쪽보다 먼저 왼쪽 결정자가 후보 Key인지 확인합니다.</p>
</blockquote>

## 왜 3NF는 만족할 수 있는가

다음 관계를 다시 보겠습니다.

```text
교수
→ 과목
```

여기서 `과목`은 후보 Key인 `학생 + 과목`을 구성하는 Attribute입니다.

즉, `과목`은 주요 Attribute입니다.

3NF는 일부 경우 결정자가 후보 Key가 아니더라도 종속자가 주요 Attribute라면 허용할 수 있습니다.

하지만 BCNF는 더 엄격합니다.

```text
결정자가 후보 Key가 아님
→ BCNF 위반
```

따라서 이 관계는 3NF를 만족하면서도 BCNF는 위반할 수 있습니다.

## BCNF로 분해

문제가 되는 함수적 종속은 다음입니다.

```text
교수
→ 과목
```

이를 별도 Table로 분리합니다.

### 교수 · 과목 Table

| 교수 | 과목 |
| --- | --- |
| 교수1 | 데이터베이스 |
| 교수2 | 운영체제 |

```text
교수
→ 과목
```

여기서는 교수가 후보 Key가 됩니다.

### 학생 · 교수 Table

| 학생 | 교수 |
| --- | --- |
| 학생1 | 교수1 |
| 학생1 | 교수2 |
| 학생2 | 교수1 |

학생이 어떤 교수에게 수강하는지를 저장합니다.

### 분해 결과

```text
교수 Table
→ 교수, 과목

수강 Table
→ 학생, 교수
```

이렇게 분리하면 후보 Key가 아닌 결정자로 인해 발생하던 중복을 줄일 수 있습니다.

## 변환 전과 후

### 변환 전

| 학생 | 과목 | 교수 |
| --- | --- | --- |
| 학생1 | 데이터베이스 | 교수1 |
| 학생2 | 데이터베이스 | 교수1 |
| 학생1 | 운영체제 | 교수2 |

```text
교수
→ 과목

교수는 후보 Key 아님
→ BCNF 위반
```

### 변환 후

```text
교수 Table
→ 교수, 과목

수강 Table
→ 학생, 교수
```

```text
모든 결정자
→ 후보 Key
→ BCNF
```

## 3NF와 BCNF 비교

| 구분 | 3NF | BCNF |
| --- | --- | --- |
| 핵심 | 이행 함수 종속 제거 | 모든 결정자가 후보 Key |
| 엄격함 | 상대적으로 낮음 | 더 엄격함 |
| 결정자가 후보 Key가 아닌 경우 | 일부 허용 가능 | 허용하지 않음 |
| 목적 | 중복과 이상 현상 감소 | 더 강한 함수적 종속 정리 |

```text
3NF
→ 일반적인 정규화 기준
```

```text
BCNF
→ 결정자 조건을 더 엄격하게 검사
```

## 판단 순서

BCNF 문제는 다음 순서로 보면 빠릅니다.

### 1. 함수적 종속을 모두 찾는다

```text
A → B
C → D
```

### 2. 후보 Key를 찾는다

어떤 Attribute 조합이 전체 Attribute를 결정하는지 확인합니다.

### 3. 각 결정자를 확인한다

```text
A
C
```

가 후보 Key인지 확인합니다.

### 4. 후보 Key가 아닌 결정자가 있으면 BCNF 위반

```text
결정자
→ 후보 Key 아님
→ BCNF 위반
```

## 잘 놓치는 핵심

### 1. BCNF는 결정자를 본다

```text
A → B
```

에서 핵심은 왼쪽의 `A`입니다.

### 2. 모든 후보 Key가 Primary Key일 필요는 없다

후보 Key 중 하나를 Primary Key로 선택할 뿐입니다.

BCNF에서는 Primary Key 하나만 보는 것이 아니라 모든 후보 Key를 기준으로 판단해야 합니다.

### 3. 3NF와 BCNF는 같지 않다

3NF를 만족해도 BCNF를 위반하는 경우가 있습니다.

### 4. BCNF가 더 엄격하다

```text
BCNF
→ 3NF보다 강한 조건
```

## 시험·면접

### 핵심 암기

```text
BCNF
→ 모든 결정자가 후보 Key
```

```text
A → B
→ A가 후보 Key인지 확인
```

```text
3NF 만족
→ BCNF는 아닐 수도 있음
```

```text
BCNF 만족
→ 3NF 만족
```

### 시험 함정

BCNF에서 종속자가 주요 Attribute인지 아닌지만 보면 안 됩니다.

가장 먼저 확인해야 하는 것은 **결정자가 후보 Key인지 여부**입니다.

### 면접 짧은 답변

BCNF는 모든 함수적 종속에서 결정자가 후보 Key가 되도록 하는 정규형입니다. 제3정규형보다 더 엄격하며, 3NF에서는 일부 허용될 수 있는 후보 Key가 아닌 결정자도 BCNF에서는 허용하지 않습니다. 따라서 함수적 종속의 결정자를 확인하고 후보 Key가 아니라면 관계를 분해합니다.

## 객관식 문제

### 문제 1 · 핵심

BCNF의 핵심 조건으로 옳은 것은?

① 모든 Attribute가 원자값이어야 한다.  
② 모든 결정자가 후보 Key여야 한다.  
③ 모든 Table에 Foreign Key가 있어야 한다.  
④ 모든 후보 Key를 삭제해야 한다.

<details markdown="1">
<summary>정답</summary>

②

BCNF에서는 모든 함수적 종속의 결정자가 후보 Key여야 합니다.

</details>

### 문제 2 · 판단

다음 함수적 종속이 있다고 가정합니다.

```text
교수 → 과목
```

교수가 후보 Key가 아니라면 BCNF 관점에서 어떻게 판단하는가?

① 반드시 BCNF 만족  
② BCNF 위반 가능  
③ 함수적 종속이 아님  
④ 제1정규형 위반만 발생

<details markdown="1">
<summary>정답</summary>

②

결정자인 교수가 후보 Key가 아니므로 BCNF를 위반합니다.

</details>

### 문제 3 · 3NF와 BCNF

다음 설명으로 옳은 것은?

① 3NF를 만족하면 항상 BCNF도 만족한다.  
② BCNF는 3NF보다 느슨하다.  
③ BCNF를 만족하면 3NF도 만족한다.  
④ 3NF와 BCNF는 완전히 같은 조건이다.

<details markdown="1">
<summary>정답</summary>

③

BCNF는 3NF보다 더 엄격한 조건이므로 BCNF를 만족하면 3NF도 만족합니다.

</details>

### 문제 4 · 결정자

다음 함수적 종속에서 BCNF 판단 시 먼저 확인할 것은?

```text
A → B
```

① B의 자료형  
② A가 후보 Key인지 여부  
③ B가 NULL인지 여부  
④ Table의 Row 개수

<details markdown="1">
<summary>정답</summary>

②

BCNF에서는 결정자인 A가 후보 Key인지 확인하는 것이 핵심입니다.

</details>

### 문제 5 · 분해

BCNF 위반 관계를 분해하는 주된 이유는?

① 모든 Attribute를 삭제하기 위해  
② 후보 Key가 아닌 결정자로 인한 중복과 이상 현상을 줄이기 위해  
③ Row 수를 무조건 늘리기 위해  
④ Primary Key를 없애기 위해

<details markdown="1">
<summary>정답</summary>

②

후보 Key가 아닌 결정자가 만드는 중복과 이상 현상을 줄이기 위해 관계를 분해합니다.

</details>

## BCNF 전체 요약

```text
함수적 종속
A → B
```

```text
A가 후보 Key
→ BCNF 조건 만족
```

```text
A가 후보 Key 아님
→ BCNF 위반
```

| 정규형 | 핵심 |
| --- | --- |
| 1NF | 원자값 |
| 2NF | 부분 함수 종속 제거 |
| 3NF | 이행 함수 종속 제거 |
| BCNF | 모든 결정자가 후보 Key |

<blockquote class="prompt-danger">
<p>BCNF 문제에서는 함수적 종속의 왼쪽 결정자를 하나씩 확인하고, 후보 Key가 아닌 결정자가 있는지 찾습니다.</p>
</blockquote>
