DBMS(Database Management System)는 **데이터베이스를 생성하고 조회·수정·삭제하며 전체적으로 관리하는 소프트웨어**입니다.  
사용자와 데이터베이스 사이에서 보안, 무결성, 동시성, 트랜잭션, 복구 등을 담당합니다.

<blockquote class="prompt-info">
<p>한 줄: DBMS는 사용자가 데이터베이스를 안전하고 편리하게 사용할 수 있도록 관리하는 시스템입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>
DBMS는 사용자와 데이터베이스 사이에서 데이터를 관리하는 소프트웨어입니다.
</details>
## 가장 먼저 큰 그림
사용자가 저장 장치의 데이터를 직접 찾는 것이 아닙니다.

```text
사용자
↓
SQL
↓
DBMS
↓
Database
```

예를 들어 다음 SQL을 실행합니다.

```sql
SELECT name
FROM student;
```

DBMS는 SQL을 해석하고 필요한 데이터를 찾아 결과를 반환합니다.
---
## 왜 DBMS가 필요한가
파일만으로 데이터를 관리할 수도 있습니다.

하지만 데이터가 많아지고 여러 사용자가 함께 사용하면 문제가 생깁니다.

```text
데이터 중복
데이터 불일치
동시 접근 충돌
보안 문제
무결성 문제
장애 복구 문제
```

DBMS는 이런 문제를 체계적으로 관리합니다.
### 데이터 중복
같은 정보가 여러 파일에 반복될 수 있습니다.

```text
student.xlsx
→ 1001, 김철수, 컴퓨터공학

enrollment.xlsx
→ 1001, 김철수, 컴퓨터공학
```
### 데이터 불일치
한 파일만 수정하면 값이 서로 달라질 수 있습니다.

```text
student.xlsx
→ 김철수, 인공지능학과

enrollment.xlsx
→ 김철수, 컴퓨터공학과
```
### 동시 접근
여러 사용자가 같은 데이터를 동시에 수정하면 충돌할 수 있습니다.
### 보안
사용자마다 접근 가능한 데이터가 달라야 합니다.
### 장애 복구
작업 도중 시스템이 종료되어도 데이터를 정상 상태로 복구할 수 있어야 합니다.

<mark>DBMS의 핵심은 단순 저장이 아니라 데이터를 안전하고 일관되게 관리하는 것입니다.</mark>
---
## DBMS의 핵심 기능
DBMS의 기능은 크게 세 가지로 정리할 수 있습니다.

```text
DBMS
├─ 데이터 정의
├─ 데이터 조작
└─ 데이터 제어
```
---
## 1. 데이터 정의
데이터의 구조를 정의합니다.

```sql
CREATE TABLE student (
    student_id INTEGER,
    name TEXT
);
```

대표적인 명령은 다음과 같습니다.

```text
CREATE
ALTER
DROP
```

이런 명령을 DDL(Data Definition Language)이라고 합니다.
---
## 2. 데이터 조작
저장된 데이터를 조회·삽입·수정·삭제합니다.

```text
SELECT → 조회
INSERT → 삽입
UPDATE → 수정
DELETE → 삭제
```

예를 들어 데이터를 조회합니다.

```sql
SELECT *
FROM student;
```

CRUD와 연결하면 다음과 같습니다.

```text
Create → INSERT
Read   → SELECT
Update → UPDATE
Delete → DELETE
```
---
## 3. 데이터 제어
데이터를 안전하고 일관되게 유지합니다.

```text
보안
권한 관리
무결성
동시성 제어
트랜잭션
장애 복구
```

예를 들어 특정 사용자에게 조회 권한을 줄 수 있습니다.

```sql
GRANT SELECT
ON student
TO user1;
```
---
## DBMS의 주요 관리 기능
### 저장과 검색
데이터를 저장하고 필요한 데이터를 찾아 반환합니다.
### 무결성
잘못된 데이터가 저장되지 않도록 규칙을 적용합니다.

```sql
student_id INTEGER NOT NULL
```
### 보안
사용자별로 접근 가능한 데이터와 작업을 제한합니다.
### 동시성
여러 사용자가 같은 데이터를 동시에 사용할 때 충돌을 제어합니다.
### 트랜잭션
여러 작업을 하나의 논리적인 작업 단위로 관리합니다.
### 복구
장애 발생 시 데이터를 정상 상태로 되돌릴 수 있도록 지원합니다.
---
## DBMS의 내부 구성
DBMS를 단순화하면 다음과 같이 볼 수 있습니다.

```text
DBMS
├─ Query Processor
├─ Storage Manager
├─ Transaction Manager
└─ Recovery Manager
```
### Query Processor
SQL을 해석하고 실행 방법을 결정합니다.

```text
SQL 입력
↓
구문 해석
↓
실행 방법 결정
↓
실행
```
### Storage Manager
데이터가 실제 저장 장치에 어떻게 저장되고 읽히는지 관리합니다.
### Transaction Manager
여러 작업을 하나의 논리적 작업으로 관리합니다.

```text
A 계좌 -10,000원
B 계좌 +10,000원
```

둘 중 하나만 실행되면 안 됩니다.
### Recovery Manager
장애 발생 시 로그 등을 이용해 데이터베이스를 정상 상태로 복구합니다.
---
## Database와 DBMS의 차이
| 구분 | Database | DBMS |
| --- | --- | --- |
| 의미 | 데이터의 집합 | Database를 관리하는 소프트웨어 |
| 역할 | 데이터 보관 | 저장·조회·수정·제어 |
| 예시 | 학생·강의·성적 데이터 | MySQL, PostgreSQL |

```text
Database = 관리 대상
DBMS = 관리 시스템
```
---
## DBMS와 SQL의 차이
```text
SQL = 명령을 표현하는 언어
DBMS = SQL을 처리하는 시스템
```

다음은 SQL입니다.

```sql
SELECT *
FROM student;
```

이 SQL을 해석하고 실행하는 것이 DBMS입니다.

<mark>SQL은 언어이고, DBMS는 소프트웨어입니다.</mark>
---
## DBMS와 RDBMS
RDBMS는 Relational Database Management System의 약자입니다.

**관계형 데이터베이스를 관리하는 DBMS**입니다.

```text
DBMS
└─ RDBMS
```

대표적인 RDBMS는 다음과 같습니다.

```text
MySQL
PostgreSQL
Oracle Database
Microsoft SQL Server
SQLite
```

관계형 데이터베이스에서는 데이터를 주로 테이블 형태로 관리합니다.

```text
student_id | name   | department
1001       | 김철수 | 컴퓨터공학
1002       | 이영희 | 통계학
```
---
## 데이터 독립성
데이터 독립성은 **저장 구조가 바뀌어도 응용 프로그램에 미치는 영향을 줄이는 것**입니다.

```text
응용 프로그램
↓
논리적인 데이터
↓
DBMS
↓
물리적인 저장 구조
```

사용자는 데이터가 디스크 어디에 저장되어 있는지 알 필요가 없습니다.
---
## 데이터 무결성
무결성은 데이터가 정확하고 일관된 상태를 유지하는 것입니다.

예를 들어 학번을 반드시 입력하도록 할 수 있습니다.

```sql
student_id INTEGER NOT NULL
```

중복을 허용하지 않으려면 PRIMARY KEY를 사용할 수 있습니다.

```sql
student_id INTEGER PRIMARY KEY
```
---
## 동시성 제어
여러 사용자가 같은 데이터를 동시에 변경하면 잘못된 결과가 생길 수 있습니다.

```text
잔액 = 100,000원

사용자 A → 출금
사용자 B → 출금
```

DBMS는 Lock과 트랜잭션 등을 이용해 충돌을 제어합니다.
---
## DBMS의 장점과 단점
| 구분 | 내용 |
| --- | --- |
| 장점 | 데이터 중복 감소 |
| 장점 | 데이터 일관성 향상 |
| 장점 | 여러 사용자 데이터 공유 |
| 장점 | 무결성 유지 |
| 장점 | 보안 및 권한 관리 |
| 장점 | 장애 복구 |
| 장점 | 데이터 독립성 |
| 단점 | 구조와 운영이 복잡함 |
| 단점 | 비용이 발생할 수 있음 |
| 단점 | 시스템 자원을 사용함 |
---
## 파일 시스템과 DBMS 비교
| 구분 | 파일 시스템 | DBMS |
| --- | --- | --- |
| 데이터 중복 | 발생하기 쉬움 | 줄일 수 있음 |
| 데이터 공유 | 제한적 | 여러 사용자 지원 |
| 무결성 | 직접 관리 | DBMS가 관리 |
| 보안 | 파일 권한 중심 | 세부 권한 관리 |
| 동시성 | 관리하기 어려움 | DBMS가 제어 |
| 복구 | 직접 처리 | 복구 기능 제공 |
| 데이터 독립성 | 낮음 | 상대적으로 높음 |
---
## 잘 놓치는 핵심
### 1. Database와 DBMS는 다르다
```text
Database = 데이터의 집합
DBMS = Database를 관리하는 소프트웨어
```
### 2. SQL과 DBMS도 다르다
```text
SQL = 언어
DBMS = SQL을 처리하는 시스템
```
### 3. RDBMS는 DBMS의 한 종류다
관계형 데이터베이스를 관리하는 DBMS가 RDBMS입니다.
### 4. DBMS는 저장만 담당하지 않는다
```text
저장
조회
수정
보안
무결성
동시성
트랜잭션
복구
```
### 5. 핵심 기능은 정의·조작·제어다
```text
정의 → 데이터 구조
조작 → 조회·삽입·수정·삭제
제어 → 보안·무결성·동시성·복구
```
---
## 시험·면접
### 핵심 암기
```text
Database = 데이터
DBMS = 관리 시스템
SQL = 명령 언어
```
### DBMS 핵심 기능
```text
정의
조작
제어
```
### 자주 나오는 장점
```text
데이터 중복 감소
데이터 일관성
데이터 공유
무결성
보안
복구
데이터 독립성
```
### 면접에서 짧게 답한다면
> DBMS는 사용자와 데이터베이스 사이에서 데이터의 저장·조회·수정뿐 아니라 무결성, 보안, 동시성, 트랜잭션, 복구까지 관리하는 소프트웨어입니다.
