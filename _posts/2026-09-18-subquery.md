Subquery(서브쿼리)는 하나의 SQL 문장 안에 포함된 또 다른 SELECT 문입니다.

복잡한 SQL도 괄호 안쪽 결과부터 작게 나누어 보면 이해하기 쉽습니다.

## 핵심 예시

대표 SQL은 다음과 같습니다.

```sql
SELECT EMP_ID, EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

먼저 안쪽 SELECT 또는 각 SELECT가 어떤 결과를 만드는지 확인합니다.

<mark>서브쿼리는 바깥 SQL이 사용할 값이나 Row 집합을 안쪽 SELECT가 먼저 만들어 주는 구조입니다.</mark>

### 규칙 1. 안쪽 SELECT의 결과를 바깥 Query가 사용한다.

이 문장은 `Subquery · 서브쿼리` 문제를 풀 때 핵심 기준입니다.

```text
질문 1 → Subquery 또는 집합 결과가 무엇인가
질문 2 → 바깥 Query가 그 결과를 어떻게 사용하는가
질문 3 → Row 수와 Column 수가 연산자에 맞는가
질문 4 → NULL과 중복은 결과에 어떤 영향을 주는가
```

## 서브쿼리의 기본 구조

바깥 Query와 안쪽 Query를 구분하면 쉽습니다.

```text
Outer Query
→ 최종 결과를 만든다.

Subquery
→ Outer Query가 사용할 중간 결과를 만든다.
```

다음 SQL에서는 평균 급여를 안쪽 Query가 계산합니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

논리적으로는 평균 급여를 먼저 구한 뒤 그 값보다 큰 직원만 남깁니다.

## WHERE 절의 서브쿼리

가장 자주 보는 형태입니다.

```sql
SELECT EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

안쪽 Query는 비교에 필요한 값을 제공합니다.

```text
서브쿼리 결과
→ 평균 급여 한 값

바깥 Query
→ 그 값보다 급여가 큰 직원
```

## SELECT 절의 서브쿼리

SELECT 목록에 하나의 값을 계산하는 서브쿼리를 둘 수 있습니다.

```sql
SELECT
    EMP_NAME,
    SALARY,
    (SELECT AVG(SALARY) FROM EMPLOYEE) AS AVG_SALARY
FROM EMPLOYEE;
```

각 결과 Row에 전체 평균 급여가 함께 표시될 수 있습니다.

이 위치에서는 보통 한 값으로 해석 가능한 Scalar Subquery를 사용합니다.

## FROM 절의 서브쿼리

FROM에 서브쿼리를 두면 그 결과를 임시 Table처럼 사용할 수 있습니다.

```sql
SELECT T.DEPT_ID, T.AVG_SALARY
FROM (
    SELECT DEPT_ID, AVG(SALARY) AS AVG_SALARY
    FROM EMPLOYEE
    GROUP BY DEPT_ID
) T;
```

이런 형태는 Derived Table이라고 부르기도 합니다.

FROM의 서브쿼리에는 일반적으로 별칭을 주는 것이 좋습니다.

## HAVING 절의 서브쿼리

GROUP BY 결과를 다른 집계 결과와 비교할 수도 있습니다.

```sql
SELECT DEPT_ID, AVG(SALARY) AS AVG_SALARY
FROM EMPLOYEE
GROUP BY DEPT_ID
HAVING AVG(SALARY) > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

전체 평균보다 부서 평균이 높은 부서를 찾는 형태입니다.

## 서브쿼리 반환 형태

반환 결과를 기준으로 다음처럼 나눌 수 있습니다.

| 종류 | 대표 결과 |
| --- | --- |
| Scalar Subquery | 한 Row, 한 Column |
| Multi-row Subquery | 여러 Row |
| Multi-column Subquery | 여러 Column |
| Correlated Subquery | 바깥 Query 값을 참조 |

문제에서는 먼저 서브쿼리가 무엇을 반환하는지 판단합니다.

## Subquery와 JOIN

JOIN은 Table 사이의 Row를 연결하는 데 강합니다.

서브쿼리는 비교값 계산, 존재 여부 확인, 중간 집합 생성에 자연스러운 경우가 많습니다.

```text
JOIN
→ 관계 연결

Subquery
→ Query 결과를 다른 Query가 사용
```

같은 문제를 둘 다로 풀 수 있는 경우도 있으므로 가독성과 실행 계획을 함께 봅니다.

## 중첩 서브쿼리

서브쿼리 안에 다시 서브쿼리를 넣을 수도 있습니다.

```text
Outer Query
└─ Subquery
   └─ Subquery
```

하지만 중첩이 너무 깊어지면 읽기 어려워집니다.

가능하면 각 단계의 반환값을 명확히 이해해야 합니다.

### 면접에서 짧게 답한다면

Subquery(서브쿼리)는 하나의 SQL 문장 안에 포함된 또 다른 SELECT 문입니다.

핵심은 반환 결과의 형태와 바깥 Query가 그 결과를 어떤 연산자로 사용하는지를 구분하는 것입니다.

## 예시로 한 바퀴

다음 SQL을 다시 봅니다.

```sql
SELECT EMP_ID, EMP_NAME, SALARY
FROM EMPLOYEE
WHERE SALARY > (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
);
```

먼저 괄호 안쪽 또는 먼저 실행되는 SELECT의 결과를 작은 표처럼 적습니다.

```text
Step 1
→ 안쪽 결과

Step 2
→ 바깥 조건과 비교

Step 3
→ NULL과 중복 확인

Step 4
→ 최종 Row 결정
```

이 흐름을 한 번 손으로 따라가면 비슷한 문제에서도 같은 순서를 사용할 수 있습니다.
