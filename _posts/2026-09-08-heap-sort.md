힙 정렬은 **배열을 최대 힙으로 만든 뒤, 루트의 최댓값을 뒤로 보내고 남은 구간만 다시 힙으로 만드는** 정렬입니다.  
뒤로 보낸 값은 더 이상 움직이지 않습니다.

<blockquote class="prompt-info">
  <p>제자리, 불안정. 구성 $$\Theta(n)$$ + 추출 $$n$$번 $$\times\,O(\log n)$$이라 최선·평균·최악이 모두 $$\Theta(n\log n)$$. 퀵과 달리 입력 순서에 최악이 안 갈립니다. 차트는 <code>https://jyjnote.github.io/assets/plotly/heap-sort-charts.html</code> 입니다.</p>
</blockquote>

## 한 줄 규칙

오름차순, 최대 힙을 기준으로 둡니다.

1. 배열을 최대 힙으로 만든다
2. 루트(최댓값)와 힙의 마지막 값을 교환한다
3. 힙 길이를 하나 줄인다. 방금 보낸 값은 확정이다
4. 새 루트를 자식과 비교하며 아래로 내린다
5. 힙 길이가 1이 될 때까지 2~4를 반복한다

기호:

- $$n$$: 배열 길이. 아래 예에서 $$n=5$$
- $$A[i]$$: $$i$$번 위치의 값. $$i$$는 $$0$$부터
- 루트: 인덱스 $$0$$. 최대 힙이면 여기가 최댓값
- 왼쪽 자식: 인덱스 $$2i+1$$
- 오른쪽 자식: 인덱스 $$2i+2$$
- 부모: 인덱스 $$\lfloor(i-1)/2\rfloor$$
- 힙 길이 $$h$$: 아직 확정되지 않은 앞구간 길이
- 내리기(sift-down, heapify): 노드 하나를 자식 중 더 큰 쪽과 바꿔 가며 아래로 보내는 일

이름은 자료구조 힙(heap)에서 왔습니다.  
동작의 핵심은 이름이 아니라 <mark>최대 힙 구성 + 루트를 뒤에 확정</mark>입니다.

선택 정렬도 최댓값을 뒤에 둡니다.  
차이는 최댓값을 찾는 방법입니다. 선택은 남은 구간을 선형으로 보고, 힙은 부모-자식만 봅니다.

## 배열이 곧 완전 이진 트리

같은 점수

$$
A=[80,\ 55,\ 90,\ 70,\ 60]
$$

인덱스와 값:

```
인덱스  0    1    2    3    4
값     80   55   90   70   60
```

트리로 펴면

```
        80(0)
       /     \
   55(1)     90(2)
   /   \
70(3)  60(4)
```

위치 $$1$$의 왼쪽 자식은 $$2\cdot 1+1=3$$, 오른쪽은 $$2\cdot 1+2=4$$입니다.  
위치 $$3$$의 부모는 $$\lfloor(3-1)/2\rfloor=1$$입니다.

최대 힙이면 **모든 부모 $$\ge$$ 두 자식**입니다.  
지금 $$55<70$$이라 아직 최대 힙이 아닙니다.

탭 **1**은 비교·교환 한 번마다, 탭 **2**는 구성이 끝난 뒤와 루트를 뺄 때만 봅니다.  
보라는 지금 내리는 노드, 노랑은 자식, 빨강은 방금 교환, 초록은 뒤에 확정된 값입니다.

## 1단계 — 최대 힙 구성

리프는 이미 힙입니다. 자식이 없기 때문입니다.  
마지막 부모부터 루트까지 내립니다.

마지막 부모 인덱스:

$$
\Big\lfloor\frac{n}{2}\Big\rfloor-1=\Big\lfloor\frac{5}{2}\Big\rfloor-1=1
$$

위치 $$1$$, 그다음 위치 $$0$$ 순서입니다.

### 위치 1 — 값 55

자식은 $$70$$(위치 3), $$60$$(위치 4).

| 비교 | 부모 | 자식 | 더 큰 자식 | 교환 |
| :---: | ---: | ---: | ---: | :--- |
| 1 | 55 | 70 | 70 | |
| 2 | 70 | 60 | 70 | 위치 1과 3 |

$$
[80,\ 55,\ 90,\ 70,\ 60] \rightarrow [80,\ 70,\ 90,\ 55,\ 60]
$$

```
        80
       /  \
    70      90
   /  \
 55    60
```

위치 $$3$$의 $$55$$는 자식이 없습니다. 여기서 멈춥니다.  
비교 $$2$$, 교환 $$1$$.

### 위치 0 — 값 80

자식은 $$70$$(위치 1), $$90$$(위치 2).

| 비교 | 지금 최댓값 후보 | 보는 자식 | 갱신 |
| :---: | ---: | ---: | :--- |
| 3 | 80 | 70 | 아니오 |
| 4 | 80 | 90 | 예. 후보는 90 |

위치 $$0$$과 $$2$$를 교환합니다.

$$
[80,\ 70,\ 90,\ 55,\ 60] \rightarrow [90,\ 70,\ 80,\ 55,\ 60]
$$

```
        90
       /  \
    70      80
   /  \
 55    60
```

위치 $$2$$의 $$80$$은 힙 길이 $$5$$에서 자식 인덱스가 $$5,6$$이라 범위 밖입니다. 멈춥니다.  
비교 $$2$$, 교환 $$1$$.

최대 힙 완성. 루트 $$90$$이 최댓값입니다.  
구성 합계: 비교 $$4$$, 교환 $$2$$.

구성은 아래에서 위로 올리기(sift-up) $$n$$번이 아닙니다.  
마지막 부모부터 **내리기만** 하면 전체 $$\Theta(n)$$입니다. 아래쪽 노드는 내릴 높이가 짧기 때문입니다.

## 2단계 — 루트를 뒤에 확정

힙 길이 $$h=5$$부터 $$2$$까지 줄입니다.

### 추출 1 — 90을 맨 뒤로

루트 $$90$$과 위치 $$4$$의 $$60$$을 교환합니다.

$$
[90,\ 70,\ 80,\ 55,\ 60] \rightarrow [60,\ 70,\ 80,\ 55,\ 90]
$$

힙 길이는 $$4$$. $$90$$은 확정입니다.

```
        60                 확정: 90
       /  \
    70      80
   /
 55
```

$$60$$을 내립니다. 자식 $$70,80$$ 중 $$80$$이 더 큽니다.

$$
[60,\ 70,\ 80,\ 55,\ 90] \rightarrow [80,\ 70,\ 60,\ 55,\ 90]
$$

비교 $$2$$, 교환 $$1$$(루트-끝) $$+1$$(내리기).

### 추출 2 — 80을 뒤로

루트 $$80$$과 위치 $$3$$의 $$55$$를 교환합니다.

$$
[80,\ 70,\ 60,\ 55,\ 90] \rightarrow [55,\ 70,\ 60,\ 80,\ 90]
$$

힙 길이 $$3$$.

$$55$$의 자식은 $$70,60$$. $$70$$이 더 큽니다.

$$
[55,\ 70,\ 60,\ 80,\ 90] \rightarrow [70,\ 55,\ 60,\ 80,\ 90]
$$

비교 $$2$$, 교환 $$2$$.

### 추출 3 — 70을 뒤로

루트 $$70$$과 위치 $$2$$의 $$60$$을 교환합니다.

$$
[70,\ 55,\ 60,\ 80,\ 90] \rightarrow [60,\ 55,\ 70,\ 80,\ 90]
$$

힙 길이 $$2$$. 자식은 $$55$$ 하나. $$55>60$$이 아니라 그대로입니다.

비교 $$1$$, 교환 $$1$$.

### 추출 4 — 60을 뒤로

루트 $$60$$과 위치 $$1$$의 $$55$$를 교환합니다.

$$
[60,\ 55,\ 70,\ 80,\ 90] \rightarrow [55,\ 60,\ 70,\ 80,\ 90]
$$

힙 길이 $$1$$. 내릴 자식이 없습니다.

교환 $$1$$.

전체: 비교 $$4+2+2+1=9$$회, 교환 $$2+2+2+1+1=8$$회.

같은 입력에서 퀵(로무토)은 비교 $$6$$·교환 $$4$$, 병합은 비교 $$7$$·보조 기록 $$12$$였습니다.  
힙은 비교가 조금 더 나와도, 최악이 입력에 안 묶입니다.

## 시간

구성: 높이 $$k$$인 노드 수는 약 $$n/2^{k+1}$$이고, 각자 최대 $$k$$번 내려갑니다.

$$
T_{\text{build}}(n)=\Theta(n)
$$

추출: $$n-1$$번, 매번 높이 $$\lfloor\log_2 h\rfloor$$까지 내릴 수 있습니다.

$$
T_{\text{extract}}(n)=\sum_{h=2}^{n}O(\log h)=\Theta(n\log n)
$$

합치면

$$
T(n)=\Theta(n)+\Theta(n\log n)=\Theta(n\log n)
$$

이미 정렬된 $$[55,\ 60,\ 70,\ 80,\ 90]$$으로 구성을 해도, 추출은 $$n-1$$번 일어납니다.  
최선도 $$\Theta(n\log n)$$입니다. 삽입의 $$\Theta(n)$$, 퀵 끝값 피벗의 $$\Theta(n^2)$$과 갈립니다.

$$n=1000$$이면 $$\log_2 1000\approx 10$$이라 추출 비교는 대략 $$10{,}000$$ 근처입니다.  
구성 $$\Theta(n)$$은 여기에 가려집니다.

## 공간

내리기는 인덱스와 임시 변수면 됩니다. 길이 $$n$$ 보조 배열은 없습니다.

$$
S_{\text{aux}}(n)=\Theta(1)
$$

재귀로 내리면 스택이 $$O(\log n)$$입니다. 학부 기본형은 `while`로 내려 스택도 상수입니다.  
제자리입니다. 병합의 $$\Theta(n)$$과 다른 축입니다.

## 안정성

같은 값 두 개의 **원래 순서**를 지키면 안정입니다.

$$
A=[70_a,\ 55,\ 70_b]
$$

트리:

```
     70_a
    /    \
  55      70_b
```

구성에서 루트 $$70_a$$와 오른쪽 $$70_b$$를 비교합니다.  
최대 힙은 값이 같으면 안 바꿔도 되고, 구현에 따라 오른쪽을 고르기도 합니다.  
추출에서 루트를 맨 뒤와 바꾸면 $$70_a$$가 $$70_b$$ 뒤로 갈 수 있습니다.

$$
[70_a,\ 55,\ 70_b] \rightarrow \cdots \rightarrow [55,\ 70_b,\ 70_a]
$$

먼 인덱스와 한 번에 바꾸므로 <mark>불안정</mark>입니다.

## 의사코드

```
heap_sort(A):
    n ← A의 길이
    i ← floor(n/2)-1 부터 0까지
        sift_down(A, i, n)
    h ← n-1 부터 1까지
        A[0]과 A[h]를 교환
        sift_down(A, 0, h)

sift_down(A, i, h):
    무한 반복
        L ← 2i+1, R ← 2i+2
        largest ← i
        L < h 이고 A[L] > A[largest] 이면 largest ← L
        R < h 이고 A[R] > A[largest] 이면 largest ← R
        largest = i 이면 종료
        A[i]와 A[largest]를 교환
        i ← largest
```

- `floor(n/2)-1`: 마지막 부모. 리프는 건너뜀
- `h`: 지금 힙 길이. 확정된 뒤는 보지 않음
- `largest`: 부모와 자식 셋 중 값이 가장 큰 인덱스
- `largest = i`: 이미 힙 성질을 만족

아래 두 코드는 위 의사코드와 같습니다.  
본문 예 `[80, 55, 90, 70, 60]`을 넣으면 `[55, 60, 70, 80, 90]`이 나옵니다.

### C

```c
#include <stdio.h>

void swap(int a[], int x, int y) {
    int t = a[x];
    a[x] = a[y];
    a[y] = t;
}

void sift_down(int a[], int i, int h) {
    while (1) {
        int L = 2 * i + 1;
        int R = 2 * i + 2;
        int largest = i;
        if (L < h && a[L] > a[largest]) largest = L;
        if (R < h && a[R] > a[largest]) largest = R;
        if (largest == i) return;
        swap(a, i, largest);
        i = largest;
    }
}

void heap_sort(int a[], int n) {
    for (int i = n / 2 - 1; i >= 0; i--) {
        sift_down(a, i, n);
    }
    for (int h = n - 1; h >= 1; h--) {
        swap(a, 0, h);
        sift_down(a, 0, h);
    }
}

int main(void) {
    int a[] = {80, 55, 90, 70, 60};
    int n = 5;
    heap_sort(a, n);
    for (int i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

- `n / 2 - 1`: C 정수 나눗셈. $$n=5$$면 $$1$$
- `L < h`: 힙 길이 밖의 확정 값은 자식으로 안 봄
- `a[L] > a[largest]`: 같으면 부모를 유지. 그래도 추출 교환 때문에 전체는 불안정

### Python

```python
def heap_sort(a):
    n = len(a)

    def sift_down(i, h):
        while True:
            L, R = 2 * i + 1, 2 * i + 2
            largest = i
            if L < h and a[L] > a[largest]:
                largest = L
            if R < h and a[R] > a[largest]:
                largest = R
            if largest == i:
                return
            a[i], a[largest] = a[largest], a[i]
            i = largest

    for i in range(n // 2 - 1, -1, -1):
        sift_down(i, n)
    for h in range(n - 1, 0, -1):
        a[0], a[h] = a[h], a[0]
        sift_down(0, h)
    return a

scores = [80, 55, 90, 70, 60]
print(heap_sort(scores))
```

- `range(n // 2 - 1, -1, -1)`: 마지막 부모부터 루트까지
- `range(n - 1, 0, -1)`: 힙 길이를 $$n-1$$에서 $$1$$까지
- `heapq`의 `heappush`/`heappop`으로도 만들 수 있지만, 그때는 보통 새 리스트를 씁니다. 이 글의 제자리 구현과 공간이 다릅니다

최소 힙으로 오름차순을 만들려면 루트를 **앞**에 확정하거나, 값을 음수로 보면 됩니다. 기본 교재는 최대 힙 + 뒤에 확정입니다.

## 퀵·병합과 한 표

같은 $$n=5$$, 같은 입력 $$[80,\ 55,\ 90,\ 70,\ 60]$$.

| 항목 | 퀵(로무토·끝값) | 병합 | 힙 |
| :--- | :--- | :--- | :--- |
| 한 단계에서 하는 일 | 피벗을 제자리에 | 두 줄을 합침 | 루트를 뒤에 확정 |
| 이 입력의 비교 | 6 | 7 | 9 |
| 최선 | $$\Theta(n\log n)$$ | $$\Theta(n\log n)$$ | $$\Theta(n\log n)$$ |
| 최악 | $$\Theta(n^2)$$ | $$\Theta(n\log n)$$ | $$\Theta(n\log n)$$ |
| 보조 배열 | $$\Theta(1)$$ | $$\Theta(n)$$ | $$\Theta(1)$$ |
| 안정 | 아니오 | 예 | 아니오 |
| 이미 정렬된 입력 | 끝값 피벗이면 $$n^2$$ | 여전히 $$n\log n$$ | 여전히 $$n\log n$$ |

시험이 셋을 같이 물으면 답의 축은 <mark>최악 보장</mark>과 <mark>제자리</mark>입니다.  
최악 $$n\log n$$ + 제자리를 동시에 원하는 기본 답이 힙입니다.

## 언제 쓰나

쓰는 때:

- 최악 $$\Theta(n\log n)$$이 필요하고, 길이 $$n$$ 보조 배열을 쓰기 싫을 때
- 우선순위 큐에서 최댓값을 반복해서 뺄 때. 정렬은 그 과정을 끝까지 한 것
- 인트로소트가 퀵 깊이를 자를 때 넘기는 알고리즘

약한 때:

- 같은 키의 원래 순서가 필요함
- 캐시. 자식 인덱스가 $$2i+1$$이라 메모리를  hop 함. 평균 퀵·병합보다 느린 경우가 많음
- $$n$$이 매우 작고 거의 정렬된 입력. 삽입이 더 쌀 수 있음

## 잘 놓치는 핵심

### 1. 힙만 만들면 정렬이다

구성이 끝나면 루트만 최댓값입니다. 둘째 큰 값은 아직 루트 자식 중 하나일 뿐입니다. 추출이 정렬입니다.

### 2. 구성도 $$\Theta(n\log n)$$이다

아래에서 내리는 구성은 $$\Theta(n)$$입니다. $$n$$번 삽입(sift-up)으로 만들면 $$\Theta(n\log n)$$이 됩니다. 기본형은 전자입니다.

### 3. 인덱스가 $$1$$부터다

이 글·C·파이썬은 $$0$$부터입니다. 왼쪽 자식이 $$2i+1$$입니다. 교재가 $$1$$부터면 왼쪽은 $$2i$$입니다. 문제를 먼저 봅니다.

### 4. 힙은 안정이다

기본형은 불안정입니다. 루트와 맨 끝을 교환하는 순간 같은 키의 순서가 깨질 수 있습니다.

### 5. 최소 힙이면 내림차순이다

최대 힙 + 뒤에 확정 = 오름차순입니다. 최소 힙 + 뒤에 확정 = 내림차순입니다.

### 6. 제자리 = 빠르다

제자리는 공간입니다. 캐시 때문에 평균 퀵보다 느린 구현이 흔합니다. 가치는 최악 보장입니다.

### 7. 선택 정렬과 같다

둘 다 최댓값을 뒤에 둡니다. 선택은 남은 원소를 모두 보고, 힙은 $$\log n$$ 높이만 봅니다.

전공자 체크:

- 구성이 $$O(n)$$인 이유: 높이 $$k$$ 노드의 작업이 $$k\cdot n/2^{k+1}$$이고 급수가 수렴
- 우선순위 큐: `insert` $$O(\log n)$$, `extract-max` $$O(\log n)$$, `peek` $$O(1)$$
- 인트로소트의 안전망이 힙인 이유: 최악 $$n\log n$$ + 제자리

## 객관식 10문제

**1.** 힙 정렬이 한 번 추출에서 하는 일은?

- ① 피벗을 가운데에 둔다
- ② 루트 최댓값을 힙 끝과 바꾸고 남은 구간을 다시 힙으로 만든다
- ③ 두 정렬 줄을 합친다
- ④ 간격 $$h$$만 삽입한다

<details>
<summary>정답</summary>

②  
① 퀵, ③ 병합, ④ 셸입니다.

</details>

**2.** $$0$$부터 세는 배열에서 인덱스 $$i$$의 왼쪽 자식은?

- ① $$i-1$$
- ② $$2i$$
- ③ $$2i+1$$
- ④ $$2i+2$$

<details>
<summary>정답</summary>

③  
오른쪽은 $$2i+2$$, 부모는 $$\lfloor(i-1)/2\rfloor$$.

</details>

**3.** $$n=5$$일 때 구성에서 먼저 내리는 인덱스는?

- ① $$0$$
- ② $$1$$
- ③ $$4$$
- ④ $$5$$

<details>
<summary>정답</summary>

②  
마지막 부모 $$\lfloor 5/2\rfloor-1=1$$부터 $$0$$까지입니다.

</details>

**4.** $$[80,55,90,70,60]$$을 최대 힙으로 만든 결과는?

- ① $$[80,70,90,55,60]$$
- ② $$[90,70,80,55,60]$$
- ③ $$[90,80,70,60,55]$$
- ④ $$[55,60,70,80,90]$$

<details>
<summary>정답</summary>

②  
위치 1에서 $$55$$와 $$70$$ 교환, 위치 0에서 $$80$$과 $$90$$ 교환.

</details>

**5.** 기본 힙 정렬의 최악 시간은?

- ① $$\Theta(n)$$
- ② $$\Theta(n\log n)$$
- ③ $$\Theta(n^2)$$
- ④ $$\Theta(2^n)$$

<details>
<summary>정답</summary>

②  
구성 $$\Theta(n)$$ + 추출 $$\Theta(n\log n)$$. 입력이 정렬되어 있어도 같습니다.

</details>

**6.** 기본 힙 정렬의 보조 공간은? (반복 내리기)

- ① $$\Theta(1)$$
- ② $$\Theta(\log n)$$
- ③ $$\Theta(n)$$
- ④ $$\Theta(n\log n)$$

<details>
<summary>정답</summary>

①  
인덱스와 임시 변수만 씁니다. 제자리.

</details>

**7.** 기본 힙 정렬의 안정성은?

- ① 안정
- ② 불안정. 루트와 먼 끝을 교환하면 같은 키의 순서가 깨질 수 있음
- ③ 제자리라서 안정
- ④ $$n\log n$$이라 안정

<details>
<summary>정답</summary>

②  
$$[70_a,55,70_b]$$에서 $$70_a$$가 뒤로 갈 수 있습니다.

</details>

**8.** 구성만 $$\Theta(n)$$인 이유는?

- ① 비교를 안 해서
- ② 리프는 건너뛰고, 아래 노드는 내릴 높이가 짧아서
- ③ 안정 정렬이라서
- ④ 보조 배열을 써서

<details>
<summary>정답</summary>

②  
$$n$$번 삽입으로 만들면 $$\Theta(n\log n)$$입니다.

</details>

**9.** 퀵(끝값 피벗)과 비교해 힙만 갖는 성질은?

- ① 최악 $$\Theta(n\log n)$$ + 제자리
- ② 안정
- ③ 최선 $$\Theta(n)$$
- ④ 보조 배열 $$\Theta(n)$$

<details>
<summary>정답</summary>

①  
퀵의 최악은 $$\Theta(n^2)$$, 병합은 제자리가 아닙니다.

</details>

**10.** 선택 정렬과 힙 정렬의 공통점과 차이는?

- ① 둘 다 최댓값을 뒤에 둔다. 찾는 비용이 선형 vs $$\log n$$
- ② 둘 다 안정하다
- ③ 둘 다 최악 $$n^2$$이다
- ④ 둘 다 보조 배열 $$n$$이 필요하다

<details>
<summary>정답</summary>

①  
선택 한 번의 최댓값 탐색은 $$O(n)$$, 힙은 $$O(\log n)$$입니다.

</details>
