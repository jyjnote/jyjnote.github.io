INSERT는 Table에 새로운 Row를 추가하는 DML 명령어입니다.

SQL 명령은 비슷해 보여도 **구조를 바꾸는지, 데이터를 바꾸는지, 권한을 바꾸는지**를 구분하면 이해하기 쉽습니다.

## 핵심 예시

대표 문법은 다음과 같습니다.

```sql
INSERT INTO DEPARTMENT(DEPT_ID, DEPT_NAME, REGION)
VALUES (60, '연구', '서울');
```

<mark>INSERT는 지정한 Column에 값을 넣어 새로운 Row를 생성합니다.</mark>

## 기본 INSERT

가장 기본적인 형태입니다.

```sql
INSERT INTO DEPARTMENT(DEPT_ID, DEPT_NAME, REGION)
VALUES (60, '연구', '서울');
```

Column 순서와 VALUES의 값 순서를 맞춰야 합니다.

## Column 목록 생략

모든 Column에 Table 정의 순서대로 값을 넣는다면 Column 목록을 생략할 수도 있습니다.

```sql
INSERT INTO DEPARTMENT
VALUES (60, '연구', '서울');
```

하지만 Schema 변경에 취약하므로 명시적인 Column 목록을 쓰는 방식이 안전합니다.

## 일부 Column만 INSERT

NULL 허용 또는 DEFAULT가 있는 Column은 생략할 수 있습니다.

```sql
INSERT INTO EMPLOYEE(EMP_ID, EMP_NAME)
VALUES (2001, '신입직원');
```

생략한 Column이 어떤 값을 가지는지는 Schema를 확인해야 합니다.

## 여러 Row INSERT

여러 Row를 한 번에 넣을 수 있습니다.

```sql
INSERT INTO DEPARTMENT(DEPT_ID, DEPT_NAME, REGION)
VALUES
    (60, '연구', '서울'),
    (70, '지원', '부산');
```

SQLite에서도 지원합니다.

## INSERT SELECT

다른 Query 결과를 새로운 Table에 넣을 수 있습니다.

```sql
INSERT INTO VIP_BACKUP(CUSTOMER_ID, NAME)
SELECT CUSTOMER_ID, NAME
FROM CUSTOMER
WHERE GRADE = 'VIP';
```

Column 개수와 자료형 호환을 확인해야 합니다.

## Primary Key 위반

이미 존재하는 Primary Key 값을 다시 넣으면 제약조건 위반이 발생할 수 있습니다.

```text
EMP_ID = 1001
이미 존재
→ 같은 Key INSERT 불가
```

Primary Key의 유일성이 적용됩니다.

## Foreign Key 위반

존재하지 않는 부모 Key를 Foreign Key에 넣으면 참조 무결성 위반이 될 수 있습니다.

```text
EMPLOYEE.DEPT_ID = 999
DEPARTMENT.DEPT_ID = 999 없음
```

SQLite에서는 `PRAGMA foreign_keys = ON` 상태에서 Foreign Key 검사가 활성화됩니다.

## NOT NULL과 INSERT

NOT NULL Column을 생략하거나 NULL을 넣으면 오류가 발생할 수 있습니다.

```sql
EMP_NAME TEXT NOT NULL
```

이 경우 `EMP_NAME = NULL`은 허용되지 않습니다.

## DEFAULT

값을 생략했을 때 DEFAULT가 사용될 수 있습니다.

```sql
STATUS TEXT DEFAULT 'READY'
```

INSERT에서 STATUS를 생략하면 기본값이 적용될 수 있습니다.

## INSERT와 UPDATE

INSERT는 새 Row를 만듭니다.

UPDATE는 이미 존재하는 Row의 값을 바꿉니다.

```text
INSERT
→ 새 Row

UPDATE
→ 기존 Row 수정
```
