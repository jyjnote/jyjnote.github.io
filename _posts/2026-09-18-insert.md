`INSERT`는 <mark>Table에 새로운 Row를 추가하는 DML 명령어</mark>입니다.

Table 구조를 만드는 것이 아니라 이미 존재하는 Table에 실제 데이터를 넣습니다.

<blockquote class="prompt-info">
<p>한 줄: INSERT는 기존 Table에 새로운 Row를 추가합니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

`INSERT`는 Table에 실제 데이터를 추가하는 명령어입니다.

</details>

## 대표 예시

DEPARTMENT Table에 새로운 부서를 추가한다고 가정합니다.

### 입력 Table · DEPARTMENT

| DEPT_ID | DEPT_NAME | REGION |
| --- | --- | --- |
| 10 | 개발 | 서울 |
| 20 | 인사 | 부산 |

```sql
INSERT INTO DEPARTMENT
VALUES (30, '영업', '대전');
```

### 결과 Table

| DEPT_ID | DEPT_NAME | REGION |
| --- | --- | --- |
| 10 | 개발 | 서울 |
| 20 | 인사 | 부산 |
| 30 | 영업 | 대전 |

새로운 Row 하나가 Table에 추가됩니다.

```text
INSERT
→ 구조 변경 아님
→ 실제 데이터 추가
```

## 기본 문법

```sql
INSERT INTO Table명
VALUES (값1, 값2, 값3);
```

Column을 따로 지정하지 않으면 Table에 정의된 Column 순서에 맞게 값을 넣어야 합니다.

## Column을 직접 지정

필요한 Column을 직접 지정해서 값을 넣을 수도 있습니다.

### 입력 Table · CUSTOMER

| CUSTOMER_ID | NAME | REGION | GRADE |
| --- | --- | --- | --- |
| C001 | 고객1 | 서울 | VIP |

```sql
INSERT INTO CUSTOMER(
    CUSTOMER_ID,
    NAME,
    REGION,
    GRADE
)
VALUES (
    'C002',
    '고객2',
    '부산',
    '일반'
);
```

### 결과 Table

| CUSTOMER_ID | NAME | REGION | GRADE |
| --- | --- | --- | --- |
| C001 | 고객1 | 서울 | VIP |
| C002 | 고객2 | 부산 | 일반 |

Column을 직접 적으면 어떤 값이 어느 Column에 들어가는지 명확하게 확인할 수 있습니다.

<blockquote class="prompt-info">
<p>실무에서는 Column 순서 변경에 덜 취약하도록 INSERT할 Column을 직접 적는 방식이 더 명확합니다.</p>
</blockquote>

## 일부 Column만 입력

NULL을 허용하거나 기본값이 있는 Column은 생략할 수 있습니다.

### 입력 Table 구조

| Column | 조건 |
| --- | --- |
| EMP_ID | PRIMARY KEY |
| EMP_NAME | NOT NULL |
| DEPT_ID | NULL 가능 |
| BONUS | NULL 가능 |

```sql
INSERT INTO EMPLOYEE(
    EMP_ID,
    EMP_NAME
)
VALUES (
    1051,
    '직원51'
);
```

### 결과 Row

| EMP_ID | EMP_NAME | DEPT_ID | BONUS |
| --- | --- | --- | --- |
| 1051 | 직원51 | NULL | NULL |

입력하지 않은 Column이 NULL을 허용한다면 `NULL`이 들어갈 수 있습니다.

## 여러 Row 한 번에 추가

여러 Row를 한 번의 INSERT문으로 추가할 수도 있습니다.

### 입력 Table · DEPARTMENT

| DEPT_ID | DEPT_NAME | REGION |
| --- | --- | --- |
| 10 | 개발 | 서울 |

```sql
INSERT INTO DEPARTMENT(
    DEPT_ID,
    DEPT_NAME,
    REGION
)
VALUES
    (20, '인사', '부산'),
    (30, '영업', '대전');
```

### 결과 Table

| DEPT_ID | DEPT_NAME | REGION |
| --- | --- | --- |
| 10 | 개발 | 서울 |
| 20 | 인사 | 부산 |
| 30 | 영업 | 대전 |

하나의 INSERT문으로 여러 Row를 추가한 것입니다.

## NULL 직접 입력

값이 없는 경우 `NULL`을 직접 넣을 수도 있습니다.

### 입력 Table · EMPLOYEE

| EMP_ID | EMP_NAME | BONUS |
| --- | --- | --- |
| 1001 | 직원1 | 200 |

```sql
INSERT INTO EMPLOYEE(
    EMP_ID,
    EMP_NAME,
    BONUS
)
VALUES (
    1002,
    '직원2',
    NULL
);
```

### 결과 Table

| EMP_ID | EMP_NAME | BONUS |
| --- | --- | --- |
| 1001 | 직원1 | 200 |
| 1002 | 직원2 | NULL |

단, `NOT NULL` 제약조건이 있는 Column에는 NULL을 넣을 수 없습니다.

## 제약조건 위반 주의

INSERT는 Table의 제약조건을 만족해야 합니다.

### 입력 Table 구조

| Column | 제약조건 |
| --- | --- |
| DEPT_ID | PRIMARY KEY |
| DEPT_NAME | NOT NULL |

이미 `DEPT_ID = 10`이 존재한다고 가정합니다.

```sql
INSERT INTO DEPARTMENT
VALUES (10, '기획', '서울');
```

Primary Key 값이 중복되므로 정상적으로 추가할 수 없습니다.

```text
PRIMARY KEY
→ 중복 불가

NOT NULL
→ NULL 불가

FOREIGN KEY
→ 참조 대상 확인
```

## INSERT와 CREATE 차이

### CREATE

```sql
CREATE TABLE DEPARTMENT(
    DEPT_ID INTEGER PRIMARY KEY,
    DEPT_NAME TEXT NOT NULL
);
```

```text
구조 생성
→ DDL
```

### INSERT

```sql
INSERT INTO DEPARTMENT
VALUES (10, '개발');
```

```text
Row 추가
→ DML
```

| 명령 | 역할 |
| --- | --- |
| CREATE | Table 구조 생성 |
| INSERT | 실제 Row 추가 |

## 잘 놓치는 핵심

### 1. INSERT는 Row를 추가한다

Table 구조를 변경하는 명령이 아닙니다.

### 2. Column을 생략하면 순서가 중요하다

```sql
INSERT INTO DEPARTMENT
VALUES (10, '개발', '서울');
```

값의 순서는 Table의 Column 순서와 맞아야 합니다.

### 3. Column을 직접 지정하면 입력 관계가 명확하다

```sql
INSERT INTO DEPARTMENT(
    DEPT_ID,
    DEPT_NAME
)
VALUES (
    10,
    '개발'
);
```

### 4. 제약조건을 만족해야 한다

Primary Key 중복, NOT NULL 위반, Foreign Key 위반 등이 있으면 INSERT가 실패할 수 있습니다.

## 시험·면접

### 핵심 암기

```text
INSERT
→ Row 추가
→ DML
```

```text
INSERT INTO
→ 대상 Table
```

```text
VALUES
→ 실제 입력값
```

```text
Column 생략
→ Table Column 순서 주의
```

### 시험 함정

`INSERT`는 Schema를 변경하는 명령이 아닙니다.

새로운 Column을 만드는 것은 `ALTER`, 새로운 Table을 만드는 것은 `CREATE`, 새로운 Row를 추가하는 것은 `INSERT`입니다.

### 면접 짧은 답변

`INSERT`는 기존 Table에 새로운 Row를 추가하는 DML 명령어입니다. Column을 생략하면 Table의 Column 순서에 맞게 값을 입력해야 하며, Column을 직접 지정하면 필요한 Column만 명확하게 입력할 수 있습니다. 입력 데이터는 Primary Key, Not Null, Foreign Key 같은 제약조건을 만족해야 합니다.

## 객관식 문제

### 문제 1 · INSERT

다음 중 `INSERT`의 역할은?

① Table 구조 생성  
② 새로운 Row 추가  
③ 기존 Row 수정  
④ Table 삭제

<details markdown="1">
<summary>정답</summary>

②

`INSERT`는 기존 Table에 새로운 Row를 추가합니다.

</details>

### 문제 2 · 결과 확인

#### 입력 Table

| DEPT_ID | DEPT_NAME |
| --- | --- |
| 10 | 개발 |

```sql
INSERT INTO DEPARTMENT(
    DEPT_ID,
    DEPT_NAME
)
VALUES (
    20,
    '인사'
);
```

결과로 옳은 것은?

① 기존 개발 Row가 인사로 변경된다.  
② 인사 Row가 새로 추가된다.  
③ DEPARTMENT Table이 삭제된다.  
④ Column이 하나 추가된다.

<details markdown="1">
<summary>정답</summary>

②

| DEPT_ID | DEPT_NAME |
| --- | --- |
| 10 | 개발 |
| 20 | 인사 |

새로운 Row가 추가됩니다.

</details>

### 문제 3 · Column 생략

다음 방식에서 특히 주의해야 할 것은?

```sql
INSERT INTO DEPARTMENT
VALUES (10, '개발', '서울');
```

① Table 이름 길이  
② Column 순서와 값의 순서  
③ SELECT문의 개수  
④ JOIN 조건

<details markdown="1">
<summary>정답</summary>

②

Column 목록을 생략했기 때문에 Table에 정의된 Column 순서에 맞게 값을 넣어야 합니다.

</details>

### 문제 4 · 제약조건

이미 `DEPT_ID = 10`이 Primary Key로 존재한다면 다음 INSERT는 어떻게 될 수 있는가?

```sql
INSERT INTO DEPARTMENT
VALUES (10, '기획', '서울');
```

① 정상적으로 중복 Row가 추가된다.  
② Primary Key 중복으로 실패할 수 있다.  
③ 기존 Table이 삭제된다.  
④ 자동으로 DEPT_ID가 11로 변경된다.

<details markdown="1">
<summary>정답</summary>

②

Primary Key는 중복될 수 없습니다.

</details>

① CREATE

③ INSERT  
④ DROP
