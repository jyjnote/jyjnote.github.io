`제2정규형`은 <mark>제1정규형을 만족하면서 복합 Key의 일부에만 종속되는 부분 함수 종속을 제거한 상태</mark>입니다.

핵심은 **일반 Attribute가 복합 Key 전체에 완전 함수 종속되도록 만드는 것**입니다.

<blockquote class="prompt-info">
<p>한 줄: 제2정규형은 복합 Key의 일부만으로 결정되는 일반 Attribute를 별도 Table로 분리합니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

1NF를 만족한 뒤 부분 함수 종속을 제거하면 2NF입니다.

</details>

## 먼저 부분 함수 종속

다음 수강 Table을 보겠습니다.

| 학생번호 | 강의번호 | 학생이름 | 강의명 | 성적 |
| --- | --- | --- | --- | --- |
| 1001 | C01 | 학생1 | 데이터베이스 | A |
| 1001 | C02 | 학생1 | 운영체제 | B |
| 1002 | C01 | 학생2 | 데이터베이스 | A |

Primary Key가 다음 복합 Key라고 가정합니다.

```text
학생번호 + 강의번호
```

각 함수적 종속은 다음과 같습니다.

```text
학생번호 + 강의번호
→ 성적
```

```text
학생번호
→ 학생이름
```

```text
강의번호
→ 강의명
```

`성적`은 학생번호와 강의번호가 모두 있어야 결정됩니다.

반면 `학생이름`은 학생번호만으로 결정되고, `강의명`은 강의번호만으로 결정됩니다.

## 완전 함수 종속

복합 Key 전체가 있어야 일반 Attribute가 결정되는 경우입니다.

```text
학생번호 + 강의번호
→ 성적
```

학생번호만 알아서는 특정 강의의 성적을 알 수 없습니다.

강의번호만 알아서도 특정 학생의 성적을 알 수 없습니다.

```text
복합 Key 전체 필요
→ 완전 함수 종속
```

이 관계는 제2정규형에서 문제가 되지 않습니다.

## 부분 함수 종속

복합 Key 전체가 아니라 일부만으로 일반 Attribute가 결정되는 경우입니다.

```text
학생번호
→ 학생이름
```

학생이름을 결정하는 데 강의번호는 필요하지 않습니다.

또한

```text
강의번호
→ 강의명
```

강의명을 결정하는 데 학생번호는 필요하지 않습니다.

```text
복합 Key 일부만 필요
→ 부분 함수 종속
```

제2정규형에서는 이러한 부분 함수 종속을 제거합니다.

## 왜 문제가 되는가

기존 Table을 다시 보겠습니다.

| 학생번호 | 강의번호 | 학생이름 | 강의명 | 성적 |
| --- | --- | --- | --- | --- |
| 1001 | C01 | 학생1 | 데이터베이스 | A |
| 1001 | C02 | 학생1 | 운영체제 | B |
| 1002 | C01 | 학생2 | 데이터베이스 | A |

학생1이 강의를 여러 개 들으면 `학생1`이라는 값이 반복됩니다.

또한 데이터베이스 강의를 여러 학생이 들으면 `데이터베이스`라는 값도 반복됩니다.

```text
학생번호 → 학생이름
강의번호 → 강의명
```

이 정보를 수강 Table에 계속 저장하면 중복이 발생합니다.

## 제2정규형으로 분해

부분 함수 종속을 별도 Table로 분리합니다.

### 학생 Table

| 학생번호 | 학생이름 |
| --- | --- |
| 1001 | 학생1 |
| 1002 | 학생2 |

```text
학생번호
→ 학생이름
```

### 강의 Table

| 강의번호 | 강의명 |
| --- | --- |
| C01 | 데이터베이스 |
| C02 | 운영체제 |

```text
강의번호
→ 강의명
```

### 수강 Table

| 학생번호 | 강의번호 | 성적 |
| --- | --- | --- |
| 1001 | C01 | A |
| 1001 | C02 | B |
| 1002 | C01 | A |

```text
학생번호 + 강의번호
→ 성적
```

이제 각 일반 Attribute는 자신의 Key에 완전 함수 종속됩니다.

## 변환 전과 후

### 변환 전

| 학생번호 | 강의번호 | 학생이름 | 강의명 | 성적 |
| --- | --- | --- | --- | --- |
| 1001 | C01 | 학생1 | 데이터베이스 | A |
| 1001 | C02 | 학생1 | 운영체제 | B |
| 1002 | C01 | 학생2 | 데이터베이스 | A |

### 변환 후

```text
학생
→ 학생번호, 학생이름

강의
→ 강의번호, 강의명

수강
→ 학생번호, 강의번호, 성적
```

```text
부분 함수 종속 제거
↓
중복 감소
↓
제2정규형
```

## 복합 Key가 중요하다

부분 함수 종속은 복합 Key의 일부에 종속되는 관계입니다.

따라서 Key가 하나의 Attribute로만 구성되어 있다면 그 Key의 일부라는 개념이 없습니다.

```text
Primary Key
→ 학생번호 하나
```

이 경우 부분 함수 종속은 발생할 수 없습니다.

<blockquote class="prompt-info">
<p>후보 Key가 모두 단일 Attribute라면 부분 함수 종속이 존재하지 않으므로 1NF를 만족한 관계는 2NF 조건도 만족합니다.</p>
</blockquote>

## 1NF와 2NF 차이

| 구분 | 핵심 |
| --- | --- |
| 제1정규형 | 모든 Attribute가 원자값 |
| 제2정규형 | 부분 함수 종속 제거 |

### 1NF에서 확인

```text
한 Cell에 여러 값이 있는가?
```

### 2NF에서 확인

```text
복합 Key가 있는가?
↓
일반 Attribute가 Key 일부만으로 결정되는가?
```

## 2NF라고 모든 이상 현상이 사라지는 것은 아니다

제2정규형을 만족해도 이행 함수 종속이 남아 있을 수 있습니다.

예를 들어 다음 관계가 있다고 가정합니다.

```text
학생번호
→ 학과코드

학과코드
→ 학과명
```

부분 함수 종속은 없어도

```text
학생번호
→ 학과코드
→ 학과명
```

이라는 이행 함수 종속이 존재할 수 있습니다.

이 문제는 제3정규형에서 다룹니다.

<blockquote class="prompt-warning">
<p>제2정규형은 부분 함수 종속만 제거하는 단계이며 이행 함수 종속까지 제거하는 것은 아닙니다.</p>
</blockquote>

## 판단 순서

제2정규형 문제는 다음 순서로 보면 빠릅니다.

### 1. 1NF인지 확인

```text
모든 값이 원자값인가?
```

### 2. 후보 Key 확인

```text
복합 Key가 있는가?
```

### 3. 함수적 종속 확인

```text
Key 전체 → 일반 Attribute
```

인지,

```text
Key 일부 → 일반 Attribute
```

인지 확인합니다.

### 4. 부분 함수 종속 분리

Key 일부에만 종속되는 Attribute를 별도 Table로 분리합니다.

## 잘 놓치는 핵심

### 1. 2NF는 1NF를 먼저 만족해야 한다

```text
1NF
→ 2NF
```

순서로 진행합니다.

### 2. 부분 함수 종속은 복합 Key에서 발생한다

Key 일부만으로 일반 Attribute가 결정되는지 봅니다.

### 3. Key 전체에 종속되면 문제가 아니다

```text
학생번호 + 강의번호
→ 성적
```

처럼 복합 Key 전체가 필요한 관계는 완전 함수 종속입니다.

### 4. 2NF 이후에도 이행 함수 종속은 남을 수 있다

이행 함수 종속은 제3정규형에서 제거합니다.

## 시험·면접

### 핵심 암기

```text
2NF
→ 1NF 만족
→ 부분 함수 종속 제거
```

```text
완전 함수 종속
→ 복합 Key 전체 필요
```

```text
부분 함수 종속
→ 복합 Key 일부만 필요
```

### 시험 함정

복합 Key가 있다는 이유만으로 제2정규형을 위반하는 것은 아닙니다.

일반 Attribute가 복합 Key 일부에만 종속될 때 문제가 됩니다.

### 면접 짧은 답변

제2정규형은 제1정규형을 만족한 상태에서 비주요 Attribute의 부분 함수 종속을 제거한 형태입니다. 복합 Key의 일부만으로 결정되는 Attribute를 별도 Table로 분리하여 모든 일반 Attribute가 후보 Key 전체에 완전 함수 종속되도록 만듭니다.

## 객관식 문제

### 문제 1 · 핵심

제2정규형의 핵심으로 가장 적절한 것은?

① 원자값 보장  
② 부분 함수 종속 제거  
③ 이행 함수 종속 제거  
④ 모든 Table 통합

<details markdown="1">
<summary>정답</summary>

②

제2정규형은 복합 Key 일부에 대한 부분 함수 종속을 제거하는 단계입니다.

</details>

### 문제 2 · 부분 함수 종속

Primary Key가 `학생번호 + 강의번호`일 때 다음 중 부분 함수 종속은?

① 학생번호 + 강의번호 → 성적  
② 학생번호 → 학생이름  
③ 학생번호 + 강의번호 → 수강여부  
④ 학생번호 + 강의번호 → 출석점수

<details markdown="1">
<summary>정답</summary>

②

복합 Key 전체가 아니라 일부인 학생번호만으로 학생이름이 결정되므로 부분 함수 종속입니다.

</details>

### 문제 3 · 완전 함수 종속

다음 중 완전 함수 종속으로 가장 적절한 것은?

```text
Primary Key
→ 학생번호 + 강의번호
```

① 학생번호 → 학생이름  
② 강의번호 → 강의명  
③ 학생번호 + 강의번호 → 성적  
④ 학생번호 → 학과

<details markdown="1">
<summary>정답</summary>

③

성적은 특정 학생과 특정 강의가 모두 정해져야 결정되므로 복합 Key 전체에 종속됩니다.

</details>

### 문제 4 · 단일 Key

후보 Key가 모두 하나의 Attribute로만 구성된 관계에 대한 설명으로 옳은 것은?

① 반드시 부분 함수 종속이 있다.  
② 부분 함수 종속이 발생할 수 없다.  
③ 반드시 3NF이다.  
④ 반드시 BCNF이다.

<details markdown="1">
<summary>정답</summary>

②

단일 Attribute Key에는 Key의 일부라는 개념이 없으므로 부분 함수 종속이 발생할 수 없습니다.

</details>

### 문제 5 · 다음 단계

제2정규형 이후 제3정규형에서 제거하는 것은?

① 원자값  
② 부분 함수 종속  
③ 이행 함수 종속  
④ Primary Key

<details markdown="1">
<summary>정답</summary>

③

제3정규형은 비주요 Attribute 사이의 이행 함수 종속을 제거하는 단계입니다.

</details>

## 제2정규형 전체 요약

### 변환 전

| 학생번호 | 강의번호 | 학생이름 | 강의명 | 성적 |
| --- | --- | --- | --- | --- |
| 1001 | C01 | 학생1 | 데이터베이스 | A |
| 1001 | C02 | 학생1 | 운영체제 | B |

```text
학생번호
→ 학생이름

강의번호
→ 강의명

학생번호 + 강의번호
→ 성적
```

### 변환 후

```text
학생 Table
→ 학생번호, 학생이름

강의 Table
→ 강의번호, 강의명

수강 Table
→ 학생번호, 강의번호, 성적
```

```text
1NF 만족
+
부분 함수 종속 제거
=
2NF
```

<blockquote class="prompt-danger">
<p>제2정규형 문제에서는 복합 Key를 찾은 뒤 일반 Attribute가 Key 전체에 종속되는지 일부에만 종속되는지 확인합니다.</p>
</blockquote>
