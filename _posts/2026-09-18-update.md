UPDATE는 이미 존재하는 Row의 Column 값을 변경하는 DML 명령어입니다.

SQL 명령은 비슷해 보여도 **구조를 바꾸는지, 데이터를 바꾸는지, 권한을 바꾸는지**를 구분하면 이해하기 쉽습니다.

</blockquote>

## 핵심 예시

대표 문법은 다음과 같습니다.

```sql
UPDATE EMPLOYEE
SET SALARY = 3500
WHERE EMP_ID = 1001;
```

<mark>UPDATE는 WHERE로 수정할 Row를 고르고 SET으로 새로운 값을 지정합니다.</mark>

## 기본 UPDATE

특정 직원의 급여를 수정합니다.

```sql
UPDATE EMPLOYEE
SET SALARY = 3500
WHERE EMP_ID = 1001;
```

`SET`은 바꿀 값을, `WHERE`는 수정 대상을 지정합니다.

## WHERE가 핵심

WHERE를 빼면 모든 Row가 수정됩니다.

```sql
UPDATE EMPLOYEE
SET SALARY = 3500;
```

모든 직원의 급여가 3500으로 바뀔 수 있습니다.

<blockquote class="prompt-danger">
<p>UPDATE 전에 WHERE 조건으로 몇 Row가 대상인지 먼저 확인하는 습관이 중요합니다.</p>
</blockquote>

## 여러 Column 수정

한 번에 여러 Column을 수정할 수 있습니다.

```sql
UPDATE EMPLOYEE
SET
    SALARY = 3600,
    BONUS = 300
WHERE EMP_ID = 1001;
```

## 기존 값 기반 수정

기존 값을 이용해 계산할 수 있습니다.

```sql
UPDATE PRODUCT
SET PRICE = PRICE * 1.1
WHERE CATEGORY = 'A';
```

해당 Category의 현재 가격을 기준으로 수정합니다.

## NULL로 변경

NULL을 허용하는 Column은 NULL로 변경할 수 있습니다.

```sql
UPDATE EMPLOYEE
SET BONUS = NULL
WHERE EMP_ID = 1001;
```

NOT NULL Column에는 사용할 수 없습니다.

## Subquery와 UPDATE

서브쿼리 결과를 이용할 수도 있습니다.

```sql
UPDATE EMPLOYEE
SET SALARY = (
    SELECT AVG(SALARY)
    FROM EMPLOYEE
)
WHERE EMP_ID = 1001;
```

DBMS별로 같은 Table을 읽고 수정하는 방식에 제한이 있을 수 있으므로 확인이 필요합니다.

## 제약조건

UPDATE 결과도 Primary Key, Foreign Key, CHECK, NOT NULL 같은 제약조건을 만족해야 합니다.

```text
수정 후 값
→ Constraint 검사
```

잘못된 값으로 바꾸면 UPDATE가 실패할 수 있습니다.

## Transaction과 UPDATE

대량 UPDATE는 Transaction과 함께 신중하게 처리합니다.

```text
BEGIN
→ UPDATE
→ 결과 확인
→ COMMIT 또는 ROLLBACK
```

실제 문법은 DBMS에 따라 다를 수 있습니다.

## SELECT로 먼저 확인

실전에서는 UPDATE 전에 같은 WHERE 조건으로 SELECT를 실행해 대상 Row를 확인하는 습관이 좋습니다.

```sql
SELECT *
FROM EMPLOYEE
WHERE EMP_ID = 1001;
```

그 다음 같은 조건으로 UPDATE합니다.
