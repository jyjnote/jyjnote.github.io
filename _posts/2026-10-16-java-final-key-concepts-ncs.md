## 1. 개발 도구와 실행 구조

**소스 → 컴파일 → 클래스 파일 → 로딩·연결·초기화 → 실행**을 구분합니다.[^execution][^tools]

| 개념 | 반드시 기억할 내용 |
| --- | --- |
| 개발 도구 묶음 `JDK` | 컴파일러와 실행기 등 개발·실행 도구를 제공합니다. |
| 실행 환경 `JRE` | 가상 머신과 실행에 필요한 라이브러리를 가리키는 개념입니다. 별도 배포·폴더 구조는 제품마다 다릅니다. |
| 가상 머신 `JVM` | 클래스 파일을 실행합니다. 언어 문법·개발 도구·프레임워크와 같은 말이 아닙니다. |
| `javac`와 `java` | 각각 컴파일러와 실행기입니다. 소스 파일을 직접 실행하는 모드도 있습니다. |
| 플랫폼 독립성 | 호환되는 실행 환경에서 바이트코드를 실행한다는 뜻입니다. 외부 라이브러리·네이티브 코드 의존까지 사라지지는 않습니다. |
| `import` | 이름을 짧게 쓰도록 돕습니다. 라이브러리를 내려받거나 객체를 만드는 명령이 아닙니다. |
| 전통적인 진입점 | `public static void main(String[] 인수)`입니다. 명령행 인수는 문자열 배열로 받습니다. |

## 2. 기본형·참조형·변수

**자료형은 저장하는 값의 종류이고, 힙·스택은 실행 상태를 관리하는 영역입니다.** 둘을 같은 분류로 외우지 않습니다.[^types][^conversions][^statements][^vm]

| 자료형 | 값의 범위·성질 |
| --- | --- |
| `byte` | 8비트 부호 있는 정수, −128~127입니다. |
| `short`·`int`·`long` | 각각 16·32·64비트 부호 있는 정수입니다. 큰 정수 리터럴에는 `L`을 붙입니다. |
| `char` | 16비트 부호 없는 문자 코드 단위, 0~65,535입니다. 화면의 문자 하나가 항상 `char` 하나는 아닙니다. |
| `float`·`double` | 각각 32·64비트 부동소수점입니다. 실수 리터럴의 기본형은 `double`이며 `float`용은 보통 `F`를 붙입니다. |
| `boolean` | `true`·`false`만 표현합니다. 언어 차원에서 저장 크기를 무조건 1바이트로 정하지 않습니다. |
| 참조형 | 객체나 배열을 가리키는 참조값을 저장합니다. `null`은 어떤 객체도 가리키지 않는 참조값입니다. |

| 구분 | 판별 규칙 |
| --- | --- |
| 필드·배열 원소 | 정수 0, 실수 0.0, 문자 코드 0, 논리값 `false`, 참조값 `null`로 기본 초기화됩니다. |
| 지역 변수 | 읽기 전에 확실히 대입되어야 합니다. 선언만 하면 0이 들어간다고 계산하지 않습니다. |
| 기본형 대입 | 값이 복사됩니다. 한 변수의 변경이 다른 변수의 값을 바꾸지 않습니다. |
| 참조형 대입 | 참조값이 복사됩니다. 같은 객체를 함께 가리킬 수 있으며 객체 복사는 아닙니다. |
| `var` | 초기값으로 지역 변수의 타입을 추론합니다. 이후 아무 타입이나 넣는 동적 타입이 아닙니다. |
| 박싱·언박싱 | 기본형과 래퍼 사이의 변환입니다. `null` 래퍼를 언박싱하면 `NullPointerException`이 발생합니다. |

## 3. 계산·제어 흐름·배열

**대입받는 변수의 타입보다 먼저, 오른쪽 식이 어떤 타입으로 계산되는지 확인합니다.** 아래 값은 각 식을 독립적으로 평가한 결과입니다.[^conversions][^expressions][^statements][^arrays]

| 코드·개념 | 결과 또는 판단 기준 |
| --- | --- |
| `double 평균 = 5 / 2;` | 정수 나눗셈 후 대입하므로 `2.0`입니다. `5 / 2.0`은 `2.5`입니다. |
| `long 곱 = 100000 * 100000;` | 먼저 `int`에서 넘칩니다. `100000L * 100000`처럼 계산 전에 확장해야 합니다. |
| `byte 작은값 = 1;` 이후 덧셈 | `작은값 + 1`은 `int`입니다. `작은값 += 1`에는 축소 변환이 포함되므로 별도로 판단합니다. |
| 확대 변환 | 범위가 넓어져도 `long → double` 등에서는 정밀도를 잃을 수 있습니다. |
| 전위·후위 증가 | 전위는 증가한 값을 식에 쓰고, 후위는 기존 값을 식에 쓴 뒤 변수는 증가합니다. |
| 문자열 연결 | `1 + 2 + "3"`은 `"33"`, `"1" + 2 + 3`은 `"123"`입니다. |
| 단락 평가 | `&&`는 왼쪽이 거짓, `\|\|`는 왼쪽이 참이면 오른쪽을 평가하지 않습니다. |
| 논리형 `&`·`\|` | 양쪽을 모두 평가합니다. 정수에 쓰면 비트 연산입니다. |
| 조건·반복 | 조건은 논리형입니다. `do-while` 본문은 최소 한 번 실행됩니다. `break`는 탈출, `continue`는 다음 반복으로 이동입니다. |
| `switch` | 전통적인 콜론 방식은 다음 분기로 이어질 수 있습니다. 화살표 방식은 관통하지 않으며, 표현식의 값 반환에는 `yield`를 사용할 수 있습니다. |
| 배열의 길이 | 생성 후 고정이고 `length` 필드로 읽습니다. 인덱스는 0부터 길이−1까지입니다. |
| 배열의 복사 | 참조 배열의 `clone`·`copyOf`는 요소의 참조값을 복사합니다. 다차원 배열도 안쪽 배열까지 자동으로 깊게 복사하지 않습니다. |
| 배열의 공변성 | `Object[] 대상 = new String[1];`은 허용됩니다. 여기에 정수를 넣으면 실행 중 `ArrayStoreException`입니다. |

## 4. 메서드와 값 전달

<mark>자바의 인수 전달은 항상 값 전달입니다. 객체를 넘길 때 복사되는 값이 참조값일 뿐입니다.</mark>[^expressions]

| 상황 | 호출자에게 미치는 영향 |
| --- | --- |
| 기본형 매개변수의 값을 바꿈 | 호출자의 기본형 변수는 바뀌지 않습니다. |
| 참조 매개변수로 객체 내부를 바꿈 | 같은 객체를 가리키므로 호출자도 변경된 내부 상태를 봅니다. |
| 참조 매개변수에 새 객체를 대입함 | 매개변수만 다른 객체를 가리킵니다. 호출자의 참조 변수는 그대로입니다. |
| 메서드 시그니처 | 기본적으로 이름과 매개변수 타입·순서를 봅니다. 반환형만 다른 선언은 오버로딩이 아닙니다. |
| 오버로딩 선택 단계 | 고정 인수의 엄격한 호출 → 박싱 등을 허용한 호출 → 가변 인수 호출 순으로 적용 가능성을 확인합니다. 각 단계에서는 가장 구체적인 후보를 고릅니다. |
| 가변 인수 | 배열로 받으며 매개변수 목록의 마지막에 하나만 선언합니다. |
| 재귀 | 호출마다 실행 상태가 쌓입니다. 종료 조건이 없거나 깊이가 지나치면 스택 초과가 발생할 수 있습니다. |

## 5. 객체·생성자·접근 제어

**생성자는 객체를 초기화하고, 정적 멤버는 객체 하나가 아니라 클래스 단위로 다룹니다.** 아래 초기화 순서는 자바 21의 일반적인 상속 예제 기준입니다.[^classes][^execution][^access]

| 개념 | 핵심 규칙 |
| --- | --- |
| 생성자 | 클래스 이름과 같고 반환형을 적지 않습니다. 상속되지 않지만 오버로딩할 수 있습니다. |
| 기본 생성자 | 일반 클래스에서 생성자를 하나도 선언하지 않았을 때만 컴파일러가 제공합니다. 직접 작성한 무인자 생성자와 구분합니다. |
| `this`·`super` | 현재 객체와 상위 클래스의 멤버·생성자 접근을 구분합니다. 정적 문맥에는 현재 인스턴스를 뜻하는 `this`가 없습니다. |
| 정적 초기화 | 상위 클래스부터 진행하며, 초기화되는 해당 런타임 클래스에 대해 한 번 수행합니다. 객체 수만큼 반복하지 않습니다. |
| 객체 초기화 | 전체 인스턴스 필드의 기본값 설정 → 상위 생성 과정 → 현재 클래스의 필드 초기화·초기화 블록 → 현재 생성자 본문을 구분합니다. |
| 생성자 안의 재정의 호출 | 상위 생성자에서도 자식의 재정의 메서드가 호출될 수 있습니다. 자식 필드의 명시적 초기화가 아직 끝나지 않았을 수 있습니다. |
| 필드와 초기화 블록 | 같은 클래스 안에서는 선언 순서대로 실행됩니다. 정적 초기화와 인스턴스 초기화는 별도입니다. |
| `static` | 클래스 단위입니다. 정적 메서드에서 인스턴스 멤버를 쓰려면 대상 객체가 필요합니다. |
| 캡슐화 | 내부 상태를 숨기고 허용된 연산을 통해 상태와 제약을 관리합니다. 접근자를 무조건 만드는 것과 다릅니다. |

| 접근 제어 | 접근 가능한 범위 |
| --- | --- |
| `private` | 선언을 둘러싼 동일 최상위 클래스 내부이며, 그 안의 중첩 타입도 포함합니다. |
| 아무것도 쓰지 않음 | 같은 패키지입니다. `default`라는 접근 제한자를 적는 것이 아닙니다. |
| `protected` | 같은 패키지 또는 다른 패키지의 하위 클래스입니다. 다른 패키지에서는 접근하는 참조의 타입 등 추가 조건이 있습니다. |
| `public` | 외부 접근을 허용합니다. 다만 선언 타입 자체의 접근성과 모듈 경계도 충족해야 합니다. |

## 6. 상속·다형성·추상화

**호출할 이름·매개변수는 컴파일 시 검사하고, 재정의한 인스턴스 메서드의 구현은 실제 객체를 따라갑니다.**[^classes][^interfaces][^expressions]

| 비교 | 왼쪽 개념 | 오른쪽 개념 |
| --- | --- | --- |
| 오버로딩 ↔ 오버라이딩 | 같은 이름, 다른 매개변수이며 컴파일 시 선택합니다. | 상위 인스턴스 메서드의 구현을 재정의하며 실제 객체가 중요합니다. |
| 필드 ↔ 재정의 메서드 | 표현식의 선언 타입을 기준으로 선택합니다. | 실제 객체의 구현을 호출합니다. |
| 정적 메서드 ↔ 인스턴스 메서드 | 정적 메서드는 가림을 구분하며 동적 재정의가 아닙니다. | 재정의 가능한 인스턴스 메서드는 동적 호출 대상입니다. |
| 상향 변환 ↔ 하향 변환 | 하위 객체를 상위 타입의 참조로 다룹니다. | 실제 객체가 대상 타입과 맞는지 검사하며 실패하면 `ClassCastException`입니다. |
| 추상 클래스 ↔ 인터페이스 | 생성자·인스턴스 상태·공통 구현을 가질 수 있습니다. | 여러 타입이 구현하는 계약이며 기본·정적·비공개 메서드도 가질 수 있습니다. |

클래스는 하나의 클래스만 직접 상속하지만 인터페이스는 여러 개 구현할 수 있습니다. 추상 클래스와 인터페이스는 그 자체를 직접 생성하지 않습니다. 인터페이스 필드는 `public static final`이며 인스턴스 필드가 아닙니다.[^classes][^interfaces]

재정의할 때 접근 범위를 좁히거나 검사 예외를 더 넓힐 수 없습니다. 참조형 반환값은 허용된 하위 타입으로 좁힐 수 있습니다. `null instanceof String`은 거짓이며, 캐스팅 자체는 새 객체를 만들지 않습니다.[^classes][^expressions]

## 7. final·불변성·동등성과 해시

**재대입 제한, 객체 내부의 불변성, 비교 기준을 따로 판단합니다.**[^types][^classes][^object]

| 개념 | 정확한 뜻 | 잘못된 확대 해석 |
| --- | --- | --- |
| `final` 변수 | 한 번 정해진 값의 재대입을 제한합니다. | 참조 대상의 모든 내부 상태도 바뀌지 않는다. |
| `final` 메서드·클래스 | 각각 재정의·상속을 금지합니다. | 메서드 실행이나 객체 생성을 금지한다. |
| `static final` | 클래스 단위의 재대입 제한입니다. | 모든 `static final`은 컴파일타임 상수다. |
| 불변 객체 | 생성 후 관찰 가능한 상태가 바뀌지 않도록 설계합니다. | 필드에 `final`만 붙이면 충분하다. |
| 방어적 복사 | 외부와 내부가 같은 가변 데이터를 공유하지 않도록 필요한 수준으로 복사합니다. | 참조 배열 복사만 하면 내부 객체도 모두 복사된다. |
| 참조형의 `==` | 같은 객체를 가리키는지 비교합니다. 두 참조가 모두 `null`인 경우도 참입니다. | 객체 내용을 자동으로 비교한다. |
| `equals` | 클래스가 정한 동등성입니다. `Object`의 기본 구현은 참조 동일성입니다. | 모든 클래스에서 내용 비교로 구현되어 있다. |
| `hashCode` | 동등한 객체는 같은 해시값이어야 합니다. | 해시값이 같으면 반드시 동등하다. |
| 가변 키 | 해시·동등성에 쓰는 상태를 저장 후 바꾸면 키 조회가 어긋날 수 있습니다. | 같은 객체이므로 어떤 변경을 해도 검색된다. |

`final`은 제한자, `finally`는 예외 흐름의 정리 구문, `finalize()`는 과거의 객체 종료 처리 메서드입니다. `finalize()`는 자바 21에서도 제거 예정으로 비권장 상태이며, 자원 해제 수단으로 의존하지 않습니다.[^object][^statements]

## 8. 제네릭·람다 캡처·고급 타입

**제네릭은 타입 안전성을 높이지만, 대상 객체를 불변으로 만들지는 않습니다.**[^types][^conversions][^classes][^interfaces][^expressions]

| 개념 | 핵심 판단 |
| --- | --- |
| 제네릭의 무공변성 | `Integer`가 `Number`의 하위 타입이어도 `List<Integer>`는 `List<Number>`의 하위 타입이 아닙니다. |
| `List<? extends Number>` | 꺼낸 값을 `Number`로 다룰 수 있습니다. 실제 요소 타입을 모르므로 일반적인 숫자 값을 추가할 수 없습니다. |
| `List<? super Integer>` | 정수 값을 넣을 수 있고, 읽을 때 확실한 타입은 `Object`입니다. |
| 와일드카드의 제한 | 타입상 넣을 수 있는 값과 실제 목록의 수정 허용 여부는 별개입니다. `extends` 목록도 불변 목록이라는 뜻이 아닙니다. |
| 타입 소거 | 컴파일 시 제네릭을 검사하고 소거된 타입·필요한 캐스팅 등을 사용합니다. 모든 제네릭 관련 메타정보가 사라진다는 뜻은 아닙니다. |
| 제네릭 제약 | 기본형을 타입 인수로 쓸 수 없으며, 타입 매개변수 이름을 `자료`로 정해도 `new 자료()`처럼 생성할 수 없습니다. |
| 지역 변수 캡처 | 람다·지역·익명 클래스가 캡처하는 지역 변수는 `final` 또는 실질적 `final`이어야 합니다. 참조 대상의 내부 변경은 별개입니다. |
| 열거형·레코드 | 열거형은 제한된 상수 집합, 레코드는 구성요소 중심의 데이터 표현입니다. 레코드도 가변 객체를 담을 수 있습니다. |
| 봉인 타입·패턴 | 봉인 타입은 허용된 하위 타입을 제한합니다. 패턴은 타입 검사와 값 추출을 연결합니다. |
| 애너테이션 | 코드에 메타정보를 붙입니다. 컴파일 시 처리와 실행 시 조회를 구분하며 보존 정책도 확인합니다. |

## 9. 문자열·숫자·날짜

**반환값을 주는지, 기존 객체를 직접 바꾸는지부터 확인합니다.**[^string][^decimal][^time]

| 대상 | 핵심 규칙 |
| --- | --- |
| `String` | 불변입니다. `replace`·`substring` 등은 결과 문자열을 반환하므로 반환값 사용 여부를 봅니다. |
| 문자열 풀 | 내용이 같은 문자열 리터럴·문자열 상수 표현식은 인턴되어 공유됩니다. 일반적인 내용 비교는 풀에 기대지 않고 `equals`로 합니다. |
| 문자열 길이 | `length()`는 `char` 코드 단위 개수입니다. 바이트 수나 사람이 보는 문자 개수와 항상 같지 않습니다. |
| `StringBuilder`·`StringBuffer` | 둘 다 가변 문자열입니다. 후자는 메서드 단위 동기화를 제공하지만 여러 호출 전체의 원자성은 별도입니다. |
| 래퍼 비교 | 캐시 때문에 우연히 `==`가 참인 사례를 일반화하지 않습니다. 널 여부와 값 비교 목적을 먼저 확인합니다. |
| `BigDecimal` | 정밀한 십진수 계산에 사용합니다. 문자열 기반 생성은 의도한 십진값을 표현하기 쉽고, 나눗셈은 반올림 정책이 필요할 수 있습니다. |
| `2.0`과 `2.00` | 각각 만든 `BigDecimal`은 `compareTo` 결과 0이지만 `equals`는 거짓입니다. 소수 자릿수까지 같은지의 차이입니다. |
| 날짜·시간 | `LocalDate`는 날짜, `Instant`는 시간선의 한 시점입니다. `Period`는 날짜 기반, `Duration`은 초·나노초 기반이며 시간대와 구분합니다. |

## 10. 컬렉션과 원본·복사본

**순서·중복·비교 기준·수정 가능성·원본 공유**의 다섯 가지를 봅니다.[^collections][^list][^arrays]

| 구조 | 핵심 성질·함정 |
| --- | --- |
| `List` | 위치 순서가 있고 중복을 허용합니다. `ArrayList`의 초기 용량과 실제 `size()`는 다릅니다. |
| `ArrayList`·`LinkedList` | 전자는 인덱스 접근에, 후자는 양끝 연결 연산에 특징이 있습니다. 연결 리스트도 특정 인덱스까지 찾는 비용은 남습니다. |
| `Set` | 중복을 허용하지 않습니다. 해시 기반과 정렬 기반의 중복 판정 기준을 구분합니다. |
| `Map` | 키와 값을 연결하며 키는 중복되지 않습니다. `Collection`의 하위 인터페이스는 아닙니다. |
| `HashMap`·`LinkedHashMap`·`TreeMap` | 각각 순서 미보장·정해진 만남 순서·키 정렬 순서를 구분합니다. 연결 해시 맵은 설정에 따라 접근 순서도 사용할 수 있습니다. |
| `Comparable`·`Comparator` | 객체 자체의 자연 순서와 외부 비교 기준입니다. 비교 결과 0은 정렬상 동순위이며 `equals`와 반드시 같지는 않습니다. |
| `Deque`·`PriorityQueue` | 양끝 조작과 우선순위 기반 꺼내기를 구분합니다. 우선순위 큐를 반복자로 돌면 전체 정렬 순서가 보장되지 않습니다. |
| 기본형 배열과 목록 | `Arrays.asList(new int[]{1, 2})`는 정수 두 개가 아니라 배열 하나를 요소로 가진 목록이므로 크기가 1입니다. |
| 삭제·순회 | 정수 목록의 `remove(1)`은 인덱스 삭제입니다. 값 1 삭제는 `remove(Integer.valueOf(1))`입니다. 빠른 실패 예외는 모든 동시 수정을 보장해서 탐지하지 않습니다. |

| 만드는 방법 | 크기 변경 | 요소 교체 | 원본의 구조 변경 반영 |
| --- | --- | --- | --- |
| `new ArrayList<>(원본)` | 가능 | 가능 | 반영하지 않지만 요소 객체는 공유할 수 있습니다. |
| `Arrays.asList(참조배열)` | 불가 | 가능 | 배열과 같은 저장 내용을 보므로 요소 교체가 서로 반영됩니다. |
| `Collections.unmodifiableList(원본)` | 이 뷰로는 불가 | 이 뷰로는 불가 | 원본 변경은 반영됩니다. |
| `List.copyOf(원본)` | 불가 | 불가 | 원본 목록의 후속 변경은 반영하지 않습니다. 요소 객체까지 깊게 복사하지는 않습니다. |
| `List.of(...)` | 불가 | 불가 | 수정 불가 목록이며 `null` 요소를 허용하지 않습니다. |
| `stream.toList()` | 불가 | 불가 | 수정 불가 결과입니다. `Collectors.toList()`는 수정 가능성을 보장하는 계약이 아닙니다. |

수정 불가 목록도 요소 객체 내부는 바뀔 수 있습니다. `List.copyOf`는 `null` 요소를 허용하지 않고, 조건에 따라 기존 수정 불가 목록을 재사용할 수 있으므로 “무조건 새 객체 생성”으로 외우지 않습니다.[^list][^wrappers][^stream]

## 11. 함수형 인터페이스·스트림

**람다는 동작의 표현이고, 스트림은 데이터를 처리하는 계산 흐름입니다.**[^interfaces][^expressions][^streampkg][^optional]

| 개념 | 최종 암기 |
| --- | --- |
| 함수형 인터페이스 | 하나의 추상적인 함수 계약을 가집니다. 기본·정적 메서드가 추가되어도 성립할 수 있습니다. |
| 대표 함수형 타입 | `Predicate`는 조건, `Function`은 변환, `Consumer`는 소비, `Supplier`는 값 공급입니다. |
| 메서드 참조 | 기존 메서드·생성자를 함수형 인터페이스에 대응시킵니다. 직접 호출 결과와 동작의 전달을 구분합니다. |
| 중간·최종 연산 | `filter`·`map`은 중간 연산, `count`·`collect` 등은 최종 연산입니다. 중간 연산은 지연됩니다. |
| `map`·`flatMap` | 요소별 변환과 여러 흐름을 펼쳐 연결하는 변환입니다. |
| 일회성·부수효과 | 소비한 스트림은 재사용하지 않습니다. 최적화로 일부 중간 연산이 생략될 수 있어 `peek`의 실행 횟수에 의존하지 않습니다. |
| 빈 스트림 | `allMatch`·`noneMatch`는 참이고 `anyMatch`는 거짓입니다. |
| 병렬 스트림 | 자동으로 더 빠르거나 공유 상태가 안전해지는 것은 아닙니다. 처리 비용·분할·결합과 순서 요구를 확인합니다. |
| `Optional` | 값의 부재를 표현합니다. `of(null)`은 예외이고 `ofNullable(null)`은 빈 값입니다. |
| `orElse`·`orElseGet` | 전자는 인수 식이 미리 평가됩니다. 후자는 비어 있을 때 공급자의 동작을 실행합니다. |

## 12. 예외·자원 해제·입출력

**어떤 예외가 어디서 발생하고, 어느 코드를 건너뛰며, 무엇이 닫히는지**를 추적합니다.[^exceptions][^statements][^io]

| 개념 | 정확한 구분 |
| --- | --- |
| 예외 계층 | `Throwable` 아래에 `Error`와 `Exception`이 있습니다. `RuntimeException`은 `Exception`의 하위입니다. |
| 검사·비검사 예외 | 실행 중 생기는 상황은 같지만, 검사 예외는 처리하거나 선언했는지를 컴파일러가 검사합니다. `RuntimeException`·`Error` 계열은 비검사입니다. |
| `throw`·`throws` | 예외를 던지는 문장과 발생 가능 예외를 선언하는 부분입니다. 선언만으로 처리되는 것은 아닙니다. |
| `catch` 순서 | 구체적인 예외부터 둡니다. 상위 예외 처리기가 먼저 모두 잡으면 뒤의 하위 예외 처리기는 도달할 수 없습니다. |
| `finally` | 정상적인 제어 흐름에서 반환·예외 발생 시에도 실행됩니다. 여기서 다시 반환하거나 던지면 앞선 결과를 덮을 수 있습니다. |
| 자동 자원 해제 | `try-with-resources`는 자원을 선언한 역순으로 닫습니다. 본문 예외와 닫기 예외가 함께 나면 닫기 예외는 억제된 예외로 붙습니다. |
| 바이트·문자 | `InputStream`·`OutputStream`은 바이트, `Reader`·`Writer`는 문자입니다. 둘의 변환에는 문자셋이 중요합니다. |
| 입력 끝 | 단일 읽기의 `-1`과 `readLine()`의 `null`을 구분합니다. 빈 줄 `""`은 입력 끝이 아닙니다. |
| 버퍼 | 위치 ≤ 한계 ≤ 용량입니다. `flip`은 읽을 범위를 준비하고 `clear`는 상태를 재설정하며 실제 데이터 삭제를 뜻하지 않습니다. |
| 직렬화 | 객체 상태를 저장·전송 형태로 다룹니다. `transient` 필드는 기본 직렬화에서 제외되며 신뢰하지 않는 입력의 역직렬화는 주의합니다. |

## 13. 데이터베이스·통신·보안

**연결 성공, 명령 실행, 업무 성공, 트랜잭션 완료는 같은 단계가 아닙니다.**[^jdbc][^prepared][^resultset][^security]

| 개념 | 핵심 판단 |
| --- | --- |
| 데이터베이스 연결 | 연결 → 명령 준비 → 값 결합 → 실행 → 결과 읽기 → 자원 해제의 순서입니다. 표준 인터페이스와 실제 드라이버를 구분합니다. |
| `PreparedStatement` | 질의 구조와 값을 분리합니다. 매개변수 번호는 1부터이며, 테이블명·열 이름을 값 매개변수로 마음대로 치환하는 방식이 아닙니다. |
| `ResultSet` | 처음에는 첫 행 앞에 있습니다. `next()` 후 읽으며, 숫자 읽기의 0과 데이터베이스 널은 `wasNull()` 등으로 구분합니다. |
| 트랜잭션 | 원자성·일관성·격리성·지속성입니다. 자동 커밋 상태와 업무 단위를 확인하고 커밋·롤백을 관리합니다. |
| 예외와 롤백 | 자바 예외가 났다는 사실만으로 모든 환경에서 자동 롤백되는 것은 아닙니다. 연결·프레임워크의 정책을 확인합니다. |
| 통신 | 소켓은 통신 끝점입니다. 웹 요청의 동기·비동기, 상태 코드, 타임아웃, 본문 검증을 구분합니다. |
| 인코딩·해시·암호화 | 표현 변경, 요약값 계산, 비밀 보호의 목적이 다릅니다. 인코딩은 비밀 보호 수단이 아닙니다. |
| 전자서명 | 서명용 개인키와 검증용 공개키로 무결성과 출처를 확인하는 데 사용합니다. 내용의 기밀성을 자동으로 제공하지는 않습니다. |

## 14. 스레드·동기화·비동기 결과

<mark>동시성 문제는 “무엇을 공유하는가 → 같은 잠금인가 → 복합 연산인가 → 완료와 가시성이 보장되는가” 순서로 봅니다.</mark>[^threads][^memory][^concurrent]

| 개념 | 최종 판별 기준 |
| --- | --- |
| `start()`·`run()` | 전자는 새 실행 흐름을 시작합니다. 일반 플랫폼 스레드의 `run()` 직접 호출은 현재 흐름의 메서드 호출입니다. |
| 스레드 재시작 | 같은 스레드 객체는 종료했더라도 다시 `start()`할 수 없습니다. |
| 상태 | `NEW`·`RUNNABLE`·`BLOCKED`·`WAITING`·`TIMED_WAITING`·`TERMINATED`입니다. 실행 중과 실행 가능은 `RUNNABLE` 안에서 다룹니다. |
| `join()` | 호출자가 대상 스레드의 종료를 기다립니다. 시간 제한이 있는 호출은 시간 만료인지 종료 확인인지 구분합니다. |
| `sleep()`·`wait()` | 전자는 보유 모니터를 놓지 않습니다. 후자는 호출 대상 모니터를 놓고 기다리며, 해당 모니터를 소유해야 합니다. |
| `notify()` | 통지 즉시 잠금을 넘기는 것은 아닙니다. 깨어난 쪽은 잠금을 다시 얻고 조건을 반복 검사합니다. |
| 인터럽트 | 강제 종료가 아니라 협력적 중단 요청입니다. `Thread.interrupted()`는 현재 스레드 상태를 확인하면서 지웁니다. |
| `synchronized` | 같은 모니터로 보호하는 구간의 상호 배제와 가시성을 연결합니다. 인스턴스 잠금과 클래스 잠금은 다릅니다. |
| `volatile` | 해당 필드의 가시성·순서 보장에 관여하지만 `값++` 전체를 원자적으로 만들지는 않습니다. |
| 원자 변수·명시적 잠금 | 원자적 증가와 여러 연산을 묶는 잠금은 목적이 다릅니다. 별개 원자 변수 둘의 갱신이 한꺼번에 원자적인 것은 아닙니다. |
| `Future` | 결과를 기다리거나 실패를 확인합니다. `isDone()`은 성공뿐 아니라 예외·취소에 따른 완료도 포함합니다. |
| 실행 서비스 | `shutdown()`은 새 작업을 거절하고 종료를 요청하지만, 그 호출 자체가 모든 작업의 완료를 기다리지는 않습니다. |
| `CompletableFuture` | 비동기 결과를 변환·결합합니다. 비동기 실행 여부와 실제 실행기를 확인합니다. |
| 스레드 지역 값·동시성 컬렉션 | `ThreadLocal`은 재사용 스레드에서 정리 경계를 확인합니다. 안전한 맵에 담았다고 값 객체 내부까지 안전해지지 않습니다. |
| 가상 스레드 | 많은 대기 작업을 다루는 확장성을 돕습니다. 계산 자체가 자동으로 빨라지거나 연결 같은 외부 자원이 무한해지는 것은 아닙니다. |

## 잘 놓치는 핵심

새 규칙을 더 외우기보다 **틀린 문장을 정확한 문장으로 바꾸는 연습**을 합니다. 아래는 앞 절의 조건을 다시 확인하는 표입니다.

| 틀리기 쉬운 문장 | 이렇게 고칩니다 |
| --- | --- |
| 객체를 전달하므로 참조 전달이다. | 참조값을 복사하는 값 전달입니다. |
| `final`이면 객체가 불변이다. | 재대입 제한과 내부 상태 변경은 별개입니다. |
| 하위 객체를 만들었으니 모든 멤버가 하위 기준이다. | 재정의 인스턴스 메서드와 필드·정적 메서드를 나눕니다. |
| 수정 불가 목록이면 내용은 영원히 같다. | 원본을 보는 뷰와 가변 요소의 내부 변경을 따로 확인합니다. |
| 해시값이 같으면 같은 객체다. | 동등하면 해시값이 같아야 하지만 역은 성립하지 않습니다. |
| 검사 예외는 컴파일할 때 발생한다. | 처리·선언 의무를 컴파일러가 검사한다는 뜻입니다. |
| 잠깐 기다렸으므로 결과가 보인다. | 완료와 가시성을 보장하는 `join`·잠금 등의 연결을 확인합니다. |
| 가비지 컬렉션이 파일까지 제때 닫는다. | 메모리 회수와 외부 자원 해제는 별개입니다. |

## 시험·면접

**컴파일 → 실제 객체 → 평가·호출 → 변경 대상 → 예외 → 동시성 → 출력**을 순서대로 확인합니다.

| 순서 | 확인 질문 | 대표 함정 |
| --- | --- | --- |
| 1 | 선언·대입·접근·반환·버전이 맞는가? | 실행 불가능한 코드의 출력부터 계산합니다. |
| 2 | 어떤 변수들이 같은 객체를 가리키는가? | 참조 복사를 객체 복사로 계산합니다. |
| 3 | 계산 타입과 호출 기준이 무엇인가? | 정수 나눗셈·넘침·필드 가림을 놓칩니다. |
| 4 | 원본·참조 변수·복사본 중 무엇이 바뀌는가? | 반환값을 버리거나 뷰를 독립 복사본으로 봅니다. |
| 5 | 첫 예외와 정리 코드의 실행 위치는 어디인가? | 예외 이후 건너뛰는 문장까지 출력합니다. |
| 6 | 순서·완료·원자성이 실제로 보장되는가? | 스레드 시작 순서를 출력 순서로 확정합니다. |
| 7 | 확정값인가, 여러 결과가 가능한가? | 관찰한 한 번의 실행을 언어의 보장으로 외웁니다. |

면접에서는 **정의 한 문장 → 비교 한 가지 → 반례 하나**로 답합니다. 예를 들어 값 전달은 “값을 복사한다 → 객체일 때는 참조값을 복사한다 → 내부 변경은 보이지만 매개변수 재대입은 호출자 변수를 바꾸지 않는다”로 설명할 수 있습니다.

## 예시로 한 바퀴

다음은 **값 전달 → 객체 공유 → 수정 불가 복사 → 스트림 계산**을 연결한 전체 프로그램입니다. `Main.java`로 저장해 실행합니다.

```java
import java.util.ArrayList;
import java.util.List;

public class Main {
    static class 점수 {
        int 값;
        점수(int 값) { this.값 = 값; }
    }

    static void 변경(점수 대상) {
        대상.값 += 10;
        대상 = new 점수(0);
    }

    public static void main(String[] 인수) {
        final List<점수> 원본 = new ArrayList<>();
        원본.add(new 점수(60));
        List<점수> 복사 = List.copyOf(원본);
        변경(원본.get(0));
        원본.add(new 점수(80));
        int 합계 = 원본.stream().mapToInt(항목 -> 항목.값).sum();
        System.out.println(원본.size() + " " + 복사.size());
        System.out.println(복사.get(0).값);
        System.out.println(합계);
    }
}
```

출력은 다음과 같습니다.

```text
2 1
70
150
```

`final`은 `원본`의 재대입만 제한합니다. `List.copyOf`로 만든 목록은 추가를 반영하지 않아 크기 1이지만, 첫 점수 객체는 공유하므로 70을 봅니다. `대상 = new 점수(0)`은 매개변수만 바꾸며, 합계는 원본의 70과 80을 더한 150입니다.

## 객관식 문제

직접 구성한 복습용 4지선다 6문제입니다. 코드 조각은 필요한 가져오기와 실행 틀을 갖춘 것으로 보며, 모든 문제는 자바 21 기준입니다.

### 문제 1. 계산 타입

다음 코드의 출력은 무엇입니까?

```java
double 평균 = 7 / 2;
byte 수 = 3;
수 += 2;
System.out.println(평균 + " " + 수);
```

① `3.5 5`  
② `3.0 5`  
③ 컴파일 오류  
④ `3.0 3`

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ②**

① 정수끼리 먼저 나누므로 소수 부분을 잃습니다.  
② 정수 3이 `double`로 대입되어 3.0이며 복합 대입 후 수는 5입니다.  
③ `수 += 2`에는 필요한 축소 변환이 포함되어 컴파일됩니다.  
④ 복합 대입은 실제 변수의 값을 갱신합니다.

</details>

### 문제 2. 필드와 재정의

다음 전체 프로그램의 출력은 무엇입니까?

```java
public class Main {
    static class 부모 {
        int 값 = 10;
        int 읽기() { return 값; }
    }
    static class 자식 extends 부모 {
        int 값 = 20;
        @Override int 읽기() { return 값; }
    }
    public static void main(String[] 인수) {
        부모 대상 = new 자식();
        System.out.println(대상.값 + " " + 대상.읽기());
    }
}
```

① `10 10`  
② `20 20`  
③ `10 20`  
④ `20 10`

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ③**

① 재정의 메서드는 실제 자식 객체의 구현을 호출하므로 뒤는 20입니다.  
② 필드는 선언 타입인 부모를 기준으로 선택하므로 앞은 10입니다.  
③ 필드 10과 자식의 재정의 메서드 결과 20이 맞습니다.  
④ 필드와 메서드의 선택 기준을 거꾸로 적용했습니다.

</details>

### 문제 3. final과 복사

다음 중 옳은 설명은 무엇입니까?

① `final` 참조는 대상 객체의 모든 필드 변경을 금지합니다.  
② `List.copyOf`는 모든 요소 객체를 깊게 복사합니다.  
③ 참조형 매개변수에 새 객체를 대입하면 호출자의 참조 변수도 바뀝니다.  
④ `List.copyOf` 결과가 원본과 같은 가변 요소 객체를 가리킬 수 있습니다.

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ④**

① 제한하는 것은 참조값의 재대입이며 대상 내부 변경은 별개입니다.  
② 목록의 요소 참조가 유지될 수 있으므로 깊은 복사가 아닙니다.  
③ 참조값을 복사해서 전달하므로 매개변수 재대입은 호출자 변수에 영향을 주지 않습니다.  
④ 목록 구조는 후속 변경을 반영하지 않아도 같은 가변 요소를 공유할 수 있습니다.

</details>

### 문제 4. 비교·해시·스트림

다음 중 옳은 설명은 무엇입니까?

① 해시값이 같으면 `equals`의 결과도 반드시 참입니다.  
② 빈 스트림에서 `allMatch`의 결과는 참입니다.  
③ `HashMap`은 삽입 순서를 보장합니다.  
④ `stream.toList()`의 결과에는 항상 요소를 추가할 수 있습니다.

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ②**

① 서로 다른 객체의 해시 충돌이 가능합니다.  
② 조건을 어기는 요소가 없으므로 참입니다.  
③ `HashMap`에는 삽입 순서 보장이 없습니다.  
④ 해당 결과는 수정 불가 목록입니다. 수정할 목록이 필요하면 목적에 맞게 수집하거나 복사합니다.

</details>

### 문제 5. 예외와 자원

자동 자원 해제 구문에서 첫째 자원, 둘째 자원 순으로 선언했습니다. 본문에서 예외가 발생하고 두 자원의 닫기에서도 각각 예외가 발생했습니다. 옳은 설명은 무엇입니까?

① 자원은 둘째·첫째 순으로 닫히고, 본문 예외에 닫기 예외들이 억제된 예외로 붙습니다.  
② 본문에서 실패했으므로 자원은 닫히지 않습니다.  
③ 자원은 첫째·둘째 순서로 닫힙니다.  
④ 가장 마지막 닫기 예외만 남고 본문 예외는 반드시 사라집니다.

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ①**

① 역순 해제와 주 예외·억제된 예외의 구분이 맞습니다.  
② 본문 예외가 발생해도 자동 자원 해제가 수행됩니다.  
③ 선언 순서의 역순으로 닫힙니다.  
④ 이 조건에서는 본문 예외가 주 예외로 유지됩니다. 정리 구문에서 직접 결과를 덮어쓰는 경우와 다릅니다.

</details>

### 문제 6. 동시성과 완료

다음 중 옳은 설명은 무엇입니까?

① `volatile int 횟수`이면 여러 스레드의 `횟수++`는 원자적입니다.  
② `sleep`을 충분히 길게 하면 다른 스레드의 종료와 변경값의 가시성이 보장됩니다.  
③ `Future.isDone()`이 참이면 결과가 성공했다는 뜻입니다.  
④ 종료를 실제로 확인한 `join()`은 대상의 종료 전 동작과 이후 관찰 사이의 가시성 연결을 제공합니다.

<details markdown="1">
<summary>정답과 선택지별 해설</summary>

**정답: ④**

① 읽기·계산·쓰기 전체는 원자적이지 않습니다.  
② 시간 경과는 종료 확인이나 동기화 규칙을 대신하지 않습니다.  
③ 예외·취소로 완료된 경우도 포함합니다.  
④ 스레드 종료를 확인하는 동기화 관계가 성립합니다. 시간 제한 대기가 단지 만료된 경우와 구분합니다.

</details>

## 버전과 검증 범위

자바 25에는 인스턴스 `main`과 유연한 생성자 본문이 정식 도입되었습니다. 따라서 전통적인 진입점과 “상위 생성자 호출 전에는 문장을 둘 수 없다”는 설명을 모든 버전의 절대 규칙으로 확대하지 않습니다. 이 글의 코드 문제는 해당 변화와 섞지 않습니다.[^versions]

**본문의 자바 코드 3개를 자바 21로 컴파일·실행하여 제시한 출력과 대조했습니다.** 별도 확인용 프로그램에서 계산·참조·컬렉션·예외·완료 관찰에 관한 검사 45개를 통과했고, 잘못된 선언·대입·예외 처리 등 10개 사례는 컴파일러가 거부하는지 확인했습니다.

검사용 프로그램은 문서 본문의 예제 수에 포함하지 않습니다. 실제 서버·데이터베이스·프레임워크 연동은 실행하지 않았으며, 동시성의 보장과 버전 차이는 한 번의 관찰 결과가 아니라 공식 명세를 기준으로 판단합니다.
