`ACID`는 <mark>Transaction이 안정적으로 처리되기 위해 지켜야 하는 네 가지 핵심 성질</mark>입니다.

각각 **Atomicity, Consistency, Isolation, Durability**를 의미합니다.

<blockquote class="prompt-info">
<p>한 줄: ACID는 Transaction을 안전하게 처리하기 위한 원자성·일관성·격리성·지속성입니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

ACID = 모두 반영하거나 모두 취소, 규칙 유지, 서로 간섭 최소화, 확정 결과 유지입니다.

</details>

## 전체 구조

| 성질 | 핵심 의미 |
| --- | --- |
| Atomicity | 전부 성공하거나 전부 실패 |
| Consistency | Transaction 전후 데이터 규칙 유지 |
| Isolation | 동시에 실행되는 Transaction끼리 간섭 최소화 |
| Durability | COMMIT된 결과는 장애 후에도 유지 |

```text
A
→ Atomicity
→ 원자성

C
→ Consistency
→ 일관성

I
→ Isolation
→ 격리성

D
→ Durability
→ 지속성
```

## Atomicity · 원자성

원자성은 <mark>Transaction의 작업이 전부 수행되거나 전부 취소되어야 한다는 성질</mark>입니다.

계좌이체를 예로 들어보겠습니다.

### 입력 Table · ACCOUNT

| ACCOUNT_ID | BALANCE |
| --- | ---: |
| A | 50000 |
| B | 30000 |

A에서 B로 10,000원을 이체합니다.

```sql
BEGIN TRANSACTION;

UPDATE ACCOUNT
SET BALANCE = BALANCE - 10000
WHERE ACCOUNT_ID = 'A';

UPDATE ACCOUNT
SET BALANCE = BALANCE + 10000
WHERE ACCOUNT_ID = 'B';

COMMIT;
```

정상적으로 끝나면 두 작업이 모두 반영됩니다.

### 결과 Table

| ACCOUNT_ID | BALANCE |
| --- | ---: |
| A | 40000 |
| B | 40000 |

하지만 A 계좌에서 돈만 빠지고 B 계좌 입금이 실패하면 안 됩니다.

```text
출금 성공
+
입금 실패
→ 허용하면 안 됨
```

따라서 문제가 생기면 전체 작업을 되돌려야 합니다.

```text
모두 성공
→ COMMIT

하나라도 실패
→ 전체 취소
```

이것이 원자성입니다.

## Consistency · 일관성

일관성은 <mark>Transaction 수행 전과 후에 데이터베이스가 정해진 규칙을 만족해야 한다는 성질</mark>입니다.

예를 들어 계좌 잔액은 음수가 될 수 없다는 규칙이 있다고 가정합니다.

```text
BALANCE >= 0
```

Transaction 전 데이터가 이 규칙을 만족했다면 정상적으로 완료된 후에도 규칙을 만족해야 합니다.

### 정상 상태

| ACCOUNT_ID | BALANCE |
| --- | ---: |
| A | 50000 |
| B | 30000 |

### 잘못된 상태 예시

| ACCOUNT_ID | BALANCE |
| --- | ---: |
| A | -10000 |
| B | 90000 |

업무 규칙상 잔액이 음수가 허용되지 않는다면 이런 상태는 일관성을 깨뜨립니다.

```text
Transaction 전
→ 규칙 만족

Transaction 후
→ 규칙 만족
```

Primary Key, Foreign Key, CHECK 같은 제약조건도 일관성 유지에 도움을 줍니다.

## Isolation · 격리성

격리성은 <mark>여러 Transaction이 동시에 실행되더라도 서로의 중간 상태에 함부로 영향을 주지 않도록 하는 성질</mark>입니다.

두 Transaction이 동시에 같은 계좌를 수정한다고 가정해보겠습니다.

```text
Transaction 1
→ A 계좌에서 10,000원 출금

Transaction 2
→ A 계좌에서 5,000원 출금
```

동시에 실행될 때 처리 순서와 읽는 시점이 꼬이면 잘못된 결과가 나올 수 있습니다.

격리성은 이런 동시 실행 문제를 제어합니다.

```text
동시 실행
→ 서로의 중간 상태 간섭 최소화
```

격리 수준이 낮으면 다음과 같은 문제가 나타날 수 있습니다.

```text
Dirty Read
Non-repeatable Read
Phantom Read
```

이 내용은 별도 글에서 자세히 다룹니다.

<blockquote class="prompt-warning">
<p>격리성을 강하게 유지할수록 동시성은 낮아질 수 있으므로 성능과 격리 수준 사이의 균형이 중요합니다.</p>
</blockquote>

## Durability · 지속성

지속성은 <mark>COMMIT된 Transaction의 결과가 시스템 장애가 발생해도 유지되어야 한다는 성질</mark>입니다.

예를 들어 다음 Transaction이 정상적으로 COMMIT되었다고 가정합니다.

```sql
UPDATE ACCOUNT
SET BALANCE = 40000
WHERE ACCOUNT_ID = 'A';

COMMIT;
```

그 직후 시스템이 종료되더라도 확정된 결과는 사라지면 안 됩니다.

```text
COMMIT 완료
↓
시스템 장애
↓
결과 유지
```

DBMS는 로그, 체크포인트, 복구 기능 등을 이용해 이러한 지속성을 지원합니다.

## 네 성질을 계좌이체로 한 번에 보기

계좌이체 하나로 ACID를 모두 연결할 수 있습니다.

### Atomicity

```text
출금 + 입금
→ 둘 다 성공 또는 둘 다 취소
```

### Consistency

```text
잔액 규칙
참조 규칙
제약조건
→ Transaction 전후 유지
```

### Isolation

```text
여러 이체가 동시에 실행
→ 서로의 중간 작업 간섭 최소화
```

### Durability

```text
COMMIT된 이체
→ 장애가 발생해도 결과 유지
```

## ACID 비교

| 성질 | 핵심 질문 |
| --- | --- |
| Atomicity | 작업이 일부만 반영될 수 있는가? |
| Consistency | 데이터 규칙이 깨지는가? |
| Isolation | 동시에 실행되는 작업끼리 간섭하는가? |
| Durability | COMMIT 결과가 장애 후에도 남는가? |

```text
일부만 실행되는 문제
→ Atomicity
```

```text
규칙이 깨지는 문제
→ Consistency
```

```text
동시 실행 간섭
→ Isolation
```

```text
확정 결과가 사라짐
→ Durability
```

## Atomicity와 Consistency 차이

둘은 자주 헷갈립니다.

### Atomicity

```text
작업 단위가 전부 반영되었는가?
```

예를 들어 출금만 되고 입금이 안 된 경우입니다.

### Consistency

```text
데이터베이스 규칙이 유지되었는가?
```

예를 들어 잔액이 음수가 되었거나 Foreign Key 규칙이 깨진 경우입니다.

| 구분 | Atomicity | Consistency |
| --- | --- | --- |
| 초점 | 작업의 전부 또는 전무 | 데이터 규칙 유지 |
| 대표 문제 | 일부 SQL만 반영 | 제약조건·업무 규칙 위반 |

## Isolation과 Durability 차이

### Isolation

```text
동시에 실행되는 Transaction 사이 문제
```

### Durability

```text
COMMIT 이후 장애 문제
```

```text
동시 실행
→ Isolation
```

```text
장애 후 유지
→ Durability
```

## 잘 놓치는 핵심

### 1. Atomicity는 전부 또는 전무

```text
All or Nothing
```

처럼 기억하면 됩니다.

### 2. Consistency는 규칙 유지

Transaction 전후에 데이터베이스의 제약조건과 업무 규칙이 지켜져야 합니다.

### 3. Isolation은 동시성 문제와 연결

여러 Transaction이 동시에 실행될 때 서로 간섭하는 문제를 다룹니다.

### 4. Durability는 COMMIT 이후

COMMIT된 결과가 장애가 발생해도 유지되어야 합니다.

## 시험·면접

### 핵심 암기

```text
Atomicity
→ 전부 성공 또는 전부 취소
```

```text
Consistency
→ 규칙 유지
```

```text
Isolation
→ 동시 Transaction 격리
```

```text
Durability
→ COMMIT 결과 유지
```

### 시험 함정

시스템 장애가 발생한 뒤에도 COMMIT 결과가 남아 있어야 한다는 설명은 `Atomicity`가 아니라 `Durability`입니다.

또한 동시에 실행되는 Transaction 사이의 간섭 문제는 `Isolation`과 관련됩니다.

### 면접 짧은 답변

ACID는 Transaction이 안정적으로 처리되기 위한 네 가지 성질입니다. Atomicity는 모든 작업이 전부 성공하거나 전부 취소되는 원자성, Consistency는 Transaction 전후 데이터 규칙을 유지하는 일관성, Isolation은 동시에 실행되는 Transaction 사이의 간섭을 줄이는 격리성, Durability는 COMMIT된 결과가 장애 이후에도 유지되는 지속성을 의미합니다.

## 객관식 문제

### 문제 1 · Atomicity

계좌이체에서 출금은 성공했지만 입금이 실패한 경우 전체 작업을 취소하는 성질은?

① Consistency  
② Atomicity  
③ Isolation  
④ Durability

<details markdown="1">
<summary>정답</summary>

②

Transaction의 일부만 반영되지 않도록 전부 성공하거나 전부 취소하는 성질은 Atomicity입니다.

</details>

### 문제 2 · Consistency

Transaction 전후에 Primary Key, Foreign Key, 잔액 규칙 등이 유지되어야 한다는 성질은?

① Atomicity  
② Consistency  
③ Isolation  
④ Durability

<details markdown="1">
<summary>정답</summary>

②

데이터베이스의 규칙과 유효한 상태를 유지하는 성질은 Consistency입니다.

</details>

### 문제 3 · Isolation

여러 Transaction이 동시에 실행될 때 서로의 중간 상태에 영향을 받지 않도록 하는 성질은?

① Atomicity  
② Consistency  
③ Isolation  
④ Durability

<details markdown="1">
<summary>정답</summary>

③

동시에 실행되는 Transaction 사이의 간섭을 제어하는 성질은 Isolation입니다.

</details>

### 문제 4 · Durability

COMMIT 직후 시스템 장애가 발생해도 변경 결과가 유지되어야 한다는 성질은?

① Atomicity  
② Consistency  
③ Isolation  
④ Durability

<details markdown="1">
<summary>정답</summary>

④

확정된 Transaction 결과가 장애 이후에도 유지되는 성질은 Durability입니다.

</details>

### 문제 5 · 구분

다음 연결 중 옳지 않은 것은?

① Atomicity → 전부 또는 전무  
② Consistency → 데이터 규칙 유지  
③ Isolation → 동시 실행 간섭 제어  
④ Durability → 일부 SQL만 실행 허용

<details markdown="1">
<summary>정답</summary>

④

Durability는 일부 SQL만 실행하는 성질이 아니라 COMMIT된 결과를 지속적으로 보존하는 성질입니다.

</details>

## ACID 전체 요약

| 성질 | 한 줄 핵심 |
| --- | --- |
| Atomicity | 전부 성공 또는 전부 취소 |
| Consistency | 데이터 규칙 유지 |
| Isolation | 동시 Transaction 간섭 최소화 |
| Durability | COMMIT 결과 유지 |

```text
A
→ All or Nothing

C
→ 규칙 유지

I
→ 동시 실행 격리

D
→ 확정 결과 지속
```

<p>ACID 문제에서는 일부 실행, 규칙 위반, 동시 실행, 장애 후 유지 중 어떤 상황인지 먼저 구분하면 빠르게 답을 찾을 수 있습니다.</p>
</blockquote>
