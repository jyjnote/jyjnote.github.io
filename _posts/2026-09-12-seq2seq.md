Seq2Seq(Sequence-to-Sequence)는 **하나의 Sequence를 입력받아 다른 Sequence를 출력하는 모델 구조**입니다.  
번역, 요약, 질의응답처럼 입력 길이와 출력 길이가 서로 달라도 처리할 수 있습니다.

<blockquote class="prompt-info">
<p>한 줄: 입력 Sequence를 Encoder가 읽고, Decoder가 그 정보를 이용해 출력 Sequence를 하나씩 생성합니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

Seq2Seq는 Encoder가 입력을 표현으로 바꾸고 Decoder가 그 표현을 조건으로 출력 Sequence를 생성하는 구조입니다.

</details>

## 가장 쉬운 예시

영어 문장을 한국어로 번역한다고 하겠습니다.

```text
입력
I love AI

출력
나는 AI를 좋아한다
```

입력 Token 수와 출력 Token 수는 같을 필요가 없습니다.

```text
Source Sequence
→ Encoder
→ Context
→ Decoder
→ Target Sequence
```

<mark>Seq2Seq의 핵심은 Sequence 하나를 다른 Sequence로 변환하는 것입니다.</mark>

## Seq2Seq는 언어모델과 무엇이 다른가

일반적인 Autoregressive Language Model은 이전 Token을 보고 다음 Token을 예측합니다.

```text
I love
→ AI
```

Seq2Seq는 **별도의 입력 Sequence**를 조건으로 출력 Sequence를 생성합니다.

```text
Source
I love AI

↓ 조건

Target
나는 AI를 좋아한다
```

확률로 보면 일반 Language Model은

$$P(y_1,\dots,y_T)=\prod_{t=1}^T P(y_t\mid y_{<t})$$

Seq2Seq는

$$P(y_1,\dots,y_T\mid x)=\prod_{t=1}^T P(y_t\mid y_{<t},x)$$

입니다.

- `x`: 입력 Source Sequence
- `y`: 출력 Target Sequence

<mark>Seq2Seq Decoder는 이전 출력 Token뿐 아니라 입력 Sequence 정보도 함께 조건으로 사용합니다.</mark>

## 대표적인 활용

```text
기계 번역
영어 → 한국어

문서 요약
긴 문서 → 짧은 요약

질의응답
질문 → 답변

문법 교정
잘못된 문장 → 수정 문장

음성 인식
음성 Sequence → Text Sequence
```

## 고전적인 Seq2Seq 구조

초기 Seq2Seq는 주로 RNN, LSTM, GRU를 사용했습니다.

```text
Source
↓
RNN Encoder
↓
Context Vector
↓
RNN Decoder
↓
Target
```

Encoder가 입력을 순서대로 읽습니다.

```text
I
↓
love
↓
AI
```

마지막 Hidden State를 Context Vector로 사용합니다.

Decoder는 이 Context Vector를 바탕으로 출력을 생성합니다.

```text
<BOS>
→ 나는
→ AI를
→ 좋아한다
→ <EOS>
```

## Encoder

RNN Encoder를 단순화하면 현재 입력과 이전 Hidden State를 사용합니다.

$$h_t=	anh(x_tW_x+h_{t-1}W_h+b)$$

- `x_t`: 현재 입력 Token의 Embedding
- `h_t`: 현재 Hidden State
- `h_(t-1)`: 이전 Hidden State

입력:

```text
I love AI
```

흐름:

```text
I
→ h1

love + h1
→ h2

AI + h2
→ h3
```

고전적인 Seq2Seq에서는 마지막 Hidden State `h3`를 Context Vector로 사용할 수 있습니다.

## Python으로 Encoder 직접 계산

설명을 위해 Embedding Dimension과 Hidden Dimension을 모두 2로 두겠습니다.

```python
import numpy as np

np.set_printoptions(precision=4, suppress=True)

tokens = ["I", "love", "AI"]

E = np.array([
    [1.0, 0.0],  # I
    [0.0, 1.0],  # love
    [1.0, 1.0],  # AI
])

print(E)

# 결과
# [[1. 0.]
#  [0. 1.]
#  [1. 1.]]
```

Encoder Weight를 임의로 정합니다.

```python
W_x = np.array([
    [0.8, 0.2],
    [0.1, 0.7],
])

W_h = np.array([
    [0.5, 0.0],
    [0.0, 0.5],
])

h = np.array([0.0, 0.0])
```

첫 번째 Token `I`:

```python
x = E[0]

h = np.tanh(x @ W_x + h @ W_h)

print(h)

# 결과
# [0.664  0.1974]
```

두 번째 Token `love`:

```python
x = E[1]

h = np.tanh(x @ W_x + h @ W_h)

print(h)

# 결과
# [0.407  0.6633]
```

세 번째 Token `AI`:

```python
x = E[2]

h = np.tanh(x @ W_x + h @ W_h)

print(h)

# 결과
# [0.8018 0.8431]
```

전체 Hidden State는

```text
I
→ [0.664  0.1974]

love
→ [0.407  0.6633]

AI
→ [0.8018 0.8431]
```

입니다.

마지막 Hidden State:

```python
context = h

print(context)

# 결과
# [0.8018 0.8431]
```

이 값을 Context Vector라고 하겠습니다.

## Context Vector

고전적인 Seq2Seq의 핵심은 Encoder가 Source Sequence를 하나의 Context Vector로 압축한다는 것입니다.

```text
I love AI
↓
Encoder
↓
[0.8018 0.8431]
```

Decoder는 이 Vector를 보고 번역을 시작합니다.

<blockquote class="prompt-warning">
<p>긴 문장을 하나의 고정 길이 Vector에 모두 압축하면 정보 손실이 생길 수 있습니다. 이것이 초기 Seq2Seq의 대표적인 한계입니다.</p>
</blockquote>

## Decoder

Decoder도 RNN 구조를 사용할 수 있습니다.

단순화하면

$$s_t=	anh(y_{t-1}W_y+s_{t-1}W_h+cW_c)$$

- `y_(t-1)`: 이전 Target Token Embedding
- `s_(t-1)`: 이전 Decoder Hidden State
- `c`: Encoder Context Vector

즉 Decoder는

```text
이전 출력 Token
+
이전 Decoder State
+
Encoder Context
```

를 사용합니다.

## Decoder 입력을 Shift한다

Target:

```text
나는 AI를 좋아한다
```

학습할 때 Decoder 입력은 보통 한 칸 Shift합니다.

```text
Decoder Input
<BOS> 나는 AI를

Target
나는 AI를 좋아한다
```

각 위치에서

```text
<BOS>
→ 나는

<BOS> 나는
→ AI를

<BOS> 나는 AI를
→ 좋아한다
```

를 학습합니다.

## Python으로 Decoder 계산

Decoder 입력 Embedding을 임의로 정하겠습니다.

```python
target_tokens = ["<BOS>", "나는", "AI를"]

E_tgt = np.array([
    [0.2, 0.1],  # <BOS>
    [0.1, 0.9],  # 나는
    [0.8, 0.2],  # AI를
])
```

Decoder Weight:

```python
W_y = np.array([
    [0.7, 0.1],
    [0.2, 0.6],
])

W_dh = np.array([
    [0.4, 0.0],
    [0.0, 0.4],
])

W_c = np.array([
    [0.5, 0.1],
    [0.1, 0.5],
])
```

초기 Decoder State는 설명을 위해 Encoder Context로 시작하겠습니다.

```python
d = context.copy()
```

첫 번째 위치:

```python
y = E_tgt[0]

d = np.tanh(
    y @ W_y
    + d @ W_dh
    + context @ W_c
)

print(d)

# 결과
# [0.7469 0.7254]
```

두 번째 위치:

```python
y = E_tgt[1]

d = np.tanh(
    y @ W_y
    + d @ W_dh
    + context @ W_c
)

print(d)

# 결과
# [0.7755 0.8721]
```

세 번째 위치:

```python
y = E_tgt[2]

d = np.tanh(
    y @ W_y
    + d @ W_dh
    + context @ W_c
)

print(d)

# 결과
# [0.8843 0.782 ]
```

세 위치의 Hidden State를 실제 코드에서 모으려면 다음처럼 작성합니다.

```python
d = context.copy()
decoder_states = []

for y in E_tgt:
    d = np.tanh(
        y @ W_y
        + d @ W_dh
        + context @ W_c
    )
    decoder_states.append(d.copy())

decoder_states = np.array(decoder_states)

print(decoder_states)

# 결과
# [[0.7469 0.7254]
#  [0.7755 0.8721]
#  [0.8843 0.7820]]
```

Decoder Hidden State는

```text
<BOS>
→ [0.7469 0.7254]

나는
→ [0.7755 0.8721]

AI를
→ [0.8843 0.782 ]
```

처럼 변합니다.

## Hidden State에서 Token 확률 만들기

Decoder Hidden State 자체는 단어가 아닙니다.

Vocabulary 크기로 Projection한 뒤 Softmax를 적용합니다.

```text
Decoder Hidden State
→ Linear
→ Logit
→ Softmax
→ 다음 Token 확률
```

Vocabulary:

```text
나는
AI를
좋아한다
<EOS>
```

아래 Weight는 **계산 흐름을 보여주기 위한 설명용 값**입니다.  
실제 모델에서는 이 값들이 학습으로 결정됩니다.

```python
vocab = ["나는", "AI를", "좋아한다", "<EOS>"]

W_vocab = np.array([
    [-14.5730, -9.1588, 23.7319, 0.0000],
    [-17.6081, 22.2321, -4.6240, 0.0000],
])

b_vocab = np.array([
    26.6578,
    -9.2866,
    -14.3712,
    -1.0000,
])

logits = decoder_states @ W_vocab + b_vocab

print(logits)

# 결과
# [[ 3.  0.  0. -1.]
#  [ 0.  3.  0. -1.]
#  [ 0.  0.  3. -1.]]
```

Softmax:

```python
def softmax(x):
    x = x - np.max(x)
    exp_x = np.exp(x)
    return exp_x / np.sum(exp_x)

probs = np.array([
    softmax(row)
    for row in logits
])

print(probs)

# 결과
# [[0.8945 0.0445 0.0445 0.0164]
#  [0.0445 0.8945 0.0445 0.0164]
#  [0.0445 0.0445 0.8945 0.0164]]
```

각 위치의 최대 확률을 보면 다음과 같습니다.

```text
<BOS>
→ 나는      0.8945

<BOS> 나는
→ AI를      0.8945

<BOS> 나는 AI를
→ 좋아한다  0.8945
```

즉 예시 계산에서도 Target이 순서대로 이어집니다.

<mark>Decoder Hidden State를 Vocabulary Logit으로 바꾸고 Softmax를 적용해야 실제 다음 Token 확률을 얻을 수 있습니다.</mark>

## Seq2Seq 학습

정답 Target이

```text
나는 AI를 좋아한다
```

라면 각 위치의 정답은 다음과 같습니다.

```text
Position 1
정답 → 나는

Position 2
정답 → AI를

Position 3
정답 → 좋아한다
```

모델이 만든 확률과 실제 정답을 비교합니다.

주로 Cross Entropy Loss를 사용합니다.

한 Token의 Loss는

$$L_t=-\log P(y_t)$$

전체 Sequence Loss는 단순화하면

$$L=-\sum_{t=1}^T\log P(y_t\mid y_{<t},x)$$

입니다.

정답 Token의 확률이 낮으면 Loss가 커집니다.

## Teacher Forcing

초기 Seq2Seq에서 매우 중요한 개념입니다.

학습할 때 이전 위치에 모델이 예측한 Token 대신 **실제 정답 Token**을 넣어주는 방식입니다.

예:

```text
정답
나는 AI를 좋아한다
```

모델이 첫 번째 위치에서 잘못 예측했더라도 학습 시 다음 입력에는 실제 정답 `나는`을 넣을 수 있습니다.

```text
<BOS>
→ 나는 예측

다음 입력
<BOS> 나는
```

이것을 Teacher Forcing이라고 합니다.

<mark>Teacher Forcing은 학습 시 이전 정답 Token을 Decoder 입력으로 사용하는 방식입니다.</mark>

## Training과 Inference 차이

### Training

정답 Target Sequence가 존재합니다.

```text
Decoder Input
<BOS> 나는 AI를

Target
나는 AI를 좋아한다
```

정답 Token을 입력으로 사용할 수 있습니다.

### Inference

정답이 없습니다.

```text
<BOS>
↓
모델 예측
↓
나는
↓
모델 예측
↓
AI를
↓
모델 예측
↓
좋아한다
```

이전 모델 출력이 다음 입력이 됩니다.

## Exposure Bias

Teacher Forcing에는 단점도 있습니다.

Training:

```text
이전 입력
→ 항상 정답에 가까움
```

Inference:

```text
이전 입력
→ 모델이 직접 생성한 Token
```

학습과 실제 생성 조건이 달라집니다.

이 차이를 **Exposure Bias**라고 부릅니다.

## 고정 Context Vector의 문제

초기 Seq2Seq에서는 Encoder 마지막 Hidden State 하나에 입력 전체를 압축했습니다.

```text
아주 긴 Source Sequence
↓
Encoder
↓
고정 길이 Context Vector 하나
```

짧은 문장에서는 가능하지만 문장이 길어질수록 정보 손실이 커질 수 있습니다.

예를 들어

```text
Token 1
Token 2
...
Token 100
```

의 정보를 마지막 Vector 하나에 모두 담아야 합니다.

이 문제를 줄이기 위해 **Attention**이 등장합니다.

## Attention을 추가한 Seq2Seq

Attention은 마지막 Hidden State 하나만 사용하는 대신 Encoder의 모든 Hidden State를 보존합니다.

```text
Encoder

x1 → h1
x2 → h2
x3 → h3
```

Decoder가 매 위치마다

```text
h1
h2
h3
```

중 어떤 정보를 얼마나 참고할지 결정합니다.

```text
Decoder State
↓
Attention
↓
Encoder Hidden States 가중합
↓
현재 Context
```

<mark>Attention은 하나의 고정 Context Vector 대신 Decoder가 필요한 Encoder 위치를 매번 선택해서 참고하게 합니다.</mark>

## Attention 예시

Source:

```text
I love AI
```

Target:

```text
나는 AI를 좋아한다
```

개념적으로 다음과 같은 Weight가 만들어질 수 있습니다.

```text
"나는" 생성 시

I     → 0.70
love  → 0.20
AI    → 0.10
```

다음 위치:

```text
"AI를" 생성 시

I     → 0.10
love  → 0.15
AI    → 0.75
```

다음 위치:

```text
"좋아한다" 생성 시

I     → 0.10
love  → 0.80
AI    → 0.10
```

실제 Attention이 반드시 이렇게 일대일 대응되는 것은 아닙니다.

핵심은 **Decoder 위치마다 Source를 보는 비율이 달라진다는 것**입니다.

## RNN Seq2Seq에서 Transformer로

고전적인 Seq2Seq:

```text
RNN Encoder
↓
Attention
↓
RNN Decoder
```

Transformer:

```text
Transformer Encoder
↓
Cross-Attention
↓
Transformer Decoder
```

가장 큰 변화 중 하나는 RNN의 순차 계산을 Self-Attention으로 바꾼 것입니다.

## Transformer도 Seq2Seq인가

네.

원래 Transformer는 대표적인 **Seq2Seq 모델**입니다.

```text
Source
↓
Transformer Encoder
↓
Encoder Output
↓
Transformer Decoder
↓
Target
```

Decoder는 Cross-Attention으로 Encoder Output을 참고합니다.

```text
Q → Decoder
K → Encoder
V → Encoder
```

즉 Transformer Encoder-Decoder 역시

```text
Sequence
→ Sequence
```

구조입니다.

## Seq2Seq와 Encoder-Decoder의 관계

두 용어는 자주 같이 사용됩니다.

### Seq2Seq

문제 형태입니다.

```text
Sequence
→ Sequence
```

### Encoder-Decoder

그 문제를 해결하는 대표적인 구조입니다.

```text
Encoder
→ 입력 표현

Decoder
→ 출력 생성
```

따라서

```text
Seq2Seq
→ Encoder-Decoder 구조를 많이 사용
```

이라고 이해하면 됩니다.

## Seq2Seq와 GPT 차이

GPT도 입력 Prompt를 받아 출력 Sequence를 만들기 때문에 넓게 보면 Sequence 변환처럼 보일 수 있습니다.

하지만 구조적으로는 일반적인 Seq2Seq Encoder-Decoder와 다릅니다.

### 전통적인 Seq2Seq

```text
Source
→ Encoder

Target
→ Decoder
```

Source와 Target 처리 경로가 분리됩니다.

### GPT

```text
Prompt + 생성 Token
→ 하나의 Decoder-only 모델
```

별도 Encoder가 없습니다.

| 구분 | Seq2Seq Encoder-Decoder | GPT |
| --- | --- | --- |
| Encoder | 있음 | 없음 |
| Decoder | 있음 | 있음 |
| Source 처리 | Encoder | Decoder Context |
| Cross-Attention | 사용 가능 | 일반적으로 없음 |
| 대표 모델 | T5, BART | GPT |

## Seq2Seq와 BERT 차이

BERT는 Encoder-only입니다.

```text
입력
→ Encoder
→ Contextual Representation
```

기본 구조 자체는 새로운 Sequence를 Autoregressive하게 생성하는 Decoder가 없습니다.

따라서 전통적인 Seq2Seq Encoder-Decoder와 다릅니다.

## 대표 구조 정리

| 구조 | 대표 모델 | 주요 목적 |
| --- | --- | --- |
| Encoder-only | BERT | 입력 이해 |
| Decoder-only | GPT | Text 생성 |
| Encoder-Decoder | T5, BART | Seq2Seq |

## 잘 놓치는 핵심

### 1. Seq2Seq는 반드시 RNN을 뜻하지 않는다

초기에는 RNN/LSTM 기반이 유명했지만 Transformer Encoder-Decoder도 Seq2Seq입니다.

### 2. 입력 길이와 출력 길이는 달라도 된다

```text
Source Length ≠ Target Length
```

이어도 됩니다.

### 3. Encoder와 Decoder는 역할이 다르다

```text
Encoder
→ Source 표현

Decoder
→ Target 생성
```

### 4. 고정 Context Vector가 초기 Seq2Seq의 병목이었다

긴 문장을 한 Vector에 압축하면 정보 손실이 생길 수 있습니다.

### 5. Attention이 병목을 완화했다

Decoder가 Encoder의 모든 Hidden State에서 필요한 정보를 선택할 수 있게 했습니다.

### 6. Teacher Forcing은 학습 시 사용한다

이전 정답 Token을 다음 Decoder 입력으로 넣는 방식입니다.

### 7. Transformer Encoder-Decoder도 Seq2Seq다

Self-Attention과 Cross-Attention을 사용하지만 기본 문제 구조는 같습니다.

## 시험·면접

### 핵심 암기

```text
Seq2Seq
= Sequence → Sequence

Encoder
→ 입력 Sequence 표현

Decoder
→ 출력 Sequence 생성
```

### Q. Seq2Seq란?

입력 Sequence를 다른 출력 Sequence로 변환하는 모델 구조입니다.

### Q. 대표적인 활용은?

기계 번역, 요약, 질의응답, 음성 인식 등이 있습니다.

### Q. 초기 Seq2Seq의 대표적인 한계는?

긴 Source Sequence 전체를 하나의 고정 길이 Context Vector에 압축하면서 정보 손실이 발생할 수 있다는 점입니다.

### Q. Attention이 필요한 이유는?

Decoder가 마지막 Context 하나에만 의존하지 않고 Encoder의 여러 Hidden State에서 필요한 정보를 선택해 참고할 수 있게 하기 위해서입니다.

### Q. Teacher Forcing이란?

학습 시 이전 모델 예측 대신 실제 정답 Token을 다음 Decoder 입력으로 사용하는 방법입니다.

### Q. Transformer도 Seq2Seq인가?

Encoder-Decoder Transformer는 대표적인 Seq2Seq 구조입니다.

<blockquote class="prompt-danger">
<p>시험 함정: Seq2Seq를 RNN 모델의 이름으로만 외우면 안 됩니다. Seq2Seq는 Sequence를 다른 Sequence로 변환하는 문제와 구조를 뜻하며 Transformer Encoder-Decoder도 포함됩니다.</p>
</blockquote>

를 생성하면 Sequence 생성이 끝납니다.

## 마지막 정리

```text
Source Sequence
↓
Encoder
↓
Context / Encoder Hidden States
↓
Decoder
↓
Target Token 1
↓
Target Token 2
↓
...
↓
Target Sequence
```

초기 구조:

```text
RNN Encoder
→ 고정 Context Vector
→ RNN Decoder
```

Attention 이후:

```text
Encoder Hidden States
→ Attention
→ Decoder
```

Transformer:

```text
Transformer Encoder
→ Cross-Attention
→ Transformer Decoder
```

<mark>Seq2Seq의 핵심은 Encoder가 입력 Sequence를 표현하고, Decoder가 그 정보를 조건으로 출력 Sequence를 생성하는 것입니다.</mark>
