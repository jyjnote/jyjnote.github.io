`HAVING`은 **GROUP BY로 만든 그룹에 조건을 적용하는 절**입니다.

WHERE가 그룹화 전 Row를 거른다면 HAVING은 그룹화 후 집계 결과를 기준으로 그룹을 거릅니다.

<blockquote class="prompt-info">
<p>한 줄: WHERE는 Row 조건, HAVING은 그룹 조건입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

HAVING = 그룹화된 결과에 조건을 적용합니다.

</details>

이 글에서는 `EMPLOYEE.DEPT_ID`와 집계 함수를 중심으로 봅니다.

## 가장 먼저 핵심

부서별 직원 수를 구합니다.

```sql
SELECT DEPT_ID, COUNT(*)
FROM EMPLOYEE
GROUP BY DEPT_ID;
```

여기서 직원이 5명 이상인 부서만 보고 싶다면 HAVING을 사용합니다.

```sql
SELECT DEPT_ID, COUNT(*)
FROM EMPLOYEE
GROUP BY DEPT_ID
HAVING COUNT(*) >= 5;
```

<mark>HAVING은 그룹별 집계 결과를 조건으로 사용할 때 핵심입니다.</mark>

## WHERE와 HAVING

둘의 차이가 가장 중요합니다.

| 구분 | WHERE | HAVING |
| --- | --- | --- |
| 대상 | Row | 그룹 |
| 시점 | GROUP BY 전 | GROUP BY 후 |
| 대표 조건 | SALARY >= 3000 | AVG(SALARY) >= 3000 |
| 집계 조건 | 일반적으로 직접 사용 목적 아님 | 자주 사용 |

한 줄로 외우면 다음과 같습니다.

```text
WHERE
→ Row

HAVING
→ Group
```

## 직원 수 기준 HAVING

```sql
SELECT
    DEPT_ID,
    COUNT(*) AS EMP_COUNT
FROM EMPLOYEE
GROUP BY DEPT_ID
HAVING COUNT(*) >= 3;
```

처리 흐름은 다음과 같습니다.

```text
GROUP BY
→ 부서별 그룹 생성

COUNT
→ 각 그룹 직원 수 계산

HAVING
→ 3명 이상인 그룹만 남김
```

## 평균 기준 HAVING

부서별 평균 급여가 3000 이상인 부서만 조회합니다.

```sql
SELECT
    DEPT_ID,
    AVG(SALARY) AS AVG_SALARY
FROM EMPLOYEE
GROUP BY DEPT_ID
HAVING AVG(SALARY) >= 3000;
```

HAVING에서 집계 함수 결과를 조건으로 사용합니다.

## 합계 기준 HAVING

```sql
SELECT
    DEPT_ID,
    SUM(SALARY) AS TOTAL_SALARY
FROM EMPLOYEE
GROUP BY DEPT_ID
HAVING SUM(SALARY) >= 10000;
```

각 부서의 급여 합계가 기준 이상인 그룹만 남깁니다.

## WHERE와 HAVING 함께 사용

둘을 동시에 사용할 수 있습니다.

```sql
SELECT
    DEPT_ID,
    AVG(SALARY) AS AVG_SALARY
FROM EMPLOYEE
WHERE SALARY >= 2500
GROUP BY DEPT_ID
HAVING AVG(SALARY) >= 3000;
```

흐름을 구분해야 합니다.

```text
WHERE SALARY >= 2500
→ 개별 Row 필터링

GROUP BY DEPT_ID
→ 부서별 그룹 생성

HAVING AVG(SALARY) >= 3000
→ 그룹 평균 조건
```

## 왜 WHERE로 집계 조건을 걸지 않는가

다음과 같은 의도를 생각해봅시다.

```text
부서별 평균 급여가 3000 이상
```

평균은 그룹을 만든 뒤 계산할 수 있습니다.

따라서 그룹화 전에 사용하는 WHERE보다 그룹화 후 조건인 HAVING이 자연스럽습니다.

```sql
HAVING AVG(SALARY) >= 3000
```

## 작성 순서

HAVING까지 포함한 기본 구조는 다음과 같습니다.

```sql
SELECT 그룹Column, 집계함수
FROM Table
WHERE Row조건
GROUP BY 그룹Column
HAVING 그룹조건
ORDER BY Column;
```

작성 순서는 다음처럼 기억할 수 있습니다.

```text
SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY
```

## 논리적 처리 관점

기본적인 논리 흐름은 다음과 같습니다.

```text
FROM
→ 대상 Table

WHERE
→ 개별 Row 필터링

GROUP BY
→ 그룹 생성

HAVING
→ 그룹 필터링

SELECT
→ 결과 생성

ORDER BY
→ 정렬
```

이 흐름을 이해하면 WHERE와 HAVING 차이가 명확해집니다.

## Alias와 HAVING

일부 DBMS에서는 SELECT Alias를 HAVING이나 ORDER BY에서 사용할 수 있습니다.

하지만 지원 범위는 DBMS마다 차이가 있을 수 있습니다.

초기 학습에서는 집계식을 직접 작성하면 가장 명확합니다.

```sql
HAVING AVG(SALARY) >= 3000
```

## HAVING 없이 GROUP BY

HAVING은 GROUP BY에 항상 필수인 것은 아닙니다.

```sql
SELECT DEPT_ID, COUNT(*)
FROM EMPLOYEE
GROUP BY DEPT_ID;
```

모든 그룹을 보고 싶다면 HAVING이 필요하지 않습니다.

HAVING은 그룹 중 일부만 선택할 때 사용합니다.

## 잘 놓치는 핵심

### 1. HAVING은 그룹 조건이다

```text
HAVING
→ GROUP BY 결과 필터링
```

### 2. WHERE는 Row 조건이다

그룹화 전에 개별 Row를 거릅니다.

### 3. 집계 함수 조건은 HAVING에서 자주 사용한다

```sql
HAVING COUNT(*) >= 3
```

### 4. WHERE와 HAVING은 함께 사용할 수 있다

각자 적용 시점과 대상이 다릅니다.

### 5. HAVING은 항상 필요한 것은 아니다

모든 그룹을 조회하면 생략할 수 있습니다.

## 시험·면접

### 핵심 암기

```text
WHERE
→ Row 조건
→ GROUP BY 전

HAVING
→ Group 조건
→ GROUP BY 후
```

### 시험 함정

`평균 급여가 3000 이상인 부서`처럼 집계 결과에 조건을 걸 때 WHERE와 HAVING을 혼동하면 안 됩니다.

### 면접에서 짧게 답한다면

HAVING은 GROUP BY로 생성한 그룹에 조건을 적용하는 절입니다.

WHERE는 그룹화 전 개별 Row를 필터링하고, HAVING은 그룹화 후 COUNT, SUM, AVG 같은 집계 결과를 기준으로 그룹을 필터링합니다.
