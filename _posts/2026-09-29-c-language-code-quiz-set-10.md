## 문제 1. 산술 연산자 우선순위

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int x = 17;

    int result = x % 5 + 2 * 3 - 4 / 2;

    printf("%d\n", result);

    return 0;
}
```

① `4`  
② `6`  
③ `8`  
④ `10`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>6</code></strong>입니다.</p>

### 1. 전체 식

```c
x % 5 + 2 * 3 - 4 / 2
```

현재:

```text
x = 17
```

곱셈, 나눗셈, 나머지 연산은 덧셈과 뺄셈보다 먼저 계산합니다.

### 2. 나머지 연산

```text
17 % 5 = 2
```

### 3. 곱셈

```text
2 × 3 = 6
```

### 4. 나눗셈

두 값 모두 정수이므로 정수 나눗셈입니다.

```text
4 / 2 = 2
```

### 5. 덧셈과 뺄셈

식은:

```text
2 + 6 - 2
```

가 됩니다.

같은 우선순위의 덧셈과 뺄셈은 왼쪽부터 계산합니다.

```text
2 + 6 = 8
8 - 2 = 6
```

### 6. 최종 출력

```text
6
```

### 반드시 알아야 할 개념

대표적인 산술 연산자 우선순위는:

```text
*, /, %
→
+, -
```

입니다.

### 자주 하는 실수

식 전체를 무조건 왼쪽부터 계산하면 안 됩니다.

먼저 곱셈·나눗셈·나머지 연산을 처리합니다.

</details>

## 문제 2. 배열 부분 초기화

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[5] = {1, 2};

    a[3] = a[0] + a[1];

    printf("%d %d %d\n",
           a[2], a[3], a[4]);

    return 0;
}
```

① `0 3 0`  
② `1 3 2`  
③ `0 3 2`  
④ 초기값을 알 수 없다.

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>0 3 0</code></strong>입니다.</p>

### 1. 배열 초기화

```c
int a[5] = {1, 2};
```

초기화 목록보다 배열 원소가 더 많으면 나머지 원소는 0으로 초기화됩니다.

따라서:

```text
인덱스   0   1   2   3   4
값       1   2   0   0   0
```

입니다.

### 2. a[3] 변경

```c
a[3] = a[0] + a[1];
```

따라서:

```text
a[3] = 1 + 2 = 3
```

현재 배열:

```text
1 2 0 3 0
```

### 3. 출력값

```text
a[2] = 0
a[3] = 3
a[4] = 0
```

따라서:

```text
0 3 0
```

### 반드시 알아야 할 개념

초기화 목록을 사용해 배열 일부만 초기화하면 나머지는 0으로 채워집니다.

```c
int a[5] = {1};
```

이라면:

```text
1 0 0 0 0
```

입니다.

### 자주 하는 실수

초기값을 지정하지 않은 일반 지역 변수와 혼동하면 안 됩니다.

**배열 초기화 목록이 존재하면 나머지 원소는 0으로 초기화됩니다.**

</details>

## 문제 3. sizeof와 문자열 길이

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <string.h>

int main(void)
{
    char s[10] = "ABC";

    printf("%zu %zu\n",
           sizeof(s),
           strlen(s));

    return 0;
}
```

① `3 3`  
② `4 3`  
③ `10 3`  
④ `10 4`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>10 3</code></strong>입니다.</p>

### 1. 배열 선언

```c
char s[10] = "ABC";
```

배열 크기는 명시적으로 10입니다.

따라서 실제 배열에는 10개의 `char` 공간이 있습니다.

문자열 내용은 앞부분에:

```text
A B C \0
```

가 들어갑니다.

나머지 공간은 0으로 초기화됩니다.

### 2. sizeof(s)

```c
sizeof(s)
```

는 배열 전체 크기를 계산합니다.

`char`의 크기는 1바이트이므로:

```text
10 × 1 = 10
```

입니다.

### 3. strlen(s)

`strlen`은 첫 번째 `\0`을 만나기 전까지의 문자 수를 계산합니다.

```text
A B C
```

세 문자이므로:

```text
strlen(s) = 3
```

### 4. 최종 출력

```text
10 3
```

### 반드시 알아야 할 개념

배열의 선언 크기와 현재 문자열 길이는 서로 다를 수 있습니다.

```text
sizeof → 배열 전체 메모리 크기
strlen → 현재 문자열 문자 수
```

### 자주 하는 실수

문자열 `"ABC"`가 저장되어 있으므로 `sizeof(s)`도 4라고 생각하면 안 됩니다.

배열 자체는 처음부터 크기 10으로 선언되었습니다.

</details>

## 문제 4. 매크로와 괄호

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

#define DOUBLE(x) x + x

int main(void)
{
    int result = 3 * DOUBLE(2 + 1);

    printf("%d\n", result);

    return 0;
}
```

① `6`  
② `10`  
③ `14`  
④ `18`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>10</code></strong>입니다.</p>

### 1. 매크로 치환

매크로:

```c
#define DOUBLE(x) x + x
```

는 함수가 아닙니다.

문자 그대로 치환됩니다.

따라서:

```c
3 * DOUBLE(2 + 1)
```

은 다음처럼 바뀝니다.

```c
3 * 2 + 1 + 2 + 1
```

### 2. 곱셈 먼저 계산

```text
3 × 2 = 6
```

따라서:

```text
6 + 1 + 2 + 1
```

입니다.

### 3. 나머지 계산

```text
6 + 1 + 2 + 1 = 10
```

따라서 실제 결과는:

```text
10
```

입니다.

### 4. 올바른 매크로

의도대로 두 배 계산을 하려면:

```c
#define DOUBLE(x) ((x) + (x))
```

처럼 작성해야 합니다.

이 경우:

```text
3 × ((2 + 1) + (2 + 1))
= 3 × 6
= 18
```

이 됩니다.

### 반드시 알아야 할 개념

함수형 매크로는 단순한 코드 치환입니다.

따라서 매개변수와 전체 식에 괄호를 넣는 것이 중요합니다.

### 자주 하는 실수

매크로를 함수처럼 생각해서:

```text
DOUBLE(3) = 6
```

으로 먼저 계산하면 안 됩니다.

전처리 단계에서 실제 코드가 어떻게 치환되는지 확인해야 합니다.

</details>

## 문제 5. 함수의 값 전달과 주소 전달

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

void change(int a, int *b)
{
    a += 2;
    *b += a;
}

int main(void)
{
    int x = 3;
    int y = 4;

    change(x, &y);

    printf("%d %d\n", x, y);

    return 0;
}
```

① `3 7`  
② `3 9`  
③ `5 9`  
④ `5 7`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>3 9</code></strong>입니다.</p>

### 1. 함수 호출 전

```text
x = 3
y = 4
```

호출:

```c
change(x, &y);
```

### 2. 매개변수 a

`a`에는 `x`의 값 3이 복사됩니다.

```text
a = 3
```

따라서 함수 내부에서 `a`를 변경해도 `x`는 바뀌지 않습니다.

### 3. 매개변수 b

`b`에는 `y`의 주소가 전달됩니다.

```text
b → y
```

따라서:

```c
*b
```

를 변경하면 실제 `y`가 바뀝니다.

### 4. a 변경

```c
a += 2;
```

따라서:

```text
a = 5
```

하지만:

```text
x = 3
```

은 그대로입니다.

### 5. y 변경

```c
*b += a;
```

현재:

```text
*b = y = 4
a = 5
```

따라서:

```text
y = 4 + 5 = 9
```

### 6. 최종 출력

```text
3 9
```

### 반드시 알아야 할 개념

C 함수 인자는 기본적으로 값으로 전달됩니다.

원본 변수를 바꾸려면 주소를 전달하여 포인터로 접근해야 합니다.

### 자주 하는 실수

함수 내부의 `a`가 5가 되었으므로 `x`도 5라고 판단하면 안 됩니다.

`a`는 `x`의 복사본입니다.

</details>

## 문제 6. switch와 폴스루

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int n = 2;
    int result = 1;

    switch (n) {
        case 1:
            result += 2;
            break;

        case 2:
            result *= 3;

        case 3:
            result += 4;
            break;

        default:
            result = 0;
    }

    printf("%d\n", result);

    return 0;
}
```

① `3`  
② `5`  
③ `7`  
④ `9`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>7</code></strong>입니다.</p>

### 1. 초기 상태

```text
n = 2
result = 1
```

### 2. case 2 선택

`n`이 2이므로:

```c
case 2:
```

부터 실행합니다.

```c
result *= 3;
```

따라서:

```text
result = 1 × 3 = 3
```

### 3. break 확인

`case 2`에는 `break`가 없습니다.

따라서 다음 `case 3`도 이어서 실행됩니다.

```c
result += 4;
```

따라서:

```text
result = 3 + 4 = 7
```

### 4. break 실행

`case 3`의:

```c
break;
```

를 만나 `switch`문을 빠져나옵니다.

### 5. 최종 출력

```text
7
```

### 반드시 알아야 할 개념

`switch`는 일치한 `case`부터 실행하며 `break`를 만날 때까지 아래 코드가 이어질 수 있습니다.

### 자주 하는 실수

`case 2`만 보고 결과를 3이라고 선택하면 안 됩니다.

`break`의 위치를 반드시 확인해야 합니다.

</details>

## 문제 7. 비트 연산과 시프트

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    unsigned int x = 12;
    unsigned int y = 10;

    unsigned int result = (x & y) | (1u << 2);

    printf("%u\n", result);

    return 0;
}
```

① `4`  
② `8`  
③ `12`  
④ `14`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>12</code></strong>입니다.</p>

### 1. 값을 이진수로 변환

```text
12 = 1100
10 = 1010
```

### 2. 비트 AND

```c
x & y
```

계산:

```text
1100
1010
----
1000
```

따라서:

```text
x & y = 8
```

### 3. 시프트 연산

```c
1u << 2
```

이진수 1을 왼쪽으로 두 칸 이동합니다.

```text
0001
→
0100
```

따라서:

```text
1 << 2 = 4
```

### 4. 비트 OR

```text
8 = 1000
4 = 0100
```

OR:

```text
1000
0100
----
1100
```

따라서:

```text
12
```

### 5. 최종 출력

```text
12
```

### 반드시 알아야 할 개념

비트 연산은 십진수로 바로 계산하기보다 이진수로 변환하면 안전합니다.

```text
&  → 둘 다 1일 때 1
|  → 하나라도 1이면 1
<< → 왼쪽 이동
```

### 자주 하는 실수

`&&`와 `&`, `||`와 `|`를 혼동하면 안 됩니다.

이번 문제는 논리 연산이 아니라 비트 연산입니다.

</details>

## 문제 8. static 지역 변수

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int next(void)
{
    static int n = 2;

    n += 3;

    return n;
}

int main(void)
{
    printf("%d ", next());
    printf("%d ", next());
    printf("%d\n", next());

    return 0;
}
```

① `5 5 5`  
② `2 5 8`  
③ `5 8 11`  
④ `3 6 9`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>5 8 11</code></strong>입니다.</p>

### 1. static 변수의 특징

```c
static int n = 2;
```

는 함수가 처음 호출될 때 한 번 초기화되고 이후 값이 유지됩니다.

### 2. 첫 번째 호출

처음:

```text
n = 2
```

실행:

```text
n = 2 + 3 = 5
```

반환값:

```text
5
```

### 3. 두 번째 호출

다시 2로 초기화되지 않습니다.

이전 값:

```text
n = 5
```

에서 시작합니다.

```text
n = 5 + 3 = 8
```

반환값:

```text
8
```

### 4. 세 번째 호출

이전 값:

```text
n = 8
```

에서 시작합니다.

```text
n = 8 + 3 = 11
```

### 5. 최종 출력

```text
5 8 11
```

### 반드시 알아야 할 개념

`static` 지역 변수는 접근 범위는 함수 내부이지만 값의 수명은 프로그램 실행 동안 유지됩니다.

### 자주 하는 실수

함수 호출마다:

```text
n = 2
```

부터 다시 시작한다고 생각하면 안 됩니다.

</details>

## 문제 9. 동적 메모리 빈칸 채우기

정수 6개를 저장하고 모두 0으로 초기화하려고 합니다.

다음 빈칸에 들어갈 코드로 가장 적절한 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *p = ______________________;

    if (p == NULL)
        return 1;

    p[2] = 5;
    p[5] = 7;

    printf("%d\n", p[0] + p[2] + p[5]);

    free(p);

    return 0;
}
```

① `malloc(6)`  
② `malloc(6 * sizeof(int))`  
③ `calloc(6, sizeof(int))`  
④ `calloc(sizeof(int), 1)`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>calloc(6, sizeof(int))</code></strong>입니다.</p>

### 1. 문제의 두 조건

필요한 조건은 두 가지입니다.

```text
정수 6개 저장
모두 0으로 초기화
```

### 2. calloc의 형태

```c
calloc(원소개수, 원소크기)
```

따라서:

```c
calloc(6, sizeof(int))
```

을 사용하면 정수 6개를 저장할 공간이 할당되고 해당 영역이 0으로 초기화됩니다.

### 3. 할당 직후 상태

```text
p[0] = 0
p[1] = 0
p[2] = 0
p[3] = 0
p[4] = 0
p[5] = 0
```

### 4. 값 변경

```c
p[2] = 5;
p[5] = 7;
```

따라서:

```text
0 0 5 0 0 7
```

### 5. 출력값 계산

```text
p[0] + p[2] + p[5]
= 0 + 5 + 7
= 12
```

따라서 실제 출력은:

```text
12
```

### 오답 분석

②:

```c
malloc(6 * sizeof(int))
```

은 필요한 공간은 만들지만 초기값을 0으로 보장하지 않습니다.

①은 바이트 수 자체도 부족할 수 있습니다.

④는 정수 6개 공간이 아닙니다.

### 반드시 알아야 할 개념

대표적인 차이:

```text
malloc → 초기값 보장 없음
calloc → 0으로 초기화
```

### 자주 하는 실수

`malloc`으로 공간을 확보하면 자동으로 0이 들어간다고 생각하면 안 됩니다.

</details>

## 문제 10. 해제된 메모리 접근 판별

다음 코드에 대한 설명으로 가장 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int *p = malloc(sizeof(int));

    if (p == NULL)
        return 1;

    *p = 30;

    int *q = p;

    free(p);

    p = NULL;

    printf("%d\n", *q);

    return 0;
}
```

① `p`가 `NULL`이 되었으므로 `q`도 자동으로 `NULL`이 되어 안전하다.  
② `q`는 별도 포인터이므로 해제 전 값 30을 안전하게 읽을 수 있다.  
③ `q`가 이미 해제된 메모리를 가리키므로 `*q` 접근은 올바르지 않다.  
④ `free(p)` 이후에도 메모리는 프로그램 종료까지 항상 유지된다.

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③</strong>입니다.</p>

### 1. 메모리 할당

```c
int *p = malloc(sizeof(int));
```

성공하면:

```text
p → 동적 메모리
```

입니다.

값 대입 후:

```text
p → [30]
```

### 2. q에 주소 복사

```c
int *q = p;
```

따라서:

```text
p ─┐
   ├→ [30]
q ─┘
```

두 포인터가 같은 동적 메모리를 가리킵니다.

### 3. free 실행

```c
free(p);
```

이 순간 동적 메모리 블록의 수명이 끝납니다.

따라서 `p`뿐 아니라 같은 블록을 가리키던 `q`도 더 이상 안전하게 역참조할 수 없습니다.

### 4. p = NULL

```c
p = NULL;
```

은 포인터 변수 `p`의 값만 변경합니다.

`q`는 자동으로 바뀌지 않습니다.

따라서:

```text
p = NULL
q = 예전 주소값
```

상태가 될 수 있습니다.

하지만 `q`가 가리키던 메모리는 이미 해제되었습니다.

### 5. 잘못된 접근

```c
*q
```

는 해제된 메모리를 역참조합니다.

따라서 올바른 코드가 아닙니다.

### 반드시 알아야 할 개념

`free` 이후 그 메모리를 가리키던 포인터는 댕글링 포인터가 될 수 있습니다.

한 포인터를 `NULL`로 바꿔도 같은 주소를 가지고 있던 다른 포인터가 자동으로 바뀌지는 않습니다.

### 자주 하는 실수

```c
p = NULL;
```

을 실행했으므로 모든 관련 포인터 문제가 해결되었다고 생각하면 안 됩니다.

`q`는 별도의 포인터 변수입니다.

</details>

## 잘 놓치는 핵심

### 1. 연산자 우선순위를 먼저 적용한다

`*`, `/`, `%`는 `+`, `-`보다 먼저 계산합니다.

### 2. 배열의 부분 초기화는 나머지를 0으로 만든다

초기화 목록이 있으면 지정되지 않은 원소는 0입니다.

### 3. 배열 크기와 문자열 길이는 다르다

`sizeof`와 `strlen`은 계산 기준이 다릅니다.

### 4. 매크로는 함수가 아니라 문자 치환이다

매개변수와 전체 표현식을 괄호로 감싸는 습관이 중요합니다.

### 5. 값 전달과 주소 전달을 구분한다

일반 매개변수의 변경은 원본에 반영되지 않지만 포인터를 통한 변경은 반영될 수 있습니다.

### 6. switch는 break가 없으면 다음 case까지 실행된다

일치한 case만 실행된다고 생각하면 안 됩니다.

### 7. 비트 연산은 이진수로 바꿔 계산한다

`&`, `|`, `<<`, `>>`의 역할을 구분합니다.

### 8. static 지역 변수는 값이 유지된다

초기화는 한 번만 이루어집니다.

### 9. calloc은 0 초기화가 필요할 때 유용하다

`malloc`과 초기화 특성을 구분합니다.

### 10. free 후에는 같은 메모리를 가리키던 모든 포인터를 의심한다

포인터 변수에 주소값이 남아 있어도 메모리는 더 이상 유효하지 않을 수 있습니다.

## 시험·면접에서 바로 보는 포인트

- 계산식은 숫자를 대입하기 전에 연산자 우선순위를 표시합니다.
- 배열 초기화 목록이 있으면 남은 원소를 0으로 채웁니다.
- `sizeof`가 배열에 적용되는지 포인터에 적용되는지 확인합니다.
- 매크로는 실제 치환 결과를 한 번 적어 봅니다.
- 함수 호출에서는 어떤 인자가 복사되고 어떤 인자가 주소인지 확인합니다.
- `switch` 코드에는 `break` 위치를 표시합니다.
- 비트 연산은 4비트 단위로 끊어 보면 빠릅니다.
- `static`은 이전 호출의 값을 이어서 사용합니다.
- 동적 메모리 문제에서는 할당 크기와 초기화 여부를 구분합니다.
- `free` 이후에는 값을 계산하지 말고 먼저 포인터 유효성을 판별합니다.
