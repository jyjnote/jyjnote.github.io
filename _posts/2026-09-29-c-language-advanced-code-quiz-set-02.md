이번 세트는 **함수 포인터와 포인터를 반환하는 함수**를 중심으로 C의 복합 선언자와 고차 함수 구조를 집중적으로 다룹니다.

단순히 `int (*f)(int)`을 외우는 수준이 아니라, 함수 포인터 배열·함수 포인터를 반환하는 함수·배열 포인터를 다루는 함수·콜백·구조체 상태 전이까지 정확하게 읽어야 풀 수 있도록 구성했습니다.

<blockquote class="prompt-info">
<p>한 줄: 변수 이름에서 시작해 선언자를 안쪽에서 바깥쪽으로 읽고, 함수가 반환하는 것이 값인지 포인터인지 함수 주소인지 끝까지 추적합니다.</p>
</blockquote>

<details markdown="1">
<summary>풀이 방법</summary>

1. 복잡한 선언은 변수 이름에서 시작합니다.
2. 이름 바로 오른쪽의 `()`와 `[]`를 먼저 확인하고 그다음 왼쪽의 `*`를 읽습니다.
3. 함수 호출 뒤에 다시 `(인자)`가 붙으면 첫 호출의 반환형이 함수 포인터인지 확인합니다.
4. 포인터 반환 함수는 반환된 주소가 어떤 객체를 가리키는지 표시합니다.
5. 함수 포인터 배열은 인덱스별 함수 대응표를 먼저 만듭니다.
6. 콜백 문제는 함수 포인터의 정확한 매개변수형과 반환형을 확인합니다.
7. 앞 호출에서 변경된 정적 객체·배열·구조체 값은 이후 호출에 그대로 반영합니다.

</details>

## 문제 1. 복합 선언자 해석

다음 중 `fp`를 **정수 하나를 인자로 받고 정수 객체를 가리키는 포인터를 반환하는 함수의 포인터**로 선언한 것은 무엇입니까?

①

```c
int *fp(int);
```

②

```c
int (*fp)(int);
```

③

```c
int *(*fp)(int);
```

④

```c
int (*fp(int))(int);
```

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>③ <code>int *(*fp)(int);</code></strong>입니다.</p>

### 1. 목표 문장을 분해

문제에서 원하는 형식은 다음입니다.

```text
fp
→ 포인터
→ 함수
→ int 하나를 인자로 받음
→ int *를 반환
```

즉 가장 바깥 의미는:

```text
함수 포인터
```

이고 그 함수의 반환형은:

```text
int *
```

입니다.

### 2. 정답 선언 읽기

```c
int *(*fp)(int);
```

변수 이름 `fp`에서 시작합니다.

바로 왼쪽에:

```text
*fp
```

가 있으므로 `fp`는 포인터입니다.

괄호 바깥 오른쪽에:

```text
(int)
```

가 붙어 있으므로 그 포인터는 함수를 가리킵니다.

그 함수의 반환형은 선언 왼쪽의:

```text
int *
```

입니다.

따라서:

```text
fp
→ 함수 포인터
→ 함수는 int를 받음
→ 함수는 int *를 반환
```

입니다.

### 3. 보기 ①

```c
int *fp(int);
```

여기서는 `fp` 이름 바로 오른쪽에 `(int)`가 붙습니다.

따라서 `fp` 자체가 함수입니다.

```text
fp
→ 함수
→ int를 받음
→ int *를 반환
```

즉 **포인터를 반환하는 함수**입니다.

함수 포인터가 아닙니다.

### 4. 보기 ②

```c
int (*fp)(int);
```

`fp`는 함수 포인터가 맞습니다.

하지만 그 함수의 반환형은:

```text
int
```

입니다.

포인터를 반환하지 않습니다.

### 5. 보기 ④

```c
int (*fp(int))(int);
```

`fp` 바로 오른쪽에 `(int)`가 있으므로 `fp` 자체가 함수입니다.

그리고 그 함수의 반환값이:

```text
int (*)(int)
```

형식의 함수 포인터입니다.

즉:

```text
fp
→ int를 받는 함수
→ int를 받아 int를 반환하는 함수의 포인터를 반환
```

입니다.

### 반드시 알아야 할 개념

다음 세 선언은 서로 전혀 다릅니다.

```c
int *f(int);
```

```text
함수 f
→ int 입력
→ int * 반환
```

```c
int (*f)(int);
```

```text
포인터 f
→ int를 받아 int를 반환하는 함수
```

```c
int *(*f)(int);
```

```text
포인터 f
→ int를 받아 int *를 반환하는 함수
```

<mark>복합 선언자는 이름에서 시작해 괄호와 오른쪽 요소를 먼저 읽으면 실수가 크게 줄어듭니다.</mark>

### 자주 하는 실수

선언 왼쪽의 `int *`만 보고 `fp`가 정수 포인터라고 판단하면 안 됩니다.

`*`가 어느 괄호 안에서 변수 이름과 묶이는지가 핵심입니다.

</details>

## 문제 2. 포인터를 반환하는 함수와 정적 배열

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int *step(int x)
{
    static int buf[3] = {2, 4, 6};

    buf[x % 3] += x;

    return &buf[(x + 1) % 3];
}

int main(void)
{
    int *p = step(4);

    *p += 3;

    int *q = step(2);

    printf("%d %d %d\n",
           *p,
           *q,
           q[1]);

    return 0;
}
```

① `9 2 8`  
② `11 2 8`  
③ `11 4 8`  
④ `9 2 11`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>11 2 8</code></strong>입니다.</p>

### 1. 정적 배열의 초기 상태

함수 내부:

```c
static int buf[3] = {2, 4, 6};
```

`static` 지역 배열이므로 초기화는 한 번만 이루어지고 함수 호출 사이에 값이 유지됩니다.

초기 상태:

```text
인덱스   0   1   2
값       2   4   6
```

### 2. 첫 번째 호출

```c
int *p = step(4);
```

함수 내부에서:

```text
x = 4
x % 3 = 1
```

따라서:

```c
buf[1] += 4;
```

실행 후:

```text
buf = {2, 8, 6}
```

### 3. 반환 포인터

```c
return &buf[(x + 1) % 3];
```

현재:

```text
(x + 1) % 3
= 5 % 3
= 2
```

따라서:

```text
p → buf[2] → 6
```

입니다.

### 4. p를 통한 변경

```c
*p += 3;
```

따라서:

```text
buf[2] = 6 + 3 = 9
```

현재 정적 배열:

```text
buf = {2, 8, 9}
```

### 5. 두 번째 호출

```c
int *q = step(2);
```

중요한 점은 함수가 다시 호출되어도 `buf`가 초기값 `{2,4,6}`으로 돌아가지 않는다는 것입니다.

현재:

```text
buf = {2, 8, 9}
```

함수 내부:

```text
x = 2
x % 3 = 2
```

따라서:

```c
buf[2] += 2;
```

결과:

```text
buf = {2, 8, 11}
```

### 6. q가 가리키는 위치

```text
(x + 1) % 3
= 3 % 3
= 0
```

따라서:

```text
q → buf[0] → 2
```

### 7. p의 현재 값

`p`는 첫 호출 때부터 계속:

```text
p → buf[2]
```

를 가리키고 있습니다.

두 번째 호출이 `buf[2]`를 9에서 11로 변경했으므로:

```text
*p = 11
```

입니다.

### 8. q[1]

현재:

```text
q → buf[0]
```

이므로:

```c
q[1]
```

은:

```text
buf[1]
```

입니다.

따라서:

```text
q[1] = 8
```

### 9. 최종 출력

```text
11 2 8
```

### 반드시 알아야 할 개념

포인터를 반환하는 함수가 항상 위험한 것은 아닙니다.

이번 함수가 반환하는 주소는 `static` 배열 원소의 주소입니다.

정적 저장 기간을 가진 객체이므로 함수 종료 후에도 유효합니다.

### 자주 하는 실수

`p`가 첫 번째 함수 호출의 결과이므로 두 번째 호출과 무관하다고 생각하면 안 됩니다.

`p`와 두 번째 호출은 **같은 정적 배열 `buf`를 공유**합니다.

</details>

## 문제 3. 함수 포인터 배열과 동적 디스패치

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef int (*Op)(int, int);

int add(int a, int b)
{
    return a + b;
}

int mul(int a, int b)
{
    return a * b;
}

int sub(int a, int b)
{
    return a - b;
}

int main(void)
{
    Op ops[3] = {
        add,
        mul,
        sub
    };

    int x = ops[1](ops[0](2, 3), 4);
    int y = ops[x % 3](x, 5);
    int z = ops[y % 3](y, 2);

    printf("%d %d %d\n", x, y, z);

    return 0;
}
```

① `20 15 17`  
② `20 25 50`  
③ `24 19 38`  
④ `20 100 98`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>20 15 17</code></strong>입니다.</p>

### 1. 함수 포인터 대응표

```text
ops[0] → add
ops[1] → mul
ops[2] → sub
```

복잡한 식을 계산하기 전에 반드시 이 표를 적는 것이 좋습니다.

### 2. x의 안쪽 호출

```c
ops[0](2, 3)
```

`ops[0]`은 `add`입니다.

따라서:

```text
add(2, 3) = 5
```

### 3. x의 바깥 호출

```c
ops[1](5, 4)
```

`ops[1]`은 `mul`입니다.

```text
5 × 4 = 20
```

따라서:

```text
x = 20
```

### 4. y 계산을 위한 함수 선택

```c
x % 3
```

```text
20 % 3 = 2
```

따라서:

```text
ops[2] → sub
```

입니다.

호출:

```text
sub(20, 5) = 15
```

따라서:

```text
y = 15
```

### 5. z 계산을 위한 함수 선택

```text
y % 3
= 15 % 3
= 0
```

따라서:

```text
ops[0] → add
```

입니다.

```text
add(15, 2) = 17
```

따라서:

```text
z = 17
```

### 6. 최종 출력

```text
20 15 17
```

### 반드시 알아야 할 개념

함수 포인터 배열은 함수 자체를 인덱스로 선택하는 디스패치 테이블을 만들 수 있습니다.

실제 컴파일러·인터프리터·프로토콜 처리 코드에서도 이런 형태를 사용할 수 있습니다.

### 자주 하는 실수

`ops[x % 3]`을 계산할 때 원래 입력값이 아니라 앞에서 계산된 `x`를 사용해야 합니다.

</details>

## 문제 4. 함수 포인터를 반환하는 함수와 포인터 반환 함수

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

static int pool[4] = {
    10, 20, 30, 40
};

int *plus_one(int i)
{
    pool[i % 4] += 1;
    return &pool[i % 4];
}

int *minus_two(int i)
{
    pool[i % 4] -= 2;
    return &pool[i % 4];
}

typedef int *(*Maker)(int);

Maker choose(int key)
{
    if (key % 2)
        return plus_one;

    return minus_two;
}

int main(void)
{
    Maker f = choose(3);

    int *p = f(2);

    f = choose(*p % 2);

    int *q = f(1);

    *p += *q / 7;

    printf("%d %d %d\n",
           *p,
           *q,
           pool[1]);

    return 0;
}
```

① `31 21 21`  
② `34 21 21`  
③ `34 18 18`  
④ `29 18 18`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>34 21 21</code></strong>입니다.</p>

### 1. Maker 자료형 해석

```c
typedef int *(*Maker)(int);
```

`Maker`는:

```text
int 하나를 입력받고
int *를 반환하는 함수의 포인터
```

입니다.

즉 `Maker` 자체가 정수 포인터가 아니라 **포인터 반환 함수를 가리키는 함수 포인터형**입니다.

### 2. 최초 pool 상태

```text
인덱스   0   1   2   3
값      10  20  30  40
```

### 3. 첫 함수 선택

```c
Maker f = choose(3);
```

`3`은 홀수입니다.

따라서:

```text
f → plus_one
```

### 4. p 계산

```c
int *p = f(2);
```

실제로는:

```c
plus_one(2)
```

입니다.

```text
2 % 4 = 2
```

따라서:

```text
pool[2] = 30 + 1 = 31
```

그리고:

```text
p → pool[2] → 31
```

### 5. 두 번째 함수 선택

```c
f = choose(*p % 2);
```

현재:

```text
*p = 31
```

따라서:

```text
31 % 2 = 1
```

다시 홀수이므로:

```text
f → plus_one
```

입니다.

### 6. q 계산

```c
int *q = f(1);
```

즉:

```c
plus_one(1)
```

입니다.

따라서:

```text
pool[1] = 20 + 1 = 21
```

그리고:

```text
q → pool[1] → 21
```

### 7. p가 가리키는 값 변경

```c
*p += *q / 7;
```

현재:

```text
*p = 31
*q = 21
```

정수 나눗셈:

```text
21 / 7 = 3
```

따라서:

```text
*p = 31 + 3 = 34
```

즉:

```text
pool[2] = 34
```

### 8. 최종 상태

```text
pool = {10, 21, 34, 40}

p → pool[2] → 34
q → pool[1] → 21
```

최종 출력:

```text
34 21 21
```

### 반드시 알아야 할 개념

이 문제는 두 개념을 동시에 사용합니다.

```text
choose
→ 함수 포인터를 반환하는 함수

plus_one / minus_two
→ int *를 반환하는 함수
```

따라서:

```text
함수
→ 함수 포인터
→ 그 함수 호출
→ 정수 포인터 반환
→ 실제 객체 변경
```

이라는 여러 단계가 연결되어 있습니다.

### 자주 하는 실수

`choose`가 정수 포인터를 직접 반환한다고 생각하면 안 됩니다.

`choose`가 반환하는 것은 **정수 포인터를 반환하는 함수의 주소**입니다.

</details>

## 문제 5. 배열 포인터를 인자로 받는 함수 포인터

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef int *(*Selector)(int (*)[3], int, int);

int *select_cell(int (*a)[3], int r, int c)
{
    return &a[r][c];
}

int main(void)
{
    int a[2][3] = {
        {1, 2, 3},
        {4, 5, 6}
    };

    Selector s = select_cell;

    int *p = s(a + 1, 0, 1);

    *p += *s(a, 0, 2);

    int *q = s(a, 1, 1);

    printf("%d %d %d\n",
           *p,
           *q,
           a[1][1]);

    return 0;
}
```

① `5 5 5`  
② `8 8 8`  
③ `8 5 8`  
④ `7 8 8`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>8 8 8</code></strong>입니다.</p>

### 1. Selector 해석

```c
typedef int *(*Selector)(int (*)[3], int, int);
```

`Selector`는 함수 포인터형입니다.

가리키는 함수는:

```text
정수 3개짜리 배열을 가리키는 포인터
정수 r
정수 c
```

를 받고:

```text
int *
```

를 반환합니다.

### 2. 초기 행렬

```text
a[0] = {1, 2, 3}
a[1] = {4, 5, 6}
```

### 3. p 계산

```c
int *p = s(a + 1, 0, 1);
```

중요한 부분은 첫 번째 인자입니다.

```text
a     → 원래 a[0]
a + 1 → 원래 a[1]
```

함수 입장에서는 `a + 1`이 새로운 행 0처럼 보입니다.

따라서:

```text
r = 0
c = 1
```

은 원본 기준:

```text
a[1][1]
```

입니다.

즉:

```text
p → 원본 a[1][1] → 5
```

### 4. 오른쪽 select 호출

```c
s(a, 0, 2)
```

는:

```text
원본 a[0][2]
```

의 주소를 반환합니다.

현재 값:

```text
3
```

### 5. p가 가리키는 값 변경

```c
*p += *s(a, 0, 2);
```

따라서:

```text
a[1][1]
= 5 + 3
= 8
```

현재 행렬:

```text
a[0] = {1, 2, 3}
a[1] = {4, 8, 6}
```

### 6. q 계산

```c
int *q = s(a, 1, 1);
```

이는 그대로:

```text
q → a[1][1]
```

입니다.

따라서 `p`와 `q`는 결국 같은 정수 객체를 가리킵니다.

```text
p ─┐
   ├→ a[1][1] = 8
q ─┘
```

### 7. 최종 출력

```text
*p      = 8
*q      = 8
a[1][1] = 8
```

따라서:

```text
8 8 8
```

### 반드시 알아야 할 개념

2차원 배열에서:

```c
a + 1
```

은 정수 하나가 아니라 **한 행 전체를 건너뜁니다.**

그리고 포인터를 함수에 전달한 위치가 바뀌면 함수 내부의 인덱스 0이 원본 배열의 다른 행을 의미할 수 있습니다.

### 자주 하는 실수

`s(a + 1, 0, 1)`을 원본의 `a[0][1]`이라고 계산하면 안 됩니다.

함수에 넘겨진 시작 주소가 이미 두 번째 행입니다.

</details>

## 문제 6. qsort 콜백과 비교 함수

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stdlib.h>

int cmp_desc(const void *lhs, const void *rhs)
{
    int a = *(const int *)lhs;
    int b = *(const int *)rhs;

    return (a < b) - (a > b);
}

int main(void)
{
    int a[] = {
        42, 7, 19, 30
    };

    qsort(
        a,
        4,
        sizeof a[0],
        cmp_desc
    );

    printf("%d %d %d %d\n",
           a[0], a[1], a[2], a[3]);

    return 0;
}
```

① `7 19 30 42`  
② `42 30 19 7`  
③ `42 19 30 7`  
④ `30 42 19 7`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>42 30 19 7</code></strong>입니다.</p>

### 1. qsort 콜백 형식

`qsort`의 비교 함수는 개념적으로 다음 형식을 사용합니다.

```c
int cmp(
    const void *,
    const void *
);
```

따라서 실제 원소 자료형으로 형변환하여 값을 읽어야 합니다.

### 2. 비교 함수의 반환식

```c
return (a < b) - (a > b);
```

세 경우를 나누어 봅니다.

#### a < b

```text
(a < b) = 1
(a > b) = 0
```

따라서:

```text
1 - 0 = 1
```

양수를 반환합니다.

`qsort`에서 첫 번째 원소가 두 번째 원소보다 **뒤에 와야 한다**는 의미입니다.

즉 작은 값이 뒤로 이동합니다.

#### a > b

```text
0 - 1 = -1
```

음수를 반환하므로 큰 값이 앞에 옵니다.

따라서 전체 정렬은 내림차순입니다.

### 3. 정렬 전

```text
42 7 19 30
```

### 4. 정렬 후

내림차순:

```text
42 30 19 7
```

### 5. 최종 출력

```text
42 30 19 7
```

### 반드시 알아야 할 개념

비교 함수에서 단순히:

```c
return b - a;
```

처럼 작성하면 값의 범위에 따라 signed 정수 오버플로 문제가 생길 수 있습니다.

이번 표현:

```c
(a < b) - (a > b)
```

은 반환값을 `-1`, `0`, `1` 범위로 제한하면서 비교 순서를 표현합니다.

### 자주 하는 실수

비교 함수가 양수를 반환하면 첫 번째 값이 앞에 온다고 생각하면 안 됩니다.

일반적으로:

```text
음수 → lhs가 rhs보다 앞
0   → 동등
양수 → lhs가 rhs보다 뒤
```

로 해석합니다.

</details>

## 문제 7. 구조체 내부 함수 포인터와 상태 전이

```c

typedef struct State State;

typedef State *(*Step)(
    State *,
    int
);

struct State {
    int value;
    Step step;
};

State *advance(State *s, int x)
{
    s->value += x;

    return s + 1;
}

State *retreat(State *s, int x)
{
    s->value *= x;

    return s - 1;
}

int main(void)
{
    State states[2];

    states[0].value = 2;
    states[0].step = advance;

    states[1].value = 3;
    states[1].step = retreat;

    State *p = &states[0];

    p = p->step(p, 4);
    p = p->step(p, 2);

    p->value += states[1].value;

    printf("%d %d %td\n",
           states[0].value,
           states[1].value,
           p - states);

    return 0;
}
```

② `12 6 0`  
③ `12 3 1`  
④ `6 12 0`

<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>12 6 0</code></strong>입니다.</p>

### 1. 초기 구조체 배열

```text
states[0]
value = 2
step  → advance

states[1]
value = 3
step  → retreat
```

초기 포인터:

```text
p → states[0]
```

```c
p = p->step(p, 4);
```

현재 `p->step`은:

```text
advance
```

입니다.

따라서 실제 호출:

```c
advance(&states[0], 4)
```

```c
s->value += x;
```

따라서:

```text
states[0].value
= 2 + 4
= 6
```

반환:

```c
return s + 1;
```

현재 `s`는 `states[0]`을 가리키므로:

```text
s + 1 → states[1]
```

따라서:

```text

```

### 4. 두 번째 간접 호출

```c
p = p->step(p, 2);
```

현재 `p`는 `states[1]`이고:

```text
states[1].step → retreat
```

입니다.

따라서:

```c
retreat(&states[1], 2)
```

를 호출합니다.

### 5. retreat 내부

```c
s->value *= x;
```

따라서:

```text
states[1].value
= 3 × 2
= 6
```

반환:

```c
return s - 1;
```

따라서:

```text
p → states[0]
```

로 돌아옵니다.

### 6. 마지막 값 변경

```c
p->value += states[1].value;
```

현재:

```text
p → states[0]
```

이므로:

```text
states[0].value
= 6 + 6
= 12
```

### 7. 포인터 차이

```c
p - states
```

현재 `p`와 `states` 모두 첫 번째 원소를 가리킵니다.

따라서:

```text
0
```

입니다.

### 8. 최종 출력

```text
12 6 0
```

### 반드시 알아야 할 개념

구조체 안에 함수 포인터를 저장하면 객체마다 서로 다른 동작을 연결할 수 있습니다.

또한 함수가 다음 상태의 포인터를 반환하도록 만들면 **상태 전이 기계**를 구현할 수 있습니다.

### 자주 하는 실수

두 번째 호출도 `advance`라고 생각하면 안 됩니다.

첫 번째 함수가 반환한 포인터 때문에 `p`가 `states[1]`로 이동했고, 따라서 두 번째 함수 포인터도 달라졌습니다.

```c
int (int *)
```

입니다.

## 문제 10. 함수 포인터를 반환하는 함수와 선택 함수 종합

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>
#include <stddef.h>

typedef int *(*Picker)(
    int *,
    size_t
);

int *pick_max(int *a, size_t n)
{
    int *best = a;

    for (size_t i = 1; i < n; i++) {
        if (a[i] > *best)
            best = &a[i];
    }

    return best;
}

int *pick_min(int *a, size_t n)
{
    int *best = a;

    for (size_t i = 1; i < n; i++) {
        if (a[i] < *best)
            best = &a[i];
    }

    return best;
}

Picker choose_picker(int mode)
{
    if (mode)
        return pick_max;

    return pick_min;
}

int main(void)
{
    int a[] = {
        7, 2, 9, 4
    };

    Picker f = choose_picker(1);

    int *p = f(a, 4);

    *p -= 5;

    f = choose_picker(*p % 2);

    int *q = f(a, 4);

    *q += *p;

    printf("%d %d %td %td\n",
           *p,
           *q,
           p - a,
           q - a);
```

### 8. q가 가리키는 값 변경

```c
*q += *p;
```

현재:

```text
*q = 2
*p = 4
```

따라서:

```text
a[1] = 2 + 4 = 6
```

최종 배열:

```text
7 6 4 4
```

### 9. 포인터 차이

```text
p → a[2]
q → a[1]
```

따라서:

```text
p - a = 2
q - a = 1
```

입니다.

### 10. 최종 출력

```text
*p = 4
*q = 6
p - a = 2
q - a = 1
```

따라서:

```text
4 6 2 1
```

### 반드시 알아야 할 개념

이 문제는 다음 계층을 모두 포함합니다.

```text
choose_picker
→ 함수 포인터 반환

f
→ pick_max 또는 pick_min을 가리키는 함수 포인터

pick_max / pick_min
→ 배열 내부 원소를 가리키는 int * 반환
```

즉:

```text
함수 호출
→ 함수 선택
→ 함수 포인터 호출
→ 데이터 포인터 반환
→ 원본 배열 변경
```

까지 이어집니다.

### 자주 하는 실수

두 번째 `pick_min` 호출에서 초기 배열:

```text
7 2 9 4
```

를 사용하면 안 됩니다.

앞에서 `*p -= 5`가 실행되어 배열은 이미:

```text
7 2 4 4
```

로 변경되었습니다.

## 잘 놓치는 핵심

### 1. 포인터를 반환하는 함수와 함수 포인터는 선언부터 다르다

```c
int *f(int);
```

와:

```c
int (*f)(int);
```

는 완전히 다른 의미입니다.

### 2. 함수 포인터가 가리키는 함수가 다시 포인터를 반환할 수 있다

```c
int *(*fp)(int);
```

처럼 포인터 단계와 함수 호출 단계를 동시에 읽어야 합니다.

### 3. 함수 포인터 배열은 실행할 함수를 데이터처럼 선택한다

디스패치 테이블, 콜백, 상태 기계 등에서 사용됩니다.

### 4. 함수가 함수 포인터를 반환할 수 있다

```text
함수 호출
→ 함수 주소 반환
→ 반환된 함수 즉시 호출
```

형태를 만들 수 있습니다.

### 5. 2차원 배열 포인터는 행 단위로 이동한다

```c
int (*p)[3]
```

에서 `p + 1`은 정수 3개짜리 한 행을 이동합니다.

### 6. 표준 라이브러리 콜백의 정확한 함수형을 확인한다

`qsort`처럼 `void *` 기반 콜백을 사용하는 함수에서는 캐스팅과 반환 규칙을 정확히 이해해야 합니다.

### 7. 구조체 안에 함수 포인터를 넣으면 상태별 동작을 연결할 수 있다

함수의 반환값으로 다음 구조체 위치를 돌려주면 상태 전이까지 표현할 수 있습니다.

### 8. 함수는 배열 포인터를 반환할 수 있다

`int (*)[4]`와 `int *`는 이동 단위와 의미가 다릅니다.

### 9. 함수 매개변수의 배열 선언은 포인터로 조정된다

```c
int a[3]
```

와:

```c
int (*a)[3]
```

를 혼동하면 안 됩니다.

### 10. 함수 포인터 반환과 데이터 포인터 반환을 여러 단계로 결합할 수 있다

복잡한 선언은 항상 한 단계씩 분해해서 읽어야 합니다.

## 시험·면접에서 바로 보는 포인트

- 선언자를 읽을 때 변수 이름부터 시작합니다.
- `()`가 변수 이름에 직접 붙는지 `(*변수)` 바깥에 붙는지 확인합니다.
- 함수 호출 뒤에 다시 `()`가 나오면 첫 호출의 반환형이 함수 포인터인지 확인합니다.
- 반환된 포인터가 정적 객체, 호출자 배열, 동적 메모리 중 무엇을 가리키는지 확인합니다.
- 함수 포인터 배열은 인덱스와 함수 대응표를 먼저 적습니다.
- `void *` 콜백은 실제 원소형으로 변환한 뒤 값을 읽습니다.
- 구조체 함수 포인터 문제는 현재 포인터가 어느 구조체를 가리키는지 매 호출 후 갱신합니다.
- 배열 포인터를 반환하는 함수는 행 전체가 하나의 포인터 연산 단위입니다.
- 함수 매개변수의 배열 표기와 실제 배열 포인터 선언을 구분합니다.
- 복잡한 문제에서도 결국 `함수 선택 → 함수 호출 → 포인터 반환 → 대상 변경` 순서로 나눠 추적합니다.
