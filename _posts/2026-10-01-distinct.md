`DISTINCT`는 **SELECT 결과에서 중복된 값을 제거하고 서로 다른 값만 보여주는 기능**입니다.

같은 값이 여러 번 존재해도 결과에서는 한 번만 나타나게 할 수 있습니다.

<blockquote class="prompt-info">
<p>한 줄: DISTINCT는 SELECT 결과의 중복 값을 제거합니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

DISTINCT = 중복 제거입니다.

</details>

## 가장 먼저 기본 구조

DISTINCT는 SELECT 뒤에 사용합니다.

```sql
SELECT DISTINCT Column
FROM Table;
```

예를 들어 직원들이 속한 부서 번호만 중복 없이 보고 싶다고 해봅시다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE;
```

같은 `DEPT_ID`가 여러 Row에 있어도 결과에서는 한 번만 나타납니다.

<mark>DISTINCT는 원본 데이터를 삭제하는 것이 아니라 조회 결과에서 중복을 제거합니다.</mark>

## 중복이 있는 경우

예를 들어 `DEPT_ID`가 다음과 같다고 해봅시다.

```text
10
20
10
30
20
10
```

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE;
```

결과는 다음처럼 중복이 제거됩니다.

```text
10
20
30
```

## DISTINCT의 핵심

DISTINCT는 **SELECT 결과의 중복 Row를 제거**합니다.

```text
중복 있음
→ 하나만 남김

서로 다른 값
→ 모두 유지
```

즉 원본 Table의 Row 개수가 바뀌는 것은 아닙니다.

```text
원본 데이터
→ 그대로 유지

조회 결과
→ 중복 제거
```


## 여러 Column에 DISTINCT 사용

DISTINCT는 여러 Column에도 사용할 수 있습니다.

```sql
SELECT DISTINCT REGION, GRADE
FROM CUSTOMER;
```

이때 중요한 점은 **각 Column을 따로 중복 제거하는 것이 아니라 Column 조합 전체를 기준으로 중복을 판단한다는 것**입니다.

예를 들어 다음 데이터가 있다고 해봅시다.

| REGION | GRADE |
| --- | --- |
| 서울 | VIP |
| 서울 | VIP |
| 서울 | GOLD |
| 부산 | VIP |

DISTINCT 결과는 다음과 같습니다.

| REGION | GRADE |
| --- | --- |
| 서울 | VIP |
| 서울 | GOLD |
| 부산 | VIP |

`서울`이 여러 번 나와도 `GRADE`가 다르면 서로 다른 조합입니다.

<mark>여러 Column에 DISTINCT를 쓰면 선택된 Column들의 조합 전체가 중복 판단 기준입니다.</mark>


## DISTINCT와 Primary Key

Primary Key는 원래 중복될 수 없습니다.

예를 들어 `EMP_ID`가 Primary Key라면

```sql
SELECT DISTINCT EMP_ID
FROM EMPLOYEE;
```

을 해도 일반적으로 중복 제거 효과가 없습니다.

이미 모든 `EMP_ID`가 서로 다르기 때문입니다.

```text
Primary Key
→ 원래 중복 없음

DISTINCT
→ 중복 제거
```

따라서 DISTINCT는 중복이 생길 수 있는 일반 Column에서 더 의미가 큽니다.

## NULL과 DISTINCT

DISTINCT 대상 Column에 NULL이 여러 개 있을 수도 있습니다.

조회 결과에서는 중복되는 NULL이 하나로 정리되어 보일 수 있습니다.

예를 들어

```text
200
NULL
300
NULL
100
```

에 DISTINCT를 적용하면 개념적으로 다음처럼 볼 수 있습니다.

```text
200
NULL
300
100
```

NULL 자체를 일반 값과 동일하게 비교한다는 뜻은 아닙니다.

DISTINCT 결과에서는 중복되는 NULL 표현이 하나로 정리된다고 이해하면 됩니다.

## DISTINCT와 WHERE

WHERE와 함께 사용할 수 있습니다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE
WHERE SALARY >= 3000;
```

먼저 WHERE로 Row를 좁힌 뒤 SELECT DISTINCT로 결과의 중복을 제거한다고 이해하면 됩니다.

## DISTINCT와 ORDER BY

DISTINCT는 중복을 제거하지만 정렬을 보장하지 않습니다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE;
```

결과가 반드시 작은 값부터 정렬된다는 뜻은 아닙니다.

정렬하려면 `ORDER BY`를 사용해야 합니다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE
ORDER BY DEPT_ID;
```

<blockquote class="prompt-warning">
<p>DISTINCT는 중복 제거 기능이지 정렬 기능이 아닙니다.</p>
</blockquote>

## DISTINCT와 COUNT

서로 다른 값의 개수를 알고 싶을 때 `COUNT(DISTINCT Column)` 형태를 사용할 수 있습니다.

```sql
SELECT COUNT(DISTINCT DEPT_ID)
FROM EMPLOYEE;
```

개념적으로 다음 의미입니다.

```text
서로 다른 DEPT_ID가 몇 개인가
```

집계 함수는 뒤에서 별도 주제로 자세히 다룹니다.

## DISTINCT와 GROUP BY 차이

DISTINCT와 GROUP BY는 결과가 비슷해 보이는 경우가 있습니다.

예를 들어 다음 두 SQL은 단순한 경우 비슷한 결과를 만들 수 있습니다.

```sql
SELECT DISTINCT DEPT_ID
FROM EMPLOYEE;
```

```sql
SELECT DEPT_ID
FROM EMPLOYEE
GROUP BY DEPT_ID;
```

하지만 목적이 다릅니다.

| 구분 | DISTINCT | GROUP BY |
| --- | --- | --- |
| 핵심 목적 | 중복 제거 | 그룹 생성 |
| 대표 사용 | 서로 다른 값 조회 | 그룹별 집계 |
| 집계 함수 | 필수 아님 | 자주 함께 사용 |

현재 단계에서는 다음처럼 기억하면 충분합니다.

```text
DISTINCT
→ 중복 제거

GROUP BY
→ 그룹 묶기
```

GROUP BY는 뒤에서 별도 주제로 자세히 다룹니다.


## DISTINCT를 남용하지 않기

결과에 중복이 생기는 원인을 이해하지 않고 DISTINCT부터 붙이면 문제가 가려질 수 있습니다.

특히 JOIN 결과에서 예상보다 많은 중복이 생겼다면 먼저 JOIN 조건이 올바른지 확인하는 것이 중요합니다.

```text
예상하지 못한 중복
→ 원인 확인

필요한 중복 제거
→ DISTINCT 사용
```

DISTINCT는 잘못된 JOIN을 고치는 도구가 아닙니다.


## 잘 놓치는 핵심

### 1. DISTINCT는 원본 데이터를 삭제하지 않는다

조회 결과의 중복만 제거합니다.

### 2. 여러 Column에서는 조합 전체를 본다

```sql
SELECT DISTINCT REGION, GRADE
FROM CUSTOMER;
```

`REGION + GRADE` 조합이 중복 판단 기준입니다.

### 3. Primary Key에는 보통 효과가 없다

Primary Key는 이미 중복될 수 없기 때문입니다.

### 4. DISTINCT는 정렬 기능이 아니다

정렬은 `ORDER BY`를 사용합니다.

### 5. WHERE와 함께 사용할 수 있다

조건에 맞는 Row를 먼저 고른 뒤 결과의 중복을 제거할 수 있습니다.

### 6. GROUP BY와 목적이 다르다

```text
DISTINCT → 중복 제거
GROUP BY → 그룹 생성
```

## 시험·면접

### 핵심 암기

```text
DISTINCT
= SELECT 결과의 중복 제거
```

### 기본 문법

```sql
SELECT DISTINCT Column
FROM Table;
```

### 여러 Column

```sql
SELECT DISTINCT A, B
FROM Table;
```

중복 판단 기준은 `A + B` 조합입니다.

### 시험 함정 1

DISTINCT는 원본 Table의 중복 Row를 삭제하지 않습니다.

조회 결과만 바뀝니다.

### 시험 함정 2

여러 Column에서 DISTINCT는 첫 번째 Column에만 적용되는 것이 아닙니다.

선택한 Column 조합 전체에 적용됩니다.

### 시험 함정 3

DISTINCT 결과가 자동 정렬되는 것은 아닙니다.

### 면접에서 짧게 답한다면

DISTINCT는 SELECT 결과에서 중복된 Row를 제거하고 서로 다른 값만 반환할 때 사용합니다.

여러 Column에 적용하면 각 Column을 따로 보는 것이 아니라 선택된 Column 조합 전체를 기준으로 중복을 판단합니다.

② 둘 다 Table 삭제 명령이다.  
③ GROUP BY만 SELECT에서 사용할 수 있다.  
④ DISTINCT는 Transaction 제어 명령이다.
