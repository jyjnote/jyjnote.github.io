<blockquote class="prompt-info">
<p>한 줄: 값만 계산하지 말고 포인터가 무엇을 가리키는지와 코드가 실행되는 순서를 먼저 추적합니다.</p>
</blockquote>

3. 이중 포인터는 한 단계씩 역참조합니다.
4. 한 줄이 실행될 때마다 값과 포인터 위치를 갱신합니다.
5. 마지막에 출력문이 실제로 읽는 값을 확인합니다.
6. 결과 계산 전에 정의된 동작인지도 확인합니다.

## 문제 1. 이중 포인터와 가리키는 대상 변경

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a = 10;
    int b = 20;

    int *p = &a;
    int **pp = &p;

    **pp += 5;
    *pp = &b;
    **pp -= 3;

    printf("%d %d\n", a, b);

    return 0;
}
```

① `10 17`  
② `15 17`  
③ `15 20`  
④ `12 17`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>15 17</code></strong>입니다.</p>

### 1. 실행 전 상태

처음 변수값은 다음과 같습니다.

```text
a = 10
b = 20
```

포인터 관계는 다음과 같습니다.

```text
pp → p → a → 10
```

조금 더 풀어서 보면:

```text
p  = &a
pp = &p
```

따라서:

```text
*p   = a의 값
**pp = a의 값
```

### 2. 첫 번째 코드 실행

```c
**pp += 5;
```

먼저 <code>*pp</code>를 생각합니다.

<code>pp</code>는 <code>p</code>의 주소를 가지고 있으므로:

```text
*pp = p
```

한 번 더 역참조하면:

```text
**pp = *p = a
```

따라서 실제 효과는 다음과 같습니다.

```c
a += 5;
```

값은:

```text
a = 15
b = 20
```

포인터 관계는 아직 그대로입니다.

```text
pp → p → a → 15
```

### 3. 두 번째 코드 실행

```c
*pp = &b;
```

<code>*pp</code>는 값 <code>a</code>가 아니라 포인터 변수 <code>p</code> 자체입니다.

따라서 이 코드는 다음과 같은 효과를 냅니다.

```c
p = &b;
```

이제 포인터 관계가 바뀝니다.

```text
pp → p → b → 20
```

중요한 점은 <code>a</code>의 값 15는 그대로 남아 있다는 것입니다.

```text
a = 15
b = 20
```

### 4. 세 번째 코드 실행

```c
**pp -= 3;
```

현재는:

```text
pp → p → b
```

이므로:

```text
**pp = b
```

따라서 실제 효과는:

```c
b -= 3;
```

입니다.

```text
b = 17
```

### 5. 최종 상태

```text
a = 15
b = 17
p → b
pp → p
```

따라서 출력은:

```text
15 17
```

### 반드시 알아야 할 개념

이중 포인터는 포인터의 주소를 저장합니다.

```c
int **pp;
```

를 해석할 때는 한 단계씩 보는 것이 안전합니다.

```text
pp   → 포인터 변수의 주소
*pp  → 포인터 변수
**pp → 그 포인터가 가리키는 실제 값
```

<mark>*pp를 변경하면 최종 값이 아니라 중간 포인터가 가리키는 대상 자체를 바꿀 수 있습니다.</mark>

### 자주 하는 실수

<code>*pp = &b;</code>를 <code>a = b</code>처럼 값 복사로 생각하면 안 됩니다.

이 코드는 값이 아니라 포인터 <code>p</code>의 저장 주소를 바꾸는 코드입니다.

</details>

## 문제 2. 포인터 배열과 배열 포인터

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[2][3] = {
        {1, 2, 3},
        {4, 5, 6}
    };

    int *p[2] = {a[0], a[1]};
    int (*q)[3] = a;

    printf("%d %d %d\n",
           p[1][0],
           q[0][2],
           *(*(q + 1) + 1));

    return 0;
}
```

① `4 3 5`  
② `4 2 6`  
③ `5 3 4`  
④ `1 3 5`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>4 3 5</code></strong>입니다.</p>

### 1. 2차원 배열의 초기 상태

```text
a[0] = {1, 2, 3}
a[1] = {4, 5, 6}
```

메모리 위치를 행 기준으로 생각하면:

```text
a[0] → 1 2 3
a[1] → 4 5 6
```

### 2. 포인터 배열 <code>p</code>

선언은 다음과 같습니다.

```c
int *p[2] = {a[0], a[1]};
```

괄호가 없으므로 <code>p</code>는 배열입니다.

정수 포인터 두 개를 저장합니다.

```text
p[0] → a[0]
p[1] → a[1]
```

즉:

```text
p[0] → 1 2 3
p[1] → 4 5 6
```

### 3. 배열 포인터 <code>q</code>

선언은 다음과 같습니다.

```c
int (*q)[3] = a;
```

<code>q</code>는 정수 3개짜리 배열 한 행을 가리키는 포인터입니다.

```text
q     → a[0]
q + 1 → a[1]
```

### 4. 첫 번째 출력값

```c
p[1][0]
```

<code>p[1]</code>은 두 번째 행의 시작 주소입니다.

```text
p[1] → a[1]
```

인덱스 0은 첫 번째 값이므로:

```text
p[1][0] = a[1][0] = 4
```

### 5. 두 번째 출력값

```c
q[0][2]
```

<code>q[0]</code>은 첫 번째 행입니다.

```text
q[0] = a[0]
```

인덱스 2는 세 번째 값입니다.

```text
q[0][2] = a[0][2] = 3
```

### 6. 세 번째 출력값

```c
*(*(q + 1) + 1)
```

먼저:

```text
q + 1 → a[1]
```

그다음:

```text
*(q + 1)
```

은 두 번째 행의 첫 원소 주소처럼 사용됩니다.

다시 한 칸 이동하면:

```text
*(q + 1) + 1 → a[1][1]
```

최종 역참조 결과:

```text
a[1][1] = 5
```

### 7. 최종 출력

```text
4 3 5
```

### 반드시 알아야 할 개념

다음 두 선언은 매우 자주 비교됩니다.

```c
int *p[2];
```

의미:

```text
정수 포인터 2개를 저장하는 배열
```

반면:

```c
int (*q)[3];
```

의미:

```text
정수 3개짜리 배열을 가리키는 포인터
```

<mark>대괄호가 변수 이름에 바로 붙어 있으면 배열이고, 별표가 괄호 안에서 변수와 묶이면 배열 포인터입니다.</mark>

### 자주 하는 실수

<code>q + 1</code>을 정수 하나 이동한다고 생각하면 안 됩니다.

<code>q</code>의 자료형은 정수 3개짜리 배열을 가리키는 포인터이므로 한 행 전체만큼 이동합니다.

</details>

## 문제 3. 배열의 일부를 함수에 전달

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

void change(int a[], int n)
{
    for (int i = 0; i < n; i++)
        a[i] += i;
}

int main(void)
{
    int x[] = {10, 10, 10, 10};

    change(x + 1, 3);

    printf("%d %d %d %d\n",
           x[0], x[1], x[2], x[3]);

    return 0;
}
```

① `10 10 11 12`  
② `10 11 12 13`  
③ `10 10 10 10`  
④ `10 10 12 14`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>10 10 11 12</code></strong>입니다.</p>

### 1. 실행 전 배열

```text
인덱스   0   1   2   3
값      10  10  10  10
```

### 2. 함수에 전달되는 주소

함수 호출은 다음과 같습니다.

```c
change(x + 1, 3);
```

배열 이름 <code>x</code>는 대부분의 식에서 첫 원소 주소처럼 사용됩니다.

```text
x     → x[0]
x + 1 → x[1]
```

따라서 함수는 배열 전체의 시작점이 아니라 <code>x[1]</code>의 주소부터 받습니다.

함수 내부의 <code>a</code>는 다음처럼 대응됩니다.

```text
a[0] → x[1]
a[1] → x[2]
a[2] → x[3]
```

### 3. 첫 번째 반복

```text
i = 0
```

실행되는 코드는:

```c
a[0] += 0;
```

<code>a[0]</code>은 실제로 <code>x[1]</code>입니다.

따라서:

```text
x[1] = 10 + 0 = 10
```

현재 배열:

```text
10 10 10 10
```

### 4. 두 번째 반복

```text
i = 1
```

```c
a[1] += 1;
```

<code>a[1]</code>은 <code>x[2]</code>입니다.

```text
x[2] = 10 + 1 = 11
```

현재 배열:

```text
10 10 11 10
```

### 5. 세 번째 반복

```text
i = 2
```

```c
a[2] += 2;
```

<code>a[2]</code>는 <code>x[3]</code>입니다.

```text
x[3] = 10 + 2 = 12
```

최종 배열:

```text
10 10 11 12
```

### 6. 최종 출력

```text
10 10 11 12
```

### 반드시 알아야 할 개념

함수 매개변수에서 다음 두 표현은 같은 방식으로 처리됩니다.

```c
void change(int a[], int n)
```

```c
void change(int *a, int n)
```

함수로 배열 전체가 복사되는 것이 아니라 첫 원소의 주소가 전달됩니다.

또한 시작 주소를 <code>x + 1</code>처럼 바꾸면 배열 중간부터 함수가 처리하도록 만들 수 있습니다.

### 자주 하는 실수

함수 안의 <code>a[0]</code>이 항상 원본 배열의 <code>x[0]</code>이라고 생각하면 안 됩니다.

이번 문제에서는 시작 주소가 <code>x + 1</code>이므로 <code>a[0]</code>은 <code>x[1]</code>입니다.

</details>

## 문제 4. 구조체 포인터와 음수 인덱스

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

typedef struct {
    int x;
    int y;
} Point;

int main(void)
{
    Point p[3] = {
        {1, 2},
        {3, 4},
        {5, 6}
    };

    Point *q = p;

    q->x += 10;
    q++;
    q->y += q[-1].x;

    printf("%d %d %d %d\n",
           p[0].x,
           p[0].y,
           p[1].x,
           p[1].y);

    return 0;
}
```

① `11 2 3 15`  
② `11 2 3 4`  
③ `1 2 3 15`  
④ `11 13 3 4`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>11 2 3 15</code></strong>입니다.</p>

### 1. 실행 전 구조체 배열

```text
p[0] = {x = 1, y = 2}
p[1] = {x = 3, y = 4}
p[2] = {x = 5, y = 6}
```

포인터 선언:

```c
Point *q = p;
```

따라서:

```text
q → p[0]
```

### 2. 첫 번째 코드 실행

```c
q->x += 10;
```

<code>q</code>가 <code>p[0]</code>을 가리키므로:

```text
q->x = p[0].x
```

따라서:

```text
p[0].x = 1 + 10 = 11
```

현재 상태:

```text
p[0] = {11, 2}
p[1] = {3, 4}
p[2] = {5, 6}
```

### 3. 포인터 이동

```c
q++;
```

<code>q</code>는 <code>Point</code> 구조체를 가리키는 포인터입니다.

따라서 한 번 증가하면 다음 구조체 원소로 이동합니다.

```text
q → p[1]
```

### 4. 세 번째 코드 실행

```c
q->y += q[-1].x;
```

먼저 왼쪽을 봅니다.

```text
q->y = p[1].y = 4
```

이제 <code>q[-1]</code>을 봅니다.

배열 표기법은 다음과 같습니다.

```text
q[-1] = *(q - 1)
```

현재 <code>q</code>가 <code>p[1]</code>을 가리키므로:

```text
q - 1 → p[0]
```

따라서:

```text
q[-1].x = p[0].x = 11
```

앞에서 이미 <code>p[0].x</code>가 11로 변경되었다는 점이 중요합니다.

결과:

```text
p[1].y = 4 + 11 = 15
```

### 5. 최종 상태

```text
p[0] = {11, 2}
p[1] = {3, 15}
p[2] = {5, 6}
```

출력은:

```text
11 2 3 15
```

### 반드시 알아야 할 개념

구조체 포인터에서:

```c
q->x
```

는 다음과 같습니다.

```c
(*q).x
```

또한 배열 범위 안에 있는 경우 음수 인덱스도 문법적으로 가능합니다.

```c
q[-1]
```

은:

```c
*(q - 1)
```

과 같습니다.

### 자주 하는 실수

<code>q[-1]</code>을 무조건 잘못된 코드라고 생각하면 안 됩니다.

현재 포인터에서 한 칸 이전 위치가 같은 배열 안에 존재한다면 접근할 수 있습니다.

이번 문제에서는 <code>q</code>가 <code>p[1]</code>을 가리키므로 <code>q[-1]</code>은 유효한 <code>p[0]</code>입니다.

</details>

## 문제 5. 문자열 포인터 이동과 포인터 차이

다음 코드의 출력 결과는 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    char s[] = "PROGRAM";
    char *p = s;

    while (*p != '\0') {
        if (*p == 'G')
            break;

        p++;
    }

    printf("%c %s %ld\n",
           *p,
           p,
           p - s);

    return 0;
}
```

① `G GRAM 3`  
② `G PROGRAM 3`  
③ `R RAM 4`  
④ `G GRAM 4`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>① <code>G GRAM 3</code></strong>입니다.</p>

### 1. 문자열의 실제 배열 상태

```text
인덱스   0   1   2   3   4   5   6   7
문자     P   R   O   G   R   A   M  \0
```

처음에는:

```text
p → s[0] → P
```

### 2. 첫 번째 반복

현재 문자는 <code>P</code>입니다.

```c
if (*p == 'G')
```

조건은 거짓입니다.

따라서:

```c
p++;
```

실행 후:

```text
p → s[1] → R
```

### 3. 두 번째 반복

현재 문자는 <code>R</code>입니다.

<code>G</code>가 아니므로 한 칸 이동합니다.

```text
p → s[2] → O
```

### 4. 세 번째 반복

현재 문자는 <code>O</code>입니다.

다시 한 칸 이동합니다.

```text
p → s[3] → G
```

### 5. 네 번째 반복

현재:

```text
*p = 'G'
```

따라서:

```c
if (*p == 'G')
    break;
```

에서 반복문을 종료합니다.

포인터는 이동하지 않고 그대로 <code>s[3]</code>을 가리킵니다.

### 6. 첫 번째 출력값

```c
*p
```

현재 문자는:

```text
G
```

### 7. 두 번째 출력값

```c
printf("%s", p);
```

문자열 출력은 포인터가 가리키는 위치부터 종료 문자까지 출력합니다.

현재 <code>p</code>가 <code>s[3]</code>을 가리키므로:

```text
G R A M \0
```

따라서:

```text
GRAM
```

### 8. 세 번째 출력값

```c
p - s
```

같은 배열 안의 두 포인터를 빼면 바이트 수가 아니라 원소 간 거리가 나옵니다.

```text
p = &s[3]
s = &s[0]
```

따라서:

```text
p - s = 3
```

### 9. 최종 출력

```text
G GRAM 3
```

### 반드시 알아야 할 개념

문자 포인터를 <code>%s</code>로 출력하면 포인터 위치의 문자 하나만 출력하는 것이 아닙니다.

그 위치부터 처음 만나는 <code>\0</code>까지 문자열 전체가 출력됩니다.

또한 같은 배열 안의 포인터끼리 뺄 때 결과는 원소 개수 차이입니다.

### 자주 하는 실수

<code>p - s</code>를 주소값의 실제 바이트 차이로 생각하면 안 됩니다.

C의 포인터 차이는 포인터가 가리키는 자료형의 원소 개수 기준으로 계산됩니다.

</details>

## 문제 6. 전처리기 조건부 컴파일

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#define MODE 2

int main(void)
{
    int x = 10;

#if MODE == 1
    x += 5;
#elif MODE == 2
    x *= 3;
#else
    x -= 2;
#endif

    return 0;
}
```

① `8`  
② `15`  
③ `30`  
④ 컴파일 오류

<details markdown="1">

```c
#define MODE 2
```

전처리기가 이후 코드의 <code>MODE</code>를 값 2로 처리합니다.

```c
#if MODE == 1
```

```c
x += 5;
```

```c
#elif MODE == 2
```

### 4. 실제 컴파일되는 핵심 코드

### 자주 하는 실수

일반 <code>if</code>문처럼 모든 분기가 프로그램 안에 남아 있다고 생각하면 안 됩니다.

## 문제 7. 함수 포인터를 함수의 인자로 전달

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int add1(int x)
{
    return x + 1;
}

int twice(int x)
{
    return x * 2;
}

int apply(int x, int (*f)(int))
{
    return f(f(x));
}

int main(void)
{
    int a = apply(3, add1);
    int b = apply(3, twice);

    printf("%d %d\n", a, b);

    return 0;
}
```

① `4 6`  
② `5 12`  
③ `5 9`  
④ `6 12`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>5 12</code></strong>입니다.</p>

### 1. 함수들의 역할

첫 번째 함수:

```c
int add1(int x)
{
    return x + 1;
}
```

입력값에 1을 더합니다.

두 번째 함수:

```c
int twice(int x)
{
    return x * 2;
}
```

입력값을 두 배로 만듭니다.

### 2. <code>apply</code> 함수의 의미

```c
int apply(int x, int (*f)(int))
{
    return f(f(x));
}
```

두 번째 매개변수:

```c
int (*f)(int)
```

는 정수 하나를 받아 정수 하나를 반환하는 함수의 주소를 저장합니다.

함수 본문:

```c
f(f(x))
```

는 받은 함수를 두 번 연속 적용한다는 뜻입니다.

### 3. 첫 번째 호출

```c
int a = apply(3, add1);
```

여기서는:

```text
f → add1
```

입니다.

안쪽 함수부터 계산합니다.

```text
add1(3) = 4
```

그 결과를 다시 <code>add1</code>에 넣습니다.

```text
add1(4) = 5
```

따라서:

```text
a = 5
```

### 4. 두 번째 호출

```c
int b = apply(3, twice);
```

이번에는:

```text
f → twice
```

안쪽부터 계산합니다.

```text
twice(3) = 6
```

다시 한 번 적용합니다.

```text
twice(6) = 12
```

따라서:

```text
b = 12
```

### 5. 최종 출력

```text
5 12
```

### 반드시 알아야 할 개념

함수 포인터를 이용하면 함수 자체를 다른 함수에 전달할 수 있습니다.

즉, 데이터뿐 아니라 어떤 동작을 수행할지도 인자로 넘길 수 있습니다.

함수 포인터 선언:

```c
int (*f)(int)
```

은:

```text
정수 하나를 입력받고 정수 하나를 반환하는 함수를 가리키는 포인터
```

입니다.

### 자주 하는 실수

<code>f(f(x))</code>를 두 함수가 동시에 실행되는 것처럼 생각하면 안 됩니다.

항상 가장 안쪽의 <code>f(x)</code>가 먼저 계산되고 그 반환값을 바깥쪽 함수가 다시 입력받습니다.

</details>

## 문제 8. 이중 포인터로 포인터 자체 교환

다음 코드가 <code>30 10</code>을 출력하도록 빈칸에 들어갈 코드로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

void swap_ptr(int **a, int **b)
{
    int *tmp = *a;
    ____________;
    *b = tmp;
}

int main(void)
{
    int x = 10;
    int y = 30;

    int *p = &x;
    int *q = &y;

    swap_ptr(&p, &q);

    printf("%d %d\n", *p, *q);

    return 0;
}
```

① `a = b;`  
② `*a = *b;`  
③ `**a = **b;`  
④ `*a = b;`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>②</strong>입니다.</p>

정답 코드는 다음과 같습니다.

```c
*a = *b;
```

### 1. 함수 호출 전 상태

```text
x = 10
y = 30
```

포인터 관계:

```text
p → x → 10
q → y → 30
```

함수 호출:

```c
swap_ptr(&p, &q);
```

따라서 함수 내부에서는:

```text
a → p → x
b → q → y
```

입니다.

### 2. 첫 번째 코드 실행

```c
int *tmp = *a;
```

<code>a</code>는 <code>p</code>의 주소입니다.

따라서:

```text
*a = p
```

현재 <code>p</code>는 <code>x</code>의 주소를 가지고 있습니다.

그러므로:

```text
tmp → x
```

현재 관계:

```text
tmp → x
p   → x
q   → y
```

### 3. 빈칸 코드가 해야 할 일

목표는 <code>p</code>가 <code>q</code>가 가리키던 대상인 <code>y</code>를 가리키도록 만드는 것입니다.

<code>*a</code>는 <code>p</code> 자체이고:

```text
*b = q
```

입니다.

따라서:

```c
*a = *b;
```

를 실행하면 실제 효과는:

```c
p = q;
```

와 같습니다.

이제:

```text
p → y
q → y
tmp → x
```

### 4. 마지막 코드 실행

```c
*b = tmp;
```

<code>*b</code>는 <code>q</code> 자체입니다.

따라서:

```c
q = tmp;
```

가 됩니다.

<code>tmp</code>는 <code>x</code>를 가리키고 있었으므로:

```text
q → x
```

최종 관계:

```text
p → y → 30
q → x → 10
```

### 5. 최종 출력

```c
printf("%d %d\n", *p, *q);
```

따라서:

```text
30 10
```

### 반드시 알아야 할 개념

일반 포인터가 가리키는 값을 변경하려면 포인터 하나면 충분합니다.

하지만 포인터 변수 자체가 저장하고 있는 주소를 함수 안에서 바꾸려면 그 포인터의 주소를 전달해야 합니다.

그래서 이중 포인터가 필요합니다.

```text
a  → p
*a = p
**a = *p = x의 값
```

### 오답 분석

① <code>a = b;</code>

함수 내부의 지역 포인터 <code>a</code>만 바뀝니다. 원본 <code>p</code>는 바뀌지 않습니다.

③ <code>**a = **b;</code>

주소를 교환하는 것이 아니라 <code>x</code>의 값에 <code>y</code>의 값을 복사합니다.

④ <code>*a = b;</code>

<code>*a</code>의 자료형은 <code>int *</code>이고 <code>b</code>의 자료형은 <code>int **</code>이므로 자료형부터 맞지 않습니다.

</details>

## 문제 9. 정의되지 않은 동작 판별

다음 코드에 대한 설명으로 가장 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int i = 1;

    int x = i++ + ++i;

    printf("%d %d\n", x, i);

    return 0;
}
```

① 항상 `4 3`을 출력한다.  
② 항상 `5 3`을 출력한다.  
③ 컴파일 오류가 반드시 발생한다.  
④ 결과를 일정하게 예측할 수 없는 코드이다.

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>④</strong>입니다.</p>

### 1. 문제의 핵심 식

```c
int x = i++ + ++i;
```

처음 값은:

```text
i = 1
```

겉으로 보면 다음처럼 각각 계산하고 싶어질 수 있습니다.

```text
i++  → 기존 값 사용 후 증가
++i  → 먼저 증가 후 값 사용
```

하지만 이 문제는 단순 계산 문제로 접근하면 안 됩니다.

### 2. 왜 결과를 계산하면 안 되는가

하나의 식 안에서 같은 변수 <code>i</code>를 두 번 변경하고 있습니다.

```c
i++
```

도 <code>i</code>를 변경하고:

```c
++i
```

도 <code>i</code>를 변경합니다.

그런데 <code>+</code> 연산자의 양쪽 피연산자를 어느 쪽부터 평가할지에 대해 필요한 순서가 보장되지 않습니다.

이런 형태는 C에서 정의되지 않은 동작에 해당합니다.

### 3. 정의되지 않은 동작의 의미

정의되지 않은 동작은 단순히 다음 둘 중 하나가 나온다는 뜻이 아닙니다.

```text
4 3
5 3
```

특정 결과를 기대할 수 없다는 뜻입니다.

컴파일러, 최적화 수준, 환경에 따라 결과가 달라질 수 있고 프로그램 동작 자체를 신뢰할 수 없습니다.

### 4. 컴파일 오류와는 다르다

보기 ③도 틀렸습니다.

정의되지 않은 동작이 있다고 해서 컴파일러가 반드시 오류를 발생시키는 것은 아닙니다.

컴파일이 성공하더라도 실행 결과는 보장되지 않습니다.

### 5. 안전하게 고치기

연산을 명확하게 분리합니다.

```c
int a = i++;
int b = ++i;
int x = a + b;
```

이 경우 각 문장이 순서대로 끝난 뒤 다음 문장이 실행되므로 동작을 명확하게 추적할 수 있습니다.

### 반드시 알아야 할 개념

시험에서는 출력값 계산보다 먼저 다음을 확인해야 합니다.

```text
같은 변수를 한 식 안에서 여러 번 변경하는가?
```

그렇다면 연산 사이에 순서가 보장되는지 확인해야 합니다.

<mark>정의되지 않은 동작 문제는 숫자를 계산하는 문제가 아니라 코드 자체의 유효성을 판별하는 문제입니다.</mark>

### 자주 하는 실수

후위 증가와 전위 증가 규칙만 이용해서 특정 숫자를 계산한 뒤 정답이라고 판단하면 안 됩니다.

먼저 평가 순서와 시퀀싱 문제를 확인해야 합니다.

</details>

## 문제 10. 포인터와 반복 조건 종합

다음 코드의 출력 결과로 옳은 것은 무엇입니까?

```c
#include <stdio.h>

int main(void)
{
    int a[] = {2, 4, 6, 8, 10};
    int *p = a;
    int sum = 0;

    for (int i = 0; i < 5; i++) {
        if (*(p + i) % 4 == 0)
            sum += *(p + i);
        else
            sum -= i;
    }

    printf("%d\n", sum);

    return 0;
}
```

① `5`  
② `6`  
③ `9`  
④ `12`

<details markdown="1">
<summary>정답 및 해설</summary>

<p>정답은 <strong>② <code>6</code></strong>입니다.</p>

### 1. 실행 전 상태

배열:

```text
인덱스   0   1   2   3   4
값       2   4   6   8  10
```

포인터:

```text
p → a[0]
```

누적값:

```text
sum = 0
```

식:

```c
*(p + i)
```

는 현재 배열의 <code>a[i]</code>와 같습니다.

### 2. 첫 번째 반복

```text
i = 0
값 = a[0] = 2
```

조건:

```c
2 % 4 == 0
```

거짓입니다.

따라서 <code>else</code>가 실행됩니다.

```c
sum -= i;
```

```text
sum = 0 - 0 = 0
```

### 3. 두 번째 반복

```text
i = 1
값 = a[1] = 4
```

조건:

```text
4 % 4 = 0
```

참입니다.

따라서:

```text
sum = 0 + 4 = 4
```

### 4. 세 번째 반복

```text
i = 2
값 = a[2] = 6
```

조건은 거짓입니다.

```text
6 % 4 = 2
```

따라서:

```text
sum = 4 - 2 = 2
```

### 5. 네 번째 반복

```text
i = 3
값 = a[3] = 8
```

조건은 참입니다.

```text
8 % 4 = 0
```

따라서:

```text
sum = 2 + 8 = 10
```

### 6. 다섯 번째 반복

```text
i = 4
값 = a[4] = 10
```

조건은 거짓입니다.

```text
10 % 4 = 2
```

따라서:

```text
sum = 10 - 4 = 6
```

### 7. 전체 추적

```text
i = 0 → 값  2 → sum = 0
i = 1 → 값  4 → sum = 4
i = 2 → 값  6 → sum = 2
i = 3 → 값  8 → sum = 10
i = 4 → 값 10 → sum = 6
```

### 8. 최종 출력

```text
6
```

### 반드시 알아야 할 개념

배열 접근:

```c
a[i]
```

와 포인터 접근:

```c
*(a + i)
```

는 같은 원소를 의미합니다.

이번 문제에서 <code>p = a</code>이므로:

```c
*(p + i)
```

도 결국:

```c
a[i]
```

와 같습니다.

### 자주 하는 실수

조건이 거짓일 때 배열 값을 빼는 것이 아닙니다.

실제 코드는:

```c
sum -= i;
```

이므로 값 <code>2, 6, 10</code>이 아니라 인덱스 <code>0, 2, 4</code>를 뺍니다.

</details>

## 잘 놓치는 핵심

### 1. 이중 포인터는 포인터 자체를 바꿀 때 사용한다

```text
pp → p → 값
```

한 단계씩 역참조해서 무엇을 변경하는지 확인해야 합니다.

### 2. 포인터 배열과 배열 포인터는 선언부터 다르다

```c
int *p[3];
```

은 포인터를 저장하는 배열입니다.

```c
int (*p)[3];
```

은 배열 한 행을 가리키는 포인터입니다.

### 3. 함수에 배열을 넘기면 주소가 전달된다

배열 전체가 복사되는 것이 아닙니다.

시작 주소를 어디로 넘기느냐에 따라 함수 내부의 <code>a[0]</code>이 원본 배열의 다른 위치가 될 수 있습니다.

### 4. 구조체 포인터도 자료형 단위로 이동한다

```c
q++;
```

는 구조체 내부의 다음 멤버로 이동하는 것이 아니라 다음 구조체 원소로 이동합니다.

### 5. 같은 배열 안의 포인터 차이는 원소 거리다

```c
p - s
```

는 단순한 바이트 주소 차이가 아니라 두 포인터 사이의 원소 개수 차이입니다.

### 6. 전처리기 조건은 실행 전에 처리된다

```c
#if
#elif
#else
#endif
```

는 일반 조건문과 처리 시점이 다릅니다.

### 7. 함수 포인터는 동작 자체를 전달한다

함수를 다른 함수에 인자로 넘겨 실행할 함수를 선택할 수 있습니다.

### 8. 정의되지 않은 동작은 숫자를 계산하지 않는다

같은 변수를 한 식 안에서 여러 번 변경하는 문제에서는 평가 순서가 보장되는지를 먼저 확인해야 합니다.

## 시험·면접에서 바로 보는 포인트

- <code>*pp</code>와 <code>**pp</code>가 각각 무엇을 의미하는지 먼저 적습니다.
- 포인터 선언은 괄호 위치까지 확인합니다.
- 배열 중간 주소를 함수에 넘길 수 있다는 점을 기억합니다.
- 구조체 포인터의 <code>-></code>는 <code>(*p).</code>와 같은 의미입니다.
- 문자 포인터를 <code>%s</code>로 출력하면 현재 위치부터 종료 문자까지 출력됩니다.
- 전처리기와 일반 조건문의 실행 시점을 구분합니다.
- 함수 포인터 문제는 함수 대응 관계부터 적습니다.
- 특정 출력값을 계산하기 전에 정의되지 않은 동작인지 먼저 확인합니다.
