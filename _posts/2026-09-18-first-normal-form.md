`제1정규형`은 <mark>모든 Attribute의 값이 더 이상 나눌 수 없는 하나의 원자값만 가지도록 Table을 정리한 상태</mark>입니다.

핵심은 **한 Cell에 여러 값을 넣지 않고 하나의 값만 저장하는 것**입니다.

<blockquote class="prompt-info">
<p>한 줄: 제1정규형은 하나의 Column 값에 하나의 원자값만 저장하도록 만드는 단계입니다.</p>
</blockquote>

<details markdown="1">
<summary>한 줄로</summary>

한 Cell에 여러 값을 넣지 않고 하나의 값만 저장하면 제1정규형의 핵심 조건을 만족합니다.

</details>

## 제1정규형이 필요한 이유

다음과 같은 Table이 있다고 가정합니다.

| 학생번호 | 학생이름 | 수강강의 |
| --- | --- | --- |
| 1001 | 학생1 | 데이터베이스, 운영체제 |
| 1002 | 학생2 | 네트워크 |

`수강강의` 하나의 Cell 안에 여러 값이 들어가 있습니다.

```text
데이터베이스, 운영체제
→ 하나의 Cell 안에 값이 2개
```

이 구조에서는 특정 강의를 검색하거나 수정하기가 불편합니다.

## 원자값

제1정규형의 핵심은 `원자값`입니다.

```text
원자값
→ 하나의 Cell에 하나의 값
```

예를 들어 다음은 제1정규형에 맞지 않습니다.

| 학생번호 | 수강강의 |
| --- | --- |
| 1001 | 데이터베이스, 운영체제 |

반면 다음처럼 나누면 각 Cell에 하나의 값만 들어갑니다.

| 학생번호 | 수강강의 |
| --- | --- |
| 1001 | 데이터베이스 |
| 1001 | 운영체제 |

## 제1정규형으로 변환

### 변환 전

| 학생번호 | 학생이름 | 수강강의 |
| --- | --- | --- |
| 1001 | 학생1 | 데이터베이스, 운영체제 |
| 1002 | 학생2 | 네트워크 |

### 문제

```text
수강강의
→ 여러 값이 한 Cell에 저장
```

### 변환 후

| 학생번호 | 학생이름 | 수강강의 |
| --- | --- | --- |
| 1001 | 학생1 | 데이터베이스 |
| 1001 | 학생1 | 운영체제 |
| 1002 | 학생2 | 네트워크 |

이제 모든 Cell에는 하나의 값만 들어갑니다.

```text
하나의 Cell
→ 하나의 값
→ 1NF
```

## 반복되는 Column도 정리

다음과 같은 구조도 좋지 않습니다.

| 학생번호 | 강의1 | 강의2 | 강의3 |
| --- | --- | --- | --- |
| 1001 | 데이터베이스 | 운영체제 | 네트워크 |

같은 의미의 Column이 반복되고 있습니다.

```text
강의1
강의2
강의3
```

강의가 더 늘어나면 `강의4`, `강의5` 같은 Column을 계속 추가해야 합니다.

이런 반복 구조는 Row 단위로 분리하는 것이 자연스럽습니다.

### 변환 후

| 학생번호 | 강의 |
| --- | --- |
| 1001 | 데이터베이스 |
| 1001 | 운영체제 |
| 1001 | 네트워크 |

## 원자값은 절대적인 개념이 아니다

어떤 값을 하나의 원자값으로 볼지는 데이터베이스에서 어떻게 사용할지에 따라 달라질 수 있습니다.

예를 들어 주소를 하나의 값으로 저장할 수도 있고

```text
서울특별시 강남구
```

시와 구를 각각 검색해야 한다면 별도 Attribute로 나눌 수도 있습니다.

| 시 | 구 |
| --- | --- |
| 서울특별시 | 강남구 |

따라서 원자값은 <mark>업무에서 더 이상 나눌 필요가 없는 하나의 값</mark>으로 이해하는 것이 좋습니다.

## 1NF라고 중복이 모두 사라지는 것은 아니다

제1정규형을 만족해도 데이터 중복은 남아 있을 수 있습니다.

### 예시

| 학생번호 | 학생이름 | 강의 |
| --- | --- | --- |
| 1001 | 학생1 | 데이터베이스 |
| 1001 | 학생1 | 운영체제 |

학생이름 `학생1`이 반복됩니다.

하지만 각 Cell은 하나의 원자값을 가지고 있으므로 제1정규형 자체는 만족합니다.

```text
1NF
→ 원자값 문제 해결

중복 전체 제거
→ 아직 아님
```

<blockquote class="prompt-warning">
<p>제1정규형을 만족했다고 해서 부분 함수 종속이나 이행 함수 종속까지 제거된 것은 아닙니다.</p>
</blockquote>

## 이상 현상과 연결

반복되는 값을 하나의 Cell에 저장하면 데이터 처리 과정이 복잡해집니다.

예를 들어 다음 값에서 운영체제만 삭제하려면

```text
데이터베이스, 운영체제
```

문자열 내부의 일부 값만 직접 찾아 수정해야 합니다.

반면 Row를 분리하면 원하는 데이터를 개별적으로 다루기 쉬워집니다.

```text
1001 | 데이터베이스
1001 | 운영체제
```

제1정규형은 이러한 반복값 구조를 정리하는 정규화의 첫 단계입니다.

## 제1정규형과 제2정규형 차이

제1정규형과 제2정규형은 검사하는 대상이 다릅니다.

| 구분 | 핵심 |
| --- | --- |
| 제1정규형 | 모든 Attribute를 원자값으로 구성 |
| 제2정규형 | 부분 함수 종속 제거 |

```text
1NF
→ Cell 안의 값 확인
```

```text
2NF
→ 복합 Key와 함수적 종속 확인
```

따라서 제2정규형으로 가기 전에 먼저 제1정규형을 만족해야 합니다.

## 잘 놓치는 핵심

### 1. 하나의 Cell에 여러 값을 넣으면 1NF 위반

```text
취미
→ 축구, 영화, 독서
```

처럼 여러 값을 한 번에 저장하면 문제가 됩니다.

### 2. 같은 종류의 Column 반복도 피한다

```text
전화번호1
전화번호2
전화번호3
```

같은 반복 속성은 별도 Row 또는 별도 관계로 정리하는 것이 좋습니다.

### 3. 중복이 있다고 무조건 1NF 위반은 아니다

중복된 Row 값이 있더라도 각 Cell이 원자값이면 제1정규형을 만족할 수 있습니다.

### 4. 1NF는 정규화의 시작 단계다

부분 함수 종속과 이행 함수 종속은 다음 단계에서 다룹니다.

## 시험·면접

### 핵심 암기

```text
1NF
→ 원자값
```

```text
한 Cell
→ 하나의 값
```

```text
반복 속성
→ 분리
```

### 시험 함정

제1정규형은 중복값 자체를 모두 제거하는 단계가 아닙니다.

핵심은 각 Attribute가 원자값을 가지는지 확인하는 것입니다.

### 면접 짧은 답변

제1정규형은 모든 Attribute가 원자값을 가지도록 Table을 구성한 상태입니다. 하나의 Cell에 여러 값을 저장하거나 같은 의미의 반복 Column을 두는 구조를 정리하고, 이후 제2정규형과 제3정규형으로 진행하기 위한 기본 단계입니다.

## 객관식 문제

### 문제 1 · 원자값

다음 중 제1정규형을 위반한 경우는?

① 한 Cell에 하나의 학과명 저장  
② 한 Cell에 `축구, 영화, 독서` 저장  
③ 학생번호 하나 저장  
④ 강의번호 하나 저장

<details markdown="1">
<summary>정답</summary>

②

하나의 Cell에 여러 값이 들어 있으므로 원자값 조건을 만족하지 않습니다.

</details>

### 문제 2 · 변환

다음 Table을 제1정규형으로 변환하는 방법으로 가장 적절한 것은?

| 학생번호 | 강의 |
| --- | --- |
| 1001 | 데이터베이스, 운영체제 |

① 강의 Column을 삭제한다.  
② 학생번호를 삭제한다.  
③ 강의를 각각 별도의 Row로 분리한다.  
④ 두 값을 그대로 유지한다.

<details markdown="1">
<summary>정답</summary>

③

다음처럼 각 Cell에 하나의 강의만 저장하도록 분리합니다.

| 학생번호 | 강의 |
| --- | --- |
| 1001 | 데이터베이스 |
| 1001 | 운영체제 |

</details>

### 문제 3 · 반복 Column

다음 구조의 문제로 가장 적절한 것은?

```text
전화번호1
전화번호2
전화번호3
```

① 반복되는 같은 종류의 Attribute가 존재한다.  
② Primary Key가 너무 많다.  
③ Foreign Key가 없다.  
④ 반드시 제3정규형이다.

<details markdown="1">
<summary>정답</summary>

①

같은 의미의 Attribute가 여러 Column으로 반복되는 구조입니다.

</details>

### 문제 4 · 중복

다음 설명으로 옳은 것은?

① 1NF에서는 모든 중복값이 반드시 사라진다.  
② 각 Cell이 원자값이면 일부 데이터 중복이 있어도 1NF를 만족할 수 있다.  
③ 1NF는 이행 함수 종속을 제거한다.  
④ 1NF는 Index를 생성하는 과정이다.

<details markdown="1">
<summary>정답</summary>

②

제1정규형의 핵심은 모든 Attribute 값이 원자값인지 여부입니다.

</details>

### 문제 5 · 다음 단계

제1정규형 다음 단계인 제2정규형에서 주로 제거하는 것은?

① 반복 Column  
② 부분 함수 종속  
③ 이행 함수 종속  
④ 모든 Foreign Key

<details markdown="1">
<summary>정답</summary>

②

제2정규형에서는 복합 Key에 대한 부분 함수 종속을 제거합니다.

</details>

## 제1정규형 전체 요약

### 변환 전

| 학생번호 | 강의 |
| --- | --- |
| 1001 | 데이터베이스, 운영체제 |

### 변환 후

| 학생번호 | 강의 |
| --- | --- |
| 1001 | 데이터베이스 |
| 1001 | 운영체제 |

```text
여러 값이 한 Cell
↓
각 값을 별도 Row로 분리
↓
모든 Cell을 원자값으로 구성
↓
제1정규형
```

<blockquote class="prompt-danger">
<p>제1정규형 문제에서는 가장 먼저 한 Cell 안에 여러 값이 들어 있는지 확인합니다.</p>
</blockquote>
