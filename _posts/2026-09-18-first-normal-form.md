제1정규형(1NF)은 모든 Attribute 값이 하나의 원자값을 가지도록 Relation을 구성한 상태입니다.

이 글에서는 정의만 외우지 않고 실제 Table을 어떻게 보고 판단하는지까지 연결합니다.

<blockquote class="prompt-info">
<p>한 줄: 1NF의 핵심은 한 Cell에 여러 값을 넣지 않고 반복되는 값을 각각 하나의 값으로 표현하는 것입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

1NF = Attribute 값은 원자값

</details>

## 1NF 위반 예시

다음 Table을 봅니다.

```text
ORDER_ID | CUSTOMER | PRODUCTS
O1       | C1       | P1, P2
O2       | C2       | P3
```

`PRODUCTS` 한 Cell에 `P1, P2`라는 두 값이 들어 있습니다.

검색과 제약조건 적용이 어렵고 하나의 값으로 다루기 어렵습니다.

따라서 1NF에 맞지 않는 구조로 봅니다.

## 원자값

원자값은 현재 모델에서 더 이상 하나의 Attribute 값으로 쪼개서 저장하지 않는 단일 값을 뜻합니다.

```text
잘못된 예
→ P1, P2

1NF 형태
→ P1
→ P2
```

문자열에 쉼표가 있다는 사실 자체보다 **여러 의미 값을 한 Attribute에 묶어 저장했는지**가 중요합니다.

## 1NF 변환

위 Table을 Row 단위로 분리합니다.

```text
ORDER_ID | CUSTOMER | PRODUCT_ID
O1       | C1       | P1
O1       | C1       | P2
O2       | C2       | P3
```

이제 각 Cell은 하나의 값만 가집니다.

하지만 ORDER_ID와 CUSTOMER가 반복되므로 중복 문제는 아직 남습니다.

1NF만 만족했다고 정규화가 끝난 것은 아닙니다.

## 반복 Column 문제

다음 구조도 좋지 않습니다.

```text
ORDER_ID | PRODUCT1 | PRODUCT2 | PRODUCT3
O1       | P1       | P2       | NULL
```

상품 개수가 늘어날 때마다 Column을 추가해야 합니다.

1NF 관점에서는 반복 그룹을 별도 Row 구조로 바꾸는 것이 자연스럽습니다.

## ORDER_ITEM으로 분리

실제 관계형 설계에서는 주문과 상품 관계를 ORDER_ITEM으로 분리합니다.

```text
ORDERS
ORDER_ID | CUSTOMER_ID

ORDER_ITEM
ORDER_ID | PRODUCT_ID | QTY
```

한 주문에 여러 상품이 있어도 각 상품이 별도 Row로 저장됩니다.

## 1NF와 다중값 Attribute

ER Model에서 다중값 Attribute가 존재한다면 관계형 모델로 변환할 때 별도 Relation으로 분리하는 경우가 많습니다.

예를 들어 고객 전화번호가 여러 개라면

```text
CUSTOMER_PHONE
CUSTOMER_ID | PHONE
```

처럼 구성할 수 있습니다.

## 1NF가 해결하지 못하는 것

1NF는 원자값 문제를 해결하지만 함수 종속 문제까지 해결하지는 않습니다.

다음 Relation이 1NF라고 해도

```text
ORDER_ID | PRODUCT_ID | PRODUCT_NAME | QTY
```

`PRODUCT_ID → PRODUCT_NAME`이라는 부분 함수 종속이 있을 수 있습니다.

이 문제는 2NF에서 다룹니다.

## 구체적 변환 순서

1NF 문제를 풀 때는 다음 순서가 좋습니다.

```text
1. 한 Cell에 여러 값이 있는지 찾는다.
2. 반복 그룹이나 다중값 Attribute를 찾는다.
3. 하나의 값이 하나의 Cell에 오도록 Row 또는 별도 Table로 분리한다.
4. 분리 후 Key를 다시 확인한다.
```

특히 분리 후 복합 Key가 생길 수 있습니다.

## 1NF 전후 비교

| 구분 | 1NF 이전 | 1NF 이후 |
| --- | --- | --- |
| 한 Cell | 여러 값 가능 | 하나의 값 |
| 반복 그룹 | 존재 가능 | 제거 |
| 검색 | 복잡 | 단순 |
| 다음 정규화 | 어려움 | 2NF 분석 가능 |

1NF는 정규화의 출발점입니다.

## 다른 개념과 비교

### 비교 1. 1NF

```text
1NF
→ 원자값
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

### 비교 2. 2NF

```text
2NF
→ 부분 함수 종속 제거
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

### 비교 3. 3NF

```text
3NF
→ 이행 함수 종속 제거
```

비교할 때는 **무엇을 결정하는가**, **어떤 중복을 줄이는가**, **어떤 성능 비용이 생기는가**를 구분합니다.

## 시험·면접

### 핵심 암기

```text
1NF = Attribute 값은 원자값
```

### 시험 접근 순서

```text
1. Entity 또는 Relation 확인
2. Candidate Key 확인
3. 함수 종속 확인
4. 이상 현상 확인
5. 정규형 조건 확인
6. 필요한 분해 확인
```

### 시험 함정

현재 예시 데이터에서 값이 우연히 유일하다고 해서 함수 종속이나 Key가 자동으로 성립하는 것은 아닙니다.

Schema와 업무 규칙을 기준으로 판단해야 합니다.

### 면접에서 짧게 답한다면

제1정규형(1NF)은 모든 Attribute 값이 하나의 원자값을 가지도록 Relation을 구성한 상태입니다.

정규화와 모델링에서는 Key와 함수 종속을 기준으로 중복과 이상 현상을 줄이는 방향으로 구조를 설계합니다.

## 예시로 한 바퀴

`제1정규형 · 1NF` 문제를 만나면 작은 Relation부터 그립니다.

```text
Key
→ 결정되는 Attribute
→ 반복되는 사실
→ 발생 가능한 이상 현상
```

그다음 어떤 Attribute가 어떤 Key에 종속되는지 화살표로 표시합니다.

마지막으로 분해가 필요하다면 **같은 사실을 한 곳에서만 관리할 수 있도록** Relation을 나눕니다.
