## 이 글의 범위와 읽는 방법

여기서 **NCS 수준**은 자바 기초 개념을 설명하고, 짧은 코드의 실행 결과와 개념형 선지를 판별할 수 있는 학습 깊이를 뜻합니다. 특정 기관의 공식 출제 범위나 출제 빈도를 보장하는 자료는 아닙니다.

기존 목차의 **001~055를 모두 유지**했습니다. 다만 세부 구현을 암기하기보다 **정의 → 짧은 예제 → 작동 이유 → 선지 판별 포인트**에 집중합니다.

| 구분 | 공부할 깊이 |
| --- | --- |
| 핵심 | 용어를 설명하고 짧은 코드의 결과까지 판단합니다. |
| 보충 | 기존 문법과 무엇이 다른지 비교합니다. |
| 선택 심화 | 이름과 목적을 알아두고, 처음에는 세부 구현을 건너뛰어도 됩니다. |

기본 설명과 실행 예제는 **자바 21의 정식 문법**을 기준으로 합니다. 자바 22·25에서 달라진 규칙은 따로 표시합니다. 미리보기 기능은 기본 예제로 사용하지 않습니다. 버전 변화는 공식 언어 변경 문서를 기준으로 구분합니다.[^versions]

코드는 예제별로 독립적입니다. `public class Main`이 있는 예제는 전체를 `Main.java`로 저장합니다. 변수 선언과 출력만 있는 짧은 예제는 `main` 메서드 안에 넣습니다. 클래스·메서드 선언만 있는 블록은 선언 예제이므로 각각 알맞은 선언 위치에 배치합니다. `컴파일 오류`라고 적은 주석은 해당 줄의 주석을 풀었을 때의 결과입니다.

<mark>코드 문제는 먼저 컴파일 가능 여부를 확인하고, 그다음 실행 순서와 출력값을 계산합니다.</mark>

## 1부. 자바의 정체성과 개발 환경

### 001. 자바 언어와 플랫폼의 구분

**언어**는 프로그램을 적는 규칙이고, **플랫폼**은 그 프로그램을 실행하는 데 필요한 기반입니다. 자바라는 이름은 언어뿐 아니라 실행 환경과 표준 라이브러리를 함께 가리키기도 합니다.[^start]

| 용어 | 의미 | 기억할 내용 |
| --- | --- | --- |
| 자바 언어 | 변수·조건문·클래스 등을 적는 문법 | 소스 코드를 작성하는 규칙입니다. |
| 자바 표준 플랫폼 | 언어·가상 머신·표준 라이브러리 등의 기반 | 문자열·배열 외에도 많은 표준 기능을 제공합니다. |
| 가상 머신 `JVM` | 클래스 파일을 읽고 실행하는 실행 기반 | 운영체제와 기계에 맞는 구현이 필요합니다. |
| 실행 환경 `JRE` | 가상 머신과 실행에 필요한 라이브러리 등의 개념 | 컴파일 도구와 구분합니다. |
| 개발 도구 모음 `JDK` | 컴파일러·실행기·분석 도구 등을 포함 | 개발에는 이것을 사용합니다. |
| `OpenJDK` | 자바 개발 도구의 공개 소스 프로젝트 | 배포판의 이름과 구분합니다. |
| 배포판 | 소스와 구성 요소를 실제 설치·실행 형태로 제공한 것 | 제공 주체에 따라 지원·구성이 다를 수 있습니다. |

학습용으로는 다음처럼 관계를 기억하면 됩니다.

```text
개발 도구 모음: 작성한 코드를 컴파일하고 실행할 도구
실행 환경: 이미 만들어진 자바 프로그램을 실행할 기반
가상 머신: 클래스 파일을 실제로 실행하는 핵심 구성 요소
```

이 관계는 **역할을 구분하는 개념도**입니다. 최신 배포판의 폴더가 반드시 `JDK → JRE → JVM`이라는 중첩 구조로 존재한다는 뜻은 아닙니다.

자카르타는 웹·기업용 응용 프로그램을 위한 별도의 표준 생태계입니다. 스프링도 자바 언어 자체가 아닙니다. 이 글에서는 언어와 표준 플랫폼의 기초만 다룹니다.[^platform]

### 002. 자바의 언어적 특징

자바는 **정적 타입을 사용하는 클래스 기반 객체지향 언어**입니다. 자료형에 맞지 않는 대입과 호출을 컴파일 단계에서 많이 검사합니다.[^types]

| 특징 | 의미 | 잘못 이해하기 쉬운 설명 |
| --- | --- | --- |
| 정적 타입 | 변수·식의 타입을 컴파일할 때 판단합니다. | 실행할 때마다 변수 타입이 자유롭게 바뀌는 것은 아닙니다. |
| 타입 검사 | 타입에 맞는 연산·대입·호출인지 확인합니다. | 모든 오류를 컴파일 단계에서 잡는다는 뜻은 아닙니다. |
| 클래스 기반 객체지향 | 상태와 기능을 클래스에 묶고 객체를 만듭니다. | 기본형 값까지 전부 객체라는 뜻은 아닙니다. |
| 플랫폼 독립성 지향 | 같은 바이트코드를 호환 실행 환경에서 실행합니다. | 가상 머신 자체가 모든 운영체제에서 같은 실행 파일인 것은 아닙니다. |
| 자동 메모리 관리 | 도달할 수 없는 객체의 메모리를 회수합니다. | 메모리 누수나 자원 관리 문제가 사라지는 것은 아닙니다. |
| 단일 클래스 상속 | 클래스의 직접 상위 클래스는 하나입니다. | 인터페이스도 하나만 구현한다는 뜻은 아닙니다. |
| 명시적 포인터 연산 부재 | 참조를 주소 숫자처럼 더하고 빼지 않습니다. | 객체 참조가 없다는 뜻은 아닙니다. |
| 사용자 정의 연산자 오버로딩 부재 | 임의 클래스에 새로운 `+` 동작을 선언하지 않습니다. | 언어가 제공하는 문자열 연결까지 없다는 뜻은 아닙니다. |

자바에는 순서대로 명령을 실행하는 문법과 람다 같은 함수형 요소도 있습니다. 객체지향이라는 말이 다른 방식의 표현을 전혀 사용할 수 없다는 뜻은 아닙니다.[^overview]

**장점과 부담을 함께 보기**

| 선택 | 얻는 점 | 감수하는 점 |
| --- | --- | --- |
| 타입을 확인하고 사용 | 잘못된 대입·호출을 일찍 발견 | 타입 규칙을 이해해야 합니다. |
| 가상 머신 위에서 실행 | 실행 환경의 차이를 줄이기 쉬움 | 실행 환경과 버전 호환성을 확인해야 합니다. |
| 자동 메모리 회수 | 직접 메모리를 해제하는 부담 감소 | 회수 시점·메모리 사용을 별도로 관리합니다. |
| 객체로 역할 분리 | 관련 상태와 기능을 묶기 쉬움 | 작은 문제를 불필요하게 복잡한 구조로 만들 수 있습니다. |

### 003. 소스 코드에서 실행까지

자바의 전통적인 실행 과정은 다음과 같습니다.[^start][^jvm]

```text
소스 파일: Main.java
        ↓ javac로 컴파일
클래스 파일: Main.class
        ↓ 가상 머신이 읽고 검사
필요한 클래스 연결·초기화
        ↓
프로그램 실행
```

| 단계 | 하는 일 |
| --- | --- |
| 컴파일 | 문법·타입 등을 검사하고 클래스 파일을 만듭니다. |
| 클래스 로딩 | 필요한 클래스의 정의를 읽습니다. |
| 검사·연결 | 클래스 파일을 검증하고 참조 관계를 준비합니다. |
| 초기화 | 필요한 정적 초기화 등을 실행합니다. |
| 실행 | 메서드의 코드를 수행합니다. |

**바이트코드**는 가상 머신이 이해하는 명령입니다. 소스 코드 자체도 아니고, 특정 운영체제의 기계어만을 뜻하는 것도 아닙니다.

가상 머신 구현은 명령을 해석하여 실행하거나, 실행 중 일부 코드를 기계어로 컴파일해 사용할 수 있습니다. 후자를 **실행 중 컴파일**이라고 합니다. 따라서 자바를 “컴파일만 한다” 또는 “한 줄씩 해석만 한다”로 단정하면 부정확합니다.[^jvm]

<blockquote class="prompt-warning">
<p>같은 클래스 파일이라도 실행 환경의 지원 버전, 사용하는 라이브러리, 운영체제 전용 기능에 따라 실행 가능 여부가 달라집니다.</p>
</blockquote>

### 004. 개발 환경과 실행 환경

기본 명령은 다음과 같습니다.[^tools]

```text
java -version
javac -version
javac -encoding UTF-8 Main.java
java Main
```

| 명령·설정 | 의미 |
| --- | --- |
| `javac` | 소스 파일을 컴파일합니다. |
| `java` | 프로그램을 실행합니다. |
| `PATH` | 명령을 찾을 폴더 목록입니다. |
| `JAVA_HOME` | 개발 도구가 설치된 위치를 다른 도구에 알려줄 때 사용합니다. |
| 클래스 경로 | 실행에 필요한 사용자 클래스·라이브러리를 찾는 위치입니다. |
| 통합 개발 환경 | 편집·실행·디버깅을 돕는 프로그램입니다. |

**편집기가 있다고 개발 도구가 자동으로 준비되는 것은 아닙니다.** `java`와 `javac`가 서로 다른 설치 경로의 프로그램일 수도 있으므로 두 버전을 함께 확인합니다.

새로운 버전용으로 만든 클래스 파일을 오래된 실행 환경에서 실행하면 지원하지 않는 클래스 버전 오류가 생길 수 있습니다. 이때는 소스 내용만 고칠 것이 아니라 **컴파일 대상 버전과 실행 버전**을 함께 확인해야 합니다.[^tools]

### 005. 프로그램의 기본 구조와 진입점

전통적인 첫 프로그램은 다음과 같습니다.

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("자바 시작");
    }
}
```

출력:

```text
자바 시작
```

| 요소 | 의미 |
| --- | --- |
| `public class Main` | 외부에서 접근 가능한 `Main` 클래스를 선언합니다. |
| `main` | 전통적인 실행 진입 메서드의 이름입니다. |
| `public` | 접근 범위를 공개합니다. |
| `static` | 객체를 먼저 만들지 않고 클래스에 속한 메서드로 사용합니다. |
| `void` | 반환값이 없습니다. |
| `String[] args` | 명령행 인수를 문자열 배열로 받습니다. |
| `System.out.println` | 값을 표준 출력에 쓰고 줄을 바꿉니다. |

일반적인 `javac` 기반 파일에서는 **공개 최상위 클래스 이름과 파일 이름을 맞춥니다.** 위 파일은 `Main.java`입니다. `args`는 일반 매개변수 이름이므로 다른 이름으로 바꿔도 됩니다. 실행할 때 받은 인수가 없다면 배열의 길이가 0이며, `args` 자체가 자동으로 `null`이 되는 것은 아닙니다.[^start][^launcher]

**보충: 단일 소스 실행**

지원되는 버전에서는 `java Main.java`로 소스 파일을 바로 실행할 수도 있습니다. 이것은 “컴파일 과정이 필요 없는 언어로 바뀐다”는 뜻이 아니라 실행기가 필요한 과정을 처리하는 방식입니다.[^launcher]

**보충: 자바 25 이후**

간결한 소스 파일과 인스턴스 `main`이 정식 도입되었습니다. 따라서 “어떤 자바 버전에서도 `main`은 반드시 위 형태뿐이다”라는 문장은 맞지 않습니다. 이 글의 기본 예제는 전통적인 형태로 통일합니다.[^compact]

### 006. 버전·명세·구현체 읽는 법

**명세**는 반드시 지켜야 할 규칙이고, **구현 세부사항**은 특정 제품이 그 규칙을 실현하는 방식입니다.

| 구분 | 예 |
| --- | --- |
| 언어가 정한 규칙 | `int`는 32비트 정수형입니다. |
| 실행 시 보장되는 검사 | 배열 범위를 벗어난 접근은 검사됩니다. |
| 구현 세부사항 | 객체의 실제 배치·메모리 회수 방식은 구현에 따라 달라질 수 있습니다. |
| 버전별 문법 변화 | 레코드·패턴·새 생성자 문법의 사용 가능 시점입니다. |

| 상태 | 뜻 |
| --- | --- |
| 정식 기능 | 해당 버전의 정식 사용 범위에 포함됩니다. |
| 미리보기 | 시험 사용 단계이며 버전 간에 변경될 수 있습니다. |
| 인큐베이터 | 주로 새 라이브러리·도구를 시험 제공하는 단계입니다. |
| 장기지원 | 배포 주체의 지원 정책과 관련된 개념입니다. |

`--release`는 지원되는 이전 버전을 대상으로 컴파일할 때 사용합니다. `--enable-preview`는 해당 버전의 미리보기 기능을 사용할 때 필요합니다. 모든 미리보기 기능이 다음 버전에서 그대로 정식화되는 것은 아닙니다.[^preview][^tools]

**1부 핵심:** 소스·클래스 파일·가상 머신·개발 도구의 역할을 구분하고, 실행 가능 여부에는 버전 조건이 있다는 점을 기억합니다.

## 2부. 기초 문법·자료형·변수

### 007. 어휘 구조와 예약어

자바 소스는 이름·키워드·리터럴·연산자·구분 기호 같은 작은 요소로 나뉩니다. 이런 문법의 기본 단위를 **토큰**이라고 합니다.[^lexical]

```java
int 점수 = 80;
```

위 문장은 `int`, `점수`, `=`, `80`, `;`로 나누어 볼 수 있습니다.

| 요소 | 예 | 뜻 |
| --- | --- | --- |
| 키워드 | `class`, `int`, `return` | 문법에서 정한 역할이 있습니다. |
| 식별자 | `점수`, `합계`, `Main` | 변수·메서드·클래스 등에 붙인 이름입니다. |
| 리터럴 | `80`, `3.5`, `'가'`, `"합격"` | 코드에 직접 쓴 값입니다. |
| 연산자 | `+`, `=`, `==` | 계산·대입·비교 등을 수행합니다. |
| 구분 기호 | `;`, `,`, `(`, `)` | 문장의 끝이나 요소의 경계를 구분합니다. |

주석은 `// 한 줄`, `/* 여러 줄 */`, `/** 문서화 */` 형태로 작성합니다. 블록 주석 안에 또 다른 블록 주석을 중첩하는 방식은 지원되지 않습니다.

식별자는 대소문자를 구분하며 숫자로 시작할 수 없습니다. 한글 이름도 사용할 수 있습니다. `true`, `false`, `null`은 리터럴이며 변수 이름으로 사용할 수 없습니다. `const`, `goto`는 예약되어 있지만 일반 문법으로 사용하지 않습니다.[^lexical]

**보충:** 유니코드 이스케이프는 주석을 처리하기보다 먼저 해석됩니다. 단순히 “주석 안이므로 어떤 문자도 아무 영향이 없다”고 일반화하지 않습니다.

**버전 주의:** `_` 한 글자는 자바 21의 일반 변수 이름으로 사용할 수 없습니다. 자바 22부터는 허용된 위치에서 “사용하지 않는 값”을 나타내는 이름 없는 변수·패턴에 사용됩니다. 그 값을 `_`로 다시 읽는 이름이 아닙니다.[^unnamed]

### 008. 이름·패키지·가져오기

**패키지**는 관련 타입을 이름 공간으로 묶는 단위입니다. **가져오기**는 다른 패키지의 타입 등을 짧은 이름으로 사용하게 해줍니다.[^packages]

```java
package study;

import java.util.ArrayList;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> 이름목록 = new ArrayList<>();
        이름목록.add("민수");
        System.out.println(이름목록.size());
    }
}
```

이 파일을 작업 폴더의 `Main.java`로 저장했다면 다음처럼 실행합니다.

```text
javac -encoding UTF-8 -d . Main.java
java study.Main
```

출력은 `1`입니다. 패키지를 선언한 프로그램은 실행할 때 `study.Main`처럼 완전한 이름을 사용합니다.

| 규칙 | 설명 |
| --- | --- |
| `java.lang`의 타입 | `String`, `System`, `Object` 등은 별도 가져오기 없이 사용합니다. |
| 같은 패키지의 타입 | 접근 가능한 타입은 별도 가져오기 없이 사용할 수 있습니다. |
| `import java.util.*` | 해당 패키지의 접근 가능한 타입을 짧게 쓰게 합니다. |
| 하위 패키지 | `java.util.*`가 `java.util.concurrent.*`까지 가져오지는 않습니다. |
| 정적 가져오기 | 접근 가능한 정적 멤버를 클래스 이름 없이 사용하게 합니다. |
| 이름 충돌 | 같은 단순 이름이 충돌하면 완전한 이름 등으로 구분합니다. |

가져오기는 클래스 코드를 소스 파일에 복사하는 기능이 아닙니다. 파일·네트워크를 읽는 기능도 아닙니다.

**보충:** `import module`은 자바 25의 정식 문법입니다. 기본적인 `import 패키지.타입`과 구분합니다.[^versions]

### 009. 기본형 여덟 가지

기본형은 **정수·실수·문자·논리값을 직접 표현하는 자료형**입니다. `String`은 기본형이 아니라 참조형입니다.[^primitive][^types]

| 종류 | 자료형 | 크기·범위 | 대표 예 |
| --- | --- | --- | --- |
| 정수 | `byte` | 8비트, -128~127 | `byte 수 = 10;` |
| 정수 | `short` | 16비트, -32,768~32,767 | `short 수 = 100;` |
| 정수 | `int` | 32비트, -2,147,483,648~2,147,483,647 | `int 수 = 1000;` |
| 정수 | `long` | 64비트, -2의 63제곱~2의 63제곱-1 | `long 수 = 1000L;` |
| 실수 | `float` | 32비트 부동소수점 | `float 수 = 1.5F;` |
| 실수 | `double` | 64비트 부동소수점 | `double 수 = 1.5;` |
| 문자 | `char` | 16비트, 0~65,535 | `char 글자 = '가';` |
| 논리 | `boolean` | `true` 또는 `false` | `boolean 통과 = true;` |

<mark>논리형의 저장 크기를 언어 규칙상 무조건 1바이트라고 단정하지 않습니다.</mark>

`char`는 부호 없는 16비트 코드 단위를 표현합니다. 화면에 보이는 문자 하나가 반드시 `char` 하나인 것은 아닙니다. 일부 문자는 두 코드 단위가 필요합니다.

**정수의 범위를 넘으면**

```java
int 수 = Integer.MAX_VALUE;
System.out.println(수 + 1);
```

출력:

```text
-2147483648
```

일반 정수 덧셈의 오버플로가 자동으로 예외를 던지는 것은 아닙니다. 변수에 더 넓은 자료형을 쓰더라도 **이미 앞에서 수행한 계산**이 좁은 자료형이었다면 문제가 남을 수 있습니다.

**실수는 항상 정확한 십진수가 아닙니다.**

```java
System.out.println(0.1 + 0.2 == 0.3);
System.out.println(1.0 / 0.0);
System.out.println(0.0 / 0.0);
```

출력:

```text
false
Infinity
NaN
```

이진 부동소수점은 일부 십진수를 정확하게 저장하지 못합니다. 실수 나눗셈의 0 처리는 정수 나눗셈과 다릅니다. `NaN`은 자기 자신과 `==`로 비교해도 `false`입니다. 양의 0과 음의 0은 `==` 비교에서는 같지만 나눗셈 등에서는 구분될 수 있습니다.[^floating]

### 010. 참조형과 null

참조형 변수는 **객체 자체가 아니라 객체를 가리키는 참조값**을 저장합니다. 클래스형·인터페이스형·배열형이 여기에 해당합니다.[^types]

```java
int[] 첫째 = {10, 20};
int[] 둘째 = 첫째;
둘째[0] = 99;
System.out.println(첫째[0]);
```

출력:

```text
99
```

```text
첫째 ─┐
      ├→ 같은 배열 [99, 20]
둘째 ─┘
```

`둘째 = 첫째`는 배열 전체를 복제하는 문장이 아닙니다. 두 변수가 같은 객체를 가리키게 합니다. 이를 **참조 공유**, 또는 별칭 관계라고 볼 수 있습니다.

| 표현 | 뜻 |
| --- | --- |
| `int 수 = 0;` | 정수값 0을 저장합니다. |
| `String 글 = "";` | 길이가 0인 문자열 객체를 참조합니다. |
| `String 글 = null;` | 현재 참조하는 객체가 없습니다. |
| `int[] 배열 = new int[0];` | 원소가 0개인 배열 객체를 참조합니다. |

`null`, 빈 문자열, 길이 0인 배열은 서로 다릅니다. `null`로 인스턴스 메서드나 배열 원소에 접근하면 널 참조 오류가 발생합니다. 기본형에는 `null`을 직접 대입할 수 없습니다.

### 011. 변수의 종류와 초기화 규칙

변수는 **어디에 선언했는지**에 따라 소속과 초기화 규칙이 달라집니다.[^variables]

| 종류 | 선언 위치 | 소속·역할 | 자동 기본값 |
| --- | --- | --- | --- |
| 인스턴스 변수 | 클래스 안, 메서드 밖 | 객체마다 따로 가집니다. | 있음 |
| 클래스 변수 | 클래스 안의 `static` 필드 | 클래스에 속합니다. | 있음 |
| 지역 변수 | 메서드·생성자·블록 안 | 해당 실행 범위에서 사용합니다. | 없음 |
| 매개변수 | 메서드·생성자의 매개변수 목록 | 호출할 때 받은 값을 저장합니다. | 인수로 초기화 |
| 배열 원소 | 생성된 배열 안 | 인덱스로 접근합니다. | 있음 |

```java
public class Main {
    int 점수;
    boolean 합격;
    String 이름;

    public static void main(String[] args) {
        Main 대상 = new Main();
        System.out.println(대상.점수);
        System.out.println(대상.합격);
        System.out.println(대상.이름);
    }
}
```

출력:

```text
0
false
null
```

지역 변수는 다릅니다.

```java
int 점수;
// System.out.println(점수); // 컴파일 오류: 읽기 전에 값이 정해지지 않음
```

| 자료형 | 필드·배열 원소의 기본값 |
| --- | --- |
| 정수형 | 0 |
| 실수형 | 양의 0 |
| `char` | 코드값 0인 문자 |
| `boolean` | `false` |
| 참조형 | `null` |

**유효 범위**는 이름을 사용할 수 있는 코드 범위입니다. 객체의 생존 기간과 같은 말이 아닙니다. 메서드가 끝나 지역 변수의 범위를 벗어나도 그 변수가 가리키던 객체를 다른 곳에서 참조하면 객체가 계속 사용될 수 있습니다.

지역 변수나 매개변수가 필드와 같은 이름이면 그 범위에서는 필드 이름이 가려질 수 있습니다. 이때 `this.필드명`으로 구분합니다. 겹치는 지역 범위 안에서 같은 이름의 지역 변수를 다시 선언하는 것은 허용되지 않습니다.[^names]

### 012. 리터럴과 상수

**리터럴**은 코드에 직접 적은 값이고, **상수 변수**는 컴파일할 때 값이 정해지는 특정한 `final` 변수입니다. 두 용어를 같은 뜻으로 사용하지 않습니다.[^lexical][^types]

```java
int 십진수 = 10;
int 이진수 = 0b1010;
int 팔진수 = 012;
int 십육진수 = 0xA;
long 큰수 = 3_000_000_000L;
float 실수 = 1.5F;
char 문자 = '가';
String 문자열 = "가";
```

정수 리터럴은 보통 `int`, 실수 리터럴은 보통 `double`로 해석합니다. `long` 접미사는 `L`, `float` 접미사는 `F`를 사용합니다. 숫자 안의 `_`는 읽기 편하게 구분하는 표시이며 아무 위치에나 넣을 수 있는 것은 아닙니다.

| 표현 | 의미 |
| --- | --- |
| `'가'` | 문자 리터럴입니다. |
| `"가"` | 문자열 리터럴입니다. |
| `\n` | 줄바꿈을 나타내는 이스케이프입니다. |
| `\t` | 탭입니다. |
| `\\` | 역슬래시 자체입니다. |
| `\"` | 큰따옴표 자체입니다. |

```java
final int 기준 = 100;
int 읽은값 = 100;
final int 복사값 = 읽은값;
```

`기준`은 상수 표현식으로 초기화된 기본형 `final` 변수입니다. 반면 `복사값`은 재대입할 수는 없지만, 초기화식이 상수 표현식이 아니므로 같은 의미의 컴파일타임 상수 변수가 아닙니다.

`static final`이라고 모두 컴파일타임 상수가 되는 것도 아닙니다. **기본형 또는 문자열 타입인지, 상수 표현식으로 초기화했는지**가 중요합니다.

**실질적 `final`**은 `final`을 적지 않았지만 초기화 이후 재대입하지 않아 같은 제약을 만족하는 지역 변수 등을 말합니다. 내부 클래스나 람다에서 바깥 지역 변수를 사용할 때 연결됩니다.

### 013. 형 변환과 숫자 승격

형 변환은 값을 다른 자료형의 값으로 바꾸거나, 참조를 다른 타입의 관점에서 사용하는 것입니다. 먼저 숫자형의 변환을 봅니다.[^conversion]

```text
byte → short → int → long → float → double
               ↑
              char
```

이 그림은 대표적인 **확대 숫자 변환 방향**입니다. `char`와 `short` 사이에는 서로 직접적인 자동 변환을 기대하면 안 됩니다.

```java
int 정수 = 10;
double 실수 = 정수;
int 잘린값 = (int) 3.9;
System.out.println(실수);
System.out.println(잘린값);
```

출력:

```text
10.0
3
```

| 구분 | 설명 |
| --- | --- |
| 확대 변환 | 허용된 방향이면 명시적 캐스팅 없이 변환합니다. |
| 축소 변환 | 일반적으로 `(자료형)`을 직접 적어야 합니다. |
| 정밀도 손실 | 정수를 실수로 확대해도 일부 큰 정수는 정확하게 보존되지 않을 수 있습니다. |
| 논리형 | 숫자형과 서로 캐스팅하지 않습니다. |

**계산할 때는 먼저 숫자 승격을 확인합니다.**

`byte`, `short`, `char`끼리 일반적인 산술 연산을 하면 보통 `int`로 승격됩니다.

```java
byte 첫째 = 10;
byte 둘째 = 20;
int 합 = 첫째 + 둘째;
// byte 작은합 = 첫째 + 둘째; // 컴파일 오류: 결과는 int
```

`double`이 있으면 보통 `double`, 그렇지 않고 `float`가 있으면 `float`, 그렇지 않고 `long`이 있으면 `long`, 나머지는 `int`로 계산합니다. 단, 이동 연산자처럼 별도 규칙이 있는 연산까지 이 규칙으로 덮어 외우지는 않습니다.

**상수 대입의 예외**

```java
byte 가능 = 10;
int 일반값 = 10;
// byte 불가 = 일반값; // 컴파일 오류
byte 명시 = (byte) 일반값;
```

표현 가능한 범위의 정수 상수는 좁은 타입에 대입할 수 있는 경우가 있습니다. 같은 숫자 10이어도 **상수 표현식인지 일반 변수인지**에 따라 다릅니다.

**더 넓은 변수에 받는 것만으로는 부족합니다.**

```java
int 수 = 1_000_000;
long 첫째 = 수 * 수;
long 둘째 = (long) 수 * 수;
System.out.println(첫째);
System.out.println(둘째);
```

출력:

```text
-727379968
1000000000000
```

첫째는 `int`끼리 곱한 뒤 결과를 `long`에 넣습니다. 둘째는 곱하기 전에 한쪽을 `long`으로 바꿉니다.

### 014. 연산자와 계산 규칙

연산자는 “무엇을 계산하는가”와 함께 **피연산자의 자료형**을 봐야 합니다.[^operators][^expressions]

| 구분 | 대표 연산자 | 확인할 점 |
| --- | --- | --- |
| 산술 | `+`, `-`, `*`, `/`, `%` | 정수·실수 여부를 봅니다. |
| 비교 | `==`, `!=`, `<`, `<=`, `>`, `>=` | 결과는 논리값입니다. |
| 논리 | `!`, `&&`, 논리합 | 단락 평가 여부를 봅니다. |
| 비트 | `&`, 비트합, `^`, `~` | 각 비트에 연산합니다. |
| 이동 | `<<`, `>>`, `>>>` | 이동 방향과 부호 유지 여부를 봅니다. |
| 증감 | `++`, `--` | 값을 사용하는 시점과 변경 시점을 구분합니다. |
| 대입 | `=`, `+=`, `-=`, `*=` | 복합 대입의 암묵적 변환을 주의합니다. |

**정수 나눗셈과 나머지**

```java
System.out.println(5 / 2);
System.out.println(5 / 2.0);
System.out.println(-5 / 2);
System.out.println(-5 % 2);
```

출력:

```text
2
2.5
-2
-1
```

정수 나눗셈은 소수 부분을 버려 **0 방향으로** 몫을 구합니다. 음수에서 무조건 수학적 내림을 하는 것이 아닙니다. 0이 아닌 나머지의 부호는 나누어지는 값의 부호를 따릅니다.

**문자열과 덧셈**

```java
System.out.println(1 + 2 + "점");
System.out.println("점" + 1 + 2);
System.out.println('A' + 1);
```

출력:

```text
3점
점12
66
```

앞에서 정수끼리 만나면 먼저 숫자 덧셈을 합니다. 문자열 연결이 시작되면 뒤의 값은 이어 붙여집니다. `'A'`는 문자열이 아니라 문자형 값이므로 숫자 연산에서 코드값을 사용합니다.

**증감 연산자**

```java
int 수 = 3;
int 첫째 = 수++;
int 둘째 = ++수;
System.out.println(첫째 + " " + 둘째 + " " + 수);
```

출력:

```text
3 5 5
```

| 문장 | 저장되는 값 | 실행 뒤 수 |
| --- | --- | --- |
| `첫째 = 수++` | 변경 전 값 3 | 4 |
| `둘째 = ++수` | 변경 후 값 5 | 5 |

**복합 대입**

```java
byte 수 = 10;
수 += 1;
System.out.println(수);
// 수 = 수 + 1; // 컴파일 오류: 오른쪽은 int
```

출력:

```text
11
```

복합 대입에는 왼쪽 타입으로 되돌리는 변환이 포함됩니다. 따라서 문장을 단순히 풀어 적으면 타입 검사 결과가 달라질 수 있습니다. 복합 대입이 값의 범위를 안전하게 보장하는 것은 아닙니다.

**비트와 이동**

```java
System.out.println(5 & 3);
System.out.println(5 | 3);
System.out.println(5 ^ 3);
System.out.println(~5);
System.out.println(8 >> 1);
System.out.println(-8 >> 1);
System.out.println(-8 >>> 1);
System.out.println(1 << 32);
```

출력:

```text
1
7
6
-6
4
-4
2147483644
1
```

`>>`는 오른쪽으로 이동하면서 왼쪽을 부호에 맞게 채웁니다. `>>>`는 왼쪽을 0으로 채웁니다. `int`의 이동 횟수는 하위 5비트, `long`은 하위 6비트를 사용하므로 이동 횟수를 그대로 무한히 적용하지 않습니다. 이 규칙은 선택 보충으로 기억합니다.[^expressions]

### 015. 래퍼 클래스와 박싱

래퍼 클래스는 **기본형 값을 객체 형태로 다룰 때 사용하는 클래스**입니다.[^boxing]

| 기본형 | 래퍼 클래스 |
| --- | --- |
| `byte` | `Byte` |
| `short` | `Short` |
| `int` | `Integer` |
| `long` | `Long` |
| `float` | `Float` |
| `double` | `Double` |
| `char` | `Character` |
| `boolean` | `Boolean` |

```java
Integer 포장값 = 10;
int 일반값 = 포장값;
System.out.println(일반값 + 1);
```

출력:

```text
11
```

기본형에서 래퍼로 바꾸는 것은 **박싱**, 래퍼에서 기본형으로 꺼내는 것은 **언박싱**입니다. 문맥에 맞으면 자동으로 일어납니다.

**래퍼끼리 `==`는 값 비교가 아닐 수 있습니다.**

```java
Integer 첫째 = 100;
Integer 둘째 = 100;
System.out.println(첫째 == 둘째);
System.out.println(첫째.equals(둘째));
```

출력:

```text
true
true
```

이 예에서 첫 결과가 참인 것은 작은 정수의 박싱에서 객체 재사용이 보장되는 범위이기 때문입니다. `Integer.valueOf`는 -128~127 범위를 캐시하며 더 넓은 범위를 캐시할 수도 있습니다. 범위 밖의 모든 `==` 결과가 반드시 거짓이라고 단정하지 않습니다. **값 비교 목적이면 캐시에 기대지 않습니다.**[^integer]

```java
Integer 값 = null;
// int 결과 = 값; // 실행 시 NullPointerException
```

`null`을 기본형으로 꺼낼 수 없으므로 언박싱 과정에서 오류가 납니다. 문자열을 숫자로 읽는 `Integer.parseInt("10")`은 기본형 `int`를 반환합니다. `Integer.valueOf("10")`은 래퍼를 반환합니다.

### 016. 타입 추론과 var

`var`는 **초기값을 보고 지역 변수의 타입을 컴파일러가 추론하게 하는 문법**입니다. 타입이 없어지는 문법이 아닙니다.[^var]

```java
var 점수 = 80;
점수 = 90;
System.out.println(점수);
// 점수 = "합격"; // 컴파일 오류: 점수는 int로 추론됨
```

출력:

```text
90
```

| 가능 여부 | 예·설명 |
| --- | --- |
| 가능 | `var 수 = 10;` |
| 가능 | 초기값을 갖는 일반 지역 변수·반복 변수 등 |
| 불가 | `var 수;`처럼 타입을 추론할 초기값이 없는 선언 |
| 불가 | `var 값 = null;` |
| 불가 | 일반적인 클래스 필드의 타입으로 사용 |
| 불가 | 일반 메서드의 반환형·매개변수 타입 대신 사용 |
| 주의 | `var`가 `final`을 뜻하지는 않습니다. |

람다 매개변수의 `var`는 별도의 허용 문법이 있습니다. 일반 메서드 매개변수까지 모두 추론한다는 뜻은 아닙니다.

**2부 핵심:** 저장 타입·계산 타입·기본값·참조 공유·형 변환을 분리해서 판단합니다.

## 3부. 제어 흐름·메서드·배열

### 017. 표현식과 평가 순서

**표현식**은 계산을 통해 값 등을 만들어내는 문법 요소이고, **문장**은 실행을 지시하는 단위입니다. 연산자의 우선순위와 실제 피연산자를 평가하는 순서는 구분해야 합니다.[^expressions][^operators]

```java
int 수 = 2;
int 결과 = 수++ + 수++ * 2;
System.out.println(결과);
System.out.println(수);
```

출력:

```text
8
4
```

| 순서 | 처리 | 값 |
| --- | --- | --- |
| 1 | 왼쪽 `수++` 평가 | 식에는 2, 변수는 3 |
| 2 | 오른쪽 `수++` 평가 | 식에는 3, 변수는 4 |
| 3 | 곱셈 결과 계산 | 3 × 2 = 6 |
| 4 | 덧셈 결과 계산 | 2 + 6 = 8 |

곱셈이 덧셈보다 우선한다고 해서 왼쪽 피연산자의 증가 동작을 무시하고 오른쪽부터 실행하는 것이 아닙니다. 메서드 호출의 인수도 왼쪽부터 평가됩니다.

**단락 평가**

`&&`는 왼쪽이 거짓이면 오른쪽을 평가하지 않습니다. `||`는 왼쪽이 참이면 오른쪽을 평가하지 않습니다. 논리값에 사용하는 `&`, `|`는 양쪽을 평가합니다.

```java
int 횟수 = 0;
boolean 첫째 = false && ++횟수 > 0;
System.out.println(횟수);
boolean 둘째 = false & ++횟수 > 0;
System.out.println(횟수);
```

출력:

```text
0
1
```

널 검사를 할 때도 순서가 중요합니다.

```java
String 글 = null;
boolean 비어있지않음 = 글 != null && 글.length() > 0;
System.out.println(비어있지않음);
```

출력:

```text
false
```

`글 != null`이 먼저 거짓이 되므로 `length()`는 호출하지 않습니다.

**보충:** 문장이 끝까지 실행되면 정상 완료입니다. `return`, `break`, `continue`, 예외 발생처럼 다른 흐름으로 이동하는 경우는 정상 완료와 구분하여 읽습니다. 여기서 “갑작스러운 완료”는 반드시 프로그램 오류만 뜻하지 않습니다.[^statements]

### 018. 조건문과 조건 연산자

조건문은 **논리값에 따라 실행할 코드를 고르는 문법**입니다. 자바는 숫자 0과 1을 논리값 대신 조건에 직접 넣지 않습니다.[^if]

```java
int 점수 = 80;
if (점수 >= 60) {
    System.out.println("합격");
} else {
    System.out.println("불합격");
}
```

출력:

```text
합격
```

| 주의점 | 설명 |
| --- | --- |
| 조건의 타입 | `boolean` 또는 언박싱 가능한 `Boolean`이어야 합니다. |
| 숫자 조건 | `if (1)`은 컴파일되지 않습니다. |
| 널 논리값 | `Boolean`이 `null`이면 조건 평가 중 언박싱 오류가 날 수 있습니다. |
| 중괄호 생략 | 바로 다음 문장 하나만 조건의 영향을 받습니다. |
| `else`의 연결 | 중괄호가 없다면 가장 가까운 연결 가능한 `if`에 붙습니다. |

조건 연산자는 선택한 값을 표현식으로 만듭니다.

```java
int 점수 = 80;
String 결과 = 점수 >= 60 ? "합격" : "불합격";
System.out.println(결과);
```

출력:

```text
합격
```

선택되는 두 식 중 실제 실행되는 것은 하나입니다. 그러나 **표현식 전체의 타입**은 두 식과 사용 문맥을 고려하여 컴파일할 때 결정됩니다. 선택되지 않는 쪽이라고 문법·타입 오류까지 허용되는 것은 아닙니다.[^expressions]

### 019. 반복문과 분기 제어

반복문은 **같은 코드를 조건에 따라 여러 번 실행**합니다.[^loops]

| 반복문 | 조건을 확인하는 시점 | 최소 실행 횟수 |
| --- | --- | --- |
| `while` | 본문 실행 전 | 0회 |
| `do-while` | 본문 실행 후 | 1회 |
| 기본 `for` | 초기화 후, 각 본문 실행 전 | 0회 |
| 향상된 `for` | 배열·반복 가능한 대상의 원소를 순회 | 원소가 없으면 0회 |

```java
int 수 = 0;
while (수 > 0) {
    System.out.print("가");
}
do {
    System.out.print("나");
} while (수 > 0);
```

출력:

```text
나
```

기본 `for`는 다음 순서로 읽습니다.

```text
초기화 → 조건 → 본문 → 증감 → 조건 → 본문 → 증감 → ...
```

```java
int 합 = 0;
for (int 수 = 1; 수 <= 4; 수++) {
    if (수 == 2) {
        continue;
    }
    합 += 수;
}
System.out.println(합);
```

출력:

```text
8
```

2만 건너뛰고 1·3·4를 더합니다.

| 문법 | 효과 |
| --- | --- |
| `break` | 가장 가까운 반복문 또는 `switch`를 끝냅니다. |
| `continue` | 가장 가까운 반복문의 다음 반복 절차로 이동합니다. |
| `return` | 현재 메서드를 끝내고 호출한 곳으로 돌아갑니다. |
| 레이블이 있는 `break` | 지정한 바깥 문장의 실행을 끝냅니다. |
| 레이블이 있는 `continue` | 지정한 바깥 반복문의 다음 반복 절차로 이동합니다. |

기본 `for`에서 `continue`를 만나도 증감식은 수행합니다. `while`에서는 조건으로, `do-while`에서는 끝의 조건 검사로 이동합니다.

**향상된 반복문의 함정**

```java
int[] 점수 = {10, 20};
for (int 값 : 점수) {
    값 = 99;
}
System.out.println(점수[0]);
```

출력:

```text
10
```

반복 변수 `값`에 배열 원소의 값이 복사된 것입니다. 반복 변수에 다른 수를 대입해도 배열 원소 자체가 바뀌지는 않습니다. 참조형 원소라면 복사된 참조를 통해 객체 내부를 바꿀 수 있다는 점은 별개입니다.

### 020. 분기문과 분기 표현식

`switch`는 **하나의 기준값 또는 패턴에 따라 실행할 분기를 선택**합니다. 기본 학습에서는 전통적인 문장형부터 확인합니다.[^switch]

```java
int 번호 = 2;
switch (번호) {
    case 1:
        System.out.print("가");
    case 2:
        System.out.print("나");
    case 3:
        System.out.print("다");
        break;
    default:
        System.out.print("라");
}
```

출력:

```text
나다
```

`case 2`로 진입한 뒤 `break`까지 아래 문장을 계속 실행합니다. 이를 **관통 실행**이라고 합니다. 다음 `case`를 만났다고 자동 종료되지 않습니다.

**기본 상수 분기의 규칙**

| 항목 | 핵심 |
| --- | --- |
| 전통적인 기준 타입 | `byte`, `short`, `char`, `int`와 대응 래퍼, 문자열, 열거형 |
| 전통적 상수 분기의 제외 대상 | `long`, `float`, `double`, `boolean`은 같은 방식으로 사용하지 않습니다. |
| `case` 값 | 허용된 상수·열거 상수 등이어야 합니다. |
| 중복 `case` | 같은 값을 중복 선언하면 컴파일 오류입니다. |
| `default` | 다른 분기에 해당하지 않을 때 사용합니다. |

자바 21의 패턴 분기는 더 넓은 참조형을 다룹니다. 따라서 위 표는 **전통적 상수 분기**의 설명이지 모든 최신 `switch`의 한계가 아닙니다. 기본형 패턴 등 미리보기 확장은 이 글의 범위에서 제외합니다.[^patterns]

**보충: 값을 만드는 분기 표현식**

```java
int 번호 = 2;
String 이름 = switch (번호) {
    case 1 -> "하나";
    case 2 -> {
        String 설명 = "둘";
        yield 설명;
    }
    default -> "기타";
};
System.out.println(이름);
```

출력:

```text
둘
```

화살표 분기는 전통적인 관통 실행을 하지 않습니다. `yield`는 분기 표현식의 결과를 내보냅니다. 메서드 전체를 끝내는 `return`과 다릅니다.

분기 **표현식**은 가능한 경우에 결과를 정할 수 있어야 합니다. 전통적인 분기 **문장**에까지 무조건 `default`가 필요하다고 일반화하지 않습니다. `null`도 단순히 `default`가 모두 처리하는 것이 아니며, 지원 문법의 명시적인 `case null` 등과 구분해야 합니다.[^switch]

### 021. 도달 가능성과 단언

도달 가능성 검사는 **실행 흐름상 도달할 수 없는 문장이 있는지**를 컴파일러가 정해진 규칙으로 판단하는 것입니다.[^statements]

```java
static int 반환() {
    return 10;
    // System.out.println("실행"); // 컴파일 오류: 도달할 수 없는 문장
}
```

반환값이 있는 메서드는 정상적으로 끝나는 경로에서 필요한 값을 반환해야 합니다. 지역 변수도 읽는 모든 경로에서 값이 정해져 있어야 합니다.

```java
int 점수;
boolean 조건 = true;
if (조건) {
    점수 = 80;
}
// System.out.println(점수); // 컴파일 오류: 모든 경로의 할당이 보장되지 않음
```

여기서 `조건`은 상수 변수가 아닙니다. 사람에게 현재 값이 분명해 보여도 컴파일러의 확정 할당 규칙은 별도로 적용됩니다.

**단언 `assert`**는 개발자가 내부적으로 기대하는 조건을 점검할 때 사용합니다.[^assert]

```java
int 수 = 10;
assert 수 >= 0 : "수는 음수가 아니어야 합니다.";
```

단언은 보통 기본적으로 비활성화되어 있으며 `java -ea Main`처럼 켭니다. 반드시 수행되어야 하는 입력 검사나 필수 처리 자체를 단언에 넣으면 안 됩니다.

**보충:** `if (false)` 안의 문장과 `while (false)` 안의 문장이 도달 가능성 검사에서 항상 같은 취급을 받는 것은 아닙니다. “실행되지 않을 것 같다”라는 직관만으로 모든 컴파일 결과를 단정하지 않습니다.

### 022. 메서드의 선언과 호출

메서드는 **이름을 붙인 처리 단위**입니다. 값을 받아 계산하고 결과를 반환하거나, 반환값 없이 특정 동작을 수행합니다.[^methods]

```java
public class Main {
    static int 더하기(int 첫째, int 둘째) {
        return 첫째 + 둘째;
    }

    public static void main(String[] args) {
        int 결과 = 더하기(3, 4);
        System.out.println(결과);
    }
}
```

출력:

```text
7
```

| 용어 | 예 | 의미 |
| --- | --- | --- |
| 반환형 | `int` | 반환하는 값의 자료형입니다. |
| 메서드 이름 | `더하기` | 메서드를 구분하는 이름입니다. |
| 매개변수 | `첫째`, `둘째` | 메서드 안에서 받은 값을 저장하는 변수입니다. |
| 인수 | `3`, `4` | 호출할 때 넘기는 값입니다. |
| 반환 | `return` | 결과를 돌려주고 메서드를 끝냅니다. |
| `void` | 반환형 위치에 사용 | 반환값이 없다는 뜻입니다. |

기본적인 메서드 시그니처는 **이름과 매개변수 타입 목록**을 중심으로 구분합니다. 반환형만 바꾸거나 매개변수 이름만 바꾸어 같은 메서드를 중복 선언할 수는 없습니다. 제네릭 메서드에서는 타입 매개변수 관련 규칙까지 함께 적용됩니다.[^classes]

**재귀 호출**은 메서드가 자기 자신을 다시 호출하는 것입니다.

```java
public class Main {
    static int 누적합(int 수) {
        if (수 == 0) {
            return 0;
        }
        return 수 + 누적합(수 - 1);
    }

    public static void main(String[] args) {
        System.out.println(누적합(3));
    }
}
```

출력:

```text
6
```

3 + 2 + 1 + 0으로 계산합니다. 호출마다 매개변수와 지역 변수를 위한 실행 정보가 만들어집니다. 종료 조건이 없거나 호출이 너무 깊으면 스택 초과가 발생할 수 있습니다.[^jvm]

### 023. 자바의 값 전달 방식

<mark>자바는 기본형이든 참조형이든 항상 값으로 전달합니다.</mark>

기본형 인수는 기본값을 복사합니다. 참조형 인수는 **참조값을 복사**합니다. 객체 내부가 바뀐다고 해서 호출자의 변수 자체를 참조로 전달한 것은 아닙니다.[^arguments]

```java
public class Main {
    static void 기본형변경(int 수) {
        수 = 99;
    }

    static void 원소변경(int[] 배열) {
        배열[0] = 99;
    }

    static void 참조변경(int[] 배열) {
        배열 = new int[] {77};
    }

    public static void main(String[] args) {
        int 수 = 10;
        int[] 배열 = {10};
        기본형변경(수);
        원소변경(배열);
        참조변경(배열);
        System.out.println(수);
        System.out.println(배열[0]);
    }
}
```

출력:

```text
10
99
```

| 호출 | 메서드 안에서 바꾼 것 | 호출자에게 미치는 영향 |
| --- | --- | --- |
| `기본형변경(수)` | 복사된 정수 변수 | 원래 변수는 10입니다. |
| `원소변경(배열)` | 함께 참조하는 배열의 원소 | 원래 배열 원소도 99입니다. |
| `참조변경(배열)` | 복사된 참조 변수가 가리키는 대상 | 호출자의 배열 참조는 그대로입니다. |

```text
호출 직후
호출자 배열 ─┐
            ├→ 기존 배열
매개변수 배열┘

매개변수에 새 배열을 대입한 뒤
호출자 배열 ──→ 기존 배열
매개변수 배열 → 새 배열
```

같은 이유로 두 매개변수의 참조를 메서드 안에서 맞바꾸는 것만으로 호출자의 두 변수가 서로 바뀌지는 않습니다. 호출자 변수에 새 값을 넣으려면 반환값을 받아 대입하는 등 별도 방법이 필요합니다.

### 024. 메서드 오버로딩과 가변 인수

**오버로딩**, 즉 중복 정의는 **같은 이름의 메서드를 매개변수 형태를 달리하여 선언**하는 것입니다.[^methods]

| 구분 기준 | 오버로딩 가능 여부 |
| --- | --- |
| 매개변수 개수가 다름 | 가능 |
| 매개변수 타입이 다름 | 가능 |
| 서로 다른 타입의 순서가 다름 | 가능 |
| 매개변수 이름만 다름 | 불가 |
| 반환형만 다름 | 불가 |
| 접근 제어자만 다름 | 불가 |

```java
public class Main {
    static String 고르기(long 값) {
        return "확대";
    }

    static String 고르기(Integer 값) {
        return "박싱";
    }

    static String 고르기(int... 값) {
        return "가변";
    }

    public static void main(String[] args) {
        System.out.println(고르기(1));
    }
}
```

출력:

```text
확대
```

이 예에서는 박싱 없이 허용되는 고정 개수 호출이 먼저 성립합니다. 기본 학습에서는 **박싱 없는 호출 검토 → 박싱을 허용한 호출 검토 → 가변 인수 호출 검토**의 단계로 기억합니다. 같은 단계에서 후보가 여러 개면 더 구체적인 메서드를 판단해야 하므로 단순한 한 줄 우선순위만으로 모든 문제를 해결할 수는 없습니다.[^invocation]

`null`은 여러 참조형에 들어갈 수 있습니다. `Object`와 `String`을 받는 후보라면 더 구체적인 `String` 쪽이 선택될 수 있습니다. 하지만 `String`과 `Integer`처럼 어느 쪽이 더 구체적이라고 정할 수 없는 후보만 있다면 호출이 모호해질 수 있습니다.

**가변 인수**

```java
public class Main {
    static int 합계(int... 값들) {
        int 합 = 0;
        for (int 값 : 값들) {
            합 += 값;
        }
        return 합;
    }

    public static void main(String[] args) {
        System.out.println(합계());
        System.out.println(합계(1, 2, 3));
    }
}
```

출력:

```text
0
6
```

가변 인수는 메서드 안에서 배열로 다룹니다. 가변 인수 매개변수는 하나만 둘 수 있고 마지막 위치에 와야 합니다. `메서드(int[])`와 `메서드(int...)`를 별개의 오버로딩으로 함께 선언할 수는 없습니다.

### 025. 배열의 타입과 동작

배열은 **같은 원소 타입의 값을 정해진 개수만큼 저장하는 객체**입니다. 인덱스는 0부터 시작합니다.[^arrays]

```java
int[] 점수 = new int[3];
점수[0] = 80;
System.out.println(점수.length);
System.out.println(점수[1]);
```

출력:

```text
3
0
```

| 확인할 내용 | 규칙 |
| --- | --- |
| 길이 | 생성한 배열 객체의 길이는 고정됩니다. |
| 인덱스 | 길이가 3이면 0·1·2가 유효합니다. |
| 기본형 원소 | 타입에 맞는 기본값으로 초기화합니다. |
| 참조형 원소 | 기본값은 `null`입니다. 객체가 자동 생성되지는 않습니다. |
| 범위 초과 | 실행 시 배열 인덱스 오류가 발생합니다. |
| 음수 길이 생성 | 실행 시 음수 배열 크기 오류가 발생합니다. |
| 길이 확인 | 배열은 `length`, 문자열은 `length()`, 컬렉션은 보통 `size()`입니다. |

`new 학생[3]`은 학생 객체 3개를 만드는 것이 아닙니다. 학생 참조를 저장할 칸 3개를 만듭니다.

**다차원 배열**

```java
int[][] 자료 = new int[2][];
자료[0] = new int[] {1, 2};
자료[1] = new int[] {3, 4, 5};
System.out.println(자료.length);
System.out.println(자료[0].length);
System.out.println(자료[1].length);
```

출력:

```text
2
2
3
```

자바의 다차원 배열은 배열을 참조하는 배열입니다. 각 행의 길이가 반드시 같을 필요는 없습니다. 아직 만들지 않은 행은 `null`일 수 있습니다.

**참조 대입과 복사**

```java
int[] 원본 = {10, 20};
int[] 공유 = 원본;
int[] 복사 = 원본.clone();
공유[0] = 99;
복사[1] = 77;
System.out.println(원본[0] + " " + 원본[1]);
```

출력:

```text
99 20
```

기본형의 1차원 배열을 복제하면 원소값은 각각 따로 저장됩니다. 참조형 배열을 복제하면 원소인 참조값을 복사하므로 **안쪽 객체까지 복제되는 것은 아닙니다.** 다차원 배열도 바깥 배열만 복제하면 내부 행 배열이 공유됩니다.

**보충: 배열 공변성**

```java
String[] 글목록 = {"자바"};
Object[] 일반목록 = 글목록;
// 일반목록[0] = 10; // 실행 시 ArrayStoreException
```

컴파일 시에는 `Object[]`로 보이지만 실제 배열은 `String[]`입니다. 실제 원소 타입과 맞지 않는 객체를 넣으면 실행 중 저장 검사에서 실패합니다. `int[]`를 `Object`에 대입할 수는 있지만 `Object[]`에 대입할 수는 없습니다. 이 차이는 제네릭과 비교할 때 중요합니다.[^arrays]

**3부 핵심:** 조건·순서·반복 횟수를 추적하고, 메서드 호출에서는 값의 복사와 객체 내부 변경을 구분합니다.

## 4부. 클래스와 객체의 기본 구조

### 026. 클래스·객체·인스턴스

**클래스**는 어떤 상태와 행동을 가지는지 정의한 타입입니다. **객체**는 실행 중 만들어진 실제 대상이고, 어떤 클래스에서 만들어졌다는 관계를 강조할 때 **인스턴스**라고 부릅니다.[^objects]

```java
class 학생 {
    String 이름;
    int 점수;

    boolean 합격여부() {
        return 점수 >= 60;
    }
}

public class Main {
    public static void main(String[] args) {
        학생 대상 = new 학생();
        대상.이름 = "민수";
        대상.점수 = 80;
        System.out.println(대상.합격여부());
    }
}
```

출력:

```text
true
```

| 요소 | 이 코드의 예 |
| --- | --- |
| 클래스 | `학생` |
| 객체 생성 | `new 학생()` |
| 참조 변수 | `대상` |
| 필드·상태 | `이름`, `점수` |
| 메서드·행동 | `합격여부()` |

`학생 대상;`만 적으면 객체가 만들어지지 않습니다. 참조 변수를 선언한 것과 객체를 생성한 것은 별개의 단계입니다.

두 객체의 필드 값이 같더라도 동일한 객체라는 뜻은 아닙니다. 반대로 참조 변수 이름이 달라도 같은 객체를 가리킬 수 있습니다.

### 027. 생성자의 역할과 규칙

생성자는 **새 객체를 초기화하기 위한 특별한 선언**입니다. 이름은 클래스 이름과 같고, 반환형을 적지 않습니다.[^constructors]

```java
class 학생 {
    String 이름;

    학생() {
        this("미정");
    }

    학생(String 이름) {
        this.이름 = 이름;
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println(new 학생().이름);
        System.out.println(new 학생("민수").이름);
    }
}
```

출력:

```text
미정
민수
```

| 규칙 | 내용 |
| --- | --- |
| 이름 | 클래스 이름과 같습니다. |
| 반환형 | `void`도 붙이지 않습니다. |
| 오버로딩 | 매개변수를 달리하여 여러 개 선언할 수 있습니다. |
| 상속 | 생성자는 상속되지 않습니다. |
| 기본 생성자 | 생성자를 전혀 선언하지 않았을 때 컴파일러가 제공하는 생성자입니다. |
| 무인자 생성자 | 매개변수가 없는 생성자입니다. 직접 작성할 수도 있습니다. |

<mark>생성자를 하나라도 직접 선언하면, 컴파일러가 별도의 기본 무인자 생성자를 자동 추가하지 않습니다.</mark>

`void 학생()`은 생성자가 아니라 반환값이 없는 일반 메서드입니다.

`this(...)`는 같은 클래스의 다른 생성자를 호출합니다. `super(...)`는 직접 상위 클래스의 생성자를 호출합니다. 자바 21의 전통적인 생성자 문법에서 명시적인 생성자 호출은 첫 문장에 와야 합니다. 직접 쓰지 않으면 적용 가능한 경우 `super()`가 암묵적으로 들어갑니다.[^classes]

부모에게 무인자 생성자가 없으면 자식에서 필요한 `super(인수)`를 직접 호출해야 할 수 있습니다. 생성자끼리 서로를 무한히 호출하는 순환 연결은 컴파일 오류입니다.

**버전 주의:** 자바 25는 `super(...)` 또는 `this(...)` 앞에 제한된 준비 문장을 허용합니다. 생성 중인 객체에 대한 접근에는 제약이 있으며, 선언된 필드에 대한 제한적 대입도 허용됩니다. 이 변경을 무시하고 “모든 버전에서 무조건 첫 문장”이라고 단정하지 않습니다.[^flexible]

### 028. 클래스와 객체의 초기화 순서

정적 초기화와 인스턴스 초기화는 **실행되는 시점과 횟수가 다릅니다.** 다음 순서는 자바 21의 전통적인 생성자 형태를 기준으로 합니다.[^execution][^initial]

```java
class 부모 {
    static {
        System.out.print("가");
    }

    {
        System.out.print("다");
    }

    부모() {
        System.out.print("라");
    }
}

class 자식 extends 부모 {
    static {
        System.out.print("나");
    }

    {
        System.out.print("마");
    }

    자식() {
        System.out.print("바");
    }
}

public class Main {
    public static void main(String[] args) {
        new 자식();
        System.out.println();
        new 자식();
    }
}
```

출력:

```text
가나다라마바
다라마바
```

| 최초 생성 때의 순서 | 실행 내용 |
| --- | --- |
| 1 | 부모의 정적 초기화: 가 |
| 2 | 자식의 정적 초기화: 나 |
| 3 | 부모의 인스턴스 초기화: 다 |
| 4 | 부모 생성자 본문: 라 |
| 5 | 자식의 인스턴스 초기화: 마 |
| 6 | 자식 생성자 본문: 바 |

두 번째 생성에서는 이미 초기화된 클래스의 정적 초기화가 반복되지 않습니다. 객체마다 필요한 인스턴스 초기화와 생성자 본문이 다시 실행됩니다.

명시적인 필드 초기화식과 초기화 블록은 해당 클래스 안의 선언 순서에 영향을 받습니다. 객체의 인스턴스 필드에는 생성자 연결을 처리하기 전에 기본값이 준비됩니다.

**부모 생성자에서 자식 메서드를 호출하면**

```java
class 부모 {
    부모() {
        출력();
    }

    void 출력() {
    }
}

class 자식 extends 부모 {
    int 값 = 7;

    @Override
    void 출력() {
        System.out.println(값);
    }
}

public class Main {
    public static void main(String[] args) {
        new 자식();
    }
}
```

출력:

```text
0
```

실제 객체가 자식이므로 재정의한 메서드가 호출됩니다. 그러나 자식 필드의 명시적 초기화 `값 = 7`은 아직 실행 전이어서 기본값 0을 읽습니다.

<blockquote class="prompt-warning">
<p>객체 초기화가 끝나기 전에 재정의 가능한 메서드를 호출하면, 아직 준비되지 않은 자식 상태를 읽을 수 있습니다.</p>
</blockquote>

### 029. this와 super

`this`는 현재 객체를 나타냅니다. `super`는 같은 객체에서 상위 클래스 쪽 멤버나 구현을 선택할 때 사용하는 특별한 문법입니다. 부모 객체를 별도로 하나 만드는 표현이 아닙니다.[^this][^super]

| 문법 | 의미 |
| --- | --- |
| `this.이름` | 현재 객체의 필드·멤버를 명확히 지정합니다. |
| `this(...)` | 같은 클래스의 다른 생성자를 호출합니다. |
| `super.이름` | 접근 가능한 상위 클래스의 멤버·구현을 지정합니다. |
| `super(...)` | 직접 상위 클래스의 생성자를 호출합니다. |
| `바깥클래스.this` | 내부 클래스에서 해당 바깥 객체를 지정할 때 사용합니다. |

```java
class 학생 {
    String 이름;

    학생(String 이름) {
        this.이름 = 이름;
    }
}
```

왼쪽은 필드, 오른쪽은 매개변수입니다. `이름 = 이름`만 적으면 매개변수에 자기 값을 다시 넣는 문장이 되어 필드가 원하는 값으로 바뀌지 않습니다.

정적 메서드에는 “현재 객체”가 없으므로 `this`와 `super`를 사용할 수 없습니다. 정적 메서드에서 특정 객체를 만들어 그 객체의 인스턴스 멤버에 접근하는 것은 가능합니다.

### 030. 접근 제어와 캡슐화

접근 제어는 **어디에서 멤버나 타입을 사용할 수 있는지** 정합니다. 캡슐화는 상태와 관련 처리를 묶고, 외부가 내부 규칙을 함부로 깨뜨리지 못하게 하는 설계입니다.[^access]

다음 표는 **클래스 멤버에 대한 기본 접근 범위**입니다. 모듈의 공개 여부 등 추가 제약은 여기서 생략합니다.

| 제어자 | 같은 클래스 | 같은 패키지 | 다른 패키지의 자식 | 다른 패키지의 일반 코드 |
| --- | --- | --- | --- | --- |
| `private` | 가능 | 불가 | 불가 | 불가 |
| 생략: 패키지 접근 | 가능 | 가능 | 불가 | 불가 |
| `protected` | 가능 | 가능 | 조건부 가능 | 불가 |
| `public` | 가능 | 가능 | 가능 | 가능 |

중첩 타입과 이를 둘러싼 타입 사이에는 비공개 멤버 접근을 허용하는 규칙이 있습니다. 위 표의 “같은 클래스”만 기계적으로 적용해 같은 최상위 선언 안의 중첩 관계까지 모두 차단된다고 판단하지 않습니다.[^names]

**`protected`의 조건**

다른 패키지의 자식 코드라고 해서 임의의 부모 객체를 통해 부모의 `protected` 인스턴스 멤버를 접근할 수 있는 것은 아닙니다. 자식 구현 문맥과 접근에 사용한 참조의 타입 조건이 함께 적용됩니다.

최상위 클래스에는 일반적으로 `public` 또는 패키지 접근을 사용합니다. 최상위 클래스에 `private`나 `protected`를 붙이는 것과, 중첩 클래스에 붙이는 것은 다릅니다.[^names]

**캡슐화의 목적은 단순히 접근자를 많이 만드는 것이 아닙니다.**

```java
class 계좌 {
    private int 잔액;

    void 입금(int 금액) {
        if (금액 <= 0) {
            throw new IllegalArgumentException("금액은 양수여야 합니다.");
        }
        잔액 += 금액;
    }

    int 잔액조회() {
        return 잔액;
    }
}
```

외부가 잔액에 임의의 값을 넣는 대신, 입금이라는 동작을 통해 변경하게 합니다. 이 예의 검증은 설계 원리를 보이기 위한 최소 예이며 모든 업무 규칙을 구현한 것은 아닙니다.

### 031. 정적 멤버와 클래스 단위 상태

`static` 멤버는 **객체 하나하나가 아니라 클래스에 속합니다.** 같은 클래스로 만든 객체들이 같은 정적 필드를 사용합니다.[^static]

```java
class 표 {
    static int 발급수;
    int 번호;

    표() {
        번호 = ++발급수;
    }
}

public class Main {
    public static void main(String[] args) {
        표 첫째 = new 표();
        표 둘째 = new 표();
        System.out.println(첫째.번호);
        System.out.println(둘째.번호);
        System.out.println(표.발급수);
    }
}
```

출력:

```text
1
2
2
```

| 비교 | 인스턴스 멤버 | 정적 멤버 |
| --- | --- | --- |
| 소속 | 개별 객체 | 클래스 |
| 필드 보관 단위 | 객체마다 별도 | 같은 클래스에서 공유 |
| 기본 접근 형태 | `객체참조.멤버` | `클래스이름.멤버` |
| `this` 사용 | 인스턴스 메서드에서 가능 | 정적 메서드에서는 불가 |
| 인스턴스 멤버 직접 접근 | 현재 객체를 기준으로 가능 | 객체 참조가 따로 필요 |

`static`은 읽기 전용을 뜻하지 않습니다. 여러 스레드가 사용한다고 자동으로 안전해지는 것도 아닙니다. 위 번호 발급 코드는 단일 스레드 학습 예제입니다.

**보충:** “프로그램 전체에서 영원히 단 하나”라기보다 해당 클래스의 실행 시 정체성에 속합니다. 서로 다른 클래스 로더가 별개의 클래스로 정의한 경우까지 무조건 하나라고 확장하지 않습니다.

### 032. final의 세 가지 의미

`final`은 **대상에 따라 제한하는 것이 다릅니다.**[^final]

| 붙이는 대상 | 제한 |
| --- | --- |
| 변수 | 초기화 후 다른 값을 재대입할 수 없습니다. |
| 인스턴스 메서드 | 자식 클래스에서 재정의할 수 없습니다. |
| 클래스 | 상속하여 자식 클래스를 만들 수 없습니다. |

```java
final int[] 점수 = {10, 20};
점수[0] = 99;
System.out.println(점수[0]);
// 점수 = new int[] {1, 2}; // 컴파일 오류: 참조 재대입
```

출력:

```text
99
```

배열 참조를 바꾸지 못할 뿐, 배열 원소까지 자동으로 불변이 되는 것은 아닙니다. `final` 필드가 가변 객체를 가리키는 경우도 같습니다.

| 비슷한 말 | 구분 |
| --- | --- |
| `final` 참조 | 다른 객체를 가리키도록 재대입할 수 없습니다. |
| 불변 객체 | 만들어진 뒤 관찰 가능한 상태가 바뀌지 않습니다. |
| 상수 변수 | 기본형·문자열의 특정한 컴파일타임 상수 조건을 만족합니다. |
| 실질적 `final` | 표시를 생략했지만 재대입하지 않는 등의 조건을 만족합니다. |

선언할 때 값을 넣지 않은 `final` 인스턴스 필드는 생성자가 정상적으로 끝나는 모든 경로에서 적절히 초기화해야 합니다. `final`을 붙였다고 필요한 초기화를 생략할 수 있는 것은 아닙니다.

**용어 주의:** `final`, 예외 처리의 `finally`, 과거 종료 처리 메서드인 `finalize()`는 서로 다른 개념입니다. `finalize()`는 현대적인 자원 정리 방법으로 학습하지 않습니다.[^finalization]

### 033. 객체의 협력과 책임

객체지향은 단순히 코드를 클래스로 감싸는 방식이 아닙니다. **어떤 객체가 무엇을 알고, 어떤 일을 책임질지 나누는 방식**입니다.[^overview]

| 개념 | 쉬운 뜻 | 학습 예 |
| --- | --- | --- |
| 추상화 | 필요한 공통 특징을 골라 표현합니다. | 결제 방식의 세부 차이보다 결제 기능을 먼저 봅니다. |
| 캡슐화 | 관련 상태와 기능을 묶고 내부 규칙을 보호합니다. | 점수 수정 규칙을 메서드에 둡니다. |
| 상속 | 기존 타입과의 하위 타입 관계를 만듭니다. | 학생은 사람의 한 종류입니다. |
| 다형성 | 같은 상위 타입으로 서로 다른 구현을 사용합니다. | 같은 호출로 구현별 다른 계산을 합니다. |

설계 관계도 구분합니다.

| 관계·성질 | 의미 |
| --- | --- |
| 연관 | 다른 객체를 알고 사용합니다. |
| 집합 | 전체가 부분을 가지되, 부분이 독립적으로 존재할 수 있는 관계를 모델링합니다. |
| 합성 | 전체가 부분의 소유와 수명에 강하게 책임지는 관계를 모델링합니다. |
| 위임 | 해야 할 일의 일부를 다른 객체에 맡깁니다. |
| 높은 응집도 | 하나의 객체에 관련성이 높은 책임을 모읍니다. |
| 낮은 결합도 | 다른 객체의 내부 구현에 덜 의존합니다. |

연관·집합·합성은 **설계를 해석하는 개념**입니다. 자바에 집합 전용 연산자나 합성 전용 키워드가 있는 것은 아닙니다. 필드에 다른 객체의 참조가 있다는 이유만으로 소유권과 수명 관계까지 자동 결정되지는 않습니다.

값 객체는 내용의 값에 중심을 두고, 엔티티는 식별되는 대상의 정체성에 중심을 둡니다. 예를 들어 같은 좌표를 나타내는 값과, 이름이 같아도 다른 사람인 회원을 구분할 수 있습니다. 이는 뒤의 동등성 비교 설계와 연결됩니다.

**4부 핵심:** 객체 생성·초기화·접근 범위·공유 상태·불변성을 서로 다른 축으로 구분합니다.

## 5부. 상속·다형성·객체 계약

### 034. 클래스 상속과 하위 타입

상속은 **기존 클래스의 특성을 이어받아 하위 타입을 정의하는 방법**입니다. 클래스는 `extends`로 상속합니다.[^inheritance]

```java
class 사람 {
    void 인사() {
        System.out.println("안녕하세요");
    }
}

class 학생 extends 사람 {
}

public class Main {
    public static void main(String[] args) {
        학생 대상 = new 학생();
        대상.인사();
    }
}
```

출력:

```text
안녕하세요
```

| 규칙 | 설명 |
| --- | --- |
| 직접 상위 클래스 | 클래스는 하나만 가집니다. |
| 여러 단계 상속 | 부모의 부모로 이어지는 계층은 가능합니다. |
| 최상위 클래스 | `Object`를 제외한 클래스는 직접 또는 간접적으로 `Object`를 상속합니다. |
| 생성자 | 상속되지 않습니다. |
| 비공개 멤버 | 자식이 직접 상속받아 접근하는 멤버가 아닙니다. |
| `final` 클래스 | 자식 클래스를 선언할 수 없습니다. |

부모의 비공개 필드가 자식 객체 안에서 사라진다는 뜻은 아닙니다. 부모가 정의한 메서드를 통해 부모의 상태를 관리할 수 있습니다.

상속은 단순히 코드를 줄이는 수단만은 아닙니다. **자식을 부모 타입이 필요한 자리에 사용할 수 있는 관계**인지도 생각해야 합니다. “학생은 사람이다”와 “학생은 책을 가지고 있다”는 다릅니다. 후자는 보통 필드로 다른 객체를 보유하는 방식이 더 직접적입니다.

### 035. 메서드 오버라이딩과 동적 호출

**오버라이딩**, 즉 재정의는 **상속받는 인스턴스 메서드의 구현을 자식에서 새로 정하는 것**입니다.[^override]

```java
class 부모 {
    String 설명() {
        return "부모";
    }
}

class 자식 extends 부모 {
    @Override
    String 설명() {
        return "자식";
    }
}

public class Main {
    public static void main(String[] args) {
        부모 대상 = new 자식();
        System.out.println(대상.설명());
    }
}
```

출력:

```text
자식
```

변수의 선언 타입은 부모지만 실제 객체는 자식입니다. 재정의 가능한 인스턴스 메서드 호출에서는 실제 객체의 구현이 선택됩니다. 이를 **동적 호출** 또는 동적 디스패치라고 합니다.

| 재정의 조건 | 확인할 내용 |
| --- | --- |
| 메서드 이름·매개변수 | 재정의 관계가 성립하는 시그니처여야 합니다. |
| 반환형 | 같은 타입 또는 허용되는 더 구체적인 참조형 등을 사용합니다. |
| 접근 범위 | 부모보다 좁힐 수 없습니다. |
| 검사 예외 | 더 넓은 검사 예외를 새로 던지도록 확장할 수 없습니다. |
| `final` 메서드 | 재정의할 수 없습니다. |
| `private` 메서드 | 상속되는 재정의 대상이 아닙니다. |
| `static` 메서드 | 인스턴스 재정의가 아니라 가림 규칙을 봅니다. |

반환형의 공변성은 예를 들어 부모가 `사람`을 반환할 때 자식이 `학생`을 반환하도록 더 구체화하는 것입니다. 기본형 반환값 `int`를 `long`으로 바꾸는 일을 같은 규칙으로 허용하지 않습니다.

`@Override`는 재정의 의도를 컴파일러에게 확인받는 표시입니다. 이름이나 매개변수를 잘못 적어 재정의가 성립하지 않으면 오류를 찾는 데 도움이 됩니다.

### 036. 필드·정적 메서드 가림과 정적 결합

<mark>필드 접근과 정적 메서드 선택은 인스턴스 메서드의 동적 호출과 같은 규칙이 아닙니다.</mark>

다음 코드는 차이를 한 번에 보여줍니다.[^hiding]

```java
class 부모 {
    int 값 = 10;

    static String 정적설명() {
        return "부모 정적";
    }

    String 설명() {
        return "부모 동작";
    }
}

class 자식 extends 부모 {
    int 값 = 20;

    static String 정적설명() {
        return "자식 정적";
    }

    @Override
    String 설명() {
        return "자식 동작";
    }
}

public class Main {
    public static void main(String[] args) {
        부모 대상 = new 자식();
        System.out.println(대상.값);
        System.out.println(대상.정적설명());
        System.out.println(대상.설명());
        System.out.println(((자식) 대상).값);
    }
}
```

출력:

```text
10
부모 정적
자식 동작
20
```

| 표현 | 판단 기준 | 결과 |
| --- | --- | --- |
| `대상.값` | 접근식의 선언 타입인 부모 | 10 |
| `대상.정적설명()` | 컴파일 시 선택되는 부모의 정적 메서드 | 부모 정적 |
| `대상.설명()` | 실제 자식 객체의 재정의 구현 | 자식 동작 |
| `((자식) 대상).값` | 캐스팅한 식의 타입인 자식 | 20 |

예제에서는 비교를 위해 객체 참조로 정적 메서드를 호출했습니다. 실제 작성에서는 `부모.정적설명()`처럼 클래스 이름으로 부르는 편이 의도가 분명합니다.

**오버로딩과 오버라이딩 비교**

| 구분 | 오버로딩 | 오버라이딩 |
| --- | --- | --- |
| 목적 | 같은 이름으로 다른 매개변수의 기능 제공 | 상위 메서드의 구현 변경 |
| 매개변수 | 다르게 선언 | 재정의 관계가 맞도록 선언 |
| 선택 시점 | 어떤 시그니처를 부를지 컴파일 시 선택 | 선택된 인스턴스 메서드의 구현을 실행 시 선택 |
| 상속 관계 | 없어도 가능 | 상위 타입과의 관계가 필요 |

한 호출에서 두 규칙이 함께 적용될 수 있습니다. **먼저 호출할 메서드를 컴파일 단계에서 고르고, 그다음 실제 객체의 재정의 구현을 찾습니다.**

### 037. 추상 클래스

추상 클래스는 **직접 완성된 객체로 만들지는 않고, 하위 클래스의 공통 기반으로 사용하는 클래스**입니다. `abstract`로 선언합니다.[^abstract]

```java
abstract class 도형 {
    abstract int 넓이();

    void 출력() {
        System.out.println(넓이());
    }
}

class 정사각형 extends 도형 {
    private final int 한변;

    정사각형(int 한변) {
        this.한변 = 한변;
    }

    @Override
    int 넓이() {
        return 한변 * 한변;
    }
}

public class Main {
    public static void main(String[] args) {
        도형 대상 = new 정사각형(3);
        대상.출력();
    }
}
```

출력:

```text
9
```

| 질문 | 답 |
| --- | --- |
| 추상 클래스를 직접 `new` 할 수 있는가? | 추상 클래스 자체를 직접 인스턴스화할 수 없습니다. |
| 필드를 가질 수 있는가? | 가능합니다. |
| 생성자를 가질 수 있는가? | 가능합니다. 자식 객체의 초기화 과정에서 사용합니다. |
| 구현이 있는 메서드를 가질 수 있는가? | 가능합니다. |
| 추상 메서드가 반드시 하나 이상 있어야 하는가? | 아닙니다. 없어도 추상 클래스로 선언할 수 있습니다. |
| 추상 메서드를 가진 클래스는 어떻게 선언하는가? | 추상 클래스여야 합니다. |
| 자식이 추상 메서드를 모두 구현하지 않으면? | 그 자식도 추상 클래스로 남아야 합니다. |

추상 메서드는 본문 대신 세미콜론으로 끝냅니다. “구현을 자식에게 요구”하는 `abstract`와 “재정의를 금지”하는 `final`을 같은 메서드에 붙일 수 없습니다. 추상 클래스 자체를 `final`로 선언하는 것도 모순되어 허용되지 않습니다.

### 038. 인터페이스

인터페이스는 **객체가 제공해야 할 동작의 계약을 표현하는 타입**입니다. 클래스는 `implements`로 구현합니다.[^interfaces]

```java
interface 출력가능 {
    void 출력();
}

class 안내문 implements 출력가능 {
    @Override
    public void 출력() {
        System.out.println("안내합니다");
    }
}

public class Main {
    public static void main(String[] args) {
        출력가능 대상 = new 안내문();
        대상.출력();
    }
}
```

출력:

```text
안내합니다
```

인터페이스의 일반 추상 메서드는 공개 계약입니다. 구현 메서드에서 `public`을 빼고 패키지 접근으로 좁히면 오류가 날 수 있습니다.

| 인터페이스 구성 요소 | 의미 |
| --- | --- |
| 필드 | 선언하면 `public static final` 성질을 가집니다. |
| 일반 추상 메서드 | 본문 없이 계약을 선언합니다. 기본적으로 `public abstract`입니다. |
| `default` 메서드 | 구현체가 사용할 기본 인스턴스 구현을 제공합니다. |
| `static` 메서드 | 인터페이스 타입에 속하는 구현을 제공합니다. |
| `private` 메서드 | 인터페이스 내부의 구현을 보조합니다. |

<mark>현대 자바의 인터페이스가 추상 메서드만 가질 수 있다는 설명은 틀립니다.</mark>

기본·정적 메서드는 자바 8, 비공개 메서드는 자바 9 이후의 문법입니다. 인터페이스에는 객체별 인스턴스 필드나 생성자가 없습니다. 인터페이스의 정적 메서드를 구현 클래스에 상속된 인스턴스 메서드처럼 사용하지 않습니다.[^interfaces]

| 비교 | 추상 클래스 | 인터페이스 |
| --- | --- | --- |
| 관계 선언 | 클래스가 `extends` | 클래스가 `implements` |
| 여러 개 사용 | 직접 상위 클래스는 하나 | 여러 인터페이스 구현 가능 |
| 객체별 상태 | 인스턴스 필드 가능 | 인스턴스 필드 없음 |
| 생성자 | 가능 | 없음 |
| 기본 목적 | 공통 상태·구현을 가진 기반 | 여러 구현이 따를 계약 |

인터페이스는 여러 인터페이스를 `extends`할 수 있습니다. **함수형 인터페이스**는 단일 추상 메서드라는 조건을 만족하여 람다의 대상이 되는 인터페이스입니다. 정적·기본 메서드가 추가로 있다고 곧바로 함수형 조건이 깨지는 것은 아닙니다. 상세 람다는 후속 범위에서 다룹니다.

### 039. 기본 메서드 충돌 해결

여러 인터페이스의 기본 메서드가 겹치면 **어느 구현을 사용할지 모호해질 수 있습니다.** 컴파일러는 정해진 우선 규칙을 적용합니다.[^default]

| 상황 | 기본적인 판단 |
| --- | --- |
| 상위 클래스에 적절한 구체 인스턴스 메서드가 있음 | 클래스 쪽 구현을 우선합니다. |
| 더 구체적인 하위 인터페이스가 기본 구현을 제공 | 더 구체적인 쪽을 봅니다. |
| 관계없는 인터페이스의 기본 구현들이 충돌 | 구현 클래스가 직접 재정의하여 해결합니다. |

```java
interface 첫째 {
    default String 설명() {
        return "첫째";
    }
}

interface 둘째 {
    default String 설명() {
        return "둘째";
    }
}

class 결합 implements 첫째, 둘째 {
    @Override
    public String 설명() {
        return 첫째.super.설명() + 둘째.super.설명();
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println(new 결합().설명());
    }
}
```

출력:

```text
첫째둘째
```

“다중 인터페이스를 지원하므로 충돌도 항상 자동 해결된다”는 설명은 틀립니다. 추상 선언이 추가로 섞인 경우에는 요구되는 구현을 다시 확인해야 합니다.

### 040. 객체 형 변환과 타입 검사

객체 형 변환은 **같은 객체를 어떤 타입으로 바라볼지 바꾸는 것**입니다. 객체의 실제 클래스를 다른 클래스로 바꾸는 작업이 아닙니다.[^casting]

| 구분 | 예 | 핵심 |
| --- | --- | --- |
| 상향 형 변환 | `부모 대상 = new 자식();` | 자식 객체를 부모 타입으로 봅니다. |
| 하향 형 변환 | `자식 대상 = (자식) 부모참조;` | 실제 객체가 해당 자식 타입과 맞아야 합니다. |
| 타입 검사 | `대상 instanceof 자식` | 실행 시 객체가 그 타입의 인스턴스인지 확인합니다. |

```java
class 부모 {
}

class 자식 extends 부모 {
    void 기능() {
        System.out.println("자식 기능");
    }
}

public class Main {
    public static void main(String[] args) {
        부모 대상 = new 자식();
        if (대상 instanceof 자식) {
            자식 실제 = (자식) 대상;
            실제.기능();
        }
        System.out.println(null instanceof 자식);
    }
}
```

출력:

```text
자식 기능
false
```

`부모 대상 = new 부모();`인 참조를 자식으로 강제 변환하면 컴파일되더라도 실행 중 `ClassCastException`이 발생할 수 있습니다. 타입 관계상 가능성 자체가 없는 일부 캐스팅은 컴파일부터 거부됩니다.

부모 타입의 변수로 자식에게만 있는 메서드를 곧바로 부를 수는 없습니다. 먼저 **선언 타입에서 그 호출이 허용되는지**를 확인합니다.

**보충:** `null`을 참조형으로 캐스팅하는 것은 가능합니다. 결과도 `null`입니다. 그러나 그 결과로 인스턴스 멤버를 사용하면 별도로 널 참조 오류가 날 수 있습니다.

### 041. Object와 동등성 계약

`Object`는 클래스 계층의 최상위 기반입니다. 객체 비교에서 특히 중요한 것은 **동일성**과 **동등성**의 구분입니다.[^object]

| 비교 | 질문 |
| --- | --- |
| 기본형의 `==` | 비교 규칙에 따라 값이 같은가? |
| 참조형의 `==` | 같은 객체를 가리키는가, 또는 둘 다 `null`인가? |
| `equals()` | 그 클래스가 정한 기준에서 동등한가? |

```java
String 첫째 = new String("자바");
String 둘째 = new String("자바");
String 셋째 = 첫째;
System.out.println(첫째 == 둘째);
System.out.println(첫째.equals(둘째));
System.out.println(첫째 == 셋째);
```

출력:

```text
false
true
true
```

`String`은 내용을 비교하도록 `equals()`를 구현합니다. 그러나 모든 클래스가 자동으로 모든 필드의 내용을 비교해 주는 것은 아닙니다. `Object`의 기본 `equals()`는 같은 객체인지 비교합니다.[^object][^string]

**동등성과 해시의 계약**

| 조건 | 올바른 관계 |
| --- | --- |
| 두 객체가 `equals()`로 같음 | 해시값도 같아야 합니다. |
| 두 객체의 해시값이 같음 | 반드시 `equals()`로 같은 것은 아닙니다. |
| 두 객체의 해시값이 다름 | 계약을 지킨 객체라면 서로 동등하지 않습니다. |

해시값이 같아도 다른 객체일 수 있는 상황을 해시 충돌이라고 합니다. `equals()`를 재정의하면 일반적으로 `hashCode()`도 일관되게 재정의해야 합니다.[^object]

**내용으로 비교하는 최소 예제**

```java
final class 번호 {
    private final int 값;

    번호(int 값) {
        this.값 = 값;
    }

    @Override
    public boolean equals(Object 대상) {
        if (this == 대상) {
            return true;
        }
        if (!(대상 instanceof 번호)) {
            return false;
        }
        번호 다른번호 = (번호) 대상;
        return 값 == 다른번호.값;
    }

    @Override
    public int hashCode() {
        return Integer.hashCode(값);
    }
}

public class Main {
    public static void main(String[] args) {
        번호 첫째 = new 번호(7);
        번호 둘째 = new 번호(7);
        System.out.println(첫째 == 둘째);
        System.out.println(첫째.equals(둘째));
        System.out.println(첫째.hashCode() == 둘째.hashCode());
    }
}
```

출력:

```text
false
true
true
```

`equals(번호 대상)`로 매개변수를 바꾸면 `equals(Object)`의 재정의가 아니라 다른 메서드의 오버로딩이 될 수 있습니다.

**선택 보충: 비교의 계약과 관련 메서드**

| 항목 | 의미 |
| --- | --- |
| 반사성 | 자기 자신과 동등합니다. |
| 대칭성 | 앞뒤를 바꿔 비교해도 결론이 같습니다. |
| 추이성 | 첫째와 둘째, 둘째와 셋째가 동등하면 첫째와 셋째도 동등합니다. |
| 일관성 | 비교에 쓰는 상태가 같다면 결과도 유지됩니다. |
| `null` | 널이 아닌 객체의 `equals(null)`은 거짓이어야 합니다. |
| `toString()` | 객체를 설명하는 문자열을 만듭니다. |
| `getClass()` | 실제 실행 시 클래스를 알려줍니다. |
| `identityHashCode()` | 재정의한 해시와 별도로 기본 객체 식별용 해시를 얻습니다. 고유 주소라는 뜻은 아닙니다. |

배열의 일반 `equals()`도 원소별 내용 비교를 자동 수행하지 않습니다. 원소 비교에는 `Arrays.equals()` 등 목적에 맞는 기능을 사용합니다.[^arraysutil]

### 042. 객체 복사와 불변성

복사는 **어느 수준까지 새로 만드는지**를 확인해야 합니다.[^copy]

| 종류 | 새로 만드는 것 | 공유되는 것 |
| --- | --- | --- |
| 참조 대입 | 객체를 새로 만들지 않음 | 기존 객체 전체 |
| 얕은 복사 | 바깥 객체 | 필드가 참조하는 내부 객체 |
| 깊은 복사 | 필요한 내부 가변 객체까지 | 설계에 따라 불변 객체 등은 공유 가능 |

`Object.clone()`의 기본 동작은 얕은 복사입니다. `Cloneable`은 복제를 지원함을 알리는 표식 인터페이스이며, 그 자체에 `clone()` 메서드가 선언되어 있는 것은 아닙니다. 복사 생성자나 정적 생성 메서드로 필요한 상태를 직접 복사할 수도 있습니다.

**방어적 복사**는 외부가 내부 상태를 변경하지 못하도록 입력이나 반환값을 복사하는 방법입니다.[^immutable]

```java
final class 성적표 {
    private final int[] 점수;

    성적표(int[] 원본) {
        this.점수 = 원본.clone();
    }

    int[] 점수조회() {
        return 점수.clone();
    }
}

public class Main {
    public static void main(String[] args) {
        int[] 입력 = {80};
        성적표 자료 = new 성적표(입력);
        입력[0] = 0;
        int[] 조회결과 = 자료.점수조회();
        조회결과[0] = 1;
        System.out.println(자료.점수조회()[0]);
    }
}
```

출력:

```text
80
```

생성할 때 입력 배열을 복사하고, 반환할 때도 내부 배열 자체를 내보내지 않습니다. 단순히 필드에 `final`만 붙였을 때보다 외부 변경을 차단하는 효과가 명확합니다.

불변 객체를 만들려면 재대입 방지뿐 아니라 **가변 객체의 외부 공유, 상태 변경 메서드, 상속을 통한 동작 변경**까지 생각해야 합니다. 복사 대상이 여러 내부 객체를 가진다면 위의 1차원 기본형 배열 예제보다 더 깊은 복사가 필요할 수 있습니다.

**5부 핵심:** 선언 타입으로 허용 여부를 확인하고, 실제 객체로 재정의 구현을 선택합니다. 동일성·동등성·복사도 구분합니다.

## 6부. 고급 타입과 메타정보

이 부는 중첩 타입·열거형·애너테이션의 기본 의미를 먼저 이해합니다. 레코드·봉인 타입·패턴은 **보충 내용**으로 읽고, 전통적인 클래스와 무엇이 다른지 비교합니다.

### 043. 중첩 클래스와 내부 클래스

중첩 클래스는 **다른 클래스 안에 선언한 클래스**입니다. 그중 정적 중첩 클래스와 인스턴스 내부 클래스는 바깥 객체와의 관계가 다릅니다.[^nested]

| 구분 | 선언 | 바깥 객체 필요 여부 |
| --- | --- | --- |
| 정적 중첩 클래스 | `static class` | 해당 바깥 객체 없이 생성 가능 |
| 인스턴스 내부 클래스 | `class` | 바깥 객체와 연결하여 생성 |

```java
class 바깥 {
    private int 값 = 7;

    class 안쪽 {
        int 읽기() {
            return 값;
        }
    }

    static class 도구 {
        int 읽기() {
            return 9;
        }
    }
}

public class Main {
    public static void main(String[] args) {
        바깥 외부 = new 바깥();
        바깥.안쪽 내부 = 외부.new 안쪽();
        바깥.도구 도구객체 = new 바깥.도구();
        System.out.println(내부.읽기());
        System.out.println(도구객체.읽기());
    }
}
```

출력:

```text
7
9
```

정적 중첩 클래스에는 바깥 객체가 자동으로 연결되지 않습니다. 따라서 바깥의 인스턴스 필드를 객체 참조 없이 바로 사용하는 방식은 불가능합니다.

**보충:** 내부 객체가 바깥 객체의 참조를 유지하면 바깥 객체도 예상보다 오래 도달 가능한 상태로 남을 수 있습니다. 다만 컴파일러의 구체적인 숨은 필드 생성 방식을 언어의 모든 구현에 똑같이 강제되는 구조로 외우지는 않습니다.

오래된 교재의 “내부 클래스에는 정적 멤버를 전혀 선언할 수 없다”는 설명도 최신 규칙과 차이가 있습니다. 이 글의 자바 21 기준에서는 관련 제한이 완화된 규칙을 적용합니다.[^classes]

### 044. 지역 클래스와 익명 클래스

지역 클래스는 **메서드나 블록 안에서 선언한 이름 있는 클래스**입니다. 익명 클래스는 **클래스 이름을 따로 선언하지 않고 구현과 객체 생성을 함께 적는 방식**입니다.[^local][^anonymous]

```java
public class Main {
    public static void main(String[] args) {
        int 기준 = 10;
        Runnable 작업 = new Runnable() {
            @Override
            public void run() {
                System.out.println(기준);
            }
        };
        작업.run();
    }
}
```

출력:

```text
10
```

이 예는 스레드를 새로 시작하는 코드가 아니라 `run()`을 일반 메서드처럼 직접 호출하는 예입니다.

바깥 지역 변수 `기준`을 내부에서 사용합니다. 이런 사용을 **캡처**라고 합니다. 캡처하는 지역 변수·매개변수는 `final` 또는 실질적 `final`이어야 합니다. 참조 변수의 재대입이 금지되는 것과 그 참조가 가리키는 가변 객체의 내부를 바꾸는 것은 별개입니다.

| 구분 | 익명 클래스 | 람다 |
| --- | --- | --- |
| 기본 목적 | 이름 없이 클래스 구현·객체 생성 | 함수형 인터페이스의 동작 표현 |
| 적용 대상 | 클래스 상속 또는 인터페이스 구현 | 함수형 인터페이스 |
| `this` | 익명 클래스의 현재 객체 | 바깥 문맥의 `this` |
| 이름 있는 생성자 선언 | 직접 선언할 수 없음 | 생성자 선언을 위한 문법이 아님 |

익명 클래스에서도 상위 생성자에 인수를 넘기거나 초기화 블록을 사용할 수 있습니다. “생성 과정 자체가 없다”는 뜻은 아닙니다.[^anonymous]

### 045. 열거형

열거형은 **허용된 값의 목록을 하나의 타입으로 선언**합니다. `enum`을 사용합니다.[^enum]

```java
enum 상태 {
    대기, 진행, 완료
}

public class Main {
    public static void main(String[] args) {
        상태 현재 = 상태.진행;
        System.out.println(현재 == 상태.진행);
        System.out.println(현재.name());
        System.out.println(현재.ordinal());
    }
}
```

출력:

```text
true
진행
1
```

| 요소 | 의미 |
| --- | --- |
| 열거 상수 | 해당 열거형의 미리 선언된 인스턴스입니다. |
| `name()` | 선언된 상수 이름을 반환합니다. |
| `ordinal()` | 선언 순서에 따른 0부터의 위치를 반환합니다. |
| `values()` | 선언한 상수들을 배열로 얻습니다. |
| `valueOf()` | 이름에 해당하는 상수를 찾습니다. |

열거형은 단순한 정수 별칭만이 아닙니다. 필드·메서드·생성자를 가질 수 있고 인터페이스도 구현할 수 있습니다. 외부에서 `new 상태()`처럼 새 상수를 임의로 만들 수는 없습니다.

열거 상수의 비교에는 `==`를 사용할 수 있습니다. `ordinal()`은 선언 순서를 바꾸면 달라지므로 변하지 않는 업무 식별값처럼 사용하는 것은 피하는 편이 좋습니다.

**선택 보충:** 상수별로 다른 메서드 본문을 둘 수 있습니다. 열거형에 특화된 집합·맵도 있으며, 상세 사용법은 컬렉션 편에서 다룹니다.

### 046. 레코드 — 보충

레코드는 **몇 개의 값으로 이루어진 데이터 타입을 간결하게 선언**하는 문법입니다. 자바 16에서 정식 도입되었습니다.[^records][^versions]

```java
record 점수(int 값) {
    점수 {
        if (값 < 0) {
            throw new IllegalArgumentException("점수는 음수가 아니어야 합니다.");
        }
    }
}

public class Main {
    public static void main(String[] args) {
        점수 첫째 = new 점수(80);
        점수 둘째 = new 점수(80);
        System.out.println(첫째.값());
        System.out.println(첫째.equals(둘째));
    }
}
```

출력:

```text
80
true
```

| 레코드의 특징 | 설명 |
| --- | --- |
| 구성요소 | 선언한 값에 대응하는 필드와 접근 메서드가 마련됩니다. |
| 접근 메서드 | 위 예에서는 `값()`입니다. `get값()`이 자동 생성되는 것은 아닙니다. |
| 생성자 | 구성요소를 받는 정규 생성자와 간결 생성자 규칙이 있습니다. |
| 객체 계약 | 구성요소를 기준으로 `equals`, `hashCode`, `toString`이 마련됩니다. |
| 상속 | 레코드는 암묵적으로 `final`이며 다른 일반 클래스를 상속하지 않습니다. |
| 인터페이스 | 구현할 수 있습니다. |
| 추가 상태 | 구성요소 외에 별도의 인스턴스 필드를 마음대로 추가할 수 없습니다. |

간결 생성자는 반복되는 필드 대입을 줄이면서 검증 등을 수행하게 합니다.

<mark>레코드의 참조 필드가 final이어도 참조 대상까지 깊게 불변이 되는 것은 아닙니다.</mark>

배열이나 가변 목록을 구성요소로 받으면 그 내부 상태를 별도로 보호해야 할 수 있습니다. 특히 배열 구성요소의 동등성은 원소별 깊은 내용 비교가 자동으로 적용되는 것이 아닙니다. 필요한 방어적 복사·비교 정책을 직접 정해야 합니다.[^records]

### 047. 봉인 클래스와 인터페이스 — 보충

봉인 타입은 **어떤 타입이 직접 하위 타입이 될 수 있는지 제한**합니다. 자바 17에서 정식 도입되었습니다.[^sealed][^versions]

```java
sealed interface 도형 permits 원, 사각형 {
}

final class 원 implements 도형 {
}

non-sealed class 사각형 implements 도형 {
}
```

| 문법 | 의미 |
| --- | --- |
| `sealed` | 허용된 직접 하위 타입만 선언하게 합니다. |
| `permits` | 허용하는 직접 하위 타입을 표시합니다. |
| `final` | 더 이상 상속하지 못하게 닫습니다. |
| `sealed`인 하위 타입 | 다음 하위 타입 목록도 제한합니다. |
| `non-sealed` | 그 하위 계층은 다시 일반 상속이 가능하게 엽니다. |

봉인 타입은 “자식을 전혀 만들지 못하게 하는 타입”이 아닙니다. 그것은 `final`과 비교해야 합니다.

**선택 보충:** 직접 하위 클래스에는 `final`, `sealed`, `non-sealed` 중 해당 규칙을 적용합니다. 하위 인터페이스는 `sealed` 또는 `non-sealed`로 이어갈 수 있습니다. 이름 있는 모듈에서는 같은 모듈, 이름 없는 모듈에서는 같은 패키지라는 배치 제약도 있습니다.

### 048. 패턴 매칭 — 보충

패턴 매칭은 **값의 구조나 타입을 확인하고, 필요한 값을 변수로 꺼내 쓰는 문법**입니다.[^patterns]

```java
Object 대상 = "자바";
if (대상 instanceof String 글) {
    System.out.println(글.length());
}
```

출력:

```text
2
```

타입 검사와 별도 캐스팅을 하나의 문법으로 묶습니다. 패턴 변수 `글`은 패턴이 일치함을 보장하는 범위에서만 사용할 수 있습니다. 참조형 `instanceof` 패턴은 `null`과 일치하지 않습니다.

**자바 21의 분기 패턴 예제**

```java
Object 대상 = "자바";
String 결과 = switch (대상) {
    case null -> "없음";
    case String 글 when 글.length() > 0 -> "문자열";
    default -> "기타";
};
System.out.println(결과);
```

출력:

```text
문자열
```

| 용어 | 뜻 |
| --- | --- |
| 타입 패턴 | 특정 타입인지 확인하고 변수로 받습니다. |
| 레코드 패턴 | 레코드 구성요소를 꺼냅니다. |
| 중첩 패턴 | 꺼낸 구성요소에도 패턴을 적용합니다. |
| `when` | 타입이 맞은 뒤 추가 조건을 확인합니다. |
| 지배 관계 | 앞의 넓은 패턴이 뒤의 좁은 패턴을 이미 포함하는지 봅니다. |
| 완전성 | 필요한 모든 경우를 분기에서 처리하는지 봅니다. |

앞에서 모든 객체를 받는 패턴으로 처리한 뒤 더 좁은 타입 패턴을 두면, 뒤 패턴이 가려져 컴파일 오류가 날 수 있습니다. 조건과 패턴의 순서를 함께 확인합니다.

**버전 구분:** 타입 패턴은 자바 16, 레코드 패턴·분기 패턴은 자바 21, 이름 없는 변수·패턴은 자바 22의 정식 기능입니다. 기본형 패턴의 미리보기 문법은 이 글의 기본 예제에 넣지 않습니다.[^versions]

### 049. 애너테이션

애너테이션은 **코드에 붙이는 부가 정보**입니다. 컴파일러나 도구, 실행 중 처리기가 그 정보를 보고 검사하거나 동작을 결정할 수 있습니다.[^annotations]

| 애너테이션 | 역할 |
| --- | --- |
| `@Override` | 재정의가 올바른지 확인합니다. |
| `@Deprecated` | 사용을 권장하지 않는 요소임을 알립니다. |
| `@SuppressWarnings` | 지정한 컴파일 경고를 억제합니다. |
| `@FunctionalInterface` | 함수형 인터페이스 조건을 확인합니다. |

`@Deprecated`가 붙었다고 곧바로 컴파일 불가인 것은 아닙니다. 경고를 숨기는 것도 문제를 해결하는 것과는 다릅니다.

**사용자 정의 애너테이션**

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.TYPE)
@interface 설명 {
    String value();
}

@설명("학생 데이터")
class 학생 {
}
```

| 메타 애너테이션 | 의미 |
| --- | --- |
| `@Target` | 클래스·메서드·필드 등 어디에 붙일지 정합니다. |
| `@Retention` | 소스·클래스 파일·실행 시 중 어디까지 유지할지 정합니다. |
| `@Inherited` | 클래스에 붙인 일부 애너테이션 조회의 상속 규칙과 관련됩니다. |
| `@Repeatable` | 같은 애너테이션을 반복해서 사용할 수 있게 합니다. |

| 유지 정책 | 의미 |
| --- | --- |
| `SOURCE` | 소스 수준에서만 유지합니다. |
| `CLASS` | 클래스 파일에 남지만 실행 중 조회를 보장하지 않습니다. 기본 유지 정책입니다. |
| `RUNTIME` | 실행 중 리플렉션으로 조회할 수 있도록 유지합니다. |

애너테이션을 붙였다고 기능이 저절로 생기는 것은 아닙니다. 그것을 해석하는 컴파일러·도구·라이브러리의 처리가 있어야 합니다. `@Inherited`도 모든 필드·메서드·인터페이스의 애너테이션을 전부 자동 상속한다는 뜻이 아닙니다.

**선택 보충:** 선언뿐 아니라 타입 사용 위치에 붙이는 애너테이션도 있습니다. 컴파일 시 애너테이션 처리와 실행 시 리플렉션은 처리 시점과 목적이 다릅니다.

**6부 핵심:** 중첩 타입은 위치와 바깥 객체 관계, 열거형은 허용 값, 레코드는 데이터 선언, 봉인 타입은 하위 타입 제한, 애너테이션은 부가 정보를 담당합니다.

## 7부. 제네릭과 타입 시스템

이 부의 핵심은 **타입을 미리 정해 잘못된 값을 넣지 못하게 하는 것**입니다. 타입 소거·브리지 메서드·복잡한 추론은 목적을 이해하는 선택 심화로 구분합니다.

### 050. 제네릭의 기본 구조

제네릭은 **타입을 매개변수처럼 받아 재사용하는 문법**입니다. 같은 구조를 문자열용·정수용으로 사용하면서 타입 검사를 받을 수 있습니다.[^generictypes]

```java
class 상자<자료형> {
    private final 자료형 값;

    상자(자료형 값) {
        this.값 = 값;
    }

    자료형 꺼내기() {
        return 값;
    }
}

public class Main {
    public static void main(String[] args) {
        상자<String> 글상자 = new 상자<>("자바");
        상자<Integer> 숫자상자 = new 상자<>(10);
        String 글 = 글상자.꺼내기();
        int 수 = 숫자상자.꺼내기();
        System.out.println(글);
        System.out.println(수);
    }
}
```

출력:

```text
자바
10
```

| 문법 요소 | 의미 |
| --- | --- |
| `<자료형>` | 선언하는 타입 매개변수입니다. |
| `<String>` | 사용하면서 정한 구체적인 타입 인수입니다. |
| `<>` | 문맥에서 타입 인수를 추론하는 다이아몬드 문법입니다. |
| `자료형 꺼내기()` | 지정한 타입을 결과로 사용합니다. |

자료에서 흔히 보이는 `<T>`의 `T`는 특별한 예약어가 아니라 타입 매개변수 이름입니다. 위 예에서는 의미를 드러내려고 한글 이름을 사용했습니다.

**제네릭이 필요한 이유**

| 방식 | 특징 |
| --- | --- |
| `Object`로 저장 | 여러 타입을 받을 수 있지만 꺼낼 때 캐스팅과 사용 규칙 확인이 필요합니다. |
| 제네릭으로 저장 | 사용한 타입에 맞게 대입·호출을 컴파일할 때 검사합니다. |

제네릭 클래스뿐 아니라 제네릭 인터페이스와 메서드도 만들 수 있습니다.

```java
public class Main {
    static <자료형> 자료형 그대로(자료형 값) {
        return 값;
    }

    public static void main(String[] args) {
        String 글 = 그대로("자바");
        System.out.println(글);
    }
}
```

출력:

```text
자바
```

메서드 자신의 타입 매개변수는 **반환형 앞**에 선언합니다. 정적 메서드도 자신만의 타입 매개변수를 가질 수 있습니다. 생성자에도 별도의 타입 매개변수를 선언할 수 있지만, 기본 학습에서는 클래스·메서드의 사용부터 익힙니다.[^genericmethods]

### 051. 타입 매개변수의 경계

경계는 **어떤 타입까지 인수로 받을 수 있는지 제한**합니다.[^bounds]

```java
public class Main {
    static <자료형 extends Number> double 실수값(자료형 값) {
        return 값.doubleValue();
    }

    public static void main(String[] args) {
        System.out.println(실수값(3));
        System.out.println(실수값(2.5));
    }
}
```

출력:

```text
3.0
2.5
```

`Number`이거나 그 하위 타입이어야 하므로 숫자 계열에서 제공하는 기능을 사용할 수 있습니다. 임의의 문자열까지 받는 메서드는 아닙니다.

| 문법 | 뜻 |
| --- | --- |
| `<자료형>` | 명시적 경계가 없으면 기본적으로 `Object`를 상한으로 봅니다. |
| `<자료형 extends Number>` | `Number` 계열로 제한합니다. |
| `<자료형 extends Number & Comparable<자료형>>` | 숫자이면서 비교 계약도 만족해야 합니다. |

타입 매개변수의 경계에서는 인터페이스를 조건으로 사용해도 `extends`를 씁니다. 클래스 경계가 있다면 인터페이스 경계보다 먼저 적습니다.

`Number`로 제한했다고 모든 숫자에 `+` 연산을 직접 적용할 수 있는 것은 아닙니다. **경계가 보장하는 메서드를 사용할 수 있다**는 의미입니다.

**선택 심화:** `Comparable<자료형>`처럼 자기 타입을 다시 사용하는 경계는 자기 타입과 비교 가능한 관계를 표현합니다. 여러 조건을 동시에 만족하는 타입을 교차 타입이라고 합니다. 기본 학습에서는 컴파일러 추론 알고리즘보다 “동시에 만족해야 할 조건”으로 이해하면 됩니다.

### 052. 와일드카드와 변성

와일드카드 `?`는 **정확히 어느 타입인지는 지정하지 않은 타입 인수**를 나타냅니다. 먼저 제네릭의 기본 대입 관계를 알아야 합니다.[^subtyping]

`Integer`가 `Number`의 하위 타입이어도 `List<Integer>`가 `List<Number>`의 하위 타입은 아닙니다. 이를 **무공변성**이라고 합니다.

```java
java.util.List<Integer> 정수목록 = new java.util.ArrayList<>();
// java.util.List<Number> 숫자목록 = 정수목록; // 컴파일 오류
```

이 대입을 허용하면 `숫자목록`에 실수를 넣어 실제 정수 목록의 타입 약속을 깨뜨릴 수 있기 때문입니다.

이제 와일드카드로 사용할 수 있는 범위를 표현합니다. 여기서 목록의 수정 메서드는 해당 구현체가 지원한다고 가정합니다.[^upper][^lower]

| 선언 | 뜻 | 읽을 때 보장되는 타입 | 새 원소 추가의 타입 조건 |
| --- | --- | --- | --- |
| `List<Integer>` | 정수 목록 | `Integer` | `Integer` |
| `List<? extends Number>` | 숫자의 어떤 하위 타입 목록 | `Number` | 구체적 비널 값을 일반적으로 추가할 수 없음 |
| `List<? super Integer>` | 정수의 어떤 상위 타입 목록 | `Object` | `Integer`를 넣을 수 있음 |
| `List<?>` | 정확한 원소 타입을 모르는 목록 | `Object` | 구체적 비널 값을 일반적으로 추가할 수 없음 |

**상한: 읽는 쪽**

```java
java.util.List<Integer> 원본 = new java.util.ArrayList<>();
원본.add(10);
java.util.List<? extends Number> 읽기목록 = 원본;
Number 값 = 읽기목록.get(0);
System.out.println(값);
// 읽기목록.add(20); // 컴파일 오류: 실제 원소 타입을 확정할 수 없음
```

출력:

```text
10
```

`? extends Number`는 `Integer` 목록일 수도 있고 `Double` 목록일 수도 있습니다. 따라서 아무 숫자나 추가할 수 없습니다. 읽은 값을 `Number`로 보는 것은 안전합니다.

**하한: 넣는 쪽**

```java
java.util.List<? super Integer> 쓰기목록 = new java.util.ArrayList<Number>();
쓰기목록.add(10);
Object 값 = 쓰기목록.get(0);
System.out.println(값);
// Integer 직접읽기 = 쓰기목록.get(0); // 컴파일 오류
```

출력:

```text
10
```

실제 목록이 `List<Number>`나 `List<Object>`이면 정수 외의 다른 값이 들어 있을 수도 있습니다. 따라서 읽을 때는 기본적으로 `Object`만 보장됩니다.

<blockquote class="prompt-warning">
<p>상한 와일드카드는 불변 목록을 만드는 문법이 아닙니다. 일반적인 값 추가가 제한되는 것과, 삭제·초기화 같은 모든 변경이 금지되는 것은 다릅니다.</p>
</blockquote>

타입 규칙상 `null`은 추가 가능한 경우가 있지만 목록 구현체 자체가 `null`이나 수정을 금지할 수 있습니다. **타입이 허용하는 것**과 **실제 목록의 수정 정책**을 구분합니다.[^wildcardguide]

**기억법:** 자료를 꺼내 쓰는 생산자 관점이면 `extends`, 값을 받아들이는 소비자 관점이면 `super`를 먼저 생각합니다. 같은 타입의 읽기·쓰기를 모두 요구하는 경우에는 정확한 타입 매개변수를 유지하는 편이 적절할 수 있습니다.

### 053. 타입 소거와 실행 시 타입 — 보충

타입 소거는 **제네릭의 타입 정보를 이용해 컴파일한 뒤, 실행 코드에서는 경계 타입 등을 사용하는 방식**입니다.[^erasure]

| 컴파일 전의 개념 | 소거 후의 기본 관점 |
| --- | --- |
| 경계 없는 타입 매개변수 | `Object`를 사용합니다. |
| 경계가 있는 타입 매개변수 | 첫 번째 경계 타입 등을 사용합니다. |
| 결과를 구체적인 타입으로 사용하는 부분 | 필요한 캐스팅이 삽입될 수 있습니다. |
| 재정의 관계를 연결해야 하는 부분 | 브리지 메서드가 생성될 수 있습니다. |

```java
java.util.ArrayList<String> 글목록 = new java.util.ArrayList<>();
java.util.ArrayList<Integer> 수목록 = new java.util.ArrayList<>();
System.out.println(글목록.getClass() == 수목록.getClass());
```

출력:

```text
true
```

타입 인수가 다르다고 보통 각 인수별로 별도의 실행 클래스가 생성되는 것은 아닙니다. 그러나 “제네릭에 관한 모든 정보가 어디에서도 남지 않는다”는 표현도 과합니다. 선언의 제네릭 정보 일부는 메타정보로 남아 조회될 수 있습니다.

**원시 타입과 힙 오염**

원시 타입은 `List`처럼 제네릭 타입의 인수를 생략한 형태입니다. `int` 같은 기본형을 뜻하는 말과 구분합니다.[^rawtypes]

```java
java.util.List<String> 글목록 = new java.util.ArrayList<>();
java.util.List 원시목록 = 글목록;
원시목록.add(10); // 비검사 경고: 문자열 목록에 정수 객체를 넣음
// String 글 = 글목록.get(0); // 실행 시 ClassCastException
```

타입 약속이 깨진 값이 제네릭 변수와 연결된 저장 공간에 섞이는 문제를 힙 오염이라고 합니다. 경고를 무시한 코드가 나중에 읽는 위치에서 오류를 일으킬 수 있습니다.

**선택 보충:** 실행 중 원소의 구체적 타입 인수를 완전히 확인할 수 있는지에 따라 실체화 가능한 타입과 그렇지 않은 타입을 구분합니다. `List<?>`처럼 와일드카드만 사용하는 경우와 `List<String>`을 구분하는 이유입니다.

### 054. 제네릭의 제약과 함정

제네릭은 매우 유용하지만 **기본형·배열·정적 문맥·실행 시 검사와 연결되는 제약**이 있습니다.[^restrictions]

| 잘못된 일반화 | 정확한 규칙 |
| --- | --- |
| 기본형도 타입 인수로 쓴다 | `상자<int>`가 아니라 `상자<Integer>` 등을 사용합니다. |
| 타입 매개변수로 바로 객체를 만든다 | 일반적으로 `new 자료형()`은 불가합니다. |
| 타입 매개변수 배열을 바로 만든다 | `new 자료형[10]`은 불가합니다. |
| 구체적 제네릭 배열을 바로 만든다 | `new List<String>[10]`은 불가합니다. |
| 정적 필드에 클래스의 타입 매개변수를 쓴다 | 클래스의 타입 매개변수를 그 정적 문맥에서 직접 사용할 수 없습니다. |
| 구체적 제네릭 원소 타입까지 검사한다 | 일반적으로 임의 객체를 `instanceof List<String>`으로 검사하지 못합니다. |
| 타입 인수만 다르게 같은 메서드를 선언한다 | 소거 후 시그니처가 충돌하면 불가합니다. |

**정적 문맥의 구분**

```java
class 보관함<자료형> {
    // static 자료형 값; // 컴파일 오류: 클래스 타입 매개변수 사용

    static <새자료형> 새자료형 그대로(새자료형 값) {
        return 값;
    }
}
```

정적 메서드가 자체적인 타입 매개변수를 선언하는 것은 가능합니다. “제네릭에서는 정적 메서드를 아예 만들 수 없다”는 뜻이 아닙니다.[^genericmethods]

**소거 후 충돌**

```java
class 예시 {
    void 처리(java.util.List<String> 값) {
    }

    // void 처리(java.util.List<Integer> 값) { } // 소거 후 충돌
}
```

타입 인수가 다르더라도 소거 후에는 두 매개변수가 같은 `List` 형태가 되어 별개 메서드로 공존할 수 없습니다.

**선택 보충:** 제네릭 클래스는 `Throwable`을 직접·간접 상속할 수 없습니다. 타입 매개변수를 `catch` 대상 타입으로 사용하는 것에도 제약이 있습니다. 반면 메서드의 `throws`에 경계가 있는 타입 매개변수를 사용하는 것은 별도 규칙으로 허용될 수 있습니다.

### 055. 제네릭 추론과 컴파일러 처리 — 선택 심화

타입 추론은 **호출 인수·대입 대상·타입 경계를 보고 생략한 타입을 결정하는 과정**입니다.[^inference]

```java
java.util.List<String> 첫째 = new java.util.ArrayList<>();
var 둘째 = new java.util.ArrayList<>();
첫째.add("자바");
둘째.add("자바");
둘째.add(10);
System.out.println(첫째.size());
System.out.println(둘째.size());
```

출력:

```text
1
2
```

첫째는 대입 대상의 `String`이 타입 추론에 도움을 줍니다. 둘째는 오른쪽 생성식만으로 `ArrayList<Object>`가 추론됩니다. **`var`와 `<>`를 함께 쓰면 무조건 내가 생각한 원소 타입을 추론하는 것은 아닙니다.**

이 아래의 용어는 이름과 목적을 알아두면 충분합니다.

| 용어 | 목적·의미 |
| --- | --- |
| 타깃 타입 | 식이 사용되는 자리에서 기대하는 타입입니다. |
| 와일드카드 캡처 | 알려지지 않은 타입을 컴파일러 내부의 한 타입으로 붙잡아 관계를 유지합니다. |
| 보조 제네릭 메서드 | 캡처한 타입의 일관된 사용을 도울 수 있습니다. |
| 최소 상한 | 여러 타입을 함께 다루기 위한 공통 상위 타입을 찾는 개념입니다. |
| 타입 투영 | 직접 이름 붙이기 어려운 내부 타입 등을 적절한 상위 표현으로 조정하는 규칙입니다. |
| 브리지 메서드 | 타입 소거 뒤에도 재정의 호출 관계를 맞추기 위해 컴파일러가 추가하는 메서드입니다. |
| 타입 토큰 | `String.class` 같은 값을 넘겨 실행 시 타입 정보가 필요한 코드를 돕습니다. |

브리지 메서드는 개발자가 매번 직접 작성하는 문법이 아닙니다. `List<String>.class`처럼 구체적인 제네릭 클래스 리터럴을 만들 수는 없으므로 타입 토큰으로도 모든 타입 정보를 같은 방식으로 표현할 수 있는 것은 아닙니다.[^bridge][^capture][^types]

**7부 핵심:** 제네릭은 타입 약속을 컴파일할 때 확인합니다. 상속 관계가 제네릭 타입 인수에 그대로 전달되는 것은 아니며, 와일드카드로 허용 범위를 표현합니다.

<span id="pitfalls"></span>

## 잘 놓치는 핵심

### 1. 기본형은 값, 참조형은 참조값을 저장합니다

`참조변수 = 다른참조변수`는 객체 복사가 아닙니다. 메서드에 전달할 때도 참조값이 복사됩니다. 객체 내부 변경이 호출자에게 보인다는 사실만으로 참조 전달이라고 결론 내리지 않습니다.

### 2. 선언 타입과 실제 객체를 구분합니다

`부모 대상 = new 자식();`에서 이름을 쓰고 호출할 수 있는지는 우선 부모 타입으로 검사합니다. 재정의한 인스턴스 메서드의 구현은 실제 자식 객체를 기준으로 선택합니다. 필드·정적 메서드는 같은 방식으로 움직이지 않습니다.

### 3. 지역 변수의 선언과 초기화는 다릅니다

필드와 배열 원소에는 기본값이 있지만, 지역 변수는 읽기 전에 값이 확실히 정해져 있어야 합니다. 선언만 했다고 0이 들어 있는 것으로 계산하지 않습니다.

### 4. 계산을 끝내고 넓은 타입에 넣어도 이미 생긴 손실은 돌아오지 않습니다

정수 나눗셈이나 오버플로가 발생한 다음에 실수형·긴 정수형 변수에 대입해도 원래 기대했던 값을 되살리지 못합니다. 필요한 변환은 계산 전에 합니다.

### 5. 오버로딩과 오버라이딩은 선택 단계가 다릅니다

오버로딩은 호출할 메서드의 시그니처를 고르는 과정입니다. 오버라이딩은 그 호출에 대응하는 실제 객체의 구현을 고르는 과정입니다. 반환형만 바꾼 선언은 오버로딩이 아닙니다.

### 6. 생성자와 기본 생성자를 구분합니다

생성자를 하나라도 직접 선언하면 기본 생성자를 별도로 자동 추가하지 않습니다. 무인자 생성자는 직접 작성할 수도 있으므로 기본 생성자와 완전히 같은 용어가 아닙니다.

### 7. 상위 생성자가 먼저 실행되어도 자식 메서드가 호출될 수 있습니다

생성자에서 재정의 가능한 메서드를 호출하면 자식 구현으로 연결될 수 있습니다. 그때 자식의 명시적 필드 초기화가 아직 끝나지 않았을 수 있습니다.

### 8. final·불변·수정 불가를 같은 말로 외우지 않습니다

`final` 참조의 대상 객체는 가변일 수 있습니다. 레코드도 내부의 가변 객체를 자동으로 깊게 보호하지 않습니다. 와일드카드에 의한 원소 추가 제한 역시 불변성 보장이 아닙니다.

### 9. 문자열·래퍼·배열의 비교 목적을 먼저 확인합니다

문자열은 보통 내용 비교가 목적입니다. 래퍼의 객체 캐시에 기대어 값을 비교하지 않습니다. 배열의 일반 `equals()`를 원소별 비교로 오해하지 않습니다.

### 10. 같은 해시값이라고 같은 객체는 아닙니다

해시 충돌이 가능합니다. 반드시 기억할 방향은 “동등하면 해시값이 같다”입니다. 그 역은 성립하지 않습니다.

### 11. 인터페이스의 모든 메서드가 추상 메서드는 아닙니다

기본·정적·비공개 메서드가 존재합니다. 그러나 인터페이스에 개별 객체의 인스턴스 필드나 생성자가 있는 것은 아닙니다.

### 12. 제네릭 타입 인수의 상속은 자동 전파되지 않습니다

`Integer`가 `Number`의 하위 타입이어도 `List<Integer>`를 `List<Number>`에 그대로 대입하지 못합니다. 배열의 공변성과 구분합니다.

### 13. 컴파일 오류·실행 오류·논리 오류를 나눕니다

| 분류 | 예 | 확인 시점 |
| --- | --- | --- |
| 컴파일 오류 | 초기화하지 않은 지역 변수 읽기, 반환형만 다른 중복 선언 | 실행하기 전 |
| 실행 오류 | 널 역참조, 배열 범위 초과, 잘못된 하향 변환 | 해당 코드 실행 시 |
| 논리 오류 | 평균을 정수 나눗셈으로 계산, 잘못된 조건 순서 | 실행은 되지만 결과가 의도와 다름 |

오버플로처럼 예외가 나지 않는 계산 오류도 있습니다. “오류이므로 반드시 예외”라는 식으로 묶지 않습니다.

### 14. 최신 문법을 과거 문제의 기본 규칙에 섞지 않습니다

문제가 버전을 정하면 그 버전을 따릅니다. 자바 21의 전통적인 생성자 예제와 자바 25의 유연한 생성자 본문은 규칙이 다릅니다. `main`의 선언 형태도 버전에 따라 확장되었습니다.

이 절의 판별 기준은 앞선 각 주제의 공식 근거와 연결됩니다. 특히 호출·생성자·형 변환·객체 계약·제네릭 규칙은 언어 명세와 표준 클래스 문서를 함께 확인합니다.[^conversion][^classes][^invocation][^object][^restrictions]

## 예시로 한 바퀴

다음 예제는 **클래스 변수·생성자·추상 클래스·재정의·배열·제네릭·참조 공유**를 한 번에 연결합니다.

```java
abstract class 평가 {
    static int 생성수;
    private final String 이름;

    평가(String 이름) {
        this.이름 = 이름;
        생성수++;
    }

    String 이름조회() {
        return 이름;
    }

    abstract int 점수조회();
}

class 시험평가 extends 평가 {
    private final int[] 점수들;

    시험평가(String 이름, int[] 점수들) {
        super(이름);
        this.점수들 = 점수들.clone();
    }

    @Override
    int 점수조회() {
        int 합 = 0;
        for (int 점수 : 점수들) {
            합 += 점수;
        }
        return 합;
    }
}

class 보관함<자료형> {
    private final 자료형 값;

    보관함(자료형 값) {
        this.값 = 값;
    }

    자료형 꺼내기() {
        return 값;
    }
}

public class Main {
    public static void main(String[] args) {
        int[] 원본 = {30, 40};
        평가 대상 = new 시험평가("민수", 원본);
        원본[0] = 0;
        보관함<평가> 상자 = new 보관함<>(대상);
        System.out.println(상자.꺼내기().이름조회());
        System.out.println(상자.꺼내기().점수조회());
        System.out.println(평가.생성수);
        System.out.println(상자.꺼내기() == 대상);
    }
}
```

출력:

```text
민수
70
1
true
```

| 위치 | 연결되는 개념 | 판단 |
| --- | --- | --- |
| `abstract class 평가` | 추상 클래스 | 직접 객체로 만들지 않고 공통 기반으로 사용합니다. |
| `static int 생성수` | 클래스 변수 | 같은 클래스의 상태를 공유합니다. |
| `private final String 이름` | 캡슐화·재대입 제한 | 이름 참조를 다시 바꾸지 않습니다. |
| `super(이름)` | 생성자 연결 | 부모 초기화를 요청합니다. |
| `점수들.clone()` | 방어적 복사 | 바깥 배열 변경이 내부 점수에 영향을 주지 않습니다. |
| `평가 대상 = new 시험평가(...)` | 상향 변환 | 선언 타입은 평가, 실제 객체는 시험평가입니다. |
| `점수조회()` | 재정의 | 실제 시험평가의 합계 계산이 실행됩니다. |
| `보관함<평가>` | 제네릭 | 평가 타입으로 저장·조회 관계를 유지합니다. |
| 마지막 `==` | 참조 동일성 | 보관함이 객체를 복제하지 않았으므로 같은 객체입니다. |

**핵심 판단:** 원본 배열은 복사했지만, 평가 객체는 보관함에 참조값만 저장했습니다. 한 코드에서도 복사 범위를 따로 판단해야 합니다.

## 공식 근거와 확인 범위

개념 확인에는 자바 언어 명세, 가상 머신 명세, 표준 클래스 문서와 공식 학습 자료를 사용했습니다. 구형 공식 학습 자료의 버전 한계는 자바 21 명세 및 이후 언어 변경 문서와 대조했습니다. 예제와 객관식 문제는 이 글의 설명을 위해 작성한 것입니다.

본문의 각주로 해당 개념의 근거를 확인할 수 있습니다. 기본 학습 범위는 자바 21이며, 자바 22·25의 변경은 해당 버전 문서에 따라 보충으로 표시했습니다.

코드 점검에서는 본문의 자바 코드 블록 93개를 각각 독립된 문맥으로 구성해 자바 21 기준으로 컴파일했습니다. 실행 가능한 86개 블록을 실행했으며, 출력이 제시되었거나 문제의 정답으로 정해진 71개 결과가 일치하는 것을 확인했습니다. 클래스·메서드 선언만 있는 블록은 선언 문맥에서 검사했습니다. 오류 설명용 주석과 선택지를 바꾼 별도 검사에서는 컴파일 오류 17건, 정상 선언 4건, 실행 시 예외 3건의 예상 결과도 확인했습니다.
