## Shared Lock

Shared Lock은 읽기 작업과 연결해서 설명합니다.

여러 Transaction이 같은 데이터를 읽는 것은 동시에 허용할 수 있습니다.

```text
S Lock + S Lock
→ 가능
```

## Exclusive Lock

Exclusive Lock은 수정 작업과 연결해서 설명합니다.

다른 Transaction의 읽기나 쓰기를 제한할 수 있습니다.

```text
X Lock + X Lock
→ 충돌

S Lock + X Lock
→ 충돌
```

## Lock 호환성

기본적인 호환성은 다음처럼 기억할 수 있습니다.

| 요청 | 기존 S | 기존 X |
| --- | --- | --- |
| S | 가능 | 불가 |
| X | 불가 | 불가 |

실제 DBMS는 Row, Page, Table 등 Lock Granularity와 Lock Mode가 더 다양할 수 있습니다.

## Lock Granularity

Lock 대상 단위가 작을수록 동시성은 높아질 수 있지만 Lock 관리 비용이 증가합니다.

```text
Database
Table
Page
Row
```

DBMS는 상황에 따라 다른 단위의 Lock을 사용할 수 있습니다.

## 2PL 기본

Two-Phase Locking은 두 단계로 나눕니다.

```text
Growing Phase
→ Lock 획득 가능
→ Lock 해제 금지

Shrinking Phase
→ Lock 해제 가능
→ 새로운 Lock 획득 금지
```

한 번 Lock을 풀기 시작하면 새 Lock을 얻지 않는 것이 핵심입니다.

## Growing Phase

필요한 Lock을 늘려 가는 단계입니다.

```text
Lock A 획득
Lock B 획득
Lock C 획득
```

아직 Lock을 해제하지 않습니다.

## Shrinking Phase

Lock을 해제하기 시작한 이후의 단계입니다.

```text
Unlock A
Unlock B
```

이 단계에서는 새로운 Lock을 획득하지 않습니다.

## 2PL과 Serializability

기본 2PL은 Conflict Serializability를 보장하는 대표적인 방법입니다.

하지만 Deadlock을 자동으로 없애주는 것은 아닙니다.

2PL을 따르면서도 서로 Lock을 기다리는 Deadlock이 발생할 수 있습니다.

## Strict 2PL

Strict 2PL은 일반적으로 쓰기 Lock을 Transaction 종료까지 유지하는 방식으로 설명합니다.

```text
X Lock
→ COMMIT 또는 ROLLBACK까지 유지
```

Cascading Rollback을 줄이고 Recovery를 단순하게 하는 데 도움이 됩니다.

## Rigorous 2PL

Rigorous 2PL은 Shared Lock과 Exclusive Lock 모두 Transaction 종료까지 유지하는 더 강한 형태로 설명됩니다.

교재마다 용어 설명 수준이 다를 수 있으므로 시험 범위를 확인합니다.

## Lock Upgrade

읽다가 수정해야 하는 경우 Shared Lock을 Exclusive Lock으로 승격할 수 있습니다.

```text
S → X
```

여러 Transaction이 동시에 승격을 기다리면 교착 가능성이 생길 수 있습니다.

## Lock과 Deadlock

다음 상황을 생각합니다.

```text
T1
→ A Lock 보유
→ B Lock 대기

T2
→ B Lock 보유
→ A Lock 대기
```

서로 기다리므로 Deadlock입니다.

### 4. Lock Granularity

Lock 대상 단위가 작을수록 동시성은 높아질 수 있지만 Lock 관리 비용이 증가합니다.

이 항목은 시험에서 비슷한 용어와 바꾸어 출제될 수 있으므로 시간 순서와 상태 변화를 함께 확인합니다.

### 5. 2PL 기본

Two-Phase Locking은 두 단계로 나눕니다.

이 항목은 시험에서 비슷한 용어와 바꾸어 출제될 수 있으므로 시간 순서와 상태 변화를 함께 확인합니다.

### 6. Growing Phase

필요한 Lock을 늘려 가는 단계입니다.

이 항목은 시험에서 비슷한 용어와 바꾸어 출제될 수 있으므로 시간 순서와 상태 변화를 함께 확인합니다.

## 시험·면접

### 핵심 암기

```text
Lock = 접근 제어 / 2PL = Growing Phase + Shrinking Phase
```

### 시험 접근 순서

```text
1. Transaction 시작점 확인
2. Read와 Write 순서 확인
3. COMMIT 여부 확인
4. Lock 또는 Isolation 확인
5. 다른 Transaction이 보는 값 확인
6. 최종 상태 확인
```

### 시험 함정

같은 용어라도 실제 DBMS의 구현에 따라 세부 동작이 달라질 수 있습니다.

시험에서는 문제에서 제시한 표준 정의를 우선하고, 실무에서는 사용하는 DBMS의 실제 구현을 확인합니다.

### 면접에서 짧게 답한다면

Lock은 데이터 접근을 제어하는 동시성 기법이고, 2PL은 Lock 획득 단계와 해제 단계를 분리하여 직렬 가능성을 확보하는 규칙입니다.

핵심은 데이터 일관성을 유지하면서 동시에 여러 작업을 안전하게 처리하고, 장애가 발생해도 정상 상태로 복구하는 것입니다.
