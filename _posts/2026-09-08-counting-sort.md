계수 정렬은 **값과 값을 비교하지 않고, 각 값이 몇 번 나왔는지를 세어 자리를 정하는** 정렬입니다.  
정수이고, 최댓값과 최솟값의 차이가 작을 때 씁니다.

<blockquote class="prompt-info">
  <p>비교 정렬이 아님. 시간·공간 모두 $$\Theta(n+k)$$. $$k=\textit{max}-\textit{min}+1$$. 뒤에서부터 넣으면 안정. 제자리가 아님(카운트 배열 + 출력 배열). 차트는 <code>https://jyjnote.github.io/assets/plotly/counting-sort-charts.html</code> 입니다.</p>
</blockquote>

## 한 줄 규칙

오름차순, 정수 키를 기준으로 둡니다.

1. 최솟값 $$\textit{min}$$, 최댓값 $$\textit{max}$$를 구한다
2. 길이 $$k=\textit{max}-\textit{min}+1$$인 카운트 배열을 0으로 둔다
3. 입력의 각 값 $$x$$에 대해 $$C[x-\textit{min}]$$을 1 늘린다
4. 카운트를 왼쪽부터 누적한다. $$C[i]$$는 “$$i+\textit{min}$$ 이하가 몇 명인지”
5. 입력을 **뒤에서부터** 보며, 그 값의 누적 자리를 하나 줄이고 출력 배열에 넣는다

기호:

- $$n$$: 입력 길이. 아래 예에서 $$n=5$$
- $$A[i]$$: $$i$$번 위치의 값. $$i$$는 $$0$$부터
- $$\textit{min}$$, $$\textit{max}$$: 입력의 최솟값·최댓값
- $$k=\textit{max}-\textit{min}+1$$: 서로 다른 정수가 들어올 수 있는 구간의 길이
- $$C[t]$$: 처음엔 값 $$t+\textit{min}$$의 등장 횟수. 누적 후에는 그 값 이하의 인원
- $$B[j]$$: 출력 배열. 길이 $$n$$
- 오프셋 $$x-\textit{min}$$: 값 $$55$$를 카운트 인덱스 $$0$$에 대응시키는 이동

이름은 “센다(count)”에서 왔습니다.  
동작의 핵심은 이름이 아니라 <mark>횟수 → 누적 위치 → 뒤에서 배치</mark>입니다.

버블·퀵·힙은 “누가 더 크냐”를 반복합니다.  
계수는 “이 점수가 몇 명인가”만 묻습니다. 그래서 비교 횟수가 시간식에 없습니다.

## 숫자로 전 과정

학생 점수. 앞 정렬 글과 같은 입력입니다.

$$
A=[80,\ 55,\ 90,\ 70,\ 60]
$$

$$
\textit{min}=55,\quad \textit{max}=90,\quad k=90-55+1=36
$$

카운트 배열은 길이 $$36$$입니다. 실제로 등장하는 값은 다섯 개뿐이라, 표에는 그 다섯 값만 적습니다.  
코드는 $$55$$부터 $$90$$까지 인덱스 $$0\ldots 35$$를 그대로 씁니다.

탭 **1**은 세기·누적·배치 한 번마다, 탭 **2**는 단계가 끝날 때만 봅니다.  
위 막대는 입력, 아래 막대는 출력입니다. 노랑은 지금 보는 값, 보라는 방금 출력에 넣은 위치입니다.

### 1. 등장 횟수

입력을 한 번 훑습니다.

| 위치 | 값 | 그 값의 횟수 |
| :---: | ---: | ---: |
| 0 | 80 | 1 |
| 1 | 55 | 1 |
| 2 | 90 | 1 |
| 3 | 70 | 1 |
| 4 | 60 | 1 |

등장한 값만 보면

| 값 | 55 | 60 | 70 | 80 | 90 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 횟수 | 1 | 1 | 1 | 1 | 1 |

나머지 정수 $$56,57,\ldots$$ 의 횟수는 $$0$$입니다.  
이 단계에서 하는 일은 $$n$$번 증가, 카운트 배열을 0으로 두는 일 $$k$$번입니다.

### 2. 누적 — “이하가 몇 명인가”

왼쪽(작은 값)부터 횟수를 더합니다.

| 값 | 횟수 | 누적(이하 인원) | 마지막 자리(인덱스) |
| ---: | ---: | ---: | ---: |
| 55 | 1 | 1 | 0 |
| 60 | 1 | 2 | 1 |
| 70 | 1 | 3 | 2 |
| 80 | 1 | 4 | 3 |
| 90 | 1 | 5 | 4 |

읽는 법:

- $$55$$ 이하인 사람은 $$1$$명 → 자리는 인덱스 $$0$$까지
- $$60$$ 이하인 사람은 $$2$$명 → 자리는 인덱스 $$1$$까지
- $$90$$ 이하인 사람은 $$5$$명 → 전체가 여기까지

누적값에서 $$1$$을 뺀 수가, 그 값이 들어갈 수 있는 **가장 오른쪽 인덱스**입니다.

중간에 횟수 $$0$$인 값(예를 들어 $$65$$)은 누적이 그대로 전달됩니다.  
“$$65$$ 이하”와 “$$60$$ 이하”의 인원이 같다는 뜻입니다.

이 단계는 카운트 배열 한 바퀴, $$\Theta(k)$$입니다.

### 3. 뒤에서부터 배치

출력을 앞에서부터 채우면, 같은 값이 여러 개일 때 먼저 본 값이 뒤로 밀립니다.  
**입력의 뒤부터** 넣으면 원래 순서가 유지됩니다.

지금 누적:

| 값 | 55 | 60 | 70 | 80 | 90 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 누적 | 1 | 2 | 3 | 4 | 5 |

| 순서 | 입력 위치 | 값 | 누적 감소 | 출력 인덱스 | 출력 |
| :---: | ---: | ---: | ---: | ---: | :--- |
| 1 | 4 | 60 | 2 → 1 | 1 | [?, 60, ?, ?, ?] |
| 2 | 3 | 70 | 3 → 2 | 2 | [?, 60, 70, ?, ?] |
| 3 | 2 | 90 | 5 → 4 | 4 | [?, 60, 70, ?, 90] |
| 4 | 1 | 55 | 1 → 0 | 0 | [55, 60, 70, ?, 90] |
| 5 | 0 | 80 | 4 → 3 | 3 | [55, 60, 70, 80, 90] |

$$
B=[55,\ 60,\ 70,\ 80,\ 90]
$$

값 비교는 한 번도 없습니다.  
자리를 정하는 덧셈·뺄셈만 $$n+k$$ 번 규모입니다.

## 시간·공간

카운트 0으로 두기 $$k$$, 세기 $$n$$, 누적 $$k$$, 배치 $$n$$, 출력 복사 $$n$$.

$$
T(n,k)=\Theta(n+k)
$$

$$n=5$$, $$k=36$$이면 차수는 $$41$$에 비례합니다.  
비교 정렬 최하한 $$\Omega(n\log n)$$을 깨는 이유는, 비교 모델이 아니기 때문입니다. 값 자체를 배열 인덱스로 사용합니다.

공간이 카운트 길이 $$k$$ + 출력 길이 $$n$$입니다.

$$
S_{\text{aux}}(n,k)=\Theta(n+k)
$$

제자리가 아닙니다.  
카운트만 두고 입력을 덮어쓰는 변형도 있으나, 그때는 안정성을 잃거나 구현이 복잡해집니다. 학부 기본형은 출력 배열을 따로 둡니다.

$$k$$가 커지면 시간이 바로 커집니다.  
점수가 $$0$$부터 $$10^9$$까지면 $$k=10^9+1$$이라 계수 단독은 쓸 수 없습니다. 그때는 기수 정렬이 자리를 나눠 계수를 여러 번 돌립니다.

$$n=1000$$, 점수가 $$0\ldots 100$$이면

$$
n+k=1000+101=1{,}101
$$

힙·병합의 약 $$n\log_2 n \approx 10{,}000$$보다 작습니다.  
같은 $$n$$에 점수가 $$0\ldots 10^7$$이면 $$n+k$$가 비교 정렬을 이깁니다.

## 안정성

같은 값 두 개의 **원래 순서**를 지키면 안정입니다.

$$
A=[70_a,\ 55,\ 70_b]
$$

횟수: $$55\to 1$$, $$70\to 2$$.  
누적: $$55\to 1$$, $$70\to 3$$.

뒤에서 배치합니다.

1. $$70_b$$: 누적 $$3\to 2$$, 출력 인덱스 $$2$$에 $$70_b$$
2. $$55$$: 누적 $$1\to 0$$, 출력 인덱스 $$0$$에 $$55$$
3. $$70_a$$: 누적 $$2\to 1$$, 출력 인덱스 $$1$$에 $$70_a$$

$$
B=[55,\ 70_a,\ 70_b]
$$

$$70_a$$가 $$70_b$$ 앞에 남습니다. <mark>안정</mark>입니다.

앞에서부터 넣으면 $$70_a$$가 인덱스 $$2$$를 먼저 차지해 $$[55,\ 70_b,\ 70_a]$$가 됩니다.  
<span style="color:#c0392b"><strong>뒤에서 넣는 이유</strong></span>가 안정성입니다.

## 의사코드

```
counting_sort(A):
    n ← A의 길이
    min ← A의 최솟값
    max ← A의 최댓값
    k ← max-min+1
    C[0..k-1] ← 0
    i ← 0 부터 n-1 까지
        C[A[i]-min] ← C[A[i]-min] + 1
    t ← 1 부터 k-1 까지
        C[t] ← C[t] + C[t-1]
    B[0..n-1] ← 빈 배열
    i ← n-1 부터 0까지
        x ← A[i]
        C[x-min] ← C[x-min] - 1
        B[C[x-min]] ← x
    A를 B로 복사하거나 B를 반환
```

- `A[i]-min`: 값 $$55$$ → 인덱스 $$0$$
- 누적 후 `C[x-min]`: 값 $$x$$ 이하의 인원. 그 값이 끝나는 인덱스 + 1
- 하나 줄인 뒤 그 인덱스가 이번에 넣을 자리
- 루프가 `n-1`부터: 안정

아래 두 코드는 위 의사코드와 같습니다.  
본문 예 `[80, 55, 90, 70, 60]`을 넣으면 `[55, 60, 70, 80, 90]`이 나옵니다.

### C

```c
#include <stdio.h>
#include <stdlib.h>

void counting_sort(int a[], int n) {
    int mn = a[0], mx = a[0];
    for (int i = 1; i < n; i++) {
        if (a[i] < mn) mn = a[i];
        if (a[i] > mx) mx = a[i];
    }
    int k = mx - mn + 1;
    int *C = calloc(k, sizeof(int));
    int *B = malloc(n * sizeof(int));
    for (int i = 0; i < n; i++) C[a[i] - mn]++;
    for (int t = 1; t < k; t++) C[t] += C[t - 1];
    for (int i = n - 1; i >= 0; i--) {
        int x = a[i];
        C[x - mn]--;
        B[C[x - mn]] = x;
    }
    for (int i = 0; i < n; i++) a[i] = B[i];
    free(C);
    free(B);
}

int main(void) {
    int a[] = {80, 55, 90, 70, 60};
    int n = 5;
    counting_sort(a, n);
    for (int i = 0; i < n; i++) printf("%d ", a[i]);
    printf("\n");
    return 0;
}
```

- `calloc`: 카운트를 0으로 둠
- `a[i] - mn`: 오프셋. $$90-55=35$$
- `i = n - 1`: 뒤에서 배치
- `free`: 보조 배열 해제

음수가 있으면 `min`이 음수여도 `x-min`은 $$0$$ 이상입니다.  
값이 `int` 범위를 넘는 키(문자열·실수)는 인덱스가 될 수 없습니다.

### Python

```python
def counting_sort(a):
    n = len(a)
    mn, mx = min(a), max(a)
    k = mx - mn + 1
    C = [0] * k
    for x in a:
        C[x - mn] += 1
    for t in range(1, k):
        C[t] += C[t - 1]
    B = [0] * n
    for i in range(n - 1, -1, -1):
        x = a[i]
        C[x - mn] -= 1
        B[C[x - mn]] = x
    return B

scores = [80, 55, 90, 70, 60]
print(counting_sort(scores))
```

- `range(n - 1, -1, -1)`: $$i=n-1,\ldots,0$$
- `C[x - mn] -= 1` 다음에 `B[...] = x`: 줄인 값이 인덱스
- 파이썬 `sort`는 팀소트라 계수가 아닙니다. 범위가 좁은 정수에만 이 코드를 씁니다

값이 모두 $$0$$ 이상이고 $$\textit{min}=0$$이면 오프셋을 생략할 수 있습니다. 정처기 예제 다수가 이 형태입니다.

## 비교 정렬과 한 표

같은 $$n=5$$, 같은 입력 $$[80,\ 55,\ 90,\ 70,\ 60]$$. $$k=36$$.

| 항목 | 힙 | 병합 | 계수 |
| :--- | :--- | :--- | :--- |
| 하는 일 | 루트를 뒤에 확정 | 두 줄을 합침 | 횟수로 자리를 계산 |
| 비교 | 있음 | 있음 | 없음(값 비교) |
| 시간 | $$\Theta(n\log n)$$ | $$\Theta(n\log n)$$ | $$\Theta(n+k)$$ |
| 보조 공간 | $$\Theta(1)$$ | $$\Theta(n)$$ | $$\Theta(n+k)$$ |
| 안정 | 아니오 | 예 | 예(뒤에서 배치) |
| 키 제약 | 비교만 되면 됨 | 비교만 되면 됨 | 작은 정수 구간 |

시험이 계수를 물으면 축은 <mark>비교가 아니다</mark>, <mark>$$n+k$$</mark>, <mark>안정</mark>, <mark>$$k$$가 크면 못 쓴다</mark>입니다.

## 언제 쓰나

쓰는 때:

- 키가 정수이고 $$k$$가 $$n$$과 비슷하거나 조금 더 클 때
- 안정 정렬이 필요하고, 비교 $$n\log n$$을 피하고 싶을 때
- 기수 정렬의 한 자리. 다음 글의 안쪽 엔진

약한 때:

- $$k$$가 $$n\log n$$보다 훨씬 큼. 점수 $$0\ldots 10^9$$
- 실수·문자열을 그대로 인덱스에 넣으려 할 때
- 제자리가 필수일 때
- 입력이 비교만 되고 값의 범위는 모를 때

## 잘 놓치는 핵심

### 1. 계수도 비교 정렬이다

아닙니다. $$A[i]$$와 $$A[j]$$를 비교하지 않습니다. 값을 인덱스로 씁니다.

### 2. 시간은 항상 $$O(n)$$이다

$$k$$를 잊으면 안 됩니다. $$T=\Theta(n+k)$$입니다. $$k=n^2$$이면 제곱입니다.

### 3. 앞에서부터 넣어도 같다

결과는 오름차순이어도 같은 키의 순서가 뒤집힐 수 있습니다. 안정은 뒤에서 넣을 때입니다.

### 4. $$\textit{min}$$을 빼는 이유

카운트 인덱스는 $$0$$부터여야 합니다. 값 $$55$$를 그대로 인덱스로 쓰면 길이 $$91$$짜리 배열이 생기고, $$0\ldots 54$$가 낭비입니다.

### 5. 누적이 횟수 그대로다

누적 전 $$C[t]$$는 그 값의 인원, 누적 후는 그 값 **이하**의 인원입니다. 두 의미를 같은 배열에 덮어씁니다.

### 6. 실수도 동일하다

$$3.14$$를 인덱스로 쓸 수 없습니다. 버킷 정렬은 구간으로 나누는 다른 알고리즘입니다.

### 7. 제자리다

기본형은 카운트 + 출력, $$\Theta(n+k)$$ 보조입니다.

## 시험·면접

<blockquote class="prompt-info">
  <p>단골: 비교 정렬 아님, $$\Theta(n+k)$$, $$k=\max-\min+1$$, 안정(뒤에서 배치), 제자리 아님, $$k$$가 크면 비효율, 기수의 한 자리.</p>
</blockquote>

전공자 체크:

- 비교 정렬 최하한 $$\Omega(n\log n)$$은 비교 모델의 이야기입니다. 계수는 모델을 바꿉니다
- 안정 + 선형에 가까운 시간이 동시에 필요하면, $$k=O(n)$$일 때 계수가 답
- 누적 배열은 “이 값이 끝나는 위치”를 주는 누적 도수입니다
