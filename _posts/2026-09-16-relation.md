Relation은 관계형 데이터 모델에서 **하나의 테이블에 대응하는 데이터 구조**입니다.  
Attribute로 구조가 정의되고, 여러 Tuple이 모여 실제 데이터를 구성합니다.

<blockquote class="prompt-info">
<p>한 줄: Relation은 여러 Attribute와 Tuple로 구성된 하나의 테이블에 대응하는 개념입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

Relation은 관계형 데이터 모델에서 테이블 전체에 대응합니다.

</details>

## 가장 먼저 큰 그림

다음과 같은 학생 데이터를 생각해봅시다.

```text
STUDENT

student_id | name   | department
1001       | 김철수 | 컴퓨터공학
1002       | 이영희 | 통계학
1003       | 박민수 | 경영학
```

관계형 데이터 모델에서는 `STUDENT` 전체를 하나의 Relation이라고 합니다.

```text
Relation ≈ Table
```

Relation 안의 각 요소는 다음과 같습니다.

```text
Relation
├─ Attribute → 열
├─ Tuple     → 행
└─ Domain    → Attribute가 가질 수 있는 값의 범위
```

<mark>Relation은 테이블 전체이고, Tuple은 그 안의 개별 행입니다.</mark>

---

## Relation이란

Relation은 관계형 데이터 모델에서 데이터를 표현하는 기본 단위입니다.

일반적인 데이터베이스의 Table과 거의 대응합니다.

```text
Table
≈
Relation
```

예를 들어 다음 전체가 하나의 Relation입니다.

```text
student_id | name   | department
1001       | 김철수 | 컴퓨터공학
1002       | 이영희 | 통계학
```

한 줄만 Relation이라고 하는 것이 아닙니다.

```text
Relation = 테이블 전체
Tuple = 테이블의 한 행
```

---

## Relation의 구성 요소

예를 들어 다음 Relation이 있습니다.

```text
EMPLOYEE

employee_id | name  | department_id | salary
1001        | 직원1 | 10            | 2890
1002        | 직원2 | 20            | 2980
```

각 요소를 구분하면 다음과 같습니다.

| 구분 | 예시 | 의미 |
| --- | --- | --- |
| Relation | EMPLOYEE | 테이블 전체 |
| Attribute | employee_id, name, department_id, salary | 열 |
| Tuple | 1001, 직원1, 10, 2890 | 행 하나 |
| Domain | salary가 가질 수 있는 값의 범위 | 속성 값의 범위 |

---

## Attribute

Attribute는 Relation을 구성하는 열입니다.

```text
employee_id
name
department_id
salary
```

일반적인 Column에 대응합니다.

```text
Attribute ≈ Column
```

Attribute는 어떤 종류의 데이터를 저장할 것인지 나타냅니다.

---

## Tuple

Tuple은 Relation을 구성하는 하나의 행입니다.

```text
1001 | 직원1 | 10 | 2890
```

일반적인 Row에 대응합니다.

```text
Tuple ≈ Row
```

다음 Relation에는 두 개의 Tuple이 있습니다.

```text
1001 | 직원1 | 10 | 2890
1002 | 직원2 | 20 | 2980
```

```text
Tuple 1
→ 1001 | 직원1 | 10 | 2890

Tuple 2
→ 1002 | 직원2 | 20 | 2980
```

<mark>개별 데이터 한 줄은 Relation이 아니라 Tuple입니다.</mark>

---

## Domain

Domain은 하나의 Attribute가 가질 수 있는 값의 범위입니다.

예를 들어 학년 Attribute가 다음 값만 가질 수 있다고 가정합니다.

```text
1
2
3
4
```

이 값들의 범위가 Domain입니다.

```text
Domain
= Attribute가 가질 수 있는 값의 범위
```

예시는 다음과 같습니다.

| Attribute | Domain 예시 |
| --- | --- |
| 학년 | 1, 2, 3, 4 |
| 점수 | 0부터 100 |
| 학번 | 정해진 형식의 학번 값 |

---

## Relation Schema

Relation Schema는 Relation의 구조를 나타냅니다.

```text
EMPLOYEE(
    employee_id,
    name,
    department_id,
    salary
)
```

이것은 실제 데이터가 아니라 어떤 Attribute가 존재하는지를 나타냅니다.

```text
Relation Schema
= Relation의 구조
```

---

## Relation Instance

Relation Instance는 **특정 시점에 Relation에 실제로 저장된 전체 Tuple의 집합**입니다.

예를 들어 현재 다음 데이터가 저장되어 있다고 가정합니다.

```text
1001 | 직원1 | 10 | 2890
1002 | 직원2 | 20 | 2980
```

이 두 Tuple 전체가 현재 시점의 Relation Instance입니다.

```text
Relation Instance

1001 | 직원1 | 10 | 2890
1002 | 직원2 | 20 | 2980
```

개별 한 줄은 Tuple입니다.

전체 실제 데이터 상태가 Instance입니다.

```text
Schema
= 구조

Instance
= 특정 시점의 전체 실제 데이터

Tuple
= Instance 안의 개별 행
```

<mark>Instance는 개별 데이터 한 줄이 아니라 특정 시점의 전체 실제 데이터입니다.</mark>

---

## Schema와 Instance 비교

| 구분 | Schema | Instance |
| --- | --- | --- |
| 의미 | Relation의 구조 | 특정 시점의 실제 데이터 |
| 구성 | Attribute | Tuple |
| 변화 | 비교적 적음 | 데이터 변경에 따라 변함 |
| 핵심 | 틀 | 내용 |

다음처럼 기억하면 쉽습니다.

```text
Schema = 그릇의 구조
Instance = 현재 그릇 안의 내용
```

---

## Degree · 차수

Degree는 Relation이 가진 Attribute의 개수입니다.

```text
employee_id | name | department_id | salary
```

Attribute는 네 개입니다.

```text
Degree = 4
```

정리하면 다음과 같습니다.

```text
Degree
= Attribute의 개수
= 열의 개수
```

---

## Cardinality · 카디널리티

Cardinality는 Relation에 존재하는 Tuple의 개수입니다.

```text
1001 | 직원1 | 10 | 2890
1002 | 직원2 | 20 | 2980
1003 | 직원3 | 10 | 3100
```

Tuple은 세 개입니다.

```text
Cardinality = 3
```

정리하면 다음과 같습니다.

```text
Cardinality
= Tuple의 개수
= 행의 개수
```

---

## Degree와 Cardinality 비교

| 구분 | 의미 | 기준 |
| --- | --- | --- |
| Degree | Attribute의 개수 | 열 |
| Cardinality | Tuple의 개수 | 행 |

예를 들어 다음 Relation이 있습니다.

```text
A | B | C | D
1 | 2 | 3 | 4
5 | 6 | 7 | 8
9 | 0 | 1 | 2
```

```text
열 = 4개
행 = 3개

Degree = 4
Cardinality = 3
```

<mark>Degree는 열의 수이고, Cardinality는 행의 수입니다.</mark>

---

## Relation의 특징

관계형 데이터 모델의 Relation에는 몇 가지 중요한 특징이 있습니다.

### 1. Tuple의 순서는 중요하지 않다

다음 두 Relation은 행의 순서만 다릅니다.

```text
1001 | 김철수
1002 | 이영희
```

```text
1002 | 이영희
1001 | 김철수
```

관계 모델에서는 Tuple의 순서 자체에 의미를 두지 않습니다.

### 2. Attribute의 순서도 본질적인 의미가 없다

Attribute는 이름으로 구분하므로 논리적으로 열의 순서 자체가 핵심은 아닙니다.

### 3. 동일한 Tuple은 중복되지 않는다

수학적인 Relation은 집합이므로 같은 Tuple을 중복해서 가지지 않습니다.

```text
1001 | 김철수
1001 | 김철수
```

관계 모델에서는 이런 동일 Tuple의 중복을 허용하지 않습니다.

### 4. 하나의 Attribute는 같은 Domain을 사용한다

하나의 Attribute에 들어가는 값들은 해당 Attribute의 Domain에 속해야 합니다.

---

## Relation과 Table은 완전히 같은가

학습 단계에서는 다음처럼 대응하면 됩니다.

```text
Relation ≈ Table
Tuple ≈ Row
Attribute ≈ Column
```

하지만 이론적인 Relation과 실제 SQL Table은 완전히 동일한 개념은 아닙니다.

관계 모델의 Relation은 동일한 Tuple의 중복을 허용하지 않습니다.

반면 실제 SQL Table은 제약조건이 없다면 동일한 행이 존재할 수 있습니다.

```text
관계 모델
→ Relation

실제 데이터베이스 구현
→ Table
```

## Relation을 한 번에 보기

다음 Relation을 기준으로 전체 개념을 정리합니다.

```text
EMPLOYEE

employee_id | name  | department_id | salary
1001        | 직원1 | 10            | 2890
1002        | 직원2 | 20            | 2980
```

```text
Relation
→ EMPLOYEE 전체

Attribute
→ employee_id, name, department_id, salary

Tuple
→ 1001 | 직원1 | 10 | 2890

Domain
→ 각 Attribute가 가질 수 있는 값의 범위

Schema
→ EMPLOYEE(employee_id, name, department_id, salary)

Instance
→ 현재 저장된 두 Tuple 전체

Degree
→ 4

Cardinality
→ 2
```

---

## 잘 놓치는 핵심

### 1. Relation은 테이블 전체다

```text
Relation ≈ Table
```

개별 행 하나를 Relation이라고 하지 않습니다.

### 2. 개별 행 하나는 Tuple이다

```text
Tuple ≈ Row
```

### 3. Instance는 전체 실제 데이터다

```text
Instance
= 특정 시점에 Relation에 저장된 전체 Tuple 집합
```

한 개의 Tuple을 Instance라고 생각하면 안 됩니다.

### 4. Schema는 구조다

```text
Schema
= Relation의 구조
```

### 5. Degree와 Cardinality를 구분한다

```text
Degree
= Attribute 수
= 열 수

Cardinality
= Tuple 수
= 행 수
```

## 시험·면접

### 핵심 암기

```text
Relation = Table
Tuple = Row
Attribute = Column
Domain = Attribute가 가질 수 있는 값의 범위
```

### Schema와 Instance

```text
Schema
= 구조

Instance
= 특정 시점의 전체 실제 데이터
```

### Degree와 Cardinality

```text
Degree
= 열의 수

Cardinality
= 행의 수
```

### 시험 함정

```text
한 행 전체
→ Tuple

테이블 전체
→ Relation

특정 시점의 실제 데이터 전체
→ Instance
```

### 면접에서 짧게 답한다면

> Relation은 관계형 데이터 모델에서 하나의 테이블에 대응하는 개념으로, Attribute로 구조가 정의되고 여러 Tuple이 모여 실제 데이터를 구성합니다.
