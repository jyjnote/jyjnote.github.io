BM25는 **검색어 Query와 문서 Document가 얼마나 관련 있는지 점수를 계산하는 대표적인 정보 검색 Ranking 함수**입니다.  
TF-IDF의 핵심 아이디어를 발전시켜 **단어 빈도 포화와 문서 길이 보정**을 함께 고려합니다.

<blockquote class="prompt-info">
<p>BM25 = 희귀한 검색어를 중요하게 보되, 같은 단어의 반복 효과는 점점 줄이고 문서 길이까지 보정하는 Ranking 함수입니다.</p>
</blockquote>

대표적인 형태는 다음과 같습니다.

$$BM25(D,Q)=\sum_{t\in Q}IDF(t)\frac{TF(t,D)(k_1+1)}{TF(t,D)+k_1\left(1-b+b\frac{|D|}{avgdl}\right)}$$

처음 보면 복잡하지만 핵심은 세 가지입니다.

```text
IDF            → 희귀한 Term에 높은 중요도
TF Saturation  → 반복 횟수의 효과를 점점 감소
Length Norm.   → 긴 문서가 유리해지는 현상 보정
```

<mark>BM25의 핵심은 IDF + TF 포화 + 문서 길이 보정입니다.</mark>

<details>
<summary>한 줄로</summary>

검색어가 문서에 잘 등장하는지 보되, 무한 반복과 긴 문서의 이점을 그대로 인정하지 않는 검색 점수입니다.

</details>

## 왜 필요한가

단순한 TF를 생각해봅시다.

```text
D1: AI 2회
D2: AI 20회
```

Raw TF만 보면 D2가 D1보다 10배 중요해 보입니다.

하지만 실제 검색에서는 같은 단어를 20번 썼다고 관련성이 반드시 10배 높아지는 것은 아닙니다.

```text
1회 → 2회
```

의 증가는 의미가 클 수 있지만

```text
19회 → 20회
```

의 증가는 상대적으로 중요하지 않을 수 있습니다.

BM25는 이런 현상을 **TF Saturation**으로 다룹니다.

## TF Saturation

BM25에서 TF가 증가하면 Score도 증가합니다.

하지만 증가 폭은 점점 작아집니다.

```text
TF
1 → 큰 증가
2 → 증가
3 → 증가
...
20 → 조금 증가
```

즉 단어를 계속 반복한다고 점수가 선형적으로 계속 커지지 않습니다.

<blockquote class="prompt-info">
<p>TF Saturation = Term Frequency가 증가할수록 추가 1회의 영향이 점점 작아지는 성질입니다.</p>
</blockquote>

이 부분을 담당하는 핵심 Parameter가 $$k_1$$입니다.

## k1

$$k_1$$은 TF Saturation의 정도를 조절합니다.

```text
k1 작음
→ TF가 빠르게 포화

k1 큼
→ TF 증가 효과를 더 오래 반영
```

실무에서는 구현과 데이터에 따라 값을 조정하며, 흔히 1~2 부근의 값이 출발점으로 사용됩니다.

중요한 것은 특정 숫자를 외우는 것보다 역할입니다.

<mark>k1은 Term Frequency를 얼마나 강하게 반영할지 조절합니다.</mark>

## 문서 길이 문제

다음 두 문서를 생각해봅시다.

```text
D1: AI model
D2: AI model data system network computer ...
```

긴 문서는 단어 자체가 많기 때문에 우연히 검색어가 여러 번 등장할 가능성도 커집니다.

단순 Count만 사용하면 긴 문서가 유리해질 수 있습니다.

BM25는 문서 길이를 평균 문서 길이와 비교합니다.

$$\frac{|D|}{avgdl}$$

여기서

```text
|D|    → 현재 문서 길이
avgdl  → 전체 문서의 평균 길이
```

입니다.

## 길이 비율 해석

현재 문서가 평균 길이와 같다면

$$\frac{|D|}{avgdl}=1$$

입니다.

평균보다 짧다면

$$\frac{|D|}{avgdl}<1$$

이고, 평균보다 길다면

$$\frac{|D|}{avgdl}>1$$

입니다.

BM25는 이 값을 이용해 긴 문서의 TF 효과를 보정합니다.

## b

문서 길이 보정의 강도를 조절하는 Parameter가 $$b$$입니다.

일반적으로

$$0\leq b\leq1$$

범위에서 사용합니다.

```text
b = 0
→ 문서 길이를 보정하지 않음

b = 1
→ 문서 길이를 강하게 반영
```

흔히 0.75가 기본값으로 사용되지만 데이터와 구현에 따라 조정할 수 있습니다.

<mark>b는 문서 길이 보정의 강도를 조절합니다.</mark>

## IDF

BM25도 흔한 단어보다 희귀한 단어를 더 중요하게 보는 IDF 아이디어를 사용합니다.

BM25 계열에서 자주 볼 수 있는 형태 중 하나는 다음과 같습니다.

$$IDF(t)=\log\left(\frac{N-DF(t)+0.5}{DF(t)+0.5}+1\right)$$

여기서

```text
N      → 전체 Document 수
DF(t)  → Term t가 등장한 Document 수
```

입니다.

DF가 작으면 희귀한 Term이므로 높은 가중치를 받을 수 있습니다.

<blockquote class="prompt-warning">
<p>BM25의 IDF 공식은 구현에 따라 조금씩 다를 수 있습니다. 하나의 식만 절대적인 공식으로 외우지 않는 것이 좋습니다.</p>
</blockquote>

## 공식 분해

전체 공식을 다시 보겠습니다.

$$BM25(D,Q)=\sum_{t\in Q}IDF(t)\frac{TF(t,D)(k_1+1)}{TF(t,D)+k_1\left(1-b+b\frac{|D|}{avgdl}\right)}$$

이를 세 부분으로 보면 쉽습니다.

```text
Σ
→ Query의 각 Term 점수를 더함

IDF(t)
→ Term의 희귀성

TF 관련 분수
→ TF Saturation + Document Length Normalization
```

즉 Query에 여러 Term이 있다면 각 Term의 BM25 기여도를 계산해 합칩니다.

## TF-IDF와 차이

TF-IDF와 BM25는 모두 Term Frequency와 Document Frequency 정보를 활용하지만 동작 방식이 다릅니다.

| 구분 | TF-IDF | BM25 |
| --- | --- | --- |
| TF | 빈도를 가중치로 사용 | 포화 효과 적용 |
| IDF | 사용 | 사용 |
| 문서 길이 | 별도 정규화 가능 | 공식 안에서 직접 보정 |
| 주요 용도 | Vector 표현·가중치 | 검색 Ranking |
| Parameter | 형태에 따라 다름 | k1, b |

가장 중요한 차이는 BM25가 **TF Saturation과 문서 길이 보정**을 명시적으로 포함한다는 점입니다.

## 코사인 유사도와 차이

TF-IDF + Cosine Similarity에서는 Query와 Document를 Vector로 표현하고 방향을 비교할 수 있습니다.

$$\cos(\theta)=\frac{\mathbf{Q}\cdot\mathbf{D}}{\|\mathbf{Q}\|\|\mathbf{D}\|}$$

BM25는 Vector 사이의 각도를 계산하지 않습니다.

각 Query Term에 대해 BM25 Score를 계산하고 합산합니다.

```text
TF-IDF + Cosine
→ Vector 방향 비교

BM25
→ Query Term별 검색 점수 합산
```

따라서 둘은 같은 방식이 아닙니다.

## 역색인과 BM25

역색인은 Query Term이 등장한 후보 문서를 빠르게 찾습니다.

```text
AI → D1, D4, D8
```

이후 BM25로 후보 문서의 관련도를 계산할 수 있습니다.

```text
Query
 ↓
Inverted Index
 ↓
Candidate Documents
 ↓
BM25 Score
 ↓
Ranking
```

<mark>역색인은 후보를 찾고, BM25는 후보 문서의 순위를 정하는 데 사용할 수 있습니다.</mark>

## Semantic Search와 차이

BM25는 기본적으로 **Lexical Matching**에 강합니다.

즉 Query와 Document에서 실제 Term이 겹치는지를 중요하게 봅니다.

예:

```text
Query: automobile
Document: car
```

두 단어의 의미는 비슷하지만 표면적인 Term은 다릅니다.

기본 BM25만으로는 이런 의미적 유사성을 직접 이해하기 어렵습니다.

Embedding 기반 Semantic Search는 이런 의미 관계를 Vector 공간에서 다룰 수 있습니다.

```text
BM25
→ 단어 일치 중심

Embedding Search
→ 의미 유사성 중심
```

실제 시스템에서는 두 방식을 결합하기도 합니다.

## 잘 놓치는 핵심

### 1. BM25는 검색 Ranking 함수다

문서를 Vector로 만드는 방법 그 자체가 아닙니다.

### 2. TF가 커진다고 점수가 선형 증가하지 않는다

TF Saturation이 있기 때문입니다.

### 3. k1과 b의 역할이 다르다

```text
k1 → TF 영향
b  → 문서 길이 영향
```

입니다.

### 4. 평균 문서 길이를 사용한다

현재 문서 길이를 전체 Collection의 평균 길이와 비교합니다.

### 5. IDF 공식은 구현마다 차이가 있을 수 있다

BM25의 핵심 아이디어와 Parameter 역할을 우선 이해해야 합니다.

### 6. BM25와 Cosine Similarity는 같은 계산이 아니다

BM25는 Query Term별 점수를 합산하고, Cosine Similarity는 Vector 방향을 비교합니다.

### 7. BM25는 기본적으로 의미 검색이 아니다

표면적인 Term Matching에 강한 Lexical Retrieval 방법입니다.

## 시험·면접

<blockquote class="prompt-info">
<p>단골: BM25의 목적, TF Saturation, 문서 길이 보정, k1과 b의 역할, TF-IDF와 차이, Semantic Search와 차이.</p>
</blockquote>

핵심 암기:

- BM25는 대표적인 정보 검색 Ranking 함수다
- IDF로 희귀한 Term을 중요하게 본다
- TF 증가 효과는 점점 포화된다
- k1은 TF Saturation을 조절한다
- b는 Document Length Normalization을 조절한다
- avgdl은 Collection의 평균 문서 길이다
- BM25는 기본적으로 Lexical Matching 방식이다

<blockquote class="prompt-warning">
<p>k1을 문서 길이 Parameter, b를 TF Parameter로 반대로 외우지 않도록 주의합니다.</p>
</blockquote>

## 예시로 한 바퀴

Query가 다음과 같다고 하겠습니다.

```text
AI search
```

두 문서가 있습니다.

```text
D1: AI search system
D2: AI AI AI AI AI search system data network computer ...
```

단순 TF만 보면 `AI`가 많이 등장하는 D2가 매우 유리합니다.

하지만 BM25에서는

```text
AI 반복
→ TF Saturation

D2의 긴 길이
→ Length Normalization
```

이 적용됩니다.

따라서 `AI`를 계속 반복하고 문서를 길게 만드는 것만으로 Score가 선형적으로 증가하지 않습니다.

여기에 `AI`, `search`의 IDF까지 반영하여 각 Term의 점수를 더합니다.

```text
BM25(D,Q)
=
AI의 기여도
+
search의 기여도
```

이렇게 얻은 Score로 문서를 Ranking할 수 있습니다.
