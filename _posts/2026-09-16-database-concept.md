데이터베이스(Database)는 **여러 사람이 함께 사용할 데이터를 일정한 구조로 저장하고 관리하는 데이터의 집합**입니다.  
단순히 파일을 모아 둔 것이 아니라, 필요한 데이터를 빠르게 찾고 수정하며 여러 사용자가 안전하게 공유할 수 있도록 관리합니다.

<blockquote class="prompt-info">
<p>한 줄: 데이터베이스는 여러 데이터를 체계적으로 저장하고, 필요할 때 쉽게 조회·추가·수정·삭제할 수 있도록 만든 데이터의 집합입니다.</p>
</blockquote>

<details>
<summary>한 줄로</summary>

데이터베이스는 서로 관련된 데이터를 체계적으로 저장하고 관리하는 데이터 저장소입니다.

</details>

## 가장 간단한 예시

학교에서 학생 정보를 관리한다고 해봅시다.

```text
학번 | 이름 | 학과 | 학년
1001 | 김철수 | 컴퓨터공학 | 2
1002 | 이영희 | 통계학 | 3
1003 | 박민수 | 경영학 | 1
```

이 데이터를 파일 하나에 저장할 수도 있습니다.

하지만 학생이 수만 명이고,

- 수강 정보
- 성적 정보
- 등록금 정보
- 교수 정보
- 강의 정보

까지 함께 관리해야 한다면 단순 파일만으로는 관리가 어려워집니다.

이때 여러 데이터를 구조적으로 저장하고 관리하는 것이 데이터베이스입니다.

---

## 왜 데이터베이스가 필요한가

데이터가 적을 때는 메모장이나 Excel 파일만으로도 관리할 수 있습니다.

하지만 데이터가 많아지면 문제가 생깁니다.

### 1. 같은 데이터가 여러 곳에 저장될 수 있다

```text
학생정보.xlsx
수강정보.xlsx
등록금정보.xlsx
```

세 파일에 같은 학생 이름과 학번이 반복해서 들어갈 수 있습니다.

이렇게 같은 데이터가 여러 곳에 반복 저장되는 것을 **데이터 중복**이라고 합니다.

### 2. 데이터가 서로 달라질 수 있다

학생이 이름을 변경했다고 해봅시다.

한 파일에서는 이름을 수정했지만 다른 파일에서는 수정하지 않았다면 같은 학생의 정보가 서로 달라집니다.

이를 **데이터 불일치**라고 합니다.

### 3. 여러 사람이 동시에 사용하기 어렵다

학교 시스템은 한 사람만 사용하는 것이 아닙니다.

```text
학생
교수
교직원
관리자
```

여러 사용자가 동시에 데이터를 조회하고 수정합니다.

데이터베이스는 이런 동시 사용을 관리할 수 있어야 합니다.

### 4. 데이터를 안전하게 관리해야 한다

모든 사용자가 모든 데이터를 볼 수 있어서는 안 됩니다.

예를 들어 학생은 자신의 성적을 볼 수 있지만 다른 학생의 성적을 수정해서는 안 됩니다.

따라서 데이터베이스에서는 사용자별로 접근 권한을 관리합니다.

---

## 데이터베이스의 기본 구조

데이터베이스를 가장 단순하게 보면 다음과 같습니다.

```text
Database
├─ 학생 데이터
├─ 교수 데이터
├─ 강의 데이터
├─ 수강 데이터
└─ 성적 데이터
```

이 데이터들은 서로 독립적으로 존재하지 않고 관계를 가질 수 있습니다.

예를 들어

```text
학생
  ↓ 수강
강의
  ↓ 담당
교수
```

처럼 서로 연결됩니다.

이러한 관계를 이용하면 여러 데이터를 함께 조회할 수 있습니다.

---

## 데이터베이스와 데이터의 차이

둘은 비슷해 보이지만 의미가 다릅니다.

| 구분 | 의미 |
| --- | --- |
| 데이터 | 하나하나의 사실이나 값 |
| 데이터베이스 | 관련된 데이터를 체계적으로 모아 둔 집합 |

예를 들어

```text
김철수
1001
컴퓨터공학과
2학년
```

각각은 데이터입니다.

이 데이터를 학생별로 구조화하여 저장한 전체 저장소는 데이터베이스입니다.

---

## 데이터베이스와 일반 파일의 차이

| 구분 | 일반 파일 | 데이터베이스 |
| --- | --- | --- |
| 데이터 구조 | 파일마다 다를 수 있음 | 일정한 구조로 관리 |
| 데이터 중복 | 발생하기 쉬움 | 중복을 줄일 수 있음 |
| 동시 사용 | 제한적 | 여러 사용자 지원 |
| 검색 | 직접 파일을 찾아야 함 | 질의를 이용해 검색 |
| 보안 | 단순한 파일 권한 | 사용자·권한 관리 가능 |
| 무결성 | 유지하기 어려움 | 제약조건으로 관리 가능 |
| 복구 | 직접 백업 필요 | 복구 기능 제공 가능 |

<blockquote class="prompt-warning">
<p>데이터베이스는 단순히 데이터가 많이 저장된 파일을 의미하지 않습니다. 데이터를 일정한 구조와 규칙에 따라 관리한다는 점이 핵심입니다.</p>
</blockquote>

## 데이터베이스의 대표적인 특징

### 1. 실시간 접근성

사용자가 필요할 때 데이터를 바로 조회할 수 있어야 합니다.

예를 들어 은행 앱에서 계좌 잔액을 확인하면 현재 저장된 계좌 정보를 바로 조회합니다.

### 2. 계속적인 변화

데이터베이스의 데이터는 계속 추가되고 수정되고 삭제됩니다.

```text
INSERT
UPDATE
DELETE
```

같은 작업이 반복적으로 발생합니다.

### 3. 동시 공유

여러 사용자가 같은 데이터베이스를 동시에 사용할 수 있습니다.

예를 들어 온라인 쇼핑몰에서는 수많은 사용자가 동시에 상품을 조회하고 주문합니다.

### 4. 내용에 의한 참조

데이터가 저장된 물리적 위치를 직접 알 필요 없이 원하는 조건을 이용하여 데이터를 찾습니다.

예를 들어

```text
이름이 김철수인 학생
급여가 3000 이상인 직원
컴퓨터공학과 학생
```

처럼 데이터의 내용이나 조건으로 조회할 수 있습니다.

## 데이터베이스에서 자주 나오는 용어

### Database

데이터를 구조적으로 저장한 전체 저장소입니다.

### DBMS

Database Management System의 약자입니다.

데이터베이스를 생성하고 관리하는 소프트웨어입니다.

대표적으로 다음이 있습니다.

```text
MySQL
PostgreSQL
Oracle Database
Microsoft SQL Server
SQLite
```

### Table

데이터를 행과 열 형태로 저장하는 구조입니다.

### Row

하나의 데이터 항목입니다.

```text
1001 | 김철수 | 컴퓨터공학 | 2
```

한 학생의 정보 전체가 하나의 Row가 될 수 있습니다.

### Column

데이터의 속성을 의미합니다.

```text
학번
이름
학과
학년
```

각 항목이 Column입니다.

### Schema

데이터베이스의 구조를 정의한 것입니다.

어떤 테이블이 존재하는지, 각 테이블에 어떤 열이 있는지 등을 나타냅니다.

---

## 데이터베이스와 DBMS는 다르다

시험에서 자주 혼동하는 부분입니다.

```text
Database
= 실제 데이터가 저장되는 공간

DBMS
= Database를 관리하는 소프트웨어
```

예를 들어

```text
학생 정보
강의 정보
성적 정보
```

가 저장된 것은 데이터베이스이고,

이를 관리하는 MySQL이나 Oracle은 DBMS입니다.

<mark>데이터베이스는 데이터이고, DBMS는 그 데이터를 관리하는 시스템입니다.</mark>

---

## SQL은 어디에 들어가는가

SQL은 데이터베이스 자체가 아닙니다.

SQL은 관계형 데이터베이스에 저장된 데이터를 다루기 위한 언어입니다.

```text
Database
    ↑
   DBMS
    ↑
   SQL
```

사용자는 SQL을 이용하여 DBMS에 명령을 전달합니다.

예를 들어

```sql
SELECT name
FROM student;
```

는 student 테이블에서 학생 이름을 조회하는 SQL입니다.

전체 흐름은 다음과 같습니다.

```text
사용자
  ↓ SQL
DBMS
  ↓
Database
```

---

## 관계형 데이터베이스

현재 가장 널리 사용되는 데이터베이스 형태 중 하나는 **관계형 데이터베이스(Relational Database)** 입니다.

관계형 데이터베이스에서는 데이터를 주로 테이블 형태로 저장합니다.

예를 들어 학생 테이블이 있습니다.

```text
STUDENT

student_id | name   | department
1          | 김철수 | 컴퓨터공학
2          | 이영희 | 통계학
```

그리고 수강 테이블이 있습니다.

```text
ENROLLMENT

student_id | course_id
1          | 101
1          | 102
2          | 101
```

두 테이블은 `student_id`를 이용하여 연결할 수 있습니다.

이처럼 데이터 사이의 관계를 이용하여 데이터를 관리하는 것이 관계형 데이터베이스의 핵심입니다.

---

## 데이터베이스의 주요 기능

데이터베이스에서는 보통 다음 작업이 이루어집니다.

### 조회

저장된 데이터를 찾습니다.

```sql
SELECT *
FROM student;
```

### 삽입

새로운 데이터를 추가합니다.

```sql
INSERT INTO student
VALUES (3, '박민수', '경영학');
```

### 수정

기존 데이터를 변경합니다.

```sql
UPDATE student
SET department = '통계학'
WHERE student_id = 3;
```

### 삭제

기존 데이터를 제거합니다.

```sql
DELETE FROM student
WHERE student_id = 3;
```

이 네 가지 작업을 묶어서 **CRUD**라고 표현하기도 합니다.

```text
Create
Read
Update
Delete
```

## 데이터베이스를 사용하는 대표적인 분야

데이터베이스는 대부분의 정보 시스템에서 사용됩니다.

```text
은행
→ 고객, 계좌, 거래내역

쇼핑몰
→ 회원, 상품, 주문, 결제

학교
→ 학생, 교수, 강의, 성적

병원
→ 환자, 진료, 예약

SNS
→ 사용자, 게시글, 댓글, 팔로우
```

서비스에서 데이터를 지속적으로 저장하고 조회해야 한다면 대부분 데이터베이스가 필요합니다.

---

## 잘 놓치는 핵심

### 1. 데이터베이스와 DBMS는 같은 것이 아니다

```text
Database = 데이터의 집합
DBMS = Database를 관리하는 시스템
```

MySQL, Oracle, PostgreSQL은 데이터베이스 그 자체가 아니라 DBMS입니다.

### 2. SQL도 데이터베이스가 아니다

SQL은 데이터베이스를 조작하기 위한 언어입니다.

```text
SQL → DBMS → Database
```

의 관계로 기억하면 쉽습니다.

### 3. 테이블은 데이터베이스 전체가 아니다

하나의 데이터베이스 안에는 여러 개의 테이블이 존재할 수 있습니다.

```text
Database
├─ STUDENT
├─ PROFESSOR
├─ COURSE
└─ ENROLLMENT
```

### 4. 데이터베이스의 핵심은 저장만이 아니다

단순 저장이 목적이라면 일반 파일도 사용할 수 있습니다.

데이터베이스의 핵심은

```text
저장
조회
수정
공유
무결성
보안
동시성
복구
```

를 체계적으로 관리하는 것입니다.

### 5. 데이터베이스는 계속 변한다

데이터베이스는 한 번 만들어 놓고 끝나는 정적인 저장소가 아닙니다.

새로운 데이터가 추가되고 기존 데이터가 수정되며 필요 없는 데이터가 삭제됩니다.

## 시험·면접

### 핵심 암기

```text
데이터베이스
= 서로 관련된 데이터를 체계적으로 저장하고 관리하는 데이터의 집합

DBMS
= 데이터베이스를 관리하는 소프트웨어

SQL
= 관계형 데이터베이스를 다루는 언어
```

### 데이터베이스의 대표적인 특징

```text
실시간 접근성
계속적인 변화
동시 공유
내용에 의한 참조
```

### 자주 나오는 구분

```text
Database ≠ DBMS
Database ≠ SQL
DBMS ≠ SQL
```

### 면접에서 간단하게 답한다면

> 데이터베이스는 여러 사용자가 함께 사용할 데이터를 구조적으로 저장하고 관리하는 데이터의 집합입니다. 단순 파일과 달리 데이터 중복과 불일치를 줄이고, 동시 접근, 무결성, 보안과 같은 기능을 체계적으로 관리할 수 있습니다.

```text
학생
교수
강의
수강
성적
```

```text
MySQL

```

```sql
SELECT *

```

전체 관계는 다음과 같습니다.

```text
사용자
  ↓
SQL
  ↓
DBMS
  ↓
Database
  ├─ STUDENT
```

이 구조가 데이터베이스를 공부할 때 가장 먼저 잡아야 할 큰 그림입니다.
